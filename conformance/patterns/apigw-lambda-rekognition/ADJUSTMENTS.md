# Adjustments

This directory is the `apigw-lambda-rekognition` pattern of [aws-samples/serverless-patterns](https://github.com/aws-samples/serverless-patterns/tree/deb84afac5425dfb4cabbc3c33f7a11fa4a71555/apigw-lambda-rekognition) at commit `deb84af`, copied with the repository's MIT-0 licence (`LICENSE`). Every change from that commit is below; nothing else differs.

| File | Change | Reason |
|---|---|---|
| `main.tf` | a `terraform` block added, with `required_providers.aws` `hashicorp/aws` at `6.68.0` | Provider override. The pattern pins no provider; 6.68.0 is the version every conformance suite pins and caches. |
| `main.tf` | `s3_use_path_style`, `skip_credentials_validation` and `skip_requesting_account_id`, each `true`, added to the `provider "aws"` block | Provider override. The settings `docs/guide/terraform.md` gives for an IP-literal endpoint: without them the provider reads the bucket's tags through S3 Control at `<account>.127.0.0.1`, which cannot resolve. |
| `main.tf` | `aws_lambda_permission.allow_api_gateway.source_arn` `"${aws_api_gateway_rest_api.api.execution_arn}/*/*"` becomes `"arn:aws:execute-api:${var.region}:${data.aws_caller_identity.current.account_id}:${aws_api_gateway_rest_api.api.id}/*/*"`, and `data "aws_caller_identity" "current" {}` is added after it | Provider override, its consequence. With `skip_credentials_validation` the provider has no account id, so `execution_arn` reads `arn:aws:execute-api:us-east-1::<api-id>`, no invocation's source ARN matches the permission, and every call is refused (`docs/guide/apigateway.md`, Terraform). On AWS the two values are equal. |
| `main.tf` | both functions' `runtime` `python3.14` becomes `python3.13` | Runtime. understudy pins no `python3.14` base image; `python3.13` is the newest Python runtime it runs. |
| `terraform.tfvars` | added, with `region = "us-east-1"` and `prefix = "understudy"` | Prompts. The README answers `var.prefix` and `var.region` at the prompts of `terraform apply` and `terraform destroy`; the suite runs Terraform without input, so the answers are given as a variables file. |

The README's test (Testing) has four steps. `conformance/patterns/checks/apigw-lambda-rekognition.sh` runs step 2: the POST to the API, through understudy's path form `/_understudy/execute-api/<api-id>/dev/generate-presigned-url` because the `api_gateway_endpoint_url` output names amazonaws.com, wanting 200 and a `presigned_url` for `image.png` in the pattern's bucket. The other steps are not run. Step 1 subscribes a mailbox to the SNS topic. Step 3 PUTs an image to the presigned URL, which the function signs for `https://s3.<region>.amazonaws.com` (its client sets that `endpoint_url` in `generate_presigned_url.zip`), so the PUT would leave the machine; the code is not changed. Step 4, the Rekognition call from the S3-triggered function, follows from step 3 (`docs/research/apigateway-rest.md` 12.7).
