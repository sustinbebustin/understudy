## Wave 5: broadening and platform

Contracts T19 to T24 set for later tasks, and follow-ups whose design belongs to the task that first needs them.

- **Pending aws-chunked trailers** (the first handler that reads a trailer through `smithy.Body`; T39's UploadPart reads it from its `awschunked.Reader`). Handlers see only `smithy.Body`, whose `Trailer(name) (string, bool)` cannot tell a trailer still pending (before EOF) from an absent one; `restbind.Body.Deferred` has the three states, but `internal/service` cannot import `restbind`. Replace `Trailer` with a three-state answer (a sum of `Pending`, `Absent` and `Sent{Value}`), implement it in `restbind.Body` (dropping `Deferred` and `PendingError`), `edge.requestBody`, `gen.TextBody`, the generated `exampleBody` and the test bodies, and assert `Pending` through the interface in `TestTrailerBoundMemberResolvesAtEOF`. Left for the first handler that reads a trailer, which designs the call site.
- **Rejected rpcv2Cbor requests** (T31). The edge has no claim that ends routing and answers with the claiming codec's `EncodeError`, so a request the rpcv2Cbor codec rejects (not a POST, a wrong Content-Type, `X-Amzn-Target`) maps to `Declined` and falls through to rules 6 to 8; one with `X-Amz-Target` gets the Unclaimed codec's awsJson body, which a CBOR client cannot decode (`wire-cbor.md 5.2`). Add an `edge.Claim` variant for it and update `rpcv2cbor/doc.go`'s Rejected paragraph; CloudWatch is the first rpcv2Cbor service.
- **awsQuery error envelope on the descriptor** (T26, T30, T31). `errorEnvelopeOf` in `internal/protocol/awsquery/codec.go` holds the `ErrorResponse` namespace and the empty `Detail` by service id (CloudWatch, IAM, SQS), because no `dev.understudy` trait and no `registry.Service` field carries them. Moving them into the overlays needs a new trait, which is an ADR 0002 amendment.
- **Version-less legacy SQS Query requests** (T26). The awsQuery codec finds the service by `Version` alone, so the API reference's own SendMessage example, which has none, is declined (`TestSQSDocumentedFormWithoutVersionIsDeclined`). If a recording shows SQS accepting such requests, the edge can confirm the service from the SigV4 signing name on a queue path.
- **SNS dead letters** (T27, T35). `delivery.Request.DLQ` names the queue only, so the outbox dead-letters the target's own payload; for an SNS-to-Lambda subscription AWS sends the SQS-style notification envelope (LocalStack `test_redrive_policy_lambda_subscription`), not the Lambda `Records` event. Replace `DLQ` with a `*DeadLetter{Queue, Body, Attributes, GroupID, DedupID}` that SNS builds with `service/sns/envelope`; the outbox sends it verbatim plus the EventBridge attributes it adds, and `TestSNSToLambda` asserts the envelope body.
- **SNS FIFO publish order** (T35). The kernel calls `Deliver` after the source cell unlocks, so two publishes to one message group can reach `Outbox.Enqueue` in the opposite order to their commits. Serialize per group in SNS, or have the kernel deliver in commit order.

Generated `BucketAccess() (string, *string)` and `ConfigID() string` methods on the inputs, and optionally `SetChecksums`/`Checksums` on the shapes carrying the x-amz-checksum-* members, would let one generic binder replace them.
- **IAM path pattern in the overlay** (codegen, iamapi, IAM). `CreateRole` and `CreateUser` check `Path` in the handler with `aws.ValidIAMPath`, which the credential store and the access recorder also apply ("Credential minting" above). A `patternValidator` on `com.amazonaws.iam#pathType` would cover `NewPath` and the List operations' `PathPrefix` too, and retire `iam.checkPath`, once its pattern is shown to accept exactly what `aws.ValidIAMPath` accepts.
- **GetSessionToken with temporary credentials under sigv4 parse** (kernel, edge, STS). AWS refuses `GetSessionToken` signed with session credentials. Under `sigv4: verify` STS now refuses it (pre-tag wave 1), reading the signing key from `kernel.Call.VerifiedAuth`. Under `sigv4: parse` the call names no key, so the refusal there needs the edge to pass the parsed key's `identity.Minted.Lifetime` to the kernel; the coverage note says so.
- **STS PolicyArns limit in the overlay** (codegen, STS; optional). A `smithy.api#length {max: 10}` on `AssumeRoleRequest$PolicyArns` would replace the handler check, but the generated message echoes the list, and how AWS renders a list of structures is unrecorded.
- **Kernel holding marker** (kernel). `Call.holding` is shared by every goroutine that uses the call, so Lambda guards its asynchronous log deliveries with a per-attempt mutex. A child call for writes, or a per-goroutine marker, would make the guard unnecessary.
- **AWS host names for S3.** Closed 2026-10-13: the AWS names are dropped from ADR 0013 (pre-tag review amendment); the configuration and host policy are unchanged.
- **Pinned model commit in the unknown-operation warning** (cmd/vendor, edge; optional). The pinned api-models-aws commit lives only in `internal/cmd/vendor` (a main package); the warning could name it once an importable package exposes it.
- **Secret dates on DeleteSecret and RestoreSecret** (Secrets Manager). Whether scheduling a deletion or restoring a secret advances `LastChangedDate` is unrecorded; they leave it as it was. A recording, or a `fidelity.Switch` labelled inferred, settles it.
- **Recordings for inferred texts** (human runs). The SNS `DeliveryPolicy` refusals and the Publish duplicate-key refusal (sns.md 7.3, 4.1), the STS session-policy refusals, the KMS policy-too-long and invalid-marker texts, and S3's refusal of `response-*` overrides on an unsigned GetObject carry understudy's own text.
- **DynamoDB table ARNs in the Go SDK suite** (conformance). BatchGetItem and GetItem naming a table by ARN with `ReturnConsumedCapacity`, reading `Responses[tableArn]`, have unit tests only. The suite runs DynamoDB only when the DynamoDB Local licence is accepted, which an agent run does not do.

Decisions this round took instead of changing code:

- Function URL responses get no `X-Content-Type-Options` or `Content-Security-Policy`: the function sets its own headers, and a sandbox would break an HTML app served from a function URL. The `<id>.lambda-url.<region>.<base>` host is its own origin; the path fallback shares understudy's, and its pages are refused AWS API calls by the edge.
- `docs/plan/PHASE1-PLAN.md` records what each wave's task owned, so the DynamoDB files added since (`table.go`, `tablekey.go`, `sse.go`, `local_client.go`, `echo.go`) are not added to its file lists.

## Hardening round 3

Follow-ups the hardening round 3 integrator did not close.

- **Admin API from function containers in-container** (edge, server, Lambda launcher; security). Decided 2026-10-13: kept for the first tag; the admin token is the control (ADR 0011 pre-tag review amendment). The design notes below are the phase 2 option. In the `InContainer` topology functions call the main listener, which binds `0.0.0.0`, so a function reaches the whole admin API there. The fix is a peer-address check on the main listener that gives a running function container's IP the container listener's treatment (admin only for `GET /_understudy/v1/health` and `/clock`, `LocalHosts`), with the IP known before the function's init code can dial out, or peers on the function network with no known IP refused. Optionally, a container listener on its own port for well-behaved functions, with `topology.Addresses.NeedsContainerListener` replaced by a placement sum type. ADR 0011 (hardening round 3 amendment) records the exposure; an admin token with `--allow-unauthenticated-aws-api` closes it in the container for users who run untrusted function code. On Docker Desktop `serve` refuses a token on the default loopback listener, so the exposure stays there (ADR 0011, pre-tag documentation fixes amendment).
- **Outbox sequencer held by request-phase latency** (kernel, outbox). A request-phase latency rule that matches an attempt's target call holds the whole sequencer for its wall time, because `kernel.Invoke` evaluates the rule and waits before returning. `kernel.Invoke` would report the request-phase decision before it waits, so the outbox could move that call to its own goroutine. Recorded in `internal/outbox/doc.go` and ADR 0018 (hardening round 3 amendment).
- **Idle `--persist` checkpoints** (kernel, store, fault, identity, server). The 30 s checkpoint takes the gate exclusively and digests the whole state even when nothing changed. Skipping the cut needs a kernel-wide revision counter, bumped on every committed mutation, partition delete, reset and import, fault-store change and identity-store change; summing `store.Cell.Rev` misses all but the first. `Cell.Rev` stays as that counter's per-cell part; the `Tx.Unchanged` doc no longer promises anything about persistence.
- **Shared function ARN** (aws, SNS, S3 notify, Lambda, EventBridge). One `FunctionARN{ARN; Name, Qualifier}` with a parser and `String` would replace the function-ARN reading in `sns/subscriptions.go`, `s3/notify/config.go` (which still accepts any number of qualifiers), Lambda's `resolve.go`, `config.go`, `resourcepolicy.go`, `code.go`, `validate.go`, the format sites in `resolve.go` and `invoke.go`, `launcher/spec.go` (which hard-codes the aws partition) and EventBridge's `functionOf`. A change across five packages, each with its own error texts to keep.
- **CloudWatch Logs name-length texts** (codegen, logs). `CreateLogGroup` and `CreateLogStream` with over-length names answer the generated validator's generic text; AWS answers "Invalid LogGroup or LogStream, both must have length less than or equal to 512." (AWS-recorded, secrets-logs-events-alarms.md). A fixed-message validation style in `internal/codegen` beside `coral`, `parameter`, `missingParameter` and `snsParameter`, with rules in `codegen/overlays/logs.json` and `logsapi` regenerated, would send it.
- **Root GetUser empty members** (codegen, IAM; carried from hardening round 1). Overlays can add traits but not remove `required`, so leaving out `User.Path` and `User.UserName` needs a codegen trait (or honouring `smithy.api#clientOptional`, which the vendored models use widely) before `iamapi` is regenerated and `iam/view.go` sets them as pointers.
- **Byte-preserving policy statements** (policydoc, SQS, SNS). SQS (`queuePolicy`, `permission`, `principal`, `oneOrMany`) and SNS (`policyStatements`, `storeStatements`, `sidOf`, `oneOrMany`) each edit stored policy statements; one editor on `document.Map` in `internal/policydoc` (stored text with `Sids`, `Append`, `RemoveSid`) would serve both.
- **Streaming snapshot loads** (snapshot; optional). `snapshot.Read` holds an archive, embedded blobs included, in memory, which is why `snapshotMaxBytes` (decided 2026-10-13, ARCHITECTURE.md 13) stops at 4 GiB. Streaming embedded blobs into the blob store during the load would lift that ceiling.
- **Hot-reload roots** (config, server; optional). A binding made through the admin API must name a directory owned by the user running understudy; allowed roots in the configuration (such as `lambda.hotReloadRoots`) would also stop another local user binding a directory of that user's, such as their home.
- **S3 lifecycle transition paths** (S3; needs a recording). Transitions that break the storage-class paths (GLACIER then ONEZONE_IA) are refused only by the storage-duration check, with understudy's text. AWS's answer, as a Terraform write-up quotes it (zenn.dev/thaim, 2024-04), is "'Days' in the 'Transition' action for StorageClass 'GLACIER' for filter '(prefix=)' must be greater than 'Days' in the 'Transition' action for StorageClass 'ONEZONE_IA' for filter '(prefix=)'". The parity backlog (R12 step 12) lists the captures that settle the lifecycle texts first.
- **No-answer timeouts for other admin clients** (admin; only if needed). The CLI tells a listener that took a call but sent no answer from one that is unreachable; `admin.UnreachableError` still says to start a server. If other `admin.Client` users hit `ResponseHeaderTimeout`, that distinction belongs in the `admin` package.

Decisions this round took instead of changing code:

- `internal/edge` imports the public `admin` package (standard library only) for the JSON error envelope it answers `/_localstack/` paths with; ARCHITECTURE.md section 2 and `internal/ref/deps_test.go` allow the edge.
- Docker-tagged tests resolve the socket through `internal/config/configtest.EngineClient`, a test helper over `config.LoadHost`, rather than `internal/docker/dockertest`, which may import only `docker`; `docker.ParseDockerHost` is gone.
- `aws.ScopeOf` refuses an ARN without a served partition or with an empty region. SQS, Lambda and Logs read some ARNs without those checks before; such ARNs now name no scope there, as they already did in SNS, S3, EventBridge and the outbox.

## Pre-tag wave 1

Follow-ups the pre-tag wave 1 integrator did not close.

- **DynamoDB conformance runs** (human run). Agents never accept the DynamoDB Local licence (`docs/brief/phase1-brief.md`), so no wave 1 run covered DynamoDB: every suite skipped it and `e2e-pipeline` did not run. Since pre-tag wave 2 every `run.sh` needs exactly one of `UNDERSTUDY_ACCEPT_DDB_LOCAL_LICENSE=1` and `CONFORMANCE_DYNAMODB=0` (both or neither exits 2), and its summary lists every skip with its reason; under the opt-out `e2e-pipeline` runs its tests that take no lock. Run `UNDERSTUDY_ACCEPT_DDB_LOCAL_LICENSE=1` with each `conformance/*/run.sh`, with `SIGV4=verify conformance/e2e-pipeline/run.sh`, and with `just test-docker`, and expect no DynamoDB test among the summaries' `SKIP` lines.
- **SigV2 presigned URLs and the clock** (edge; S3). A SigV2 URL carries only its `Expires` instant, not when it was signed, so the edge compares it with emulator time directly: it expires as intended only while the clock has not moved away from wall time since it was signed. SigV4 URLs are placed on the emulator timeline. `docs/configuration.md` says so and tells users to presign with SigV4 when a test moves the clock.
- **Admin answers wait under verify** (edge). `X-Amz-Date` has whole-second precision, so under `sigv4: verify` a clock change takes effect on the timeline from the next whole second, and every admin answer waits until the latest change has taken effect (`edge/timeline.go` `settledWriter`), up to one second per call. A finer timeline would need a signing instant finer than the header carries.
- **Actions audits** (SQS, SNS, IAM, KMS, Secrets Manager, CloudWatch, DynamoDB). These services declare no secondary actions, so each operation records its whole generated list (ADR 0004 pre-tag amendment), which over-grants. Each needs per-input decisions and a `kerneltest.UndeclaredActions` guard test, as S3, Lambda, STS, EventBridge and Logs have: `kms:ReEncryptTo` on `ReEncrypt` always; `iam:PassRole` on `AddRoleToInstanceProfile` always (same prefix in IAM); `sqs:ReceiveMessage`, `sqs:DeleteMessage`, `sqs:GetQueueAttributes` and `sqs:SendMessage` on `StartMessageMoveTask`, and `sqs:GetQueueAttributes` on `CancelMessageMoveTask` and `ListMessageMoveTasks`, always; the tag-on-create actions (`sqs:TagQueue`, `kms:TagResource`, `kms:PutKeyPolicy` with a policy, SNS `CreateTopic` with tags or a data protection policy, `secretsmanager:TagResource` and replication actions on `CreateSecret`, `iam:Tag*` on the create calls, `cloudwatch:TagResource` on `PutMetricAlarm`) only when the request sends them; the DynamoDB replication actions never.
- **iam:PassRole for SNS delivery roles** (SNS). `CreateTopic`, `SetTopicAttributes`, `Subscribe` and `SetSubscriptionAttributes` need a `WithResources` that returns the IAM role ARNs in their attributes (`*FeedbackRoleArn`, `SubscriptionRoleArn`), so `iam:PassRole` is recorded on those roles. The policy guide lists the gap.
- **Version actions missing from the generated lists** (codegen, S3). A versioned `HeadObject` needs `s3:GetObjectVersion` and a versioned `GetObjectAttributes` `s3:GetObjectVersionAttributes`, but the Service Reference does not list them for those operations, so the binding cannot declare them and the record never carries them. A codegen overlay that extends an operation's action list would close it; the policy guide lists both gaps.
- **Logs CreateLogStream resource** (Logs; needs the Service Reference). `CreateLogStream` touches the stream ARN, so a generated policy grants `logs:CreateLogStream` on the stream, not the log group. Check the action's resource type in the Service Reference (the vendored `third_party/aws-service-reference/actions.json` keeps action lists only, and this wave had no network) and touch the log group if that is what it names.
- **Lambda layers' action** (Lambda). When Lambda accepts layers, declare `lambda:GetLayerVersion` and touch the layer version ARNs in the `CreateFunction` and `UpdateFunctionConfiguration` resolvers.
- **Terraform's other user files under sealed** (scripts/sealed; needs a decision). Terraform still reads `~/.terraform.d/credentials.tfrc.json` (written by `terraform login`, not covered by `TF_CLI_CONFIG_FILE`) and, without a `provider_installation` block, the implied local mirror directories (`~/.terraform.d/plugins`, `~/.local/share/terraform/plugins`). Closing either means overriding `HOME` or writing a `provider_installation` block into the managed config.
- **Fixed conformance ports and build paths** (conformance). Only `aws-cli` and `terraform` take `CONFORMANCE_PORT`; the other runners serve on fixed ports (45661 to 45666), and every runner builds its binary at a fixed `.build/conformance/<suite>/understudy` (the work directories are `mktemp -d` under it, except `terraform`'s fixed `run/`), so two runs of one suite collide. Pre-tag wave 2 saw another process hold 45664 for a moment and fail an `aws-cli` run to bind. Agents waiting for a run should wait on the port, not on `pgrep -f run.sh`, which matches the waiting shell itself.
