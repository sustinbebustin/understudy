## Wave 5: broadening and platform

Contracts T19 to T24 set for later tasks, and follow-ups whose design belongs to the task that first needs them.

- **Pending aws-chunked trailers** (the first handler that reads a trailer through `smithy.Body`; T39's UploadPart reads it from its `awschunked.Reader`). Handlers see only `smithy.Body`, whose `Trailer(name) (string, bool)` cannot tell a trailer still pending (before EOF) from an absent one; `restbind.Body.Deferred` has the three states, but `internal/service` cannot import `restbind`. Replace `Trailer` with a three-state answer (a sum of `Pending`, `Absent` and `Sent{Value}`), implement it in `restbind.Body` (dropping `Deferred` and `PendingError`), `edge.requestBody`, `gen.TextBody`, the generated `exampleBody` and the test bodies, and assert `Pending` through the interface in `TestTrailerBoundMemberResolvesAtEOF`. Left for the first handler that reads a trailer, which designs the call site.
- **Rejected rpcv2Cbor requests** (T31). The edge has no claim that ends routing and answers with the claiming codec's `EncodeError`, so a request the rpcv2Cbor codec rejects (not a POST, a wrong Content-Type, `X-Amzn-Target`) maps to `Declined` and falls through to rules 6 to 8; one with `X-Amz-Target` gets the Unclaimed codec's awsJson body, which a CBOR client cannot decode (`wire-cbor.md 5.2`). Add an `edge.Claim` variant for it and update `rpcv2cbor/doc.go`'s Rejected paragraph; CloudWatch is the first rpcv2Cbor service.
- **awsQuery error envelope on the descriptor** (T26, T30, T31). `errorEnvelopeOf` in `internal/protocol/awsquery/codec.go` holds the `ErrorResponse` namespace and the empty `Detail` by service id (CloudWatch, IAM, SQS), because no `dev.understudy` trait and no `registry.Service` field carries them. Moving them into the overlays needs a new trait, which is an ADR 0002 amendment.
- **Version-less legacy SQS Query requests** (T26). The awsQuery codec finds the service by `Version` alone, so the API reference's own SendMessage example, which has none, is declined (`TestSQSDocumentedFormWithoutVersionIsDeclined`). If a recording shows SQS accepting such requests, the edge can confirm the service from the SigV4 signing name on a queue path.
- **SNS dead letters** (T27, T35). `delivery.Request.DLQ` names the queue only, so the outbox dead-letters the target's own payload; for an SNS-to-Lambda subscription AWS sends the SQS-style notification envelope (LocalStack `test_redrive_policy_lambda_subscription`), not the Lambda `Records` event. Replace `DLQ` with a `*DeadLetter{Queue, Body, Attributes, GroupID, DedupID}` that SNS builds with `service/sns/envelope`; the outbox sends it verbatim plus the EventBridge attributes it adds, and `TestSNSToLambda` asserts the envelope body.

## Hardening round 3

Follow-ups the hardening round 3 integrator did not close.

- **Admin API from function containers in-container** (edge, server, Lambda launcher; security). Decided 2026-10-13: kept for the first tag; the admin token is the control (ADR 0011 pre-tag review amendment). The design notes below are the phase 2 option. In the `InContainer` topology functions call the main listener, which binds `0.0.0.0`, so a function reaches the whole admin API there. The fix is a peer-address check on the main listener that gives a running function container's IP the container listener's treatment (admin only for `GET /_understudy/v1/health` and `/clock`, `LocalHosts`), with the IP known before the function's init code can dial out, or peers on the function network with no known IP refused. Optionally, a container listener on its own port for well-behaved functions, with `topology.Addresses.NeedsContainerListener` replaced by a placement sum type. ADR 0011 (hardening round 3 amendment) records the exposure; an admin token with `--allow-unauthenticated-aws-api` closes it in the container for users who run untrusted function code. On Docker Desktop `serve` refuses a token on the default loopback listener, so the exposure stays there (ADR 0011, pre-tag documentation fixes amendment).
- **Outbox sequencer held by request-phase latency** (kernel, outbox). A request-phase latency rule that matches an attempt's target call holds the whole sequencer for its wall time, because `kernel.Invoke` evaluates the rule and waits before returning. `kernel.Invoke` would report the request-phase decision before it waits, so the outbox could move that call to its own goroutine. Recorded in `internal/outbox/doc.go` and ADR 0018 (hardening round 3 amendment).
- **Idle `--persist` checkpoints** (kernel, store, fault, identity, server). The 30 s checkpoint takes the gate exclusively and digests the whole state even when nothing changed. Skipping the cut needs a kernel-wide revision counter, bumped on every committed mutation, partition delete, reset and import, fault-store change and identity-store change; summing `store.Cell.Rev` misses all but the first. `Cell.Rev` stays as that counter's per-cell part; the `Tx.Unchanged` doc no longer promises anything about persistence.
- **Shared function ARN** (aws, SNS, S3 notify, Lambda, EventBridge). One `FunctionARN{ARN; Name, Qualifier}` with a parser and `String` would replace the function-ARN reading in `sns/subscriptions.go`, `s3/notify/config.go` (which still accepts any number of qualifiers), Lambda's `resolve.go`, `config.go`, `resourcepolicy.go`, `code.go`, `validate.go`, the format sites in `resolve.go` and `invoke.go`, `launcher/spec.go` (which hard-codes the aws partition) and EventBridge's `functionOf`. A change across five packages, each with its own error texts to keep.
- **CloudWatch Logs name-length texts** (codegen, logs). `CreateLogGroup` and `CreateLogStream` with over-length names answer the generated validator's generic text; AWS answers "Invalid LogGroup or LogStream, both must have length less than or equal to 512." (AWS-recorded, secrets-logs-events-alarms.md). A fixed-message validation style in `internal/codegen` beside `coral`, `parameter`, `missingParameter` and `snsParameter`, with rules in `codegen/overlays/logs.json` and `logsapi` regenerated, would send it.
- **Root GetUser empty members** (codegen, IAM; carried from hardening round 1). Overlays can add traits but not remove `required`, so leaving out `User.Path` and `User.UserName` needs a codegen trait (or honouring `smithy.api#clientOptional`, which the vendored models use widely) before `iamapi` is regenerated and `iam/view.go` sets them as pointers.
- **Byte-preserving policy statements** (policydoc, SQS, SNS). SQS (`queuePolicy`, `permission`, `principal`, `oneOrMany`) and SNS (`policyStatements`, `storeStatements`, `sidOf`, `oneOrMany`) each edit stored policy statements; one editor on `document.Map` in `internal/policydoc` (stored text with `Sids`, `Append`, `RemoveSid`) would serve both.
- **Streaming snapshot loads** (snapshot; optional). `snapshot.Read` holds an archive, embedded blobs included, in memory, which is why `snapshotMaxBytes` (decided 2026-10-13, ARCHITECTURE.md 13) stops at 4 GiB. Streaming embedded blobs into the blob store during the load would lift that ceiling.
- **Hot-reload roots** (config, server; optional). A binding made through the admin API must name a directory owned by the user running understudy; allowed roots in the configuration (such as `lambda.hotReloadRoots`) would also stop another local user binding a directory of that user's, such as their home.
- **S3 lifecycle transition paths** (S3; needs a recording). Transitions that break the storage-class paths (GLACIER then ONEZONE_IA) are refused only by the storage-duration check, with understudy's text. AWS's answer, as a Terraform write-up quotes it (zenn.dev/thaim, 2024-04), is "'Days' in the 'Transition' action for StorageClass 'GLACIER' for filter '(prefix=)' must be greater than 'Days' in the 'Transition' action for StorageClass 'ONEZONE_IA' for filter '(prefix=)'". The parity backlog (R12 step 12) lists the captures that settle the lifecycle texts first. Recorded 2026-10-14: the quoted text is AWS's word for word, with `ArgumentName` Days and `ArgumentValue` 60 (`testdata/parity/s3/R12/15-lifecycle-glacier-then-onezone-ia.json`); the order check is still to do (see "Recorded differences from AWS").
- **No-answer timeouts for other admin clients** (admin; only if needed). The CLI tells a listener that took a call but sent no answer from one that is unreachable; `admin.UnreachableError` still says to start a server. If other `admin.Client` users hit `ResponseHeaderTimeout`, that distinction belongs in the `admin` package.

Decisions this round took instead of changing code:

- **SigV2 presigned URLs and the clock** (edge; S3).
