## Wave 5: broadening and platform

Contracts T19 to T24 set for later tasks, and follow-ups whose design belongs to the task that first needs them.

- **Pending aws-chunked trailers** (the first handler that reads a trailer through `smithy.Body`; T39's UploadPart reads it from its `awschunked.Reader`). Handlers see only `smithy.Body`, whose `Trailer(name) (string, bool)` cannot tell a trailer still pending (before EOF) from an absent one; `restbind.Body.Deferred` has the three states, but `internal/service` cannot import `restbind`. Replace `Trailer` with a three-state answer (a sum of `Pending`, `Absent` and `Sent{Value}`), implement it in `restbind.Body` (dropping `Deferred` and `PendingError`), `edge.requestBody`, `gen.TextBody`, the generated `exampleBody` and the test bodies, and assert `Pending` through the interface in `TestTrailerBoundMemberResolvesAtEOF`. Left for the first handler that reads a trailer, which designs the call site.
- **Rejected rpcv2Cbor requests** (T31). The edge has no claim that ends routing and answers with the claiming codec's `EncodeError`, so a request the rpcv2Cbor codec rejects (not a POST, a wrong Content-Type, `X-Amzn-Target`) maps to `Declined` and falls through to rules 6 to 8; one with `X-Amz-Target` gets the Unclaimed codec's awsJson body, which a CBOR client cannot decode (`wire-cbor.md 5.2`). Add an `edge.Claim` variant for it and update `rpcv2cbor/doc.go`'s Rejected paragraph; CloudWatch is the first rpcv2Cbor service.
- **awsQuery error envelope on the descriptor** (T26, T30, T31). `errorEnvelopeOf` in `internal/protocol/awsquery/codec.go` holds the `ErrorResponse` namespace and the empty `Detail` by service id (CloudWatch, IAM, SQS), because no `dev.understudy` trait and no `registry.Service` field carries them. Moving them into the overlays needs a new trait, which is an ADR 0002 amendment.
- **Version-less legacy SQS Query requests** (T26). The awsQuery codec finds the service by `Version` alone, so the API reference's own SendMessage example, which has none, is declined (`TestSQSDocumentedFormWithoutVersionIsDeclined`). If a recording shows SQS accepting such requests, the edge can confirm the service from the SigV4 signing name on a queue path.
- **SNS dead letters** (T27, T35). `delivery.Request.DLQ` names the queue only, so the outbox dead-letters the target's own payload; for an SNS-to-Lambda subscription AWS sends the SQS-style notification envelope (LocalStack `test_redrive_policy_lambda_subscription`), not the Lambda `Records` event. Replace `DLQ` with a `*DeadLetter{Queue, Body, Attributes, GroupID, DedupID}` that SNS builds with `service/sns/envelope`; the outbox sends it verbatim plus the EventBridge attributes it adds, and `TestSNSToLambda` asserts the envelope body.
- **SNS FIFO publish order** (T35). The kernel calls `Deliver` after the source cell unlocks, so two publishes to one message group can reach `Outbox.Enqueue` in the opposite order to their commits. Serialize per group in SNS, or have the kernel deliver in commit order.
- **Docker and DynamoDB Local health** (T33, T38). `admin.Health.Docker` and `DynamoDBLocal` stay absent: `serveradmin.Options` has no source for them, so the first service that runs on each adds the hook.
- **Periodic `--persist` checkpoint** (T44). It takes the lock `serveradmin.Handler` holds over reset, snapshot save and load (through a method the handler exposes), or a checkpoint can cut between a reset's gate and its late data.
- **Admin token and container exposure for `serve`** (T44). `server.Config.AdminToken` lets a non-loopback listener serve the admin API behind a bearer token, but `understudy serve` has no setting for it, so the CLI still listens only on loopback; read it from the environment or the config file rather than a flag, which process listings show. `Exposed{ContainerPublished}` (ARCHITECTURE.md 20) arrives with the topology wiring; `server.ListenError` names both options.
- **CloudWatch query-mode statuses** (T31). Only `ResourceNotFound` carries `statusOverride` 400 (LocalStack snapshot evidence). `DashboardNotFoundError` and `ResourceNotFoundException` may need the same once their JSON status is recorded.
- **S3 POST on an object without `uploadId`** (S3; T39 left it). Route rows require query and header presence only where needed to tell rows apart, so such a POST reaches `CompleteMultipartUpload` and fails validation rather than finding no route. A recording decides; a `routeOverrides` entry in `codegen/services/s3.json` can require `uploadId`.

## Wave 6: protocol corpus, coverage and the first service wave

Follow-ups the wave 6 integrator did not close, with what each needs. No later plan task owns `internal/awserr`, `internal/codegen`, `internal/docker` or `internal/delivery` outright, so the task named is the first that needs the fix.

- **Protocol compliance known failures** (T36 for S3's error members, T45 otherwise). 15 cases are recorded in `internal/protocoltest/skips.json` under `gap` and counted as failed in `docs/coverage.md` (ARCHITECTURE.md 6.4 amendment). Three fixes close them, after which `just protocoltest-baseline` records them passing and the `gap` category can go if nothing else uses it:
  - `internal/awserr`: an error member that holds a structure (`ComplexError` in awsJson1_0, awsJson1_1, awsQuery, restJson1, restXml and rpcv2Cbor, 6 cases). `*awserr.Error` holds flat string `Fields`; it needs a structured member value its renderers write per protocol.
  - `internal/codegen`: modeled defaults written for output members a handler leaves unset (`ServerPopulatesDefaults*`, 5 cases). Generated types hold defaulted members as plain values, so an unset member serializes as its zero value.
  - `internal/codegen`: a null value in a sparse map of sets (`*SparseSetMapAndRetainsNull`, 4 cases). The generated serde reads and writes a sparse map's set values as lists only.
- **SQS redrive and move-task journal edge** (T41). ARCHITECTURE.md 16 asks for a journal edge from the receive that exceeds `maxReceiveCount` to the dead-letter send; today the receive's `APICall` touches the DLQ ARN and the moved message's `Enqueued` cause is that receive's event (`internal/service/sqs/doc.go`). `journal.Delivery` needs a declared `delivery.Mechanism`, a closed set whose members the outbox delivers and Delivery-phase fault rules match; an in-service move is neither, so adding `SQSRedrive` there needs a decision first: a mechanism the outbox and fault validation refuse, or a new journal `Detail` for in-service moves (an ADR 0007 amendment). Once decided, `deadLetter` (receive.go) and the move-task step (movetasks.go) emit it with `kernel.Tx.Record`, which stamps the receive or task event as parent, and `TestRedriveMovesAfterMaxReceiveCount` asserts it.
- **SQS per-change copy of the message list** (T41). `Queue.message(i)` clones the whole `Messages` slice on a queue's first in-place change, so each receive, visibility change or out-of-order delete at a 10,000-message backlog copies the backlog (measured: 1.84 MB per `ReceiveMessage`); an ESM draining a backlog is quadratic. Store messages in fixed-size chunks shared between the stored record and the working copy, so a change copies one chunk, keeping the persisted JSON a flat list; extend `TestSendCostDoesNotGrowWithTheBacklog` with `ReceiveMessage` and `ChangeMessageVisibility`.
- **Edge seam for the synthetic REST services** (T45). `internal/protocoltest` routes the synthetic restJson1 and restXml services through `routeFront`, codecs and the kernel, skipping the edge's body caps, framing and auth parsing (362 cases), because the edge's REST rule knows only the lambda and s3 route tables. An `edge.Options` field for extra REST route tables would let the bench run every suite through `edge.New` and delete `routeFront`.
- **DynamoDB Local port binding** (T37). `internal/docker` has no `ExposedPorts`, `HostConfig.PortBindings` or `NetworkSettings.Ports`, so the Manager reaches Local at its bridge IP, which Docker Desktop does not route (ADR 0014 wave 6 amendment). Add the fields (with the allowing section the `HostConfig` doc requires) and `dockertest` support, publish `8000/tcp` on `127.0.0.1` with an ephemeral host port, read it back from `NetworkSettings.Ports`, keep the container-IP path for `InContainer`, and drop the Docker Desktop caveat from `NotReadyError` and `ddblocal/doc.go`. With `HostConfig.CapAdd`, `ddblocal/egress_docker_test.go` can create its sink through `docker.Client` too.
- **Injecting DynamoDB transaction conflicts** (T37). A fault rule cannot give `TransactionCanceledException` its `CancellationReasons`, so `TransactionConflict` cancellations cannot be injected; the coverage notes of `TransactWriteItems`, `TransactGetItems` and `ExecuteTransaction` say so. It needs structured error members (the awserr item above).
- **Headers on modeled S3 successes** (T36). A handler can set headers only on an error, so `x-amz-bucket-region` reaches a success only where the output models it (HeadBucket); ARCHITECTURE.md 7 is amended to say so. A kernel hook that lets a handler add a header to a modeled success response closes it.
- **The DynamoDB `Disabled` setting's key** (T44). `ddblocal.LicenceError` names "the DynamoDB setting of the understudy configuration (understudy.json, or the file --config names)"; name the exact key once `internal/config` has it.
- **An image-pull work kind** (T38). Lambda image pulls count as `InvocationRunning` in settle diagnostics, since `kernel.WorkKind` is a closed set; add a kind of their own.
- **Top-level alternations in model patterns** (T45). `TranslatePattern` keeps Smithy's find semantics, so a pattern such as `^a|b$` is checked more loosely than AWS checks it; Lambda's `NumericLatestPublishedOrAliasQualifier` is overridden with a whole-value pattern (`codegen/overlays/lambda.json`). A codegen check for top-level alternations would find the others.
- **Unknown ACL enum values** (T36). AWS answers an `AccessControlPolicy` with an unknown `Permission` or grantee `Type` with `MalformedACLError`; the generated enum check answers `InvalidArgument` in the Coral grammar before the handler's check runs, as for every S3 constraint (`internal/service/s3/doc.go`).

## Wave 7: second service wave

Follow-ups the wave 7 integrator did not close. Each needs a seam, a design decision or a recording outside the wave's code.

- **Lambda data plane wiring** (T45). `internal/server/wire.go` builds no `lambda.Execution`, so Invoke answers 501 in the server, and the admin Drainer, HotReloader and ImagePuller hooks reach the Service, whose `Drain` is a no-op. Detect the topology; build the `runtimeapi.Server`, the launcher, the pool (running `pool.Run`) and the code store; call `lambda.NewExecution(lambdaSvc, deps(lambdaapi.Service()), lambda.ExecutionOptions{Pool, Docker: "unix://"+socket, Images: launcher, Code: codestore, Logs: lambda.ContainerLogs(launcher), HotReload: <lambda.hotReload from config>})`, with `Pool` nil when no daemon answers. Give `kernel.New` a forwarding `Linker` set once the Execution exists (`linkTo` in `internal/service/lambda/invoke_test.go` shows the shape; `kerneltest` needs a `Linker` option too). Hook the Execution as Drainer, HotReloader and ImagePuller; list `exec.AsyncQueue()` among the Stateful views (ServiceID `lambda-async`, ARCHITECTURE.md 14.7) and its schema in `Snapshots.Schemas()`; register `lambda.TimerAsync` before `Run`; call `Execution.Close` at shutdown; set `ServiceDeps.Docker` and `Topology`; build `dynamodb.Options` with its `Local`. Then delete `func (*Service) Drain` in `internal/service/lambda/invoke.go` and update `TestAdminUnimplementedHooksAreUnavailable`, whose HotReload and PullImages assertions turn positive.
- **Calls made by function code link to the Invoke call** (journal owner, ADR 0010 amendment). ARCHITECTURE.md 10 and 14.7 link an in-function call, init phase included, to the Invocation event, and a call between invocations to its environment only. `journal.Begin` and `End` take only an `APICall`, events cannot be amended, and `ref.Cause` has no environment-only form, so the Execution parents those calls to the Invoke call (the Invocation event's own parent) and lets calls between invocations root their own trace (`TestCallsWithTheEnvironmentsKeyLinkToTheInvocation`). Either give Invocation events an open and close form (or an `InvocationStarted` detail) plus an environment-only link, or amend ARCHITECTURE.md 10 and 14.7 to the current behavior; then update that test to the ratified contract.
- **Lambda hot reload from the magic bucket** (Lambda control plane; no later task owns `code.go`). ARCHITECTURE.md 14.4 and the T38 spec accept `S3Bucket "hot-reload"` with `S3Key` an absolute path on CreateFunction and UpdateFunctionCode; today the bucket is fetched like any other and the call fails (`hotreload_wiring.go`). It needs a code variant in the state that snapshots carry, a stable placeholder `CodeSha256`, and an entry from the Service into `Execution.startOverlay` (the `overlayDir` hook shows the direction), rebound on `Rearm`. Test: create with the magic bucket, invoke, edit the directory, assert a cold start with the new code.
- **Hot-reload paths inside a container** (topology, launcher). ARCHITECTURE.md 14.4 translates host paths through `GET /containers/<self>/json` mounts when understudy runs in a container; `topology.InContainer` drops the container's mounts and the topology is detected after `ExecutionOptions` are built, so the directory must be given as understudy sees it (`HotReloadBinding`, `hotreload.DirError`). Expose the mounts on `InContainer` and translate in `startOverlay`, or amend 14.4 and the admin hint to say so.
- **Zip runtime images pulled at CreateFunction** (Lambda control plane). ARCHITECTURE.md 14.3 pulls images at CreateFunction and never on first invoke; a zip function's runtime base image is made present on its first Invoke (`resolveImage`, `envs.go`). Pull `launcher.ImageForRuntime` for the declared architecture through the `PullingImage` path at CreateFunction and when `Runtime` or `Architectures` changes, and leave `resolveImage` a lookup that fails with the existing ServiceException.
- **Which digest an image function recorded** (launcher, Lambda state). `ImageCode.Digest` is a repository digest or, for a local build under Docker's classic image store, an image ID; `Execution.pinnedImage` therefore tries `repo@digest` first, which for that one case contacts the registry once per process. Record which kind was stored (`launcher.Image` exposing a pinned reference) so Invoke resolves it directly.
- **Asynchronous destinations, unminted-credential advisory, paused environments** (stretch, T38 follow-up). A discarded asynchronous event is only logged; `DestinationConfig` is stored but nothing is delivered (coverage notes say so). The advisory for a call with credentials no environment minted needs the remote address in `kernel.Linker.Link`. Pausing environments between invocations stays deferred (ADR 0010, F18).
- **Presigned URL verification** (edge or kernel owner, then S3). The edge recognizes a presigned request (`edge/claim.go`) but nothing calls `auth.VerifyPresigned` or `auth.VerifySigV2Presigned`, and `kernel.Call` carries neither the parsed auth nor the query, so a presigned URL never expires (s3.md 12). Verify in the edge with the emulator clock when SigV4 checking is on, or hand S3 the parsed `auth.Auth` and normalized request; then add `internal/service/s3/presign.go` with tests for a valid URL, expiry after a clock advance past `X-Amz-Expires` (403 AccessDenied "Request has expired" with `X-Amz-Expires`, `Expires`, `ServerTime`), `X-Amz-Expires` outside 1..604800, missing parameters (`AuthorizationQueryParametersError`) and a SigV2 query.
- **CopyObject 200-with-error** (kernel owner). A handler cannot produce `kernel.StatusOKFailure`, so a CopyObject error is a plain 4xx before the response starts. Every error the implementation can raise happens before then; a seam is needed only once a copy streams before it can fail.
- **SNS filter policies per account** (SNS). The 10,000-per-account quota is not enforced: state is per account and Region, so no topic write sees the account's count. The Subscribe and SetSubscriptionAttributes coverage notes say so.
- **DynamoDB snapshot journal events** (T15, T16). ARCHITECTURE.md 13 and the ADR 0014 amendment ask for one summary journal event per DynamoDB export, import and reset, with `Origin Internal{Via: Snapshot}`. `journal.Detail` and `AdvisoryKind` are closed sets without a fitting kind, and `kernel.Invoke` refuses a nil parent, so `ExportLate`, `ImportLate` and `ResetLate` (`internal/service/dynamodb/snapshot.go`, `reset.go`) write none. Add a journal `Detail` kind, or a kernel entry point for a parentless `Internal{Via: Snapshot}` call, or amend ADR 0014 to drop the requirement. Then emit one event from each and assert it with a journal query.
- **Recordings for wave 7 texts** (human runs). SNS: R09 items 1, 6, 7, 8 and H1 to H7 settle the `sns.filter-policy.*` switches; the FilterPolicyLimitExceeded text and the same-scope RedrivePolicy text are inferred. S3: XXHASH and SHA512 trailers (R08); SSE-C headers on a read of a non-SSE-C object; a KMS key id without `aws:kms` on an `aws:kms` default bucket; the over-5-GiB copy source text. DynamoDB: the unknown KMS key text on CreateTable and UpdateTable, more than 50 tags, the `aws:` tag-key prefix, `TableNotFoundException`, the tag `ResourceNotFoundException` text, TTL repeat-change refusals, and whether a switch from PAY_PER_REQUEST to PROVISIONED stamps `LastIncreaseDateTime`. Lambda: the Event-mode (1 MB) oversized-request text.

## Wave 9: CLI, wiring and smoke

Follow-ups the wave 9 integrator did not close.

- **Settings serve refuses** (edge, identity, S3, DynamoDB owners, then the CLI). `serve` refuses `sigv4 verify`, `accounts.keys`, `s3.maxObjectBytes` and `dynamodb.registry` by name with exit 2 (`unapplied` in `internal/cli/serve.go`), because `server.Config` has nothing to apply them to: the edge has no SigV4 verify option, `identity.Store` takes no static keys, S3 has no object size cap setting and the DynamoDB proxy no registry setting. Each needs its owner to add the option, then `server.Config` a field, then `serverConfig` a mapping and `unapplied` one row fewer. Until SigV4 verify lands, the coverage note of `InvokeFunctionUrl` ("verified under sigv4 verify") describes a mode serve cannot enter.
- **TLS certificate across restarts** (server). `env --tls` reads the self-signed certificate from the listener's handshake and writes it to the user cache, which meets ADR 0013. serve makes a new certificate at every start, so a CA bundle written before a restart stops trusting the listener; under `--persist`, keep the key and certificate in the data directory and reuse them while valid.
- **TLS listener in health** (admin, server; optional). `admin.Health` names the main listener only, so `env --tls` assumes port 4567 on the endpoint's host unless `--tls-endpoint` says otherwise. Add the TLS listener's URL to health and have `env --tls` read it.
- **Configuration warnings in the banner** (server; optional). serve logs `config.Config.Warnings` before the server starts and doctor shows them, but the banner does not repeat them; `server.Config` would need a field for them.
- **Container markers in config** (config, topology). `config.DetectPlacement` repeats the marker check `topology.RunsInContainer` makes, because `config` may not import `topology`, which imports `docker`. Moving the check into a leaf package both may import, or passing the placement into `config.Load`, removes the copy; the server now calls `topology.RunsInContainer`.
- **Sweep sparing test objects** (docker; optional). `cleanup --all` lists and removes `understudy.dev/managed` objects itself to spare those labeled `understudy.dev/test`. A `docker.Client` sweep option for every owner that spares test objects would replace that loop in `internal/cli/cleanup.go`.
- **Lambda without a pool for another reason** (Lambda; optional). `lambda.errNoDocker` says no Docker daemon is reachable whenever the pool is nil. If a future setting turns Lambda execution off without a pool, `ExecutionOptions` needs a reason field so Invoke names the real cause.

## Conformance round 1

Follow-ups the conformance round 1 integrator did not close.

- **Lambda operations naming their function before fault rules run** (Lambda). Only Invoke binds `kernel.WithResources` (`invokedFunction`), so a resource-scoped request-phase fault rule cannot match any other Lambda operation. Each binding addresses a different ARN (unqualified function, qualified function, alias, mapping), and the kernel touches what `WithResources` returns, so every binding needs its own resolver that names the ARN its handler already touches; doing that across the 47 bindings is a change of its own, with a kernel test per ARN form. - **GetObjectAttributes part list** (S3). `ObjectParts` carries `TotalPartsCount` only; the per-part `Parts` list and its `MaxParts`, `PartNumberMarker`, `NextPartNumberMarker` and `IsTruncated` paging are not returned (`internal/service/s3/attributes.go`). - **JS SDK v3 against DynamoDB** (human run). The round 1 JS run left DynamoDB out because the DynamoDB Local licence was not accepted for it; aws-cli and e2e covered DynamoDB under `--persist`.
