# Roadmap

Where understudy goes after phase 1, ordered by value to the people it is for: teams testing event-driven systems on AWS who want fast, deterministic, free tests of how services interact, including time, failures and permissions. The ordering follows from three facts: the product's bet is fidelity (so trust comes before breadth), the phase 1 workload is a webhook-to-worker pipeline (so the services that sit at its edges come next), and the platform seams listed in [ARCHITECTURE.md section 21](ARCHITECTURE.md#21-phase-2-extension-points) make some items much cheaper than others.

Phase 1, the twelve services and platform features the README describes, is the baseline. Nothing here is scheduled; the order is the priority.

## Phase 2: earn the trust the README asks for

Phase 1 ships every promised feature, but most of the evidence behind its behavior is documentation and inference, not recordings of real AWS. Until that changes, every other item inherits the same uncertainty, so this comes first and is mostly cheaper than any new service.

1. **Recorded parity against real AWS.** In progress (2026-10-26). Recorded: the backlog in `docs/research/s3-checksum-residuals-and-record-backlog.md` (R01 to R18 and the KMS alias, some items in part, as each `notes.md` says) and the matching-engine H cases, captured with the [recording kit](recording-kit.md) on 2026-10-14 and checked in under `testdata/parity/`. Replayed: `internal/parity` replays the KMS alias, R01, R15's STS calls and R14's `TestEventPattern` cases H1, H8, H9 and H14 against an in-process server in `go test`, as a ratchet over `internal/parity/baseline.json`, and the coverage page's evidence column shows, per operation, its weakest evidence and the replay's verdict. Left: replay scenarios for the other items, including the REST (S3, Lambda) and Docker steps the replayer skips today; retiring the `inferred` overlay entries and fidelity switches (48 and 52 today) the recordings settle, and changing the behavior they contradict; and recording what a scenario still queues, which `scripts/parity-record` prints for a human with credentials, never an agent.
2. **SigV4 verification and presigned URLs.** Closed before the first tag (pre-tag review, 2026-10-13; ADR 0012 amendment): `--sigv4 verify` verifies every credential form in the edge, checks session tokens and temporary-credential expiry, expires presigned URLs on the emulator clock with S3's own error texts, and verifies signed `aws-chunked` uploads. The default stays `parse`.
3. **Protocol corpus to zero known failures.** Closed (2026-10-26; `smithy-protocol-tests.md` sections 9 to 14): the coverage page lists no known failure. Structured error members in `awserr` pass 5 of their 6 cases; the sixth, restXml `ComplexError`, is a corpus bug, since its body expects a `<Message>` the shape does not model. Modeled defaults on unset members and null-preserving sparse collections in the generator pass their 9. A DynamoDB fault rule's `members` set `CancellationReasons` on an injected `TransactionCanceledException`, one reason per item of the transaction.
4. **Release.** In progress (2026-10-26). Built: the Testcontainers modules for Go, Python and Node under `testcontainers/`, unpublished, each with a suite run against the image in CI's `testcontainers` job ([guide](guide/testcontainers-modules.md)), and the `dockerLabels` setting that hands a test session's reaper labels to the containers understudy starts. Not yet: the Desktop run, the tag, the binaries, the GHCR image, the Homebrew tap and publishing the modules. The macOS Docker Desktop run, then the first tag: binaries for linux and darwin, the multi-arch image on GHCR, a Homebrew tap, and Testcontainers modules for Go, Python and JS over `--ready-file` and `/health`. The DynamoDB Local licence questions are settled (ADR 0014 amendment of 2026-10-14). Every conformance suite runs DynamoDB, locally and in CI.

## Phase 3: close the loop on permissions

5. **IAM enforcement, opt-in.** In progress (2026-10-26). Built: the AWS managed policy catalogue (1,608 policies retrieved 2026-10-26), its generator and offline check (`internal/cmd/managedpolicies -verify`, run by `just generate`), its embedding, and IAM serving AWS managed policies from it. Also built (2026-10-27): enforcement itself, opt-in with `--iam-enforce advise` (journal each denial AWS would issue) or `enforce` (answer it). The evaluator (`internal/policydoc` per document, `internal/authz` across policies) passes the vectors of `iam-evaluation.md` 9. It decides identity policies (inline, customer managed and AWS managed from the catalogue), permissions boundaries, session policies, resource policies on queues, topics, buckets, functions, secrets, KMS keys and event buses, and role trust policies on `AssumeRole`. It applies every condition operator family, treats keys it cannot supply as absent with an advisory, and substitutes policy variables. Each service answers with its denial error, and deliveries a target refuses are dead-lettered or dropped, never retried. The generator tightened with it: each action is paired with the resources it applies to, multi-action operations declare their actions, and `POST /iam/evaluate` decides pairs without making the calls. The loop the [policy guide](guide/policy.md#enforce) walks through: run the tests, print the least-privilege policy, enforce it, and watch what removing a statement breaks. Not yet: `conformance/iam-loop`, the same loop over the aws-cli and go-sdk suites, does not pass. Run by hand with its script's gaps patched, check (a) passes (no call as the root after setup), as do (c) (an empty policy denies every one of 3,092 recorded pairs) and (e) (denial texts match where recorded). Four things keep it from passing. First, the script needs fixes: a role whose only call is `GetCallerIdentity` has no policy, the pairs exceed one shell argument, and an empty advisories file is counted as a failure; the go-sdk recording client also needs a CA bundle. Second, the rendered user policy is far over IAM's inline policy quota. Third, check (b), zero denials on the second run, fails in three groups: identifiers AWS mints (KMS keys, secret suffixes, mapping and subscription ids, log streams) differ between the two runs; some suite tests do what AWS itself denies (a trust policy that names only a service, a delivery to a queue with no policy, a call signed by a user with no policy); and tests that assert an AccessDenied are counted as denials. Fourth, check (d), a denial for each removed statement, fails for 167 of 1,232 statements. Most are redundant because calls that failed before naming a resource are also granted on `*`; the rest name minted identifiers or are covered by a same-account resource policy. Each needs a fix to the suites or a choice about the generator. IAM groups, KMS grants, the policy simulator and S3 Block Public Access are not implemented; each has a coverage note. LocalStack sells this; moto has a basic opt-in. It is the highest-value item that touches no new service, and it also forces the policy generator to tighten (its over-approximation would otherwise deny calls the generated policy itself allowed). Evaluating attached AWS managed policies needs their documents. The source is settled (ADR 0016 amendment of 2026-10-14): a catalogue built from the AWS Managed Policy Reference Guide and shipped as a separately licensed data directory. Building it is part of this item.

## Phase 4: the edges of the pipeline

The phase 1 workload starts at a webhook and ends at a worker. The services at those edges are what users will ask for first, and each reuses a seam that exists.

6. **API Gateway: HTTP APIs (v2) first, then a REST (v1) subset.** Function URLs already serve payload format 2.0, so Lambda proxy integrations are mostly routing, stages and `$default` handling, plus the payload format 1.0 Terraform defaults to and deployments as snapshots; add SQS and EventBridge direct integrations as synchronous calls through `kernel.Invoke` (SNS has no integration subtype) and the Terraform `aws_apigatewayv2_*` resources with an empty second plan. REST APIs follow with the subset Terraform and SAM templates use (resources, methods, `AWS_PROXY`, deployments, stages). Routing, request validation and mapping templates are parser work that suits property tests. In progress (2026-10-27). Built: HTTP APIs ([guide](guide/apigateway.md)), with routes and their documented precedence, Lambda proxy integrations in payload formats 1.0 and 2.0, stages, deployments and automatic deployment, tags, the execute-api host and its `/_understudy/execute-api/` path, and Terraform's `aws_apigatewayv2_api`, `_route`, `_integration`, `_stage` and `_deployment` with an empty second plan; except authorizers, WebSocket APIs, OpenAPI import and export, custom domain names and VPC links, which answer `NotImplemented`, and SQS, EventBridge and other service integrations, HTTP proxy integrations, `AWS_IAM` routes and CORS, which are stored and answer `NotImplemented` when a request reaches them. Not yet: HTTP APIs are not done while the serverless-patterns check of `apigw-http-api-lambda-terraform` fails (its function reads a mixed-case payload 1.0 header that understudy lowercases as the AWS documentation says; [patterns](../conformance/patterns/README.md), until recording APIGW2-08 settles the case); REST APIs.
7. **Step Functions.** An ASL interpreter (states, choices, JSONPath and intrinsics, retry and catch, map and parallel) over the existing targets: Lambda, SQS, SNS, DynamoDB, EventBridge. The clock makes `Wait`, timeouts and backoff instant; the journal gives each execution's tree for free; snapshots capture mid-execution state. Standard and Express, `StartExecution`, `GetExecutionHistory`, and the Terraform resource. The combination of real timing semantics in milliseconds and a causal history is where understudy can be better than the alternatives, not merely present. In progress (2026-10-27). Built: Standard workflows written in JSONPath ([guide](guide/stepfunctions.md)), with Pass, Task, Choice, Wait, Succeed, Fail, Parallel and inline Map states, Retry and Catch, the context object and the intrinsic functions, on the emulator clock, persisted mid-execution and re-armed after a snapshot load; Lambda tasks by function ARN and through `lambda:invoke`, invoked as the execution role; `StartExecution`, `StopExecution`, `DescribeExecution`, `ListExecutions` and `GetExecutionHistory` with AWS's event ids, links and details; the PassRole, role-trust and log-delivery checks under `--iam-enforce`; and Terraform's `aws_sfn_state_machine` with an empty second plan. Not yet: Express workflows and `StartSyncExecution`, versions and aliases, activities, task tokens, redrive, `TestState`, Distributed Map and Map Runs, which answer `NotImplemented`; JSONata, variables, Task resources other than Lambda (SQS, SNS, DynamoDB, EventBridge, nested executions) and task `Credentials`, which a definition is refused for at create with `UNSUPPORTED_BY_UNDERSTUDY`; EventBridge and Scheduler targets that start executions.
8. **DynamoDB Streams to Lambda, then Kinesis.** Streams was a phase 1 stretch with its seam named (`EventSourceKind.DynamoDBStream`, TTL deletes already tagged); the stream is an understudy-owned log fed from DynamoDB Local after each write, not Local's Streams API (ADR 0014 amendment of 2026-10-26). It completes DynamoDB for the lock-table and change-capture patterns. Kinesis Data Streams is a new service with the same consumer shape (shard iterators, retention on the clock, event source mappings with batching windows, bisect-on-error and parallelization), so it comes right after and shares the poller. Done (2026-10-30). Built: DynamoDB Streams ([guide](guide/streams.md)), served from understudy's stream log with all four operations, iterators expiring and records trimmed on the emulator clock, and streams, records and labels kept across snapshots; and Lambda mappings on a stream, with `TRIM_HORIZON` and `LATEST`, batching windows, retry and record-age limits, `ReportBatchItemFailures` and SQS or SNS on-failure destinations, through the AWS CLI, the three SDK suites, Terraform and the `dynamodb-streams-lambda-terraform` serverless pattern; except `ParallelizationFactor` above 1, `BisectBatchOnFunctionError`, tumbling windows, filters that compile on a stream and S3 on-failure destinations, which answer `NotImplemented`; and Kinesis Data Streams ([guide](guide/streams.md#kinesis-data-streams)), with 21 of its 45 operations: streams in both modes, shards that split the hash key space evenly, tags, retention, `PutRecord` and `PutRecords`, all five iterator types, `GetRecords`, iterators expiring and records trimmed on the emulator clock, everything kept across snapshots, and Lambda mappings on a Kinesis stream with the same settings as on a DynamoDB stream, through the AWS CLI, the three SDK suites, Terraform and the `kinesis-lambda-terraform` serverless pattern; except resharding, enhanced fan-out consumers and `SubscribeToShard`, encryption, resource policies, `AT_TIMESTAMP` on a mapping, and the CBOR and HTTP/2 that Java clients send by default, which answer `NotImplemented` (the guide names the client settings that avoid them).
9. **Phase 1 leftovers that users will ask about:** SNS HTTP/S delivery with signed envelopes and confirmation, Lambda asynchronous destinations and layers, S3 SSE-C and Object Lock, CloudWatch alarm evaluation over stored metric data with `GetMetricStatistics`, custom EventBridge buses, SSM Parameter Store (small, and read by nearly every Lambda in the wild), and SES in a journal-only form for notification paths. In progress (2026-10-26). Done: S3 SSE-C and Object Lock, except Object Lock event holds, which answer `NotImplemented`, and `s3:BypassGovernanceRetention`, which waits for IAM enforcement (item 5); custom EventBridge buses, with bus policies and event bus targets, except partner event buses, archives, replays, connections, API destinations and global endpoints, which answer `NotImplemented`, and target roles, which are stored and not assumed; bus policies are enforced under `--iam-enforce enforce` (item 5); SNS HTTP/S delivery ([guide](guide/sns-http.md)), with SubscriptionConfirmation, Notification and UnsubscribeConfirmation signed under SignatureVersion 1 and 2, confirmation by token or `SubscribeURL`, `DeliveryPolicy` retries and throttling and the dead-letter queue, sent only to hosts listed in `sns.httpDelivery.allow`, except the 3,600-second total-retry limit, which is not checked, and `sicklyRetryPolicy` and `guaranteed`, which are stored and not applied; topic policies on `Subscribe` and `Publish` are enforced under `--iam-enforce enforce` (item 5); Lambda asynchronous destinations, dead-letter queues and layers ([guide](guide/lambda.md)), except the execution role's permission to reach a destination, which is recorded, not checked, until IAM enforcement (item 5), and AWS-published layers, which must be published to understudy first; CloudWatch alarm evaluation on the emulator clock with `GetMetricStatistics` ([guide](guide/clock.md#cloudwatch-alarms)), with SNS and Lambda actions, `StateUpdate` history and state and configuration change events on the default bus, except alarms on an `ExtendedStatistic`, `Metrics`, a threshold metric, evaluation criteria or a wall-clock window, which are stored and not evaluated, EC2, Auto Scaling, Systems Manager and investigation actions, which are journaled and not run, and `GetMetricStatistics` `ExtendedStatistics`, which answers `NotImplemented`. In progress: SSM Parameter Store ([guide](guide/ssm.md)). Built: its thirteen operations with String, StringList and standard SecureString parameters through KMS, versions, labels, paths, tiers and tags, except AWS public parameters, Secrets Manager references, parameter policies, `DataType` `aws:ec2:image`, Advanced-tier SecureString and the legacy Query protocol, which answer `NotImplemented`, and Parameter Store Change events, which are not sent. Not yet: the AWS CLI conformance file does not yet pass under `--iam-enforce enforce` as a user holding only its generated policy, since it opens a default-key ciphertext with a direct KMS `Decrypt` that the `aws/ssm` key policy allows only through SSM. In progress: SES in its journal-only form ([guide](guide/ses-email.md)). Built: v1 and v2 over one store, with email and domain identities, verification by link or `ses.verifiedIdentities` and expiry on the emulator clock, the sandbox and `ses.productionAccess`, `SendEmail`, `SendRawEmail`, `SendTemplatedEmail` and v2 `SendEmail` with Simple, Raw and Template content, recorded for `GET /_understudy/v1/ses/messages` and `understudy ses messages` and never sent, templates in both APIs, tags, `GetAccount` and the send quota, through the AWS CLI, the three SDK suites, Terraform and the `s3-lambda-ses-terraform` serverless pattern's check; except configuration sets, receipt rules, sending authorization, `EndpointId`, `TenantName` and `ListManagementOptions`, which answer `NotImplemented`, and the `GET /v2/email/identities` binding older SDKs send. Not yet: the maintainer's sign-off on the pattern's three adjustments.

## Phase 5: seeing it

10. **A web UI over the journal.** Done (2026-10-26). `serve` serves the page at `/_understudy/ui/` and prints its URL with a per-run session secret (ADR 0020; [guide](guide/ui.md)): live trace trees from the journal stream, resources, fault rules (add, remove), the clock (freeze, resume, advance), IAM policy per principal and coverage. The admin API journals resets, snapshot saves and loads, fault rule changes and every clock move, so the page sees changes made elsewhere. Built with Bun from `ui/` (`just ui`, checked by `just ui-check` in CI) and embedded. Not verified in a browser: the page opened at a non-loopback name of a listener beyond loopback. The data plane exists: the NDJSON stream, `/resources`, `/coverage`, `/iam/policy`, snapshots. A static single-page app served at `/_understudy/ui/` showing live traces as trees, resources by account and region, fault rules and the clock would make the journal the thing people open first. It is deliberately after enforcement and the edge services because it adds no fidelity, but it is independent of them and can run in parallel. The build toolchain lives outside the Go module, like the conformance suites; the module stays standard-library-only by embedding built assets.

## Later, and why not sooner

- **ECS.** High demand, large surface. Fargate `RunTask` and services could reuse the Lambda launcher (labels, networking, log capture) and land logs in CloudWatch Logs, but a faithful ECS needs VPC, load balancers and service discovery to mean anything in a test, so most of it would be stored-only. Worth doing once Step Functions and API Gateway exist, as the compute option for long-running workers.
- **RDS.** The engine cannot be emulated; the realistic shape is a control plane plus a managed Postgres or MySQL container, as DynamoDB uses DynamoDB Local. Most teams already run the database from compose, so the value is Terraform plan cleanliness and connection details, which is small next to the items above.
- **Cognito, EC2 and VPC, CloudFormation and CDK deploys.** Cognito is a token issuer and hosted UI, a product of its own. EC2 and VPC only make sense stored-only for Terraform. CloudFormation would be the largest adoption lever (CDK users) and the largest build; it belongs after the services it would create exist.
- **Platform.** SigV4A and signed streaming for non-Go SDKs (the `auth` sum type names them), a write-ahead log for persistence instead of whole-state checkpoints, a reused TLS certificate under `--persist`, an admin-token boundary between function containers and the admin API in the in-container topology, and wildcard DNS for containers.

## How items get in

A service enters with research in `docs/research/`, a pinned model, an overlay with evidence, a conformance file per client and a Terraform lifecycle, as `CONTRIBUTING.md` describes. A platform feature enters with an ADR. Anything that would make understudy fake what it does not do stays out.
