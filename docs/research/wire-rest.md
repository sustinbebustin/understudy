## 1. Smithy HTTP bindings, as a server must implement them

Source for this whole section is the [HTTP bindings spec](https://github.com/smithy-lang/smithy/blob/ec88e02aa1e6315f3453b1eb99625352750282f3/docs/source-2.0/spec/http-bindings.rst) unless another URL is given.

### 1.1 Locations and request matching

- Only top-level members of an operation's input, output or error are bound, and a member binds to exactly one location ([L10-13](https://github.com/smithy-lang/smithy/blob/ec88e02aa1e6315f3453b1eb99625352750282f3/docs/source-2.0/spec/http-bindings.rst#L10-L13)).
- The `http` trait has `method`, `uri`, and `code` (default 200) ([L37-59](https://github.com/smithy-lang/smithy/blob/ec88e02aa1e6315f3453b1eb99625352750282f3/docs/source-2.0/spec/http-bindings.rst#L37-L59)).
- A uri pattern starts with `/`, has no empty segments, no fragment, no dot-segments, does not end in `?`; trailing slashes on a request are ignored when matching ([L134-143, L154-185](https://github.com/smithy-lang/smithy/blob/ec88e02aa1e6315f3453b1eb99625352750282f3/docs/source-2.0/spec/http-bindings.rst#L134-L185)). S3 keys violate all of these (empty segments, `..`, significant trailing `/`), so S3 cannot use generic Smithy matching (section 3.3).
- A label spans a whole path segment and is required; a greedy label `{Key+}` matches one or more segments and at most one is allowed; `/my/uri/{label+}` does not match `/my/uri` ([L189-275, L346-427](https://github.com/smithy-lang/smithy/blob/ec88e02aa1e6315f3453b1eb99625352750282f3/docs/source-2.0/spec/http-bindings.rst#L346-L427)). Consequence: `GET /bucket/` has no key and must resolve to a bucket-level operation.
- Literal query pieces in the uri are matching conditions: `?requiredKey` requires the key present with any value (also `requiredKey=`); `/path?` alone does not match ([L277-343](https://github.com/smithy-lang/smithy/blob/ec88e02aa1e6315f3453b1eb99625352750282f3/docs/source-2.0/spec/http-bindings.rst#L277-L343)).
- Ambiguous patterns are resolved by "specificity routing": literal segment beats label, non-greedy label beats greedy label, longer path wins, then more query literals wins; path specificity beats query literals ([L464-575](https://github.com/smithy-lang/smithy/blob/ec88e02aa1e6315f3453b1eb99625352750282f3/docs/source-2.0/spec/http-bindings.rst#L464-L575)). Lambda needs this (section 4.3); S3 needs a richer rule (section 3.2).

### 1.2 Labels

- Serialized as RFC 3986 unreserved characters only (`A-Za-z0-9-._~`), everything else percent-encoded; in a greedy label `/` is not encoded ([L934-946](https://github.com/smithy-lang/smithy/blob/ec88e02aa1e6315f3453b1eb99625352750282f3/docs/source-2.0/spec/http-bindings.rst#L934-L946)). boto3 does the same: greedy labels are encoded with `safe='/~'`, others with the default safe set ([serialize.py L839-856](https://github.com/boto/botocore/blob/bfb412faf00c249a54816e287a09a8bb79442c65/botocore/serialize.py#L839-L856)).
- A non-greedy label can carry an encoded slash. The restXml test sends `GET /HttpRequestWithLabels/%20%25%3A%2F%3F%23%5B%5D%40%21%24%26%27%28%29%2A%2B%2C%3B%3D%F0%9F%98%B9/1/2/3/4.1/5.1/true/2019-12-16T23%3A48%3A18Z`, whose first label decodes to ` %:/?#[]@!$&'()*+,;=` followed by an emoji ([http-labels.smithy L35-50](https://github.com/smithy-lang/smithy/blob/ec88e02aa1e6315f3453b1eb99625352750282f3/smithy-aws-protocol-tests/model/restXml/http-labels.smithy#L35-L50)). A server must therefore split on the raw (escaped) path first and decode each segment afterwards.
- Timestamps in labels default to RFC 3339 `date-time` (`2019-12-16T23:48:18Z`); booleans are `true`/`false`; floats may be `NaN`, `Infinity`, `-Infinity` ([http-labels.smithy L193-218](https://github.com/smithy-lang/smithy/blob/ec88e02aa1e6315f3453b1eb99625352750282f3/smithy-aws-protocol-tests/model/restXml/http-labels.smithy#L193-L218)).

### 1.3 Query string

- Unreserved characters unescaped, all others percent-encoded; timestamps default to `date-time`; lists repeat the key (`foo=a&foo=b`); for a non-list member a server uses the first value ([L1098-1120](https://github.com/smithy-lang/smithy/blob/ec88e02aa1e6315f3453b1eb99625352750282f3/docs/source-2.0/spec/http-bindings.rst#L1098-L1120)).
- `httpQueryParams` (a `map<string,string>` or `map<string,list<string>>`): a `map<string,string>` takes the first value per key; keys with no value (`?anotherTag`, `?lastTag=`) deserialize to the empty string; `httpQuery` wins over `httpQueryParams` on a name clash ([L1242-1341](https://github.com/smithy-lang/smithy/blob/ec88e02aa1e6315f3453b1eb99625352750282f3/docs/source-2.0/spec/http-bindings.rst#L1242-L1341)). Neither Lambda nor S3 phase 1 operations use `httpQueryParams` in their models (checked by scanning both models for the trait).
- The S3 model overrides the timestamp default in one query member: `response-expires` is `http-date` ([MODEL, `GetObjectRequest$ResponseExpires`](https://github.com/aws/api-models-aws/blob/1cfdfb4bb9ea858e65623e66d73af04bec353201/models/s3/service/2006-03-01/s3-2006-03-01.json)).

### 1.4 Headers

- Booleans `true`/`false`; timestamps default to `http-date` (IMF-fixdate, e.g. `Tue, 29 Apr 2014 18:30:38 GMT`); a deserializer should reject fractional-second `http-date` with 400 ([http-bindings L646-663](https://github.com/smithy-lang/smithy/blob/ec88e02aa1e6315f3453b1eb99625352750282f3/docs/source-2.0/spec/http-bindings.rst#L646-L663), [protocol-traits L229-235](https://github.com/smithy-lang/smithy/blob/ec88e02aa1e6315f3453b1eb99625352750282f3/docs/source-2.0/spec/protocol-traits.rst#L229-L235)).
- Lists: values are comma-joined on one line or sent as repeated header lines ([L649-652](https://github.com/smithy-lang/smithy/blob/ec88e02aa1e6315f3453b1eb99625352750282f3/docs/source-2.0/spec/http-bindings.rst#L649-L652)). S3 `x-amz-optional-object-attributes` is sent as repeated lines by Go ([ListObjectsV2.request.snap](https://github.com/aws/aws-sdk-go-v2/blob/ab2110b01f03b3990bfd50208a8a05df1d8c5eac/service/s3/request_snapshot/ListObjectsV2.request.snap)).
- String-list elements that contain `,` or `"` are quoted with backslash-escaped quotes. Spec test: `X-StringList: "b,c", "\"def\"", a` is `["b,c", "\"def\"", "a"]` ([restJson1 http-headers.smithy L47-57](https://github.com/smithy-lang/smithy/blob/ec88e02aa1e6315f3453b1eb99625352750282f3/smithy-aws-protocol-tests/model/restJson1/http-headers.smithy#L47-L57)). boto3 emits elements joined by `,` with no space and quotes only when needed ([serialize.py L993-1030](https://github.com/boto/botocore/blob/bfb412faf00c249a54816e287a09a8bb79442c65/botocore/serialize.py#L993-L1030)); the spec tests use `, `. Parse both.
- Timestamp lists contain commas inside each http-date: `X-TimestampList: Mon, 16 Dec 2019 23:48:18 GMT, Mon, 16 Dec 2019 23:48:18 GMT` ([http-headers.smithy L104](https://github.com/smithy-lang/smithy/blob/ec88e02aa1e6315f3453b1eb99625352750282f3/smithy-aws-protocol-tests/model/restJson1/http-headers.smithy#L104)). Neither the S3 nor the Lambda model binds a list of timestamps to a header or query (parsed: the only header-bound lists are S3 `x-amz-object-attributes` and `x-amz-optional-object-attributes`, both enum strings; the only query-bound lists are Lambda `Statuses`, enums, and `tagKeys`, strings), so this matters only to the generic layer. Lists in query strings repeat the key (`tagKeys=a&tagKeys=b`).
- `httpPrefixHeaders`: each map entry becomes `<prefix><key>`; S3 `Metadata` uses prefix `x-amz-meta-` on request and response ([MODEL, `PutObjectRequest$Metadata`](https://github.com/aws/api-models-aws/blob/1cfdfb4bb9ea858e65623e66d73af04bec353201/models/s3/service/2006-03-01/s3-2006-03-01.json); [spec L771-861](https://github.com/smithy-lang/smithy/blob/ec88e02aa1e6315f3453b1eb99625352750282f3/docs/source-2.0/spec/http-bindings.rst#L771-L861)). An `httpHeader` member wins over a prefix-header entry for the same name ([L659-704](https://github.com/smithy-lang/smithy/blob/ec88e02aa1e6315f3453b1eb99625352750282f3/docs/source-2.0/spec/http-bindings.rst#L659-L704)).
- Header names are case-insensitive; Go sends `Content-Md5` and `X-Amz-Checksum-Crc32` ([PutObject.request.snap](https://github.com/aws/aws-sdk-go-v2/blob/ab2110b01f03b3990bfd50208a8a05df1d8c5eac/service/s3/request_snapshot/PutObject.request.snap)) and `X-Amz-Meta-Key0` ([CreateMultipartUpload.request.snap](https://github.com/aws/aws-sdk-go-v2/blob/ab2110b01f03b3990bfd50208a8a05df1d8c5eac/service/s3/request_snapshot/CreateMultipartUpload.request.snap)). S3 stores user-metadata keys lowercase ([DOCS UsingMetadata](https://docs.aws.amazon.com/AmazonS3/latest/userguide/UsingMetadata.html)).

### 1.5 Payload, status code, empty bodies

- `httpPayload` binds one member to the whole body; a `string`/`blob` member is the raw bytes, anything else is a protocol document (XML or JSON). When present on an input, every other member must be a label, header, prefix header or query; on an output or error, every other member must be a header or prefix header ([L1010-1037](https://github.com/smithy-lang/smithy/blob/ec88e02aa1e6315f3453b1eb99625352750282f3/docs/source-2.0/spec/http-bindings.rst#L1010-L1037)).
- `httpResponseCode` binds an output `integer` to the status; if unset the server uses the `http` trait `code` ([L1350-1389](https://github.com/smithy-lang/smithy/blob/ec88e02aa1e6315f3453b1eb99625352750282f3/docs/source-2.0/spec/http-bindings.rst#L1350-L1389)). Test: `Status: 201` comes back as `201` with an empty body ([restXml http-response-code.smithy L23-31](https://github.com/smithy-lang/smithy/blob/ec88e02aa1e6315f3453b1eb99625352750282f3/smithy-aws-protocol-tests/model/restXml/http-response-code.smithy#L23-L31)). Lambda uses this for `Invoke.StatusCode`, `InvokeAsync.Status` and `DeleteFunction.StatusCode`; the server computes it per request (section 4.4).
- Response serialization order: status from the `http` trait (or `httpError`, else 400 client / 500 server), then prefix headers, headers, payload or document ([L1516-1535, L578-615](https://github.com/smithy-lang/smithy/blob/ec88e02aa1e6315f3453b1eb99625352750282f3/docs/source-2.0/spec/http-bindings.rst#L1516-L1535)).
- An operation with no input or no output members sends no body at all (restJson1 `NoInputAndNoOutput`: "they should omit a payload altogether"); servers must tolerate an `Accept: application/json` on such requests ([restJson1 empty-input-output.smithy](https://github.com/smithy-lang/smithy/blob/ec88e02aa1e6315f3453b1eb99625352750282f3/smithy-aws-protocol-tests/model/restJson1/empty-input-output.smithy)). boto3 sends `{}` for restJson1 inputs that have unbound members ([serialize.py L1080-1095](https://github.com/boto/botocore/blob/bfb412faf00c249a54816e287a09a8bb79442c65/botocore/serialize.py#L1080-L1095)), so accept an empty body, `{}`, or no `Content-Type`.
- Default `Content-Type`: structure/union payload `application/xml` (restXml) or `application/json` (restJson1); blob `application/octet-stream`; string `text/plain`; a `mediaType` trait overrides ([restXml L213-246](https://github.com/smithy-lang/smithy/blob/ec88e02aa1e6315f3453b1eb99625352750282f3/docs/source-2.0/aws/protocols/aws-restxml-protocol.rst#L213-L246), [restJson1 L210-243](https://github.com/smithy-lang/smithy/blob/ec88e02aa1e6315f3453b1eb99625352750282f3/docs/source-2.0/aws/protocols/aws-restjson1-protocol.rst#L210-L243)). A server must ignore `Content-Type` parameters (`application/xml; charset=utf-8`) ([restXml content-type.smithy L20-24](https://github.com/smithy-lang/smithy/blob/ec88e02aa1e6315f3453b1eb99625352750282f3/smithy-aws-protocol-tests/model/restXml/content-type.smithy#L20-L24)).
- Smithy's own server contract demands `415 UnsupportedMediaTypeException` for a wrong `Content-Type` ([malformed-content-type.smithy](https://github.com/smithy-lang/smithy/blob/ec88e02aa1e6315f3453b1eb99625352750282f3/smithy-aws-protocol-tests/model/restJson1/malformedRequests/malformed-content-type.smithy)). Real clients send inconsistent values for Lambda `Invoke` (section 4.4), so do not enforce it there.

## 2. restXml serialization

### 2.1 Shape rules

Source: [protocol-traits.rst XML bindings L260-1027](https://github.com/smithy-lang/smithy/blob/ec88e02aa1e6315f3453b1eb99625352750282f3/docs/source-2.0/spec/protocol-traits.rst#L260-L1027) and [aws-xml-serialization](https://github.com/smithy-lang/smithy/blob/ec88e02aa1e6315f3453b1eb99625352750282f3/docs/source-2.0/aws/protocols/aws-xml-serialization.rst.template).

| Shape | XML |
|---|---|
| structure / union | element named after the member (or `xmlName`); root element is the shape name or its `xmlName` |
| blob | base64 text |
| boolean | `true` / `false` |
| numbers | decimal text; floats in scientific notation only when an exponent is needed |
| timestamp | `date-time` text by default, e.g. `2020-01-05T20:13:26Z`; S3 uses millisecond precision `2009-10-12T17:50:30.000Z` ([CopyObject sample](https://docs.aws.amazon.com/AmazonS3/latest/API/API_CopyObject.html)) |
| list (wrapped, default) | `<values><member>a</member><member>b</member></values>`; `xmlName` on the list member renames `member` (S3 `Buckets` uses `Bucket`, `TagSet` uses `Tag`) |
| list (`xmlFlattened`) | repeated `<flat>a</flat>` directly in the parent, named by the parent member (or its `xmlName`); `xmlName` on the list member is ignored |
| map (wrapped) | `<values><entry><key>k</key><value>v</value></entry></values>`; `xmlName` may rename `key` and `value`, not `entry` |
| map (`xmlFlattened`) | repeated `<flatMap><key/><value/></flatMap>` in the parent |
| `xmlAttribute` | member becomes an attribute on the enclosing element |
| `xmlNamespace` | `xmlns="uri"` (or `xmlns:prefix="uri"`) on that element; conflicts with `xmlAttribute` |

### 2.2 S3 specifics in the model

All parsed from [MODEL](https://github.com/aws/api-models-aws/blob/1cfdfb4bb9ea858e65623e66d73af04bec353201/models/s3/service/2006-03-01/s3-2006-03-01.json):

- Service traits: `aws.protocols#restXml {noErrorWrapping: true}` and `smithy.api#xmlNamespace {uri: "http://s3.amazonaws.com/doc/2006-03-01/"}`. So every success document root carries `xmlns="http://s3.amazonaws.com/doc/2006-03-01/"`; error documents do not (every DOCS error sample is a bare `<Error>`).
- Output structures carry an `xmlName` that is the real root element: `ListObjectsV2Output` is `ListBucketResult`; `ListObjectsOutput` shares it; `ListBucketsOutput` is `ListAllMyBucketsResult`; `ListObjectVersionsOutput` is `ListVersionsResult`; `ListMultipartUploadsOutput` is `ListMultipartUploadsResult`; `ListPartsOutput` is `ListPartsResult`; `CreateMultipartUploadOutput` is `InitiateMultipartUploadResult`; `CompleteMultipartUploadOutput` is `CompleteMultipartUploadResult`; `DeleteObjectsOutput` is `DeleteResult`; `GetBucketTaggingOutput` is `Tagging`; `GetBucketVersioningOutput` is `VersioningConfiguration`; `GetBucketAclOutput` is `AccessControlPolicy`; `GetBucketLocationOutput` is `LocationConstraint`.
- Unbound output members are the document; `httpPayload` outputs are bare: `CopyObjectOutput.CopyObjectResult` and `UploadPartCopyOutput.CopyPartResult` are payload members (document root is `CopyObjectResult` / `CopyPartResult`), while their metadata (`x-amz-version-id`, `x-amz-copy-source-version-id`) are headers.
- Request payload members carry `xmlName` for the request root: `Delete`, `CompleteMultipartUpload`, `CreateBucketConfiguration`, and for the `Put*` configuration ops the structure name (`Tagging`, `VersioningConfiguration`, `CORSConfiguration`, ...).
- Flattened lists: `ListBucketResult` has `Contents` and `CommonPrefixes` flattened; `ListPartsResult` has `Part` flattened (member `Parts`, `xmlName` `Part`); `DeleteResult` flattens `Deleted` and `Error`; `CompleteMultipartUpload` request flattens `Part`; `Delete` request flattens `Object`. `ListAllMyBucketsResult` wraps: `<Buckets><Bucket>...</Bucket></Buckets>`.
- `GetBucketLocation` is annotated `aws.customizations#s3UnwrappedXmlOutput`: the member value is the document, not a child. Wire: `<?xml version="1.0" encoding="UTF-8"?>\n<LocationConstraint xmlns="http://s3.amazonaws.com/doc/2006-03-01/">us-west-2</LocationConstraint>` ([s3.smithy L248-262](https://github.com/smithy-lang/smithy/blob/ec88e02aa1e6315f3453b1eb99625352750282f3/smithy-aws-protocol-tests/model/restXml/services/s3.smithy#L320-L330)); boto3 reads `root.text` ([handlers.py L611-623](https://github.com/boto/botocore/blob/bfb412faf00c249a54816e287a09a8bb79442c65/botocore/handlers.py#L611-L623)). The DOCS "Response Syntax" shows a nested `<LocationConstraint><LocationConstraint>` ([API_GetBucketLocation](https://docs.aws.amazon.com/AmazonS3/latest/API/API_GetBucketLocation.html)); that is the modeling artifact, not the wire. For a `us-east-1` bucket the value is empty ("Buckets in Region us-east-1 have a LocationConstraint of null", same page); `<LocationConstraint xmlns="..."/>` is the expected form (UNVERIFIED exact bytes).
- ACL grants need a prefixed attribute: `Grant.Grantee` has `xmlNamespace {uri: http://www.w3.org/2001/XMLSchema-instance, prefix: xsi}` and `Grantee.Type` is `xmlAttribute` with `xmlName "xsi:type"`, giving `<Grantee xmlns:xsi="http://www.w3.org/2001/XMLSchema-instance" xsi:type="CanonicalUser">`. Go's `encoding/xml` does not emit namespace-prefixed attributes cleanly, so S3 output needs a small purpose-built XML writer.
- ETag in XML: DOCS samples show literal quotes (`<ETag>"3858f62230ac3c915f300c664312c11f-9"</ETag>`, [CompleteMultipartUpload](https://docs.aws.amazon.com/AmazonS3/latest/API/API_CompleteMultipartUpload.html)); real S3 is commonly seen emitting `&quot;` (UNVERIFIED). Both parse to the same string. ETag headers are always quoted.
- Element presence: real list responses include an empty `<Prefix></Prefix>` when no prefix was sent (REC: `Prefix: ""` in [test_s3_list_operations](https://github.com/localstack/localstack/blob/8b9a79f05846835cf4dff63ab7eefdde9df83783/tests/aws/services/s3/test_s3_list_operations.snapshot.json)); `Delimiter` is omitted when not sent.

### 2.3 Parsing XML requests

- Request bodies (`CreateBucketConfiguration`, `Delete`, `CompleteMultipartUpload`, `Tagging`, ...) arrive with `xmlns="http://s3.amazonaws.com/doc/2006-03-01/"` from Go ([PutBucketTagging.request.snap](https://github.com/aws/aws-sdk-go-v2/blob/ab2110b01f03b3990bfd50208a8a05df1d8c5eac/service/s3/request_snapshot/PutBucketTagging.request.snap)) but docs show some samples without it ([CompleteMultipartUpload sample](https://docs.aws.amazon.com/AmazonS3/latest/API/API_CompleteMultipartUpload.html)). Match element names ignoring namespace.
- Schema-invalid XML returns `MalformedXML`, 400, message "The XML you provided was not well-formed or did not validate against our published schema" (REC: [test_bucket_versioning_crud](https://github.com/localstack/localstack/blob/8b9a79f05846835cf4dff63ab7eefdde9df83783/tests/aws/services/s3/test_s3_api.snapshot.json)); `DeleteObjects` accepts up to 1,000 keys and `Quiet` must be `true` when present ([API_DeleteObjects](https://docs.aws.amazon.com/AmazonS3/latest/API/API_DeleteObjects.html)).

## 3. S3 server behavior

### 3.1 Addressing: path-style, virtual-hosted, and what SDKs send to `AWS_ENDPOINT_URL`

AWS rules ([DOCS VirtualHosting](https://docs.aws.amazon.com/AmazonS3/latest/userguide/VirtualHosting.html)):
1. Host omitted (HTTP/1.0) or equal to `s3.<region>.amazonaws.com`: bucket is the first path segment.
2. Host ends in `.s3.<region>.amazonaws.com`: bucket is the leading part of the host, key is the whole path.
3. Otherwise the bucket is the lowercased Host value (CNAME bucket).

What clients build against a custom endpoint, per AWS's own S3 endpoint rule set (the model carries 393 `endpointTests`, parsed locally from [MODEL](https://github.com/aws/api-models-aws/blob/1cfdfb4bb9ea858e65623e66d73af04bec353201/models/s3/service/2006-03-01/s3-2006-03-01.json)):

| Endpoint override | Bucket | Result | Test doc string |
|---|---|---|---|
| `http://example.com` | `bucket.name` | `http://bucket.name.example.com` (virtual) | "subdomains are allowed in virtual buckets on http endpoints" |
| `https://example.com` | `bucket-name` | `https://bucket-name.example.com` | "virtual addressing, aws-global region with custom endpoint" |
| `http://127.0.0.1` | `bucket` | `http://127.0.0.1/bucket` (path) | "use global endpoint + IP address endpoint override" |
| `https://123.123.0.1` | `bucketname` | `https://123.123.0.1/bucketname` | "using an IPv4 address forces path style" |
| any host, `ForcePathStyle=true` | any | `https://example.com/bucket-name` | "ForcePathStyle, aws-global region custom endpoint uses the custom endpoint" |
| `http://control.vpce-...amazonaws.com/foo` | `bucketname` | `http://bucketname.control.vpce-...amazonaws.com/foo` (path prefix of the endpoint is kept) | "scheme is respected (virtual addressing)" |
| non-DNS bucket (`99_ab`) | | path-style regardless | "scheme is respected" |

The rule set has no special case for `localhost` (the serialized rule set contains zero occurrences of the string; checked locally), and `parseURL(...).isIp` is true only for IPv4 or IPv6 literals ([Smithy rules-engine standard library](https://github.com/smithy-lang/smithy/blob/ec88e02aa1e6315f3453b1eb99625352750282f3/docs/source-2.0/additional-specs/rules-engine/standard-library.rst)). Hence `AWS_ENDPOINT_URL=http://localhost:4566` makes a ruleset-driven SDK address `http://<bucket>.localhost:4566/<key>`. This resolves the open item in [smithy-protocol-tests.md](smithy-protocol-tests.md).

Per SDK:
- Go v2 defaults to virtual-hosted "when possible", and `UsePathStyle` is a code option; no environment variable or shared-config key for it was found ([options.go](https://github.com/aws/aws-sdk-go-v2/blob/ab2110b01f03b3990bfd50208a8a05df1d8c5eac/service/s3/options.go), searched `config/shared_config.go` and `config/env_config.go`). `manager.GetBucketRegion` also defaults to virtual-hosted and unsigned ([bucket_region.go](https://github.com/aws/aws-sdk-go-v2/blob/ab2110b01f03b3990bfd50208a8a05df1d8c5eac/feature/s3/manager/bucket_region.go)).
- JS v3: `forcePathStyle` defaults to `false` ([EndpointParameters.ts](https://github.com/aws/aws-sdk-js-v3/blob/0317bb822abed1302aaae350a8bbfa40f60ef32d/clients/client-s3/src/endpoint/EndpointParameters.ts)); same ruleset, same result for `localhost`. Env/config knob: none found (UNVERIFIED).
- botocore (boto3 and the AWS CLI): with a custom `endpoint_url` the builtin `ForcePathStyle` is true unless `addressing_style` is `virtual`, so boto3 and the CLI use path-style against `http://localhost:4566` ([args.py L826-838](https://github.com/boto/botocore/blob/bfb412faf00c249a54816e287a09a8bb79442c65/botocore/args.py#L826-L838)).
- Terraform's AWS provider passes `UsePathStyle` from `s3_use_path_style` and calls `GetBucketRegion` with it ([bucket.go L1798-1816](https://github.com/hashicorp/terraform-provider-aws/blob/972faab3f6e4e37aff0453fe05366f3bd3fc2b97/internal/service/s3/bucket.go#L1798-L1816)); default is virtual-hosted.
- Name resolution: `bucket.localhost` resolves on this machine through the NSS `myhostname` module (`getent hosts foo.localhost` returned `::1` here). Go's resolver hands names that end in `.localhost` to the cgo resolver when `myhostname` is a configured NSS source ([net/conf.go L398-402, L519-523](https://github.com/golang/go/blob/master/src/net/conf.go), read from the installed go1.27.1 toolchain), so it works only where that module (or systemd-resolved) is present. It is not guaranteed on other systems, in static or scratch images, or inside containers (UNVERIFIED beyond this host).

How reference emulators detect virtual-hosted requests: LocalStack matches `<bucket>.s3.<region?>...` only (`(?P<bucket>.*).s3.(?P<region>...)?.*`, [utils.py L101-105, L538-551](https://github.com/localstack/localstack/blob/8b9a79f05846835cf4dff63ab7eefdde9df83783/localstack-core/localstack/services/s3/utils.py#L101-L105)); MinIO matches `{bucket}.<configured domain>` for each configured domain, path-style otherwise ([api-router.go L255-283](https://github.com/minio/minio/blob/7aac2a2c5b7c882e68c1ce017d8256be2feea27f/cmd/api-router.go#L255-L283)); moto uses heuristics (no dot in host, `localhost`, IPs, `host.docker.internal` all mean path-style) ([s3/responses.py L283-342](https://github.com/getmoto/moto/blob/5cab9c903b2a26d08f353da2afc753b1adc1eb10/moto/s3/responses.py#L283-L342)).

Bucket name rules (3-63 chars; lowercase letters, digits, `.`, `-`; begin and end alphanumeric; no `..`; not an IP; not prefixed `xn--`, `sthree-`, `amzn-s3-demo-`; not suffixed `-s3alias`, `--ol-s3`, `.mrap`, `--x-s3`, `--table-s3`; `-an` only in the account regional namespace) are in [DOCS bucket naming rules](https://docs.aws.amazon.com/AmazonS3/latest/userguide/bucketnamingrules.html). An invalid name returns `InvalidBucketName`, 400, "The specified bucket is not valid." (REC: [test_s3_uppercase_bucket_name](https://github.com/localstack/localstack/blob/8b9a79f05846835cf4dff63ab7eefdde9df83783/tests/aws/services/s3/test_s3.snapshot.json)). Dotted names are legal for path-style and break wildcard TLS for virtual-hosted (same DOCS page).

### 3.3 Path and key handling hazards

- Go's `http.ServeMux` cleans paths and redirects (307) any request containing `.`/`..` segments or repeated slashes ([net/http/server.go `findHandler` L2711-2755](https://github.com/golang/go/blob/master/src/net/http/server.go), read from the installed go1.27.1 toolchain). The Smithy S3 tests require `GET /../key.txt` and `/foo/../key.txt` to be preserved ([s3.smithy L270-310](https://github.com/smithy-lang/smithy/blob/ec88e02aa1e6315f3453b1eb99625352750282f3/smithy-aws-protocol-tests/model/restXml/services/s3.smithy#L270-L310)). Route S3 (and everything sharing the port) from `r.URL.EscapedPath()` or `RequestURI`, never `ServeMux`.
- A key can contain `/`, a leading `/` (vhost path `//key`), a trailing `/`, `%`, `+`, and non-ASCII. Greedy-label decoding: percent-decode each escaped segment, keep `+` literal in paths (query strings treat `+` as space; botocore decodes list-response keys with `unquote_plus`, section 3.4).
- Empty key (`/bucket/` or vhost `/`) is a bucket-scope request ([Smithy greedy-label rule](https://github.com/smithy-lang/smithy/blob/ec88e02aa1e6315f3453b1eb99625352750282f3/docs/source-2.0/spec/http-bindings.rst#L384-L387) plus MinIO's `Path("/{object:.+}")` requiring at least one character, [api-router.go L302](https://github.com/minio/minio/blob/7aac2a2c5b7c882e68c1ce017d8256be2feea27f/cmd/api-router.go#L302)).
- `x-amz-copy-source` is `[/]bucket/key[?versionId=...]`, percent-encoded by botocore (key encoded with `safe='/'`, the `?versionId=` suffix left alone) ([handlers.py L452-520](https://github.com/boto/botocore/blob/bfb412faf00c249a54816e287a09a8bb79442c65/botocore/handlers.py#L452-L520)); the Go SDK passes the string through untouched and its own integration test passes `"/" + sourceBucket + "/" + key` ([setup_test.go L395-399](https://github.com/aws/aws-sdk-go-v2/blob/ab2110b01f03b3990bfd50208a8a05df1d8c5eac/service/internal/integrationtest/s3/setup_test.go#L395-L399)). Accept a leading slash, decode `%XX` leniently, split the version off at the last `?versionId=`. Access-point ARN forms exist ([API_CopyObject](https://docs.aws.amazon.com/AmazonS3/latest/API/API_CopyObject.html)); out of scope.

### 3.4 Encoded and structured values

- `encoding-type=url` list responses: boto3 sets `EncodingType=url` on every `ListObjects`/`ListObjectsV2`/`ListObjectVersions` unless the caller set one, then decodes with `unquote_plus` ([handlers.py L822-880](https://github.com/boto/botocore/blob/bfb412faf00c249a54816e287a09a8bb79442c65/botocore/handlers.py#L822-L880), [compat.py L62](https://github.com/boto/botocore/blob/bfb412faf00c249a54816e287a09a8bb79442c65/botocore/compat.py#L62)). Fields encoded: ListObjects `Delimiter`, `Marker`, `NextMarker`, `Key`, `Prefix` of common prefixes; V2 `Delimiter`, `Prefix`, `StartAfter`, `Key`; versions `KeyMarker`, `NextKeyMarker`, `Prefix`, `Delimiter`, `Key` ([same file](https://github.com/boto/botocore/blob/bfb412faf00c249a54816e287a09a8bb79442c65/botocore/handlers.py#L830-L880)); the response must carry `<EncodingType>url</EncodingType>`. Because the decoder is `unquote_plus`, a literal `+` in a key must be emitted `%2B` (a bare `+` would decode to a space); space may be `+` or `%20`. REC, for responses where the caller set `EncodingType="url"` itself (so nothing was auto-decoded): `/` stays literal, `=` becomes `%3D` (`date=2026-03-01/` is returned as `date%3D2026-03-01/`, and `StartAfter` is echoed encoded the same way), `%` becomes `%25` (a `%2F` delimiter comes back as `%252F`). The server does not URL-decode `StartAfter` on input: a client-quoted `StartAfter=date%3D2026-02-01/` is compared literally ([test_s3_list_operations.snapshot.json](https://github.com/localstack/localstack/blob/8b9a79f05846835cf4dff63ab7eefdde9df83783/tests/aws/services/s3/test_s3_list_operations.snapshot.json), test source [test_s3_list_operations.py L482-545](https://github.com/localstack/localstack/blob/8b9a79f05846835cf4dff63ab7eefdde9df83783/tests/aws/services/s3/test_s3_list_operations.py#L482-L545)). The full set of characters S3 leaves unencoded is not documented in the pages read (UNVERIFIED); RFC 3986 unreserved plus `/` is a safe superset to leave unescaped, anything else may be escaped because clients decode generically.
- Go v2 does not auto-set or decode `EncodingType` (the Go snapshot only has it because the test populates every field), so Go callers see raw XML keys when the server is not asked to encode. Servers must support both ([api_op_ListObjectsV2.go docs](https://github.com/aws/aws-sdk-go-v2/blob/ab2110b01f03b3990bfd50208a8a05df1d8c5eac/service/s3/api_op_ListObjectsV2.go)).
- Non-ASCII user metadata is stored RFC 2047-decoded and returned RFC 2047-encoded; unprintable entries are dropped and counted in `x-amz-missing-meta`; combined size limit 2 KB, request headers 8 KB ([DOCS UsingMetadata](https://docs.aws.amazon.com/AmazonS3/latest/userguide/UsingMetadata.html), [LocalStack encode/decode helpers](https://github.com/localstack/localstack/blob/8b9a79f05846835cf4dff63ab7eefdde9df83783/localstack-core/localstack/services/s3/utils.py)).
- Timestamp header formats in the S3 model (parsed): `Last-Modified`, `If-Modified-Since`, `If-Unmodified-Since`, `x-amz-copy-source-if-*-since`, `x-amz-abort-date` use the `http-date` default; `x-amz-object-lock-retain-until-date` is `date-time` (`2000-01-01T00:00:00Z`, Go [CreateMultipartUpload.request.snap](https://github.com/aws/aws-sdk-go-v2/blob/ab2110b01f03b3990bfd50208a8a05df1d8c5eac/service/s3/request_snapshot/CreateMultipartUpload.request.snap)); `x-amz-if-match-last-modified-time`, `x-amz-if-match-initiated-time`, `x-amz-rename-source-if-*-since` are `http-date`; `Expires` is a plain string, not a timestamp ([MODEL](https://github.com/aws/api-models-aws/blob/1cfdfb4bb9ea858e65623e66d73af04bec353201/models/s3/service/2006-03-01/s3-2006-03-01.json)). Parse all three HTTP date forms; Go's `http.ParseTime` does.
- Flexible checksums and `aws-chunked` bodies are covered elsewhere; routing-relevant fact only: 25 operations carry `aws.protocols#httpChecksum {requestChecksumRequired: true}` in the model (parsed): `DeleteObjects`, `PutBucketAcl`, `PutBucketCors`, `PutBucketEncryption`, `PutBucketLifecycleConfiguration`, `PutBucketLogging`, `PutBucketOwnershipControls`, `PutBucketPolicy`, `PutBucketReplication`, `PutBucketRequestPayment`, `PutBucketTagging`, `PutBucketVersioning`, `PutBucketWebsite`, `PutObjectAcl`, `PutObjectLegalHold`, `PutObjectLockConfiguration`, `PutObjectRetention`, `PutObjectTagging`, `PutPublicAccessBlock`, `UpdateObjectEncryption`, and five metadata-configuration operations. A current client therefore sends `Content-MD5` or an `x-amz-checksum-*` header with all of them; DOCS: Content-MD5 "is required for all Multi-Object Delete requests" on general purpose buckets ([API_DeleteObjects](https://docs.aws.amazon.com/AmazonS3/latest/API/API_DeleteObjects.html)). A server may verify when present; whether to reject their absence is a fidelity decision (the real error text is UNVERIFIED).
- `Expect: 100-continue`: botocore adds it to every `PUT`/`POST` with a file-like body ([handlers.py L380-397](https://github.com/boto/botocore/blob/bfb412faf00c249a54816e287a09a8bb79442c65/botocore/handlers.py#L380-L397)). Go's `net/http` server sends `100 Continue` automatically when the handler first reads the body, so validate headers (auth, existence of bucket, preconditions) before reading the body to get the early-reject behavior.

### 3.5 CreateBucket, regions and redirects

Rules, with the evidence for each:
- Body is optional; `CreateBucketConfiguration/LocationConstraint` names the region; omitted means `us-east-1`; `EU` is an alias for `eu-west-1`; valid values are the 38 listed in the model enum (`af-south-1` ... `us-west-2`, `EU`) ([API_CreateBucket](https://docs.aws.amazon.com/AmazonS3/latest/API/API_CreateBucket.html), MODEL `BucketLocationConstraint`). `us-east-1` itself is not in the enum.
- Request to a non-`us-east-1` regional endpoint without a matching constraint: `IllegalLocationConstraintException`, 400, "The unspecified location constraint is incompatible for the region specific endpoint this request was sent to." Constraint naming a different region than the endpoint: same code. Constraint `us-east-1` sent to `us-east-1` (or an unknown value like `foo`): `InvalidLocationConstraint`, 400, "The specified location-constraint is not valid", with a `LocationConstraint` context element (REC: [test_create_bucket_with_invalid_location_constraint, test_bucket_constraint_aws_global](https://github.com/localstack/localstack/blob/8b9a79f05846835cf4dff63ab7eefdde9df83783/tests/aws/services/s3/test_s3.snapshot.json); the DOCS describe the first as "location constraint that corresponds to a different region than the regional endpoint", [ErrorResponses](https://docs.aws.amazon.com/AmazonS3/latest/developerguide/ErrorResponses.html)).
- Terraform omits the configuration in `us-east-1` and sends the provider region otherwise ([bucket.go L790-794](https://github.com/hashicorp/terraform-provider-aws/blob/972faab3f6e4e37aff0453fe05366f3bd3fc2b97/internal/service/s3/bucket.go#L790-L794)); it also sends `x-amz-acl: private` by default.
- Re-creating a bucket you own: `us-east-1` returns 200 and resets ACLs; other regions return `BucketAlreadyOwnedByYou` 409 "Your previous request to create the named bucket succeeded and you already own it." (DOCS [CreateBucket](https://docs.aws.amazon.com/AmazonS3/latest/API/API_CreateBucket.html), REC [test_create_bucket_with_existing_name](https://github.com/localstack/localstack/blob/8b9a79f05846835cf4dff63ab7eefdde9df83783/tests/aws/services/s3/test_s3.snapshot.json)). Terraform pre-checks `HeadBucket` in `us-east-1` and fails with `BucketAlreadyExists` for exactly this reason ([bucket.go L762-768](https://github.com/hashicorp/terraform-provider-aws/blob/972faab3f6e4e37aff0453fe05366f3bd3fc2b97/internal/service/s3/bucket.go#L762-L768)). A name owned by another account is `BucketAlreadyExists` 409.
- Success response: `200`, empty body, `Location: /<bucket>` for `us-east-1`; for other regions the DOCS say the global endpoint URL form `http://<bucket>.s3.amazonaws.com/` ([API_CreateBucket](https://docs.aws.amazon.com/AmazonS3/latest/API/API_CreateBucket.html)). Clients ignore it.
- `HeadBucket`: `200` with `x-amz-bucket-region`; for a bucket in another region `301` with `x-amz-bucket-region`; no access `403` with `x-amz-bucket-region`; missing `404` (no body for any) ([API_HeadBucket](https://docs.aws.amazon.com/AmazonS3/latest/API/API_HeadBucket.html)). Go's `GetBucketRegion` reads only that header and treats a 404 with no header as "bucket not found" ([bucket_region.go](https://github.com/aws/aws-sdk-go-v2/blob/ab2110b01f03b3990bfd50208a8a05df1d8c5eac/feature/s3/manager/bucket_region.go)); it sends the request unsigned by default, so a signature-less `HEAD /bucket` must still return the header (Terraform overrides this by passing credentials).
- boto3 follows redirects automatically on: error code `PermanentRedirect`; status 301/302/307; `AuthorizationHeaderMalformed` with a `Region` element; `HeadObject`/`HeadBucket` with 301/400 (the latter only when `x-amz-bucket-region` is present); and `IllegalLocationConstraintException` on any operation except `CreateBucket`. It takes the region from `x-amz-bucket-region`, else the error's `Region`, else a `HeadBucket` ([utils.py S3RegionRedirectorv2 L1735-1900](https://github.com/boto/botocore/blob/bfb412faf00c249a54816e287a09a8bb79442c65/botocore/utils.py#L1735-L1900)). An emulator that returns `IllegalLocationConstraintException` outside `CreateBucket`, or any 301/307, makes boto3 re-resolve and retry once.

### 3.7 200-with-error responses

- DOCS: `CompleteMultipartUpload` sends the `200 OK` status line first, then may emit periodic whitespace while working, and "A request could fail after the initial 200 OK response has been sent ... The error response might be embedded in the 200 OK response" ([API_CompleteMultipartUpload](https://docs.aws.amazon.com/AmazonS3/latest/API/API_CompleteMultipartUpload.html)). `CopyObject` does the same, including cross-region throttling inside a 200 ([API_CopyObject](https://docs.aws.amazon.com/AmazonS3/latest/API/API_CopyObject.html)). Verbatim embedded error from DOCS:

```
HTTP/1.1 200 OK
x-amz-id-2: Uuag1LuByRx9e6j5Onimru9pO4ZVKnJ2Qz7/C1NPcfTWAtRPfTaOFg==
x-amz-request-id: 656c76696e6727732072657175657374
Connection: close
Server: AmazonS3

<?xml version="1.0" encoding="UTF-8"?>

<Error>
 <Code>InternalError</Code>
 <Message>We encountered an internal error. Please try again.</Message>
 <RequestId>656c76696e6727732072657175657374</RequestId>
 <HostId>Uuag1LuByRx9e6j5Onimru9pO4ZVKnJ2Qz7/C1NPcfTWAtRPfTaOFg==</HostId>
</Error>
```

- Which operations: not just those two. Go applies the detector to every S3 operation whose output is structured XML and not a streaming blob, streaming union or string payload ([S3ErrorWith200Status.java](https://github.com/aws/aws-sdk-go-v2/blob/ab2110b01f03b3990bfd50208a8a05df1d8c5eac/codegen/smithy-aws-go-codegen/src/main/java/software/amazon/smithy/aws/go/codegen/customization/service/s3/S3ErrorWith200Status.java)); botocore applies it to every operation except event-stream outputs and blob/string payloads, so `GetObject` is excluded ([handlers.py L1293-1322](https://github.com/boto/botocore/blob/bfb412faf00c249a54816e287a09a8bb79442c65/botocore/handlers.py#L1293-L1322)).
- Detection rule: Go reads the first XML start element, and if it is `Error` (case-insensitive) rewrites the status to 500 so normal error handling and retries apply; an empty body is not an error ([handle_200_error.go](https://github.com/aws/aws-sdk-go-v2/blob/ab2110b01f03b3990bfd50208a8a05df1d8c5eac/service/s3/internal/customizations/handle_200_error.go)). botocore parses the whole 200 body: root tag `Error`, or unparsable XML (a truncated stream), both become 500 ([handlers.py L170-185](https://github.com/boto/botocore/blob/bfb412faf00c249a54816e287a09a8bb79442c65/botocore/handlers.py#L170-L185)).
- Consequence for the writer: keep the XML declaration at the very start of the body. Whitespace keep-alives placed before `<?xml` would make an XML 1.0 parser fail on the declaration; botocore would then classify the response as a truncated-stream failure (inference from the two sources above; where real S3 puts its keep-alive whitespace is UNVERIFIED).
- Errors detected before the response starts (`EntityTooSmall`, `InvalidPart`, `InvalidPartOrder`, `NoSuchUpload`, `MalformedXML`, access errors) are ordinary 4xx responses (REC statuses in section 3.6).

### 3.8 Response headers worth getting right

- Always: `x-amz-request-id`, `x-amz-id-2`, `Server: AmazonS3`, `Date`, and `Content-Type: application/xml` for XML bodies ([DOCS common response headers](https://docs.aws.amazon.com/AmazonS3/latest/developerguide/RESTCommonResponseHeaders.html), [ErrorResponses](https://docs.aws.amazon.com/AmazonS3/latest/developerguide/ErrorResponses.html)).
- Object responses bind (from the model's `GetObjectOutput`/`HeadObjectOutput`): `Last-Modified`, `Content-Length`, `ETag`, `accept-ranges`, `Content-Range`, `Content-Type`, `Content-Encoding`, `Content-Language`, `Content-Disposition`, `Cache-Control`, `Expires`, `x-amz-version-id`, `x-amz-delete-marker`, `x-amz-storage-class` (omitted for STANDARD in real S3, UNVERIFIED), `x-amz-server-side-encryption`, `x-amz-server-side-encryption-aws-kms-key-id`, `x-amz-server-side-encryption-bucket-key-enabled`, `x-amz-mp-parts-count`, `x-amz-tagging-count`, `x-amz-missing-meta`, `x-amz-checksum-*`, `x-amz-checksum-type`, `x-amz-object-lock-*`, `x-amz-meta-*` ([MODEL](https://github.com/aws/api-models-aws/blob/1cfdfb4bb9ea858e65623e66d73af04bec353201/models/s3/service/2006-03-01/s3-2006-03-01.json)). Canonical header-key forms (`Etag` vs `ETag`) do not matter to SDKs; set `ETag` via direct map assignment if exact casing is wanted.
- Response `Content-Length` for HEAD is the object size even though no body is sent.

## 4. restJson1 and Lambda

### 4.1 restJson1 serialization

Source: [aws-restjson1-protocol.rst L252-314](https://github.com/smithy-lang/smithy/blob/ec88e02aa1e6315f3453b1eb99625352750282f3/docs/source-2.0/aws/protocols/aws-restjson1-protocol.rst#L252-L314).
- blob: base64 JSON string; timestamps: epoch seconds number by default (`timestampFormat` may override); `float`/`double` non-finite values are the strings `NaN`, `Infinity`, `-Infinity`; map is an object, set is an array; structure members use `jsonName` when present; a union is an object with one member and an unknown `__type` member must be ignored.
- `httpPayload` may target only structure, document, string, blob or union.
- Lambda exercises this: `Invoke` payload is a raw blob (any bytes, not re-encoded); `CreateFunction` request has `Code.ZipFile` as base64 in JSON ([CreateFunction.request.snap](https://github.com/aws/aws-sdk-go-v2/blob/ab2110b01f03b3990bfd50208a8a05df1d8c5eac/service/lambda/request_snapshot/CreateFunction.request.snap): `"ZipFile":"YmxvYg=="`).

### 4.2 Error responses

- New servers MUST send `X-Amzn-Errortype`; clients accept that header, a body `__type`, or a body `code`, in that order of preference; the value should be only the shape name; clients sanitize by taking text before the first `:` and after the first `#` ([spec L331-362](https://github.com/smithy-lang/smithy/blob/ec88e02aa1e6315f3453b1eb99625352750282f3/docs/source-2.0/aws/protocols/aws-restjson1-protocol.rst#L331-L362)). Client behavior: Go reads `code` then `__type` from the body and the header, sanitizes, and reads the message from `message` or `Message` (Go's JSON decoder matches keys case-insensitively) ([restjson/decoder_util.go](https://github.com/aws/aws-sdk-go-v2/blob/ab2110b01f03b3990bfd50208a8a05df1d8c5eac/aws/protocol/restjson/decoder_util.go)); botocore checks `x-amzn-errortype` first, then body `code`/`Code`, and message from `message` or `Message` ([parsers.py L727-745, L1315-1334](https://github.com/boto/botocore/blob/bfb412faf00c249a54816e287a09a8bb79442c65/botocore/parsers.py#L727-L745)).
- Status: the error's `httpError` or 400 client / 500 server ([http-bindings L578-615](https://github.com/smithy-lang/smithy/blob/ec88e02aa1e6315f3453b1eb99625352750282f3/docs/source-2.0/spec/http-bindings.rst#L578-L615)). Error members bound to headers are honored (restJson1 `ComplexError` sets `X-Header`, [errors.smithy L104-114](https://github.com/smithy-lang/smithy/blob/ec88e02aa1e6315f3453b1eb99625352750282f3/smithy-aws-protocol-tests/model/restJson1/errors.smithy#L104-L114)).
- Lambda error shapes use inconsistent member capitalization, exactly as modeled ([MODEL](https://github.com/aws/api-models-aws/blob/1cfdfb4bb9ea858e65623e66d73af04bec353201/models/lambda/service/2015-03-31/lambda-2015-03-31.json), parsed): `ResourceNotFoundException` (404), `ServiceException` (500), `InvalidRuntimeException` (502), `ResourceInUseException` (400), `ServiceQuotaExceededException` (402) have `Type` and `Message`; `InvalidParameterValueException` (400), `InvalidRequestContentException` (400), `RequestTooLargeException` (413), `ResourceConflictException` (409), `ResourceNotReadyException` (502), `PolicyLengthExceededException` (400), `PreconditionFailedException` (412), `CodeStorageExceededException` (400), `UnsupportedMediaTypeException` (415) have `Type` and `message`; `TooManyRequestsException` (429) has `Type`, `message`, `Reason` and header `Retry-After` (`retryAfterSeconds`). Generate the body key from the model member name, not from a convention; both spellings parse in every SDK read above.
- Shape of the body the Go SDK's own test fixtures use (synthetic, derived from the model, not from AWS): `{"__type":"ResourceNotFoundException","Message":"__Message__","Type":"__Type__"}` with `404` ([ResourceNotFoundException.error.snap](https://github.com/aws/aws-sdk-go-v2/blob/ab2110b01f03b3990bfd50208a8a05df1d8c5eac/service/lambda/response_snapshot/ResourceNotFoundException.error.snap)). The value domain of `Type` (`User` for client faults, `Service` for server faults) is UNVERIFIED; the DOCS only say "The exception type" ([API_Invoke errors](https://docs.aws.amazon.com/lambda/latest/api/API_Invoke.html)). Send `X-Amzn-Errortype: <ShapeName>` (the spec's required form for new servers) and omit `__type` and `code` from the body.

### 4.4 Invoke wire behavior

Request ([API_Invoke](https://docs.aws.amazon.com/lambda/latest/api/API_Invoke.html), [MODEL `InvocationRequest`](https://github.com/aws/api-models-aws/blob/1cfdfb4bb9ea858e65623e66d73af04bec353201/models/lambda/service/2015-03-31/lambda-2015-03-31.json)):

```
POST /2015-03-31/functions/{FunctionName}/invocations?Qualifier={Qualifier} HTTP/1.1
X-Amz-Invocation-Type: Event | RequestResponse | DryRun     (default RequestResponse)
X-Amz-Log-Type: None | Tail                                 (sync only)
X-Amz-Client-Context: <base64, up to 3,583 bytes>            (sync only)
{raw payload bytes}
```

- Payload passthrough: the body is the raw blob (`httpPayload`, a `blob`). Go sends `Content-Type: application/octet-stream` with it ([Invoke.request.snap](https://github.com/aws/aws-sdk-go-v2/blob/ab2110b01f03b3990bfd50208a8a05df1d8c5eac/service/lambda/request_snapshot/Invoke.request.snap)); botocore sets no `Content-Type` for streaming payloads ([serialize.py L1094-1105](https://github.com/boto/botocore/blob/bfb412faf00c249a54816e287a09a8bb79442c65/botocore/serialize.py#L1094-L1105)); the Smithy server contract would answer 415 for these ([malformed-content-type.smithy](https://github.com/smithy-lang/smithy/blob/ec88e02aa1e6315f3453b1eb99625352750282f3/smithy-aws-protocol-tests/model/restJson1/malformedRequests/malformed-content-type.smithy)). A real service documents `UnsupportedMediaTypeException` for a non-JSON body type ([API_Invoke](https://docs.aws.amazon.com/lambda/latest/api/API_Invoke.html)), but because both major clients send other or no `Content-Type`, accept all.
- The documented model error for bad input: `InvalidRequestContentException` 400, "The request body could not be parsed as JSON, or a request header is invalid" ([MODEL docs](https://github.com/aws/api-models-aws/blob/1cfdfb4bb9ea858e65623e66d73af04bec353201/models/lambda/service/2015-03-31/lambda-2015-03-31.json)). Limits: 6 MB sync, 1 MB async ([API_Invoke](https://docs.aws.amazon.com/lambda/latest/api/API_Invoke.html)); over the limit is 413 `RequestEntityTooLargeException`, not the modeled `RequestTooLargeException` (see [lambda-api.md section 8.2](lambda-api.md)). Behavior for an empty body is UNVERIFIED here (see [lambda-api.md section 8](lambda-api.md)).
- Response: `StatusCode` is `httpResponseCode`: 200 for `RequestResponse`, 202 for `Event`, 204 for `DryRun` ([API_Invoke](https://docs.aws.amazon.com/lambda/latest/api/API_Invoke.html)). Headers: `X-Amz-Function-Error`, `X-Amz-Log-Result`, `X-Amz-Executed-Version` (the version an alias resolved to, pattern `(\$LATEST|[0-9]+)`), `X-Amz-Durable-Execution-Arn`. Body is the raw function result (a blob); for `Event` and `DryRun` the body is empty.
- `X-Amz-Function-Error`: "If present, indicates that an error occurred during function execution"; the HTTP status stays 200 ([API_Invoke](https://docs.aws.amazon.com/lambda/latest/api/API_Invoke.html)). Value: `Unhandled` in every recording ([lambda-api.md section 8.3](lambda-api.md)); `Handled` appears in old documentation and in moto, not in recordings, so emit `Unhandled`.
- `X-Amz-Log-Result`: base64 of the execution log tail, present only for `X-Amz-Log-Type: Tail` on sync invokes. The API reference says "The last 4 KB"; the developer guide's Live Tail comparison says "--log-type Tail returns only the first 4 KB" ([monitoring-cloudwatchlogs-view](https://docs.aws.amazon.com/lambda/latest/dg/monitoring-cloudwatchlogs-view.html)). The API wording and the name "Tail" agree on the last 4 KB; prefer it. Log format (`START RequestId: <id> Version: $LATEST`, user lines, `END RequestId: <id>`, `REPORT RequestId: <id>\tDuration: .. ms\tBilled Duration: .. ms\tMemory Size: .. MB\tMax Memory Used: .. MB`, optional `Init Duration`) is in [DOCS python-logging](https://docs.aws.amazon.com/lambda/latest/dg/python-logging.html).
- Async (`Event`): `202`, empty body; the function error is not visible to the caller. Retries and destinations are out of this document's scope ([lambda-api.md section 7.7](lambda-api.md)).
- RIE does not produce these headers (no occurrence of `X-Amz-Function-Error` in the RIE repository by code search; probe transcripts in [lambda-api.md section 8.3](lambda-api.md)), so the Invoke handler must synthesize `X-Amz-Function-Error`, `X-Amz-Executed-Version`, `X-Amz-Log-Result` and the status itself.
- `Content-Type` of a successful Invoke response: Go's fixture uses `application/octet-stream` ([Invoke.response.snap](https://github.com/aws/aws-sdk-go-v2/blob/ab2110b01f03b3990bfd50208a8a05df1d8c5eac/service/lambda/response_snapshot/Invoke.response.snap), synthetic); moto sends `application/json` ([awslambda/responses.py](https://github.com/getmoto/moto/blob/5cab9c903b2a26d08f353da2afc753b1adc1eb10/moto/awslambda/responses.py)). Real value UNVERIFIED; no client reads it.

## 5. One port, several protocols: how requests are claimed

- restXml and restJson1 claim by method and path; awsJson claims by `POST /` plus `X-Amz-Target`; awsQuery by `POST /` form body ([restXml L196-210](https://github.com/smithy-lang/smithy/blob/ec88e02aa1e6315f3453b1eb99625352750282f3/docs/source-2.0/aws/protocols/aws-restxml-protocol.rst#L196-L210), [awsJson template L28-47](https://github.com/smithy-lang/smithy/blob/ec88e02aa1e6315f3453b1eb99625352750282f3/docs/source-2.0/aws/protocols/aws-json.rst.template#L28-L47)).
- S3 path-style and Lambda collide (section 4.3). Disambiguate with the SigV4 service name in the credential scope (`Credential=<key>/<date>/<region>/s3|lambda/aws4_request`), which every SDK request carries, including presigned S3 URLs in `X-Amz-Credential`. For unsigned requests, a path matching `^/\d{4}-\d{2}-\d{2}/` is Lambda only if no bucket by that name exists (UNVERIFIED heuristic).
- Function URL traffic and virtual-hosted S3 are claimed by Host (not by path); keep Host-based claiming ahead of path-based claiming.

## Implications for understudy

1. **Own the HTTP front door; do not use `http.ServeMux`.** It redirects dot-segments and double slashes (section 3.3), which breaks S3 keys such as `../key.txt`, `a//b`, and anything with a trailing slash. Route on the raw escaped request target, split into segments, then decode each segment. The same layer provides the required traversal-safe key-to-disk mapping: decode once, reject NUL, never join a decoded key to a filesystem path (map keys to opaque storage ids).
2. **Generate S3 dispatch from the model, then override.** Build the `(method, scope, query keys, required header)` table in section 3.2 by code generation from the vendored S3 model (strip `x-id`, treat literal query keys as presence tests, add "required query/header member present" as a tie-breaker, order rows by specificity: more query keys and required headers first). Do not rely on Smithy's generic URI matching for S3. Add a table-driven test that sends the Go snapshot request lines (`?uploads=`, `?tagging=`, `&x-id=...`) and the botocore forms (`?uploads`, no `x-id`) and expects the same operation.
3. **Host parsing is configuration, not heuristics.** Accept a list of S3 base domains (default: `localhost`, plus the AWS names `s3.<region>.amazonaws.com`, `s3-fips`, `s3.dualstack`); a request is virtual-hosted iff the Host (port stripped) ends in `.`+base and the remaining prefix is non-empty, else path-style; Host equal to a base domain or an IP literal is path-style. Document both facts users hit: Go and JS SDKs pointed at `http://localhost:PORT` send `bucket.localhost:PORT` unless `UsePathStyle`/`forcePathStyle` is set, while boto3 and the AWS CLI send path-style.
4. **Lambda containers need a path-style-safe endpoint.** Functions get `AWS_ENDPOINT_URL` for SDK calls routed back to understudy. A hostname endpoint makes Go and JS SDKs inside the container resolve `<bucket>.<host>`, which Docker DNS does not provide. Hand containers an IPv4 literal endpoint (the bridge gateway or host IP), which the SDK ruleset forces to path-style. Verify with the three SDKs in the conformance suites.
5. **S3 vs Lambda path collision.** Choose the protocol router from the SigV4 service name (header `Authorization` credential scope or presigned `X-Amz-Credential`) before path matching; fall back to Host-based claiming (function URL host, virtual-hosted bucket host), and only then to a path heuristic.
6. **Write one S3 error writer.** Root `<Error>` without namespace, children `Code`, `Message`, then context elements (section 2.4 table), then `RequestId` and `HostId`; status from the code table (section 3.6); `x-amz-request-id`, `x-amz-id-2`, `Content-Type: application/xml`. `HEAD` errors: status only, no body. Model errors from the generated types give code and status; unmodeled S3 codes (`NoSuchBucketPolicy`, `BucketNotEmpty`, `EntityTooSmall`, ...) need a small hand-maintained registry seeded from section 3.6, because the Smithy model carries only 21 error shapes.
7. **Make "not configured" responses data-driven.** One table keyed by operation: error code, status, message, context element (section 3.6), plus the six operations that return empty or default configurations instead of errors. Seed new buckets with SSE-S3 default encryption and `BucketOwnerEnforced` so those reads succeed. The Terraform references in the table are the acceptance test for "second `terraform plan` shows no changes".
8. **Support the 200-with-error path in the fault engine.** Implement a post-header failure mode for `CompleteMultipartUpload`, `CopyObject` and `UploadPartCopy` that writes `200`, the XML declaration immediately, then an `<Error>` body (section 3.7); never write whitespace before the declaration. This lets users test SDK retry paths with fault injection, which is a differentiator.
9. **Be lenient in parsing, strict in output.** Inputs: header lists with comma and quoted forms, three HTTP date forms, first query value wins, empty subresource values, `Content-Type` parameters, absent or arbitrary `Content-Type` on Lambda `Invoke`, XML with and without namespace, empty or `{}` JSON bodies, leading `/` in `x-amz-copy-source`. Outputs: exact Smithy shapes, `xmlns` on S3 success roots, `EncodingType` echo with `%2B` for `+`.
10. **Treat `encoding-type=url` as mandatory.** boto3 requests it on every list call; implement it for `Key`, `Prefix`, `Delimiter`, `StartAfter`, `Marker`/`NextMarker`, `KeyMarker`/`NextKeyMarker`, common prefixes (section 3.4), with property tests that round-trip arbitrary keys through `unquote_plus`.
11. **CreateBucket follows the REC-verified rules in section 3.5.** Reject constraint `us-east-1` sent to `us-east-1`; require a matching constraint outside `us-east-1`; make `us-east-1` re-create idempotent; never return `IllegalLocationConstraintException` from non-`CreateBucket` operations (it triggers boto3's redirect logic). Return `x-amz-bucket-region` on `HeadBucket` and on bucket-addressed errors, including for unsigned requests. Because understudy wants per-account and per-region isolation, decide explicitly how a bucket created in region A is addressed from a request signed for region B; mimicking AWS means `301`/`PermanentRedirect` or `AuthorizationHeaderMalformed` with `Region`, which only boto3 follows automatically, so lenient cross-region access is friendlier (decision for the S3 implementer; recorded as open).
12. **Lambda restJson1 conventions.** Send `X-Amzn-Errortype: <Shape>` and a body keyed with the model's exact member names (`Type` plus `Message` or `message`), generated from the model; compute `httpResponseCode` members per request; accept any `Content-Type` on `Invoke` and treat the body as opaque bytes; synthesize `X-Amz-Function-Error: Unhandled`, `X-Amz-Executed-Version` and `X-Amz-Log-Result` (last 4096 bytes of the log, base64) because RIE does not provide them; status `200/202/204` by invocation type. Event source mapping create/update/delete return `202`; most other creates return `201`.
13. **XML writer.** Use a small streaming writer rather than `encoding/xml` for responses: it must emit `xmlns` on roots, `xsi:type` attributes with a prefixed namespace (ACL grantees), flattened lists, and control the XML declaration and byte order exactly. `encoding/xml` is acceptable for parsing requests (match on local names).
14. **Testing.** Run the Smithy restXml and restJson1 suites (including `services/s3.smithy`) as the protocol layer gate; add the Go snapshot request lines as golden routing tests; add recorded-error golden tests from section 3.6; add property tests (rapid) for label/query/header codecs, `encoding-type=url`, and key-to-path mapping.
15. **Unimplemented operations.** For S3 return `NotImplemented` 501 in S3 XML error form with a message naming the unimplemented operation; note that Terraform's legacy `aws_s3_bucket` reads swallow 501 on several inline attributes, so a 501 there is silent by Terraform's design. For Lambda return the restJson1 error shape with a clear `UnknownOperationException`-style code (exact AWS behavior for unknown Lambda routes is UNVERIFIED).
