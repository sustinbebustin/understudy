### 1.2 awsQuery wire details (IAM, STS)

Request, from the [Smithy awsQuery spec](https://smithy.io/2.0/aws/protocols/aws-query-protocol.html):

- `POST /`, `Content-Type: application/x-www-form-urlencoded`, `Content-Length` required, chunked transfer not supported. GET with a query string is allowed but discouraged.
- Body carries `Action=<OperationShapeName>` and `Version=<service version>`. Keys and values are RFC 3986 percent-encoded, pairs joined with `&`, key segments joined with `.`.
- Lists: `Name.member.N` with N from 1. Structures: `Name.field`. Maps: `Name.entry.N.key` / `.value`. `xmlName` renames the segment and `xmlFlattened` drops it.
- I scanned the IAM and STS models for `smithy.api#xmlName` on list members and for `smithy.api#xmlFlattened` on any member: zero hits in both. So every list in both services uses the literal `member` segment, and no list or map is flattened. Example from the STS docs: `PolicyArns.member.1.arn=...`, `Tags.member.1.Key=...`, `TransitiveTagKeys.member.1=...` ([AssumeRole example](https://docs.aws.amazon.com/STS/latest/APIReference/API_AssumeRole.html)).
- Booleans are `true`/`false`, blobs base64, timestamps default to `date-time` ([Smithy awsQuery](https://smithy.io/2.0/aws/protocols/aws-query-protocol.html)).

Success response ([Smithy awsQuery](https://smithy.io/2.0/aws/protocols/aws-query-protocol.html), [protocol tests: xml-lists.smithy](https://github.com/smithy-lang/smithy/blob/main/smithy-aws-protocol-tests/model/awsQuery/xml-lists.smithy)):

```xml
<GetCallerIdentityResponse xmlns="https://sts.amazonaws.com/doc/2011-06-15/">
  <GetCallerIdentityResult>
    <Arn>arn:aws:iam::123456789012:user/Alice</Arn>
    <UserId>AIDACKCEVSQ6C2EXAMPLE</UserId>
    <Account>123456789012</Account>
  </GetCallerIdentityResult>
  <ResponseMetadata><RequestId>01234567-89ab-cdef-0123-456789abcdef</RequestId></ResponseMetadata>
</GetCallerIdentityResponse>
```

(That body is verbatim from the [GetCallerIdentity docs](https://docs.aws.amazon.com/STS/latest/APIReference/API_GetCallerIdentity.html); the docs also show an `x-amzn-RequestId` response header, `Content-Type: text/xml`.)

- Root element is `<Action>Response` with `xmlns`; output sits in `<Action>Result`; `ResponseMetadata/RequestId` follows. Lists are `<Roles><member>...</member></Roles>`.
- Operations with no output (Smithy `Unit`, e.g. `DeleteRole`, `AttachRolePolicy`, `PutRolePolicy`) return only `<ResponseMetadata>` inside the `<Action>Response` root, no `Result` element. Source: [empty-input-output.smithy, QueryNoInputAndNoOutputWithResponseMetadata](https://github.com/smithy-lang/smithy/blob/main/smithy-aws-protocol-tests/model/awsQuery/empty-input-output.smithy).

Error response ([Smithy awsQuery](https://smithy.io/2.0/aws/protocols/aws-query-protocol.html), real IAM fixture [aws-cli iam-get-user.xml](https://github.com/aws/aws-cli/blob/develop/tests/unit/botocore/response_parsing/xml/errors/iam-get-user.xml)):

```xml
<ErrorResponse xmlns="https://iam.amazonaws.com/doc/2010-05-08/">
  <Error>
    <Type>Sender</Type>
    <Code>NoSuchEntity</Code>
    <Message>The user with name foobar cannot be found.</Message>
  </Error>
  <RequestId>358299bb-b7f8-11e2-8d39-e3a125f625ee</RequestId>
</ErrorResponse>
```

- `Type` is `Sender` (client fault) or `Receiver` (server fault). `Code` comes from the `awsQueryError.code` trait, otherwise the shape name. HTTP status comes from `awsQueryError.httpResponseCode`, otherwise 400 for client and 500 for server errors ([Smithy awsQuery](https://smithy.io/2.0/aws/protocols/aws-query-protocol.html)).
- Go SDK v2 reads `Error>Code`, `Error>Message` and top-level `RequestId`; with a missing `ErrorResponse` wrapper it also accepts unwrapped `Code`/`Message`/`RequestId` ([error_utils.go](https://github.com/aws/aws-sdk-go-v2/blob/main/aws/protocol/xml/error_utils.go)). The Go SDK matches XML element names case-insensitively in IAM output deserializers (`strings.EqualFold("CreateDate", ...)` in [iam deserializers.go](https://github.com/aws/aws-sdk-go-v2/blob/main/service/iam/deserializers.go)). Emit the exact Smithy member names anyway.
- IAM CreateDate parsing in Go v2 uses `smithytime.ParseDateTime` (same file), which accepts fractional seconds. Docs samples show both `2012-05-08T23:34:01.495Z` ([CreateRole](https://docs.aws.amazon.com/IAM/latest/APIReference/API_CreateRole.html)) and `2012-05-08T23:34:01Z` ([GetRole](https://docs.aws.amazon.com/IAM/latest/APIReference/API_GetRole.html)). Recorded real responses show whole seconds, e.g. `"CreateDate": "2020-08-09T16:55:28Z"` in [cloudsploit fixtures](https://github.com/aquasecurity/cloudsploit/blob/master/plugins/aws/iam/crossAccountMfaExtIdAccess.spec.js) (UNVERIFIED as real capture). Emit `YYYY-MM-DDTHH:MM:SSZ`.
- The awsQuery `Message` is the human text. Common IAM/STS error codes shared by every action (status codes from [IAM CommonErrors](https://docs.aws.amazon.com/IAM/latest/APIReference/CommonErrors.html)): `AccessDenied`/`AccessDeniedException` 403, `ExpiredTokenException` 403, `IncompleteSignature` 400, `InternalFailure` 500, `InvalidClientTokenId`/`UnrecognizedClientException` 403, `InvalidParameterValue` 400, `MissingAuthenticationToken` 403, `MissingAction`/`MissingParameter` 400, `NotAuthorized` 401, `RequestExpired` 400, `ServiceUnavailable` 503, `ThrottlingException` 400, `ValidationError` 400, `InvalidAction`/`InvalidQueryParameter` 400, `MalformedQueryString` 404.

### 1.3 awsJson1.1 wire details (KMS)

From the [Smithy awsJson1.1 spec](https://smithy.io/2.0/aws/protocols/aws-json-1_1-protocol.html) and [awsJson1.0 spec](https://smithy.io/2.0/aws/protocols/aws-json-1_0-protocol.html):

- `POST /`, `Content-Type: application/x-amz-json-1.1`, `Content-Length` required, `X-Amz-Target: TrentService.<OperationName>`. Go SDK v2 request snapshots confirm the shape: `POST /`, `Content-Type: application/x-amz-json-1.1`, `X-Amz-Target: TrentService.CancelKeyDeletion`, body `{"KeyId":"__KeyId__"}` ([request_snapshot](https://github.com/aws/aws-sdk-go-v2/tree/main/service/kms/request_snapshot)).
- Timestamps are JSON numbers in epoch seconds (double). Blobs are base64 JSON strings. A client sends `{}` for empty input; servers must accept an empty body and may reply `{}`.
- Error marker is one of: header `X-Amzn-Errortype`, body field `code`, or body field `__type`. Clients sanitize: if `:` is present keep what precedes the first one; then if `#` is present keep what follows the first one. For 1.1, servers send the bare shape name. Go SDK snapshot of a KMS error: `{"__type":"DisabledException","message":"__Message__"}` ([DisabledException.error.snap](https://github.com/aws/aws-sdk-go-v2/blob/main/service/kms/response_snapshot/DisabledException.error.snap)). Go's helper reads `code`, `__type` and `message` ([restjson decoder_util.go](https://github.com/aws/aws-sdk-go-v2/blob/main/aws/protocol/restjson/decoder_util.go)); Go's JSON decode is case-insensitive, so `Message` also works. Emit lowercase `message`.
- Docs examples render timestamps as ISO strings (`"CreationDate": "2025-04-16T16:03:04.060000-07:00"` in [CreateKey docs](https://docs.aws.amazon.com/kms/latest/APIReference/API_CreateKey.html)), but the protocol default is epoch seconds and the SDK snapshots carry numbers (`"CreationDate":946684800` in [CreateKey.response.snap](https://github.com/aws/aws-sdk-go-v2/blob/main/service/kms/response_snapshot/CreateKey.response.snap)). The docs rendering is CLI output. Emit numbers. Emitting an ISO string would break strict JSON-number parsers (JS v3 `parseEpochTimestamp(expectNumber(...))`, UNVERIFIED but implied by the protocol spec).
- Smithy test suites to bind the protocol layer against: [awsQuery](https://github.com/smithy-lang/smithy/tree/main/smithy-aws-protocol-tests/model/awsQuery) (files include `xml-errors.smithy`, `xml-lists.smithy`, `input-lists.smithy`, `empty-input-output.smithy`) and [awsJson1_1](https://github.com/smithy-lang/smithy/tree/main/smithy-aws-protocol-tests/model/awsJson1_1).

## 2. Identifiers, ARNs and access keys

### 2.1 Prefixes and formats

Unique ID prefixes ([IAM identifiers](https://docs.aws.amazon.com/IAM/latest/UserGuide/reference_identifiers.html)): `AKIA` access key, `ASIA` temporary (STS) access key id, `AROA` role, `ANPA` managed policy, `ANVA` managed policy version, `AIDA` user, `AGPA` group, `AIPA` EC2 instance profile, `APKA` public key, `ASCA` certificate, `ABIA` STS service bearer token, `ACCA` context-specific credential. The page adds "Prefixes may vary based on when they were created". `ASIA` ids are "unique only in combination with the secret access key and the session token".

Lengths: observed role IDs and instance profile IDs are 21 characters (`AROADBQP57FF2AEXAMPLE` in [CreateRole sample](https://docs.aws.amazon.com/IAM/latest/APIReference/API_CreateRole.html); `AIPAJJOHXXHTHDZB5BVFE`, `AROAJVFVDALUIEJPNG236` in [cloud-custodian ListInstanceProfiles_1.json](https://github.com/cloud-custodian/cloud-custodian/blob/main/tests/data/placebo/test_iam_role_unused/iam.ListInstanceProfiles_1.json)). Access key ids are 20 characters (`AKIAIOSFODNN7EXAMPLE`, [GetAccessKeyInfo docs](https://docs.aws.amazon.com/STS/latest/APIReference/API_GetAccessKeyInfo.html)). Model constraints: IDs `^[\w]+$`, length 16..128 (`idType` in the IAM model); access key id `^[\w]*$` length 16..128 (`accessKeyIdType` in the STS model); the quota page caps unique IDs at 128 characters ([quotas](https://docs.aws.amazon.com/IAM/latest/UserGuide/reference_iam-quotas.html)). Secret access key example is 40 characters (`wJalrXUtnFEMI/K7MDENG/bPxRfiCYEXAMPLEKEY`, [GetAccessKeyInfo docs](https://docs.aws.amazon.com/STS/latest/APIReference/API_GetAccessKeyInfo.html)); the model types it as an unconstrained string (`accessKeySecretType`).

ARN formats ([IAM identifiers](https://docs.aws.amazon.com/IAM/latest/UserGuide/reference_identifiers.html)); the region field is empty for IAM:

```
arn:aws:iam::<acct>:root
arn:aws:iam::<acct>:user/<path><name>
arn:aws:iam::<acct>:role/<path><name>
arn:aws:iam::<acct>:policy/<path><name>
arn:aws:iam::<acct>:instance-profile/<path><name>
arn:aws:iam::aws:policy/<path><name>                       (AWS managed policy; account field is the literal "aws")
arn:aws:sts::<acct>:assumed-role/<role-name>/<session-name>   (role name only, no path)
arn:aws:sts::<acct>:federated-user/<name>
```

`<path>` is `/` or begins and ends with `/` (model pattern `^(/)|(/[!-~]+/)$` for role/user/instance-profile paths; `^((/[A-Za-z0-9\.,\+@=_-]+)*)/$` for policy paths; max 512). Names: `[\w+=,.@-]+`; role 1..64, user 1..64, policy 1..128, instance profile 1..128 (model). Names are unique case-insensitively but case is preserved, and "case-sensitive when you use it in a policy or as part of an ARN" ([identifiers](https://docs.aws.amazon.com/IAM/latest/UserGuide/reference_identifiers.html), [quotas](https://docs.aws.amazon.com/IAM/latest/UserGuide/reference_iam-quotas.html), [CreateRole](https://docs.aws.amazon.com/IAM/latest/APIReference/API_CreateRole.html)).

Terraform guards against an eventual-consistency quirk where a freshly created role's `Arn` comes back as the unique ID: `waitRoleARNIsNotUniqueID` polls until `arn.IsARN` ([role.go](https://github.com/hashicorp/terraform-provider-aws/blob/main/internal/service/iam/role.go)). Always return a full ARN.

### 2.2 How an account ID is encoded in an access key ID

Algorithm (credited to Aidan Steele, refined by Tal Be'ery; documented at [hackingthe.cloud](https://hackingthe.cloud/aws/enumeration/get-account-id-from-keys/) and the [Medium post](https://medium.com/@TalBeerySec/a-short-note-on-aws-key-id-f88cc4317489)):

1. Drop the 4-character prefix (`AKIA`, `ASIA`, ...).
2. Base32-decode the remaining 16 characters (RFC 4648 alphabet `A-Z2-7`), giving 10 bytes.
3. Read the first 6 bytes as a big-endian 48-bit integer `z`.
4. `account = (z & 0x7fffffffff80) >> 7`, printed zero-padded to 12 digits.

I ran this check locally (Python, no network):

- `AKIAIOSFODNN7EXAMPLE` decodes to `581039954779`.
- `ASIAQNZGKIQY56JQ7WML` decodes to `029608264753`.
- A key built with top bit set, `account<<7`, 7 random bits then 32 random bits, prefix `AKIA`, round-trips (`123456789012` -> `AKIARZPUZDIKNGW42DFU` -> `123456789012`; `0` -> `ASIAQAAAAAAAFMLBRZQW` -> `000000000000`).

Layout, from [WithSecure's bitwise analysis](https://labs.withsecure.com/publications/a-bitwise-analysis-of-aws-access-key-identifiers) as relayed by search results (the page itself redirected on fetch, so UNVERIFIED against the original text): bits 0-19 are the prefix; bit 20 is a "generation" flag (1 = new generation); bits 21-60 are the 40-bit account number for new-generation keys; later bits are not understood. The mask above is consistent with this (bit 47 of the 48-bit window is the generation flag and is excluded; 40 bits cover any 12-digit account since 10^12 < 2^40). A new-generation body therefore starts with a base32 character in `Q-Z2-7` (top bit set); `AKIAIOSFODNN7EXAMPLE` starts with `I` (top bit clear) and still decodes by the same formula.

moto's generator implements the same layout from the other direction: `account_id // 2 + 549755813888` (that constant is `base32decode("QAAAAAAA")`, i.e. 2^39) packed into 5 bytes, base32-encoded to 8 characters, then a 9th character taken from the upper half of the alphabet when the account number is odd and the lower half when even, then random characters up to total length 20 for keys or 21 for role IDs ([moto/iam/utils.py](https://github.com/getmoto/moto/blob/608bfa92a71ddd19b0efa0a9e5eaaffaa54c38af/moto/iam/utils.py)). That is the same encoding: the low account bit lands in the first bit of the 9th character. Role IDs (`AROA...`) are generated with the same account encoding in moto; whether real role IDs embed the account is UNVERIFIED.

`GetAccessKeyInfo` returns `Account` for any `AKIA`/`ASIA` id, does not report key state, and "providing a deleted access key might return an error that the key doesn't exist" ([GetAccessKeyInfo](https://docs.aws.amazon.com/STS/latest/APIReference/API_GetAccessKeyInfo.html)); WithSecure reports it ignores invalid base32 characters (UNVERIFIED, same search-result relay).

AWS documentation example keys are not all valid base32: `AKIAI44QH8DHBEXAMPLE` contains `8` and fails a strict decode (my local run: "Non-base32 digit found"). SDK test suites and docs use these. Any account derivation must tolerate non-decodable keys.

### 2.3 Prior art for "account derived from the access key"

[LocalStack credentials docs](https://docs.localstack.cloud/references/credentials/) (LocalStack's OSS repo is archived, [GitHub API: `archived: true`, last push 2026-03-23](https://github.com/localstack/localstack)):

1. A 12-digit numeric access key id is taken as the account id (`112233445566`).
2. A structured key (20+ chars) decodes to an account; by default only `LSIA...`/`LKIA...` prefixes are accepted, and `AKIA`/`ASIA` keys are rejected (falling back to `000000000000`) "to prevent misuse of production AWS access key IDs". `PARITY_AWS_ACCESS_KEY_ID` disables the guard.
3. Anything else (`test`, `foobar123`) maps to `000000000000`.
4. The secret access key is ignored.

moto's STS `GetCallerIdentity` fallback returns user id `AKIAIOSFODNN7EXAMPLE` and ARN `arn:<partition>:sts::<account>:user/moto` ([moto/sts/models.py](https://github.com/getmoto/moto/blob/608bfa92a71ddd19b0efa0a9e5eaaffaa54c38af/moto/sts/models.py)); LocalStack rewrites that ARN to `arn:<partition>:iam::<account>:root` ([localstack sts/provider.py](https://github.com/localstack/localstack/blob/main/localstack-core/localstack/services/sts/provider.py)).

### 3.3 Policy document encoding

- `AssumeRolePolicyDocument` (every `Role` in `CreateRole`, `GetRole`, `ListRoles`, and nested in `InstanceProfile.Roles`), `GetRolePolicy.PolicyDocument`, `GetUserPolicy`/`GetGroupPolicy` and `PolicyVersion.Document` are URL-encoded in responses ([GetRole note](https://docs.aws.amazon.com/IAM/latest/APIReference/API_GetRole.html), [GetRolePolicy note](https://docs.aws.amazon.com/IAM/latest/APIReference/API_GetRolePolicy.html), [PolicyVersion.Document docs in model](https://github.com/aws/api-models-aws/blob/1cfdfb4bb9ea858e65623e66d73af04bec353201/models/iam/service/2010-05-08/iam-2010-05-08.json)). `CreateRole`'s response is also encoded in recorded traffic (a SDK test for `CreateRoleResponse` asserts `%7B%22Version%22%3A%222012-10-17%22...`, [mattandneil/aws-sdk IAMTest.cls](https://github.com/mattandneil/aws-sdk/blob/master/IAMTest.cls), UNVERIFIED as real capture), although the [CreateRole docs](https://docs.aws.amazon.com/IAM/latest/APIReference/API_CreateRole.html) say "the response includes the same trust policy in JSON format".
- Recorded real form: `%7B%22Version%22%3A%222012-10-17%22%2C%22Statement%22%3A%5B%7B%22Effect%22%3A%22Allow%22%2C%22Principal%22%3A%7B%22Service%22%3A%22lambda.amazonaws.com%22%7D%2C%22Action%22%3A%22sts%3AAssumeRole%22%7D%5D%7D` ([cloud-custodian ListRoles_1.json](https://github.com/cloud-custodian/cloud-custodian/blob/main/tests/data/placebo/test_iam_role_has_specific_managed_policy/iam.ListRoles_1.json)). The stored JSON there is compact (no spaces), so the space encoding (`%20` vs `+`) is not shown; the docs say RFC 3986, which means `%20`.
- Why encoding matters: Terraform decodes with `url.QueryUnescape`, which turns `+` into a space ([role.go](https://github.com/hashicorp/terraform-provider-aws/blob/main/internal/service/iam/role.go), [policy.go resourcePolicyFlattenPolicyDocument](https://github.com/hashicorp/terraform-provider-aws/blob/main/internal/service/iam/policy.go), [role_policy.go](https://github.com/hashicorp/terraform-provider-aws/blob/main/internal/service/iam/role_policy.go)). A plain-JSON response containing a `+` (for example a condition value) would be corrupted and cause a perpetual diff. Percent-encode everything outside RFC 3986 unreserved characters so that both `QueryUnescape` and botocore's `unquote` round-trip.
- botocore's decode is tolerant of un-encoded input (`json.loads(unquote(value))`, falling back to the raw string on `ValueError`, [handlers.py `decode_quoted_jsondoc`](https://github.com/boto/botocore/blob/bfb412faf00c249a54816e287a09a8bb79442c65/botocore/handlers.py#L293-L300)); it only touches members whose shape is named `policyDocumentType`, so boto3 returns dicts for those fields ([handlers.py L577-L608](https://github.com/boto/botocore/blob/bfb412faf00c249a54816e287a09a8bb79442c65/botocore/handlers.py#L577-L608), registered via `('after-call.iam', json_decode_policies)` at L1539). JS v3 and Go v2 return the raw encoded string (UNVERIFIED for JS; Go v2 deserializes `policyDocumentType` as a plain string per the [IAM model](https://github.com/aws/api-models-aws/blob/1cfdfb4bb9ea858e65623e66d73af04bec353201/models/iam/service/2010-05-08/iam-2010-05-08.json)).
- Request side: the document arrives as a normal form value (already decoded by the form parser). IAM stores policies as JSON; the stored text is what comes back (Terraform normalizes both sides with `structure.NormalizeJsonString` / `verify.PolicyToSet`, so whitespace differences are tolerated, key order is not material to its equivalence check, but value semantics are).
- Validation (`MalformedPolicyDocument`, 400): moto's validator is the only wide public catalogue of messages: `Syntax errors in policy.`, `Policy document must be version 2012-10-17 or greater.`, `The policy failed legacy parsing`, `Statement IDs (SID) in a single policy must be unique.`, `Policy statement must contain actions.`, `Policy statement must contain resources.`, `Actions/Conditions must be prefaced by a vendor, e.g., iam, sdb, ec2, etc.`, `Actions/Condition can contain only one colon.`, `Vendor <x> is not valid`, trust policies: `Has prohibited field Resource.` ([moto iam/policy_validation.py](https://github.com/getmoto/moto/blob/608bfa92a71ddd19b0efa0a9e5eaaffaa54c38af/moto/iam/policy_validation.py), UNVERIFIED against real AWS). Grammar reference: [IAM policy grammar](https://docs.aws.amazon.com/IAM/latest/UserGuide/reference_policies_grammar.html). Valid `Version`: `2008-10-17`, `2012-10-17` (moto `VALID_VERSIONS`).
- Identity policies (`CreatePolicy`, `CreatePolicyVersion`, `PutRolePolicy`, `PutUserPolicy`) must not name a principal: `MalformedPolicyDocument` `Policy document should not specify a principal.` moto lacks this rule. Sources: [versitygw iamapi/policy/validate.go](https://github.com/versity/versitygw/blob/2147a0c30473dc9314e9106b527d50a36c484594/iamapi/policy/validate.go) and an [ansible amazon.aws test fixture](https://github.com/ansible-collections/amazon.aws/blob/main/tests/unit/plugins/module_utils/s3/test_s3_error_handler.py) (third-party, UNVERIFIED against AWS). Unconfirmed candidate for trust policies: `Missing required field Principal`, seen only in [versitygw iamapi/policy/trust.go](https://github.com/versity/versitygw/blob/2147a0c30473dc9314e9106b527d50a36c484594/iamapi/policy/trust.go); understudy does not implement it.
- Real AWS validates principals in trust policies: `MalformedPolicyDocument: Invalid principal in policy: "AWS":"arn:aws:iam::..."` is the eventual-consistency error TF retries ("Invalid principal in policy", [role.go retryCreateRole / UpdateAssumeRolePolicy](https://github.com/hashicorp/terraform-provider-aws/blob/main/internal/service/iam/role.go)). A local emulator can skip principal existence checks; TF only retries on that message, never requires it.

How Terraform reacts, so the emulator's error choice drives the apply flow:

- `DeleteRole` is retried for up to 2 minutes on `DeleteConflict`; a `NoSuchEntity` on delete is treated as success ([role.go deleteRole](https://github.com/hashicorp/terraform-provider-aws/blob/main/internal/service/iam/role.go); `propagationTimeout = 2 * time.Minute` in [consts.go](https://github.com/hashicorp/terraform-provider-aws/blob/main/internal/service/iam/consts.go)).
- `AttachRolePolicy`/`DetachRolePolicy` retry on `ConcurrentModification` ([role_policy_attachment.go](https://github.com/hashicorp/terraform-provider-aws/blob/main/internal/service/iam/role_policy_attachment.go)). Never return `ConcurrentModification` spuriously.
- After create, TF re-reads with retry-on-not-found for new resources (role, policy, instance profile, attachments, inline policies), so strongly consistent reads are fine and no artificial delay is needed.
- Policy update: `policyPruneVersions` deletes the oldest non-default version when 5 exist, then `CreatePolicyVersion(SetAsDefault=true)`; with `delay_after_policy_creation_in_ms` it creates non-default, sleeps, then `SetDefaultPolicyVersion` ([policy.go](https://github.com/hashicorp/terraform-provider-aws/blob/main/internal/service/iam/policy.go)). `ListPolicyVersions` must therefore return `IsDefaultVersion` and `CreateDate` for each version, and `DeleteConflict` for the default.
- Policy destroy: lists versions, deletes every non-default version, then `DeletePolicy` (same file).
- `GetPolicy` is read together with `GetPolicyVersion(DefaultVersionId)`; both must agree, else the retry loop treats it as not found (same file).
- Instance profile add-role retries on `NoSuchEntity` messages containing `The role with name` and on `InvalidParameterValue ... Invalid IAM Instance Profile name`: "IAM unfortunately does not provide a better error code or message for eventual consistency" ([instance_profile.go](https://github.com/hashicorp/terraform-provider-aws/blob/main/internal/service/iam/instance_profile.go)).

### 3.5 Managed policy ARNs owned by AWS

`arn:aws:iam::aws:policy/<path><name>` ARNs (for example `service-role/AWSLambdaBasicExecutionRole`) are attachable without being created in the account. `ListPolicies` with `Scope=AWS` lists them; `GetPolicy` on them returns `PolicyId` (`ANPA...`), `IsAttachable=true` and a default version ([ListPolicies docs in model](https://github.com/aws/api-models-aws/blob/1cfdfb4bb9ea858e65623e66d73af04bec353201/models/iam/service/2010-05-08/iam-2010-05-08.json)). `AttachRolePolicy` to a nonexistent ARN returns `NoSuchEntity` (model error list; message UNVERIFIED, moto uses `Policy <arn> was not found.`). TF's `aws_iam_role_policy_attachment` does not call `GetPolicy`; it only needs `AttachRolePolicy` and `ListAttachedRolePolicies` to round-trip `PolicyArn` and `PolicyName` ([role_policy_attachment.go](https://github.com/hashicorp/terraform-provider-aws/blob/main/internal/service/iam/role_policy_attachment.go)). `AttachedPolicy.PolicyName` is derived from the ARN's last segment (UNVERIFIED).

### 3.6 Global behavior and endpoints

- IAM is global: ARNs have an empty region; the model's endpoint rules resolve `https://iam.amazonaws.com` with `authSchemes: [{name: sigv4, signingRegion: us-east-1}]` for the `aws` partition (FIPS and dual-stack variants differ; `aws-cn` signs as `cn-north-1`, `aws-us-gov` as `us-gov-west-1`). I enumerated the `endpoint` results in the ruleset ([IAM model, `smithy.rules#endpointRuleSet`](https://github.com/aws/api-models-aws/blob/1cfdfb4bb9ea858e65623e66d73af04bec353201/models/iam/service/2010-05-08/iam-2010-05-08.json)).
- With `AWS_ENDPOINT_URL` (or per-service endpoint) set, the first rule returns the custom URL with empty properties (`{"c":"","url":{"ref":"Endpoint"},"props":{}}` in the same ruleset), so no `signingRegion` override applies and the SDK signs with the client's configured region, not `us-east-1` (inference, UNVERIFIED by live test). The emulator must accept any region in the SigV4 credential scope for IAM and STS, and must not tie IAM data to a region.
- Eventual consistency (docs): "Any changes that you make in IAM ... take time to become visible from all possible endpoints" ([IAM troubleshooting](https://docs.aws.amazon.com/IAM/latest/UserGuide/troubleshoot_general.html#troubleshoot_general_eventual-consistency)). Emulator choice: be strongly consistent; TF and the SDKs only add retries.

### 5.3 Key policies

These are predefined aliases that Amazon Web Services has created but has not yet associated with a KMS key" ([ListAliases docs in model](https://github.com/aws/api-models-aws/blob/1cfdfb4bb9ea858e65623e66d73af04bec353201/models/kms/service/2014-11-01/kms-2014-11-01.json)). AWS-created aliases do not count against the alias quota.
- AWS managed keys: `DescribeKey` on a predefined alias with no key "associates the alias with an AWS managed key and returns its KeyId and Arn" ("AWS services use DescribeKey to create AWS managed keys from a predefined AWS alias with no key ID", [DescribeKey docs in model](https://github.com/aws/api-models-aws/blob/1cfdfb4bb9ea858e65623e66d73af04bec353201/models/kms/service/2014-11-01/kms-2014-11-01.json)). They have `KeyManager: "AWS"`. S3: "If you don't specify a customer managed key, Amazon S3 automatically creates an AWS managed key in your AWS account the first time that you add an object encrypted with SSE-KMS" ([S3 SSE-KMS](https://docs.aws.amazon.com/AmazonS3/latest/userguide/UsingKMSEncryption.html)); Secrets Manager: "If you choose the AWS managed key aws/secretsmanager and it doesn't already exist yet, Secrets Manager creates it" ([SM encryption](https://docs.aws.amazon.com/secretsmanager/latest/userguide/security-encryption.html)). TF also looks up `alias/aws/<service>` through `DescribeKey` ([key.go findDefaultKeyARNForService](https://github.com/hashicorp/terraform-provider-aws/blob/main/internal/service/kms/key.go)). AWS managed keys cannot be tagged, have rotation always reported `true` and cannot have rotation toggled ([GetKeyRotationStatus](https://docs.aws.amazon.com/kms/latest/APIReference/API_GetKeyRotationStatus.html)).
- moto's reserved alias table (service -> alias, with fixed per-service key ids) is a convenient list of services: acm, dynamodb, ebs, elasticfilesystem, es, glue, kinesisvideo, lambda, rds, redshift, s3, secretsmanager, ssm, xray ([moto kms/utils.py](https://github.com/getmoto/moto/blob/608bfa92a71ddd19b0efa0a9e5eaaffaa54c38af/moto/kms/utils.py)). Its description for generated keys is just `Default key`; real AWS managed key descriptions are service-specific text (UNVERIFIED; not captured).
- AWS managed key policy example (Secrets Manager): `Id: auto-secretsmanager-2`, statements gated on `kms:ViaService = secretsmanager.<region>.amazonaws.com` and `kms:CallerAccount`, plus a third statement giving the account root `kms:Describe*`, `kms:Get*`, `kms:List*`, `kms:RevokeGrant` ([SM encryption](https://docs.aws.amazon.com/secretsmanager/latest/userguide/security-encryption.html)).
- `UpdateAlias` changes the target; allowed when the source key is pending deletion, rejected (`KMSInvalidStateException ... is pending deletion.`) when the destination is ([key-state table footnote 10](https://docs.aws.amazon.com/kms/latest/developerguide/key-state.html)). `DeleteAlias` works in every state.
- TF reads an alias by paging `ListAliases` and matching `AliasName`; it derives the target key ARN by replacing the alias portion of `AliasArn` with `key/<TargetKeyId>` ([alias.go resourceAliasFlatten / aliasARNToKeyARN](https://github.com/hashicorp/terraform-provider-aws/blob/main/internal/service/kms/alias.go)). `AliasArn` must be a well-formed ARN.

### 5.5 Rotation

- `EnableKeyRotation(KeyId, RotationPeriodInDays?)`: period 90..2560, default 365; first rotation one period after enable; only for symmetric encryption keys with `AWS_KMS` origin; not for asymmetric, HMAC, imported-material or custom-store keys; AWS managed keys cannot be toggled ([EnableKeyRotation docs in model](https://github.com/aws/api-models-aws/blob/1cfdfb4bb9ea858e65623e66d73af04bec353201/models/kms/service/2014-11-01/kms-2014-11-01.json)).
- `GetKeyRotationStatus` -> `{KeyId, KeyRotationEnabled, RotationPeriodInDays?, NextRotationDate?, OnDemandRotationStartDate?}`; "default value is 365 days"; AWS managed keys always `true`; while pending deletion the status is `false` and returns to its prior value on cancel; disabling a key does not change the status ([GetKeyRotationStatus](https://docs.aws.amazon.com/kms/latest/APIReference/API_GetKeyRotationStatus.html)). For a never-enabled customer key the response is `KeyRotationEnabled=false`; whether `RotationPeriodInDays`/`NextRotationDate` are omitted then is UNVERIFIED. TF's `rotation_period_in_days` is `Optional + Computed` and is set from `output.RotationPeriodInDays` (nil is fine) ([key.go](https://github.com/hashicorp/terraform-provider-aws/blob/main/internal/service/kms/key.go)).
- Key-state matrix (7): `EnableKeyRotation`/`DisableKeyRotation` on a `Disabled` key -> `DisabledException: <key ARN> is disabled.`; on `PendingDeletion` -> `KMSInvalidStateException: <key ARN> is pending deletion (or pending replica deletion).`; on `EXTERNAL` origin -> `UnsupportedOperationException: <key ARN> origin is EXTERNAL which is not valid for this operation.` ([key states](https://docs.aws.amazon.com/kms/latest/developerguide/key-state.html)). TF retries rotation updates on `NotFoundException`/`DisabledException` for up to 10 minutes and then polls `GetKeyRotationStatus` until it matches ([key.go updateKeyRotationEnabled](https://github.com/hashicorp/terraform-provider-aws/blob/main/internal/service/kms/key.go)).
- Rotation changes `CurrentKeyMaterialId` and keeps old material for decrypt only (`CurrentKeyMaterialId` docs in model). Out of scope for phase 1 except the status flag and period.

### 5.6 Key states, deletion and the state matrix

Key states: `Creating`, `Enabled`, `Disabled`, `PendingDeletion`, `PendingImport`, `PendingReplicaDeletion`, `Unavailable`, `Updating` (model `KeyState`). For single-Region symmetric keys only `Enabled`, `Disabled`, `PendingDeletion` matter ([key states](https://docs.aws.amazon.com/kms/latest/developerguide/key-state.html)).

Condensed from the [key-state table](https://docs.aws.amazon.com/kms/latest/developerguide/key-state.html) (OK = succeeds, NO = fails with the footnoted error), for the three relevant states:

| API | Enabled | Disabled | PendingDeletion |
|---|---|---|---|
| Encrypt, Decrypt, ReEncrypt, GenerateDataKey, GenerateDataKeyWithoutPlaintext | OK | NO `DisabledException: <key ARN> is disabled.` | NO `KMSInvalidStateException: <key ARN> is pending deletion (or pending replica deletion).` (table also lists the `DisabledException` form with the "pending deletion" text for crypto ops; two variants are documented, choose `KMSInvalidStateException` as the more common form, UNVERIFIED; footnotes [2] and [3]) |
| DescribeKey, GetKeyPolicy, PutKeyPolicy, ListResourceTags, DeleteAlias | OK | OK | OK |
| EnableKey | OK | OK | NO `KMSInvalidStateException` (pending deletion) |
| DisableKey | OK | OK | NO `KMSInvalidStateException` (pending deletion) |
| ScheduleKeyDeletion | OK | OK | NO `KMSInvalidStateException` (pending deletion) |
| CancelKeyDeletion | NO `KMSInvalidStateException: <key ARN> is not pending deletion (or pending replica deletion).` | NO (same) | OK |
| TagResource, UntagResource, CreateAlias | OK | OK | NO `KMSInvalidStateException` (pending deletion) |
| UpdateAlias | OK | OK | source: OK; destination: NO `KMSInvalidStateException: <key ARN> is pending deletion.` |
| GetKeyRotationStatus | OK | OK | OK (reports `false`) |
| EnableKeyRotation / DisableKeyRotation | OK | NO `DisabledException: <key ARN> is disabled.` | NO `KMSInvalidStateException: ... is pending deletion ...` |

Other emulators' messages for pending-deletion operations (`<ARN> is pending deletion.`, `KMSInvalidStateException`) match this table: [LocalStack kms/provider.py](https://github.com/localstack/localstack/blob/main/localstack-core/localstack/services/kms/provider.py), [Kroxylicious ErrorResponseTest](https://github.com/kroxylicious/kroxylicious/blob/main/kroxylicious-kms-providers/kroxylicious-kms-provider-aws-kms/src/test/java/io/kroxylicious/kms/provider/aws/kms/model/ErrorResponseTest.java) (UNVERIFIED as real captures).

`ScheduleKeyDeletion` ([docs in model](https://github.com/aws/api-models-aws/blob/1cfdfb4bb9ea858e65623e66d73af04bec353201/models/kms/service/2014-11-01/kms-2014-11-01.json)):

- `PendingWindowInDays` 7..30, default 30. Success sets `KeyState=PendingDeletion`; "the key can't be used in any cryptographic operations". After the window "KMS deletes the KMS key, its key material, and all KMS data associated with it, including all aliases that refer to it".
- Response: `{KeyId (the key ARN), DeletionDate, KeyState: "PendingDeletion", PendingWindowInDays}`. `DeletionDate` is the epoch-seconds time `now + window`; it is omitted for a multi-Region primary with replicas.
- A second `ScheduleKeyDeletion` on a pending key returns `KMSInvalidStateException` with text containing `is pending deletion`; TF treats that as already deleted ([key.go resourceKeyDelete](https://github.com/hashicorp/terraform-provider-aws/blob/main/internal/service/kms/key.go)). TF then waits (up to 20 minutes) until `DescribeKey` reports `PendingDeletion` or `NotFoundException` ([key.go waitKeyDeleted / findKeyByID](https://github.com/hashicorp/terraform-provider-aws/blob/main/internal/service/kms/key.go)). `DescribeKey` therefore must keep returning the key with `KeyState=PendingDeletion` and `Enabled=false` until the deadline, then `NotFoundException`.
- `CancelKeyDeletion` response `{KeyId (ARN)}`; the key comes back as `Disabled` (not `Enabled`); `EnableKey` is needed afterward ([CancelKeyDeletion docs in model](https://github.com/aws/api-models-aws/blob/1cfdfb4bb9ea858e65623e66d73af04bec353201/models/kms/service/2014-11-01/kms-2014-11-01.json)).
- Timing must run on the emulator clock (brief requirement 2): store `DeletionDate` as an instant, evaluate "deleted" lazily against the clock, and cascade-delete aliases at that point. Real deletion is asynchronous; "after the waiting period ends" has no exact-second guarantee (UNVERIFIED).

### 5.7 Cryptographic operations

Shapes (model): `Encrypt{KeyId, Plaintext 1..4096 bytes, EncryptionContext, GrantTokens, EncryptionAlgorithm, DryRun}` -> `{CiphertextBlob 1..6144, KeyId (ARN), EncryptionAlgorithm}`; `Decrypt{CiphertextBlob, EncryptionContext, GrantTokens, KeyId, EncryptionAlgorithm, Recipient, DryRun, DryRunModifiers}` -> `{KeyId (ARN), Plaintext, EncryptionAlgorithm, CiphertextForRecipient, KeyMaterialId}`; `GenerateDataKey{KeyId, EncryptionContext, NumberOfBytes 1..1024, KeySpec AES_128|AES_256, GrantTokens, Recipient, DryRun}` -> `{CiphertextBlob, Plaintext, KeyId (ARN), CiphertextForRecipient, KeyMaterialId}`; `GenerateDataKeyWithoutPlaintext` (same minus `Plaintext`/`Recipient`) -> `{CiphertextBlob, KeyId, KeyMaterialId}`; `ReEncrypt{CiphertextBlob, SourceEncryptionContext, SourceKeyId, DestinationKeyId (required), DestinationEncryptionContext, SourceEncryptionAlgorithm, DestinationEncryptionAlgorithm, GrantTokens, DryRun, DryRunModifiers}` -> `{CiphertextBlob, SourceKeyId, KeyId, SourceEncryptionAlgorithm, DestinationEncryptionAlgorithm, SourceKeyMaterialId, DestinationKeyMaterialId}`. The model leaves `Decrypt.CiphertextBlob` and `ReEncrypt.CiphertextBlob` optional only because of `DryRun` + `IGNORE_CIPHERTEXT`; outside that mode they are required ([model docs for CiphertextBlob](https://github.com/aws/api-models-aws/blob/1cfdfb4bb9ea858e65623e66d73af04bec353201/models/kms/service/2014-11-01/kms-2014-11-01.json)). `EncryptionContext` is `map<string,string>`.

Semantics ([Encrypt](https://docs.aws.amazon.com/kms/latest/APIReference/API_Encrypt.html) and siblings, via the model docs):

- Blobs are base64 on the wire (JSON). `Plaintext` limit 4096 bytes for symmetric keys. Ciphertext is opaque: "KMS stores [key id] in the ciphertext blob", and "KMS cannot decrypt symmetric ciphertext produced by other libraries, such as the Amazon Web Services Encryption SDK or Amazon S3 client-side encryption". Real format is undocumented; Go/Java/JS/Python clients never parse it. moto states its own format "is not what KMS actually does" (36-byte key id + 12-byte IV + 16-byte tag header, [kms/utils.py](https://github.com/getmoto/moto/blob/608bfa92a71ddd19b0efa0a9e5eaaffaa54c38af/moto/kms/utils.py)). A self-describing blob (key id, key material id, nonce, tag, ciphertext) with real AES-256-GCM satisfies every documented property.
- `Decrypt` of a symmetric ciphertext: `KeyId` is optional because the blob carries it; if `KeyId` is supplied and differs, the call "throws an `IncorrectKeyException`" ([DecryptRequest.KeyId docs in model](https://github.com/aws/api-models-aws/blob/1cfdfb4bb9ea858e65623e66d73af04bec353201/models/kms/service/2014-11-01/kms-2014-11-01.json)). `ReEncrypt.SourceKeyId` behaves the same.
- Encryption context: non-secret key-value pairs used as AAD. "If you specify an `EncryptionContext` when encrypting data, you must specify the same encryption context (a case-sensitive exact match) when decrypting the data. Otherwise, the request to decrypt fails with an `InvalidCiphertextException`" ([Encrypt docs in model](https://github.com/aws/api-models-aws/blob/1cfdfb4bb9ea858e65623e66d73af04bec353201/models/kms/service/2014-11-01/kms-2014-11-01.json)). Empty/omitted context equals empty map. Context applies to symmetric keys only. Do not log it as secret (docs: "may be displayed in plaintext in CloudTrail").
- `GenerateDataKey`: exactly one of `KeySpec` or `NumberOfBytes` ("but not both"; "You must specify either"). `AES_256` -> 32 bytes, `AES_128` -> 16. Plaintext key bytes are random and "not related to the caller or the KMS key". The `CiphertextBlob` decrypts via `Decrypt` with the same context ([GenerateDataKey docs in model](https://github.com/aws/api-models-aws/blob/1cfdfb4bb9ea858e65623e66d73af04bec353201/models/kms/service/2014-11-01/kms-2014-11-01.json)). Violation error class is `ValidationException` (UNVERIFIED text).
- `GenerateDataKeyWithoutPlaintext`: identical, no `Plaintext` in the response.
- `ReEncrypt`: decrypt under source key with `SourceEncryptionContext`, encrypt under `DestinationKeyId` with `DestinationEncryptionContext`, response `SourceKeyId` and `KeyId` are key ARNs.
- Key checks: `Encrypt` etc. require `KeyUsage=ENCRYPT_DECRYPT`; symmetric-only operations on other keys raise `InvalidKeyUsageException` (400; model). `Decrypt` of garbage -> `InvalidCiphertextException` (400). A wrong-region or deleted key id inside the blob -> `NotFoundException`/`KMSInvalidStateException` per key state; moto instead raises `AccessDeniedException` ("The ciphertext refers to a customer master key that does not exist, does not exist in this region, or you are not allowed to access.", [kms/utils.py](https://github.com/getmoto/moto/blob/608bfa92a71ddd19b0efa0a9e5eaaffaa54c38af/moto/kms/utils.py)), UNVERIFIED which AWS returns.
- Input validation texts seen in moto (modeled after the constraint messages): `1 validation error detected: Value at 'plaintext' failed to satisfy constraint: Member must have length greater than or equal to 1` / `... less than or equal to 4096` ([kms/utils.py](https://github.com/getmoto/moto/blob/608bfa92a71ddd19b0efa0a9e5eaaffaa54c38af/moto/kms/utils.py), UNVERIFIED). Corrected by gap G7, 2026-10-08: the `less than or equal to 4096` form is confirmed by an AWS-validated recording from 2024-04-11, `1 validation error detected: Value at 'plaintext' failed to satisfy constraint: Member must have length less than or equal to 4096` (https://github.com/localstack/localstack/blob/8b9a79f05846835cf4dff63ab7eefdde9df83783/tests/aws/services/kms/test_kms.snapshot.json#L1501); the `greater than or equal to 1` form is not recorded. The real wording is AWS's own validation grammar documented in [error-matrix.md](error-matrix.md) section 4, not the Smithy-framework test messages.
- `GenerateRandom` (`NumberOfBytes` 1..1024) is trivial to add; Terraform does not use it.

### 5.8 How S3 SSE-KMS and Secrets Manager call KMS

S3 ([S3 SSE-KMS](https://docs.aws.amazon.com/AmazonS3/latest/userguide/UsingKMSEncryption.html), [specifying SSE-KMS](https://docs.aws.amazon.com/AmazonS3/latest/userguide/specifying-kms-encryption.html)):

- Headers (model, `PutObjectOutput`/`PutObjectRequest`): `x-amz-server-side-encryption` (`aws:kms`; enum also `AES256`, `aws:kms:dsse`, `aws:fsx`, `aws:backup`), `x-amz-server-side-encryption-aws-kms-key-id`, `x-amz-server-side-encryption-context` (base64 of UTF-8 JSON), `x-amz-server-side-encryption-bucket-key-enabled` ([S3 model](https://github.com/aws/api-models-aws/blob/1cfdfb4bb9ea858e65623e66d73af04bec353201/models/s3/service/2006-03-01/s3-2006-03-01.json)). Note the user-guide text spells the last one `...-aws-bucket-key-enabled`; the model says `x-amz-server-side-encryption-bucket-key-enabled`; follow the model.
- Key id may be a key ID, key ARN or alias; "If the KMS key doesn't exist in the same account that's issuing the command, you must use the full Key ARN" (`SSEKMSKeyId` docs in the S3 model). If `aws:kms` is given without a key id, S3 uses the AWS managed key `aws/s3`; "Incorrect key specification results in an HTTP 400 Bad Request error". Responses (`PutObject`, `CopyObject`, `CreateMultipartUpload`, `UploadPart`, `CompleteMultipartUpload`, `GetObject`, `HeadObject`) carry `x-amz-server-side-encryption: aws:kms` and the key id used ("If present, indicates the ID of the KMS key that was used for object encryption", `PutObjectOutput.SSEKMSKeyId` docs in the S3 model). Whether S3 echoes the caller's string or the resolved key ARN is UNVERIFIED; the usual real behavior is the full key ARN. Do not send encryption headers on GET/HEAD for SSE-KMS objects ("you'll get an HTTP 400"). Since 2023-01-05 every new object is encrypted by default with SSE-S3 ([S3 SSE-KMS](https://docs.aws.amazon.com/AmazonS3/latest/userguide/UsingKMSEncryption.html)); `ServerSideEncryptionByDefault{SSEAlgorithm, KMSMasterKeyID}` is the bucket default (S3 model).
- KMS calls: `PutObject` needs `kms:GenerateDataKey`; `GetObject` needs `kms:Decrypt`; multipart needs both. Workflow: S3 calls `GenerateDataKey`, encrypts with the plaintext data key, stores the encrypted data key as object metadata; on read S3 calls `Decrypt` with the stored blob ([S3 SSE-KMS](https://docs.aws.amazon.com/AmazonS3/latest/userguide/UsingKMSEncryption.html)).
- Encryption context: `aws:s3:arn` = the object ARN (`arn:aws:s3:::<bucket>/<key>`), or the bucket ARN when a Bucket Key is enabled; any user context from `x-amz-server-side-encryption-context` is stored alongside and `aws:s3:arn` is appended (same page). With Bucket Keys S3 uses a time-limited bucket-level key to reduce KMS calls.
- Only symmetric encryption keys are allowed; the key must be in the bucket's Region. For an emulator, S3 should call the in-process KMS package, not HTTP.

Secrets Manager ([SM encryption](https://docs.aws.amazon.com/secretsmanager/latest/userguide/security-encryption.html)):

- Envelope scheme: on `CreateSecret` (with a value), `PutSecretValue` and `UpdateSecret` (value or key change) SM calls `GenerateDataKey` with `KeySpec=AES_256`, encrypts the secret value outside KMS with the plaintext key, and stores the encrypted data key with the version. `GetSecretValue`/`BatchGetSecretValue` call `Decrypt` on the stored data key. Idempotent `PutSecretValue`/`UpdateSecret` on an existing version calls `Decrypt` to compare. Changing the key calls `Encrypt` to re-wrap data keys for `AWSCURRENT`/`AWSPREVIOUS`/`AWSPENDING`; old versions stay decryptable by either key. SM does not use grants.
- Encryption context on both `GenerateDataKey` and `Decrypt`: `{"SecretARN": "<secret ARN>", "SecretVersionId": "<version id>"}`. Access validation on key set/change sends `GenerateDataKey` and `Decrypt` with `SecretVersionId = "RequestToValidateKeyAccess"` and discards the results.
- Default key is `aws/secretsmanager`, created on first use; `DescribeSecret`/`ListSecrets` do not return `KmsKeyId` for the AWS managed key.

Both services must tolerate a disabled or pending-deletion key by surfacing the KMS error (S3 documents `KMS.DisabledException`-style failures; exact S3 error code text is UNVERIFIED).

### 5.9 Eventual consistency in KMS

KMS "follows an eventual consistency model" (every operation's doc). Terraform sleeps/polls for key description, policy, rotation and enabled-state changes with `ContinuousTargetOccurence: 5` loops of 1-2 s ([key.go wait helpers](https://github.com/hashicorp/terraform-provider-aws/blob/main/internal/service/kms/key.go)), up to 10 minutes. An emulator that is immediately consistent just shortens these waits. Do not simulate delay unless a fault rule asks for it.

## Implications for understudy

Protocol and generation

1. IAM and STS share one awsQuery codec: form decode with `.member.N`, no flattened lists anywhere, `<Action>Response` / `<Action>Result` / `ResponseMetadata` envelope, `ErrorResponse > Error{Type,Code,Message} + RequestId`, root `xmlns` per service. Operations with `Unit` output return `ResponseMetadata` only. Bind to the Smithy awsQuery and awsJson1_1 protocol tests (links in 1.3).
2. KMS uses the awsJson1.1 codec with `X-Amz-Target: TrentService.<Op>`, epoch-second numeric timestamps, base64 blobs, errors as `{"__type":"<Shape>","message":"..."}`. Emit lowercase `message`.
3. Keep a small error-status override table: generated KMS statuses (404/409/503) disagree with the documented and observed 400/400/500 (1.4 #2). Clients ignore the status, but curl-level tests and some third-party tools do not.
4. Do not trust generated range checks for `ScheduleKeyDeletion.PendingWindowInDays` (7..30) or key-policy length (32768); add hand-written constraints beside the generated ones (1.4 #3, #4).
5. Accept any region in the SigV4 credential scope for IAM and STS; IAM data is account-scoped, not region-scoped (3.6). Never return `ConcurrentModification` spuriously (TF retries it but other clients may not).

Identity and accounts

6. Mint access key ids as `AKIA`/`ASIA` + 16 base32 characters with the account in the 48-bit window (2.2): set the top bit, `account<<7`, random remainder. Provide one `accountFromAccessKey` function that (a) accepts a 12-digit numeric key as the account (LocalStack convention), (b) decodes 20-character base32 keys, (c) falls back to `000000000000` for anything else, including documentation keys with non-base32 characters such as `AKIAI44QH8DHBEXAMPLE`. Decide whether to reject real-looking `AKIA`/`ASIA` keys (LocalStack does by default, to avoid mapping a developer's production key to an arbitrary account); a decoded real key would otherwise silently select a foreign account number. Recommendation: honor decoded accounts only for keys that understudy itself minted (a reserved prefix like LocalStack's `LSIA`/`LKIA`, or keys present in the IAM store), and use the numeric/default path otherwise. This is a design decision to record in an ADR.
7. `GetCallerIdentity` for any principal: IAM user -> `arn:aws:iam::<acct>:user/<path><name>` + `AIDA...`; assumed role -> `arn:aws:sts::<acct>:assumed-role/<role-name>/<session>` + `<AROA RoleId>:<session>` (no role path in the ARN); root or unknown static keys -> `arn:aws:iam::<acct>:root` + account id. Persist an access-key-to-principal table (static keys from `CreateAccessKey`, session keys from `AssumeRole`) so the access recorder and the IAM policy generator can attribute calls.
8. `AssumeRole`: return `Credentials{AccessKeyId ASIA..., SecretAccessKey 40 chars, SessionToken opaque, Expiration}`, `AssumedRoleUser{Arn, AssumedRoleId}`, echo `SourceIdentity` only if sent, default `DurationSeconds` 3600, validate 900..43200 and against the role's `MaxSessionDuration` (`ValidationError` text in 4.2). Since phase 1 does not enforce IAM, decide explicitly whether a nonexistent role is an error: real AWS returns `AccessDenied`; moto lets it succeed. Recommended: succeed only if the role exists in the emulator store, else `AccessDenied` with the real message shape, because Terraform and CDK flows assume that failure mode; add a config switch to relax it. G4 correction: the issued `Expiration` must be wall-clock (`wall_now + DurationSeconds`), not the emulator clock, because SDKs compare it to their own wall clock (Go: "credential expiry time is always based on reported wall-clock time", [credentials.go L152-L159](https://github.com/aws/aws-sdk-go-v2/blob/v1.47.1/aws/credentials.go#L152-L159); botocore `_seconds_remaining`, [credentials.py L524-L526](https://github.com/boto/botocore/blob/1.42.97/botocore/credentials.py#L524-L526)); an emulator-clock value frozen in the past makes cached credentials look expired on every call ([lambda-runtime-contract.md](lambda-runtime-contract.md) row 14).
9. Make the same STS code path mint Lambda execution-role credentials so `GetCallerIdentity` inside a function returns the assumed-role identity (session name = function name is UNVERIFIED).
10. Implement `GetAccessKeyInfo`, `GetSessionToken` (cheap, SDK credential chains use them) and keep `AssumeRoleWithWebIdentity` as a stub that fails loudly.

IAM store and behavior

11. Always percent-encode `AssumeRolePolicyDocument` and `PolicyDocument` in every response (3.3), using RFC 3986 unreserved characters only. A plain-JSON response corrupts `+` in Terraform and diverges from real AWS. Store the original string verbatim.
12. IDs: roles `AROA`+17, policies `ANPA`+17, versions `ANVA`, users `AIDA`, instance profiles `AIPA`, all 21 characters of `[A-Z2-7]` (observed lengths in 2.1). Consider embedding the account the same way as access keys (moto does; real behavior UNVERIFIED).
13. Round-trip the fields Terraform diffs on: role `MaxSessionDuration` default 3600, `Path` default `/`, `Description`, `Tags` (also on create), `PermissionsBoundary`; policy `DefaultVersionId`, `AttachmentCount` (live count), `Path`, `Description`, `Tags`, `CreateDate`, `UpdateDate`; instance profile `Roles`. `ListRoles` omits `Tags`/`PermissionsBoundary`/`RoleLastUsed`; `GetRole` includes them.
14. Policy versions: `v1` on create, cap 5, `CreatePolicyVersion(SetAsDefault)`, `SetDefaultPolicyVersion`, `DeletePolicyVersion` refuses the default (`DeleteConflict`), `ListPolicyVersions` omits `Document`, `GetPolicyVersion` returns it encoded, `DeletePolicy` requires zero attachments and deletes the default version with it.
15. Delete ordering: `DeleteRole` fails with `DeleteConflict` while managed policies, inline policies or instance-profile membership remain; `DeleteInstanceProfile` fails while a role remains; `DeleteUser` fails while access keys or policies remain (messages for the user case, `Cannot delete entity, must delete access keys first.` and `Cannot delete entity, must delete policies first.`, come only from third-party emulators such as [versitygw](https://github.com/versity/versitygw/blob/main/iamapi/controller_test.go): UNVERIFIED). Use the message texts in 3.4. These are the failures that make `terraform destroy` order-dependent, so they must be exact.
16. Attaching `arn:aws:iam::aws:policy/...` ARNs must succeed without a catalog, or with a small embedded list of the common names (Lambda, SQS, SNS, S3, DynamoDB, CloudWatch Logs, KMS, SecretsManager execution policies). Decide how `GetPolicy` on those behaves (synthesized record, `IsAttachable=true`, `PolicyId=ANPA...`). `AttachRolePolicy` for an unknown non-AWS ARN returns `NoSuchEntity`.
17. Validate policy documents at the boundary at a modest level (JSON object, `Version` in {`2008-10-17`,`2012-10-17`}, `Statement` present, `Effect` in {Allow,Deny}, action/resource presence) with `MalformedPolicyDocument`; skip principal existence checks. Cap document sizes (3.2). Keep the grammar checker as a separate pure package; it is a good `rapid` target.
18. Pagination: honor `MaxItems`/`Marker`/`IsTruncated`; make `Marker` opaque; default page 100. Terraform paginators and `ListRoles(MaxItems=1)` in provider startup depend on it.
19. The Terraform provider bootstrap calls `GetCallerIdentity` once with default flags; only with `skip_credentials_validation = true` does it call `GetUser` (no name), then `GetCallerIdentity`, then `ListRoles(MaxItems=1)` (CORRECTED (G6), see the paragraph after the table in section 3.1). `GetUser` with no name should return the caller's user when the key belongs to an IAM user, and `ValidationError`/`AccessDenied`-class errors otherwise (both are skipped by `aws-sdk-go-base`); any other error is collected and the provider moves on to `GetCallerIdentity`. Prefer returning a valid user for the default test key.

KMS

20. Implement real crypto with the standard library: AES-256-GCM per key (and per-material for rotation), with the encryption context as AAD (canonical, sorted, length-prefixed serialization, unlike moto's concatenation). The ciphertext blob is an internal versioned envelope carrying key id, key material id, nonce and tag; return 6144-byte-bounded blobs. This satisfies: `Decrypt` without `KeyId`, `IncorrectKeyException` on mismatch, `InvalidCiphertextException` on wrong context or corruption, `ReEncrypt` across keys, data keys of 16/32/n bytes.
21. `DescribeKey`, `GetKeyRotationStatus` and friends must follow the key-state matrix in 5.6 (use a discriminated `KeyState` type; each operation declares the states it accepts and the exact error/message for the rest). Messages embed the full key ARN.
22. Scheduled deletion: state `PendingDeletion`, `DeletionDate = clock.Now() + window`, key stays describable until the deadline, then `NotFoundException` and aliases cascade away. `CancelKeyDeletion` returns the key as `Disabled`. Do this lazily at read time against the controllable clock (no background timers) so frozen/advanced clocks behave.
23. Default key policy is the single `Enable IAM User Permissions` statement with the account root principal, wrapped in `{"Version":"2012-10-17","Id":"key-default-1","Statement":[...]}`. Only policy name `default`. Store whatever policy the caller supplies. Policy enforcement is out of scope for phase 1, so skip the lockout check unless cheap.
24. AWS managed keys: create `alias/aws/<service>` keys on first `DescribeKey` of that alias and on first use by S3 (`aws:kms` with no key id) or Secrets Manager (no `KmsKeyId`). `KeyManager=AWS`; not taggable; rotation status `true`. Decide whether `ListAliases` pre-lists predefined aliases (docs say it can list some without `TargetKeyId`). Keep the list of services in a table.
25. Alias rules: `alias/` prefix, 1..256, model pattern, reject `alias/aws/` for customer aliases, unique per account+region, 50 per key, `UpdateAlias`/`DeleteAlias` semantics from 5.4, `ListAliases` paginated and filterable by `KeyId`. Terraform reads aliases only through `ListAliases`.
26. Expose the KMS package to S3 and Secrets Manager through an in-process interface (`GenerateDataKey`, `Decrypt`, `Encrypt`, key-state checks, AWS-managed-key bootstrap) rather than self-HTTP calls, but record the calls in the journal as KMS API calls so fault injection and the access recorder see them. Use the encryption contexts in 5.8 (`aws:s3:arn`; `SecretARN` + `SecretVersionId`) so conformance tests can assert them.
27. Timestamps: emit numbers for KMS, ISO strings for IAM/STS. Epoch value for KMS includes fractional seconds.
