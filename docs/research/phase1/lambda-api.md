## 1. Findings that change the plan

1. **The RIE does not behave like Lambda's Invoke.** For a function error it returns HTTP 200 with the error JSON as body and no `X-Amz-Function-Error` header; for a timeout it returns HTTP 200 with the plain text `Task timed out after N.00 seconds`; for an init failure or runtime crash it returns HTTP 502 with a JSON body. See section 8.3 for the probe transcripts and [handlers.go](https://github.com/aws/aws-lambda-runtime-interface-emulator/blob/3ccddd7d980cb7d0f12e8a44adce139b0176a2a5/internal/lambda/rie/handlers.go) and [server.go](https://github.com/aws/aws-lambda-runtime-interface-emulator/blob/3ccddd7d980cb7d0f12e8a44adce139b0176a2a5/internal/lambda/rapidcore/server.go). Real Lambda returns `X-Amz-Function-Error: Unhandled` and a JSON body for all of these ([REC](https://github.com/localstack/localstack/blob/8b9a79f05846835cf4dff63ab7eefdde9df83783/tests/aws/services/lambda_/test_lambda.snapshot.json)).
2. **A second concurrent request to one RIE crashes it** (nil-pointer panic in `Server.Invoke`, process exits, container stops). PROBE, section 8.3. understudy must serialize to one in-flight invocation per RIE process.
3. **The official entrypoint skips the RIE when `AWS_LAMBDA_RUNTIME_API` is set** and execs the runtime directly ([`/lambda-entrypoint.sh` extracted from the image](https://gallery.ecr.aws/lambda/provided), PROBE; same logic in the [RIE README](https://github.com/aws/aws-lambda-runtime-interface-emulator/blob/3ccddd7d980cb7d0f12e8a44adce139b0176a2a5/README.md)). understudy can therefore host the Runtime API itself in official images and get exact Lambda semantics. Decision in section 12.
4. **Async invoke payload limit is 1 MB, not 256 KB.** [Quotas page](https://docs.aws.amazon.com/lambda/latest/dg/gettingstarted-limits.html) and [Invoke API reference](https://docs.aws.amazon.com/lambda/latest/api/API_Invoke.html) both say 1 MB. The brief's 256 KB figure is outdated. 256 KB survives only as the SNS destination limit ([invocation-async-retain-records](https://docs.aws.amazon.com/lambda/latest/dg/invocation-async-retain-records.html)).
5. **The Smithy model is wider than the documented limits.** `Timeout` is modeled 1..5400 and `MemorySize` 128..32768 ([SMITHY](https://github.com/aws/api-models-aws/blob/f3c23808b1414b9e9e23373dc40d3fc2bbca3608/models/lambda/service/2015-03-31/lambda-2015-03-31.json), `CreateFunctionRequest`) because of Lambda Managed Instances. The docs say 900 s and 10,240 MB for ordinary functions ([quotas](https://docs.aws.amazon.com/lambda/latest/dg/gettingstarted-limits.html)). Enforce the documented limits; the exact validation message above 900 is UNVERIFIED.
6. **Terraform's read path needs more than GetFunction.** It also calls `ListVersionsByFunction` (to compute `version` and `qualified_arn`) and `GetFunctionCodeSigningConfig` ([TF](https://github.com/hashicorp/terraform-provider-aws/blob/972faab3f6e4e37aff0453fe05366f3bd3fc2b97/internal/service/lambda/function.go), `resourceFunctionFlatten`). Both must exist for a clean second `plan`.
7. **Function URLs need two permission statements for new URLs since October 2025** (`lambda:InvokeFunctionUrl` and `lambda:InvokeFunction` with `lambda:InvokedViaFunctionUrl`). Older recorded behavior needed only the first ([urls-auth](https://docs.aws.amazon.com/lambda/latest/dg/urls-auth.html)).
8. **RIE hard-codes the invoked ARN** to `arn:aws:lambda:us-east-1:012345678912:function:<name>` regardless of region or account, and defaults memory to 3008 MB, log group to `/aws/lambda/Functions`, log stream to `$LATEST` ([handlers.go](https://github.com/aws/aws-lambda-runtime-interface-emulator/blob/3ccddd7d980cb7d0f12e8a44adce139b0176a2a5/internal/lambda/rie/handlers.go), PROBE).
9. **The Runtime API gained `Lambda-Runtime-Invocation-Id`** (optional to echo back; mismatch gives `400 InvalidInvocationId`) ([runtimes-api](https://docs.aws.amazon.com/lambda/latest/dg/runtimes-api.html)). Not emitted by RIE v1.37 (PROBE).
10. **Terraform waits start with a fixed 5 s delay** (`Delay: 5 * time.Second`) in `waitFunctionCreated` and `waitFunctionUpdated` ([TF](https://github.com/hashicorp/terraform-provider-aws/blob/972faab3f6e4e37aff0453fe05366f3bd3fc2b97/internal/service/lambda/function.go)). Every `aws_lambda_function` create or update costs at least 5 s wall time against any backend, including understudy. Not fixable server-side.

### 2.1 Error body shape

Modeled error structures differ in member casing, and the casing is on the wire: `InvalidParameterValueException`, `ResourceConflictException`, `PreconditionFailedException`, `TooManyRequestsException`, `RequestTooLargeException`, `PolicyLengthExceededException`, `AliasLimitExceededException`, `CodeStorageExceededException`, `InvalidRequestContentException` use **`message`** (lowercase) plus `Type`. `ResourceNotFoundException`, `ServiceException`, `NoPublishedVersionException`, `RecursiveInvocationException`, `PublicPolicyException`, `ServiceQuotaExceededException` and the 502 family use **`Message`**, except `ResourceNotReadyException` (502), which uses lowercase `message` (corrected by gap G7, 2026-10-08, checked at api-models-aws 1cfdfb4: https://github.com/aws/api-models-aws/blob/1cfdfb4bb9ea858e65623e66d73af04bec353201/models/lambda/service/2015-03-31/lambda-2015-03-31.json; this file's own model pin f3c2380 differs from the project pin 1cfdfb4, see [error-matrix.md](error-matrix.md) section 2). `TooManyRequestsException` additionally has `Reason` and `retryAfterSeconds` (bound to header `Retry-After`) ([SMITHY](https://github.com/aws/api-models-aws/blob/f3c23808b1414b9e9e23373dc40d3fc2bbca3608/models/lambda/service/2015-03-31/lambda-2015-03-31.json)). Recorded real responses carry `"Type": "User"` for 4xx ([REC](https://github.com/localstack/localstack/blob/8b9a79f05846835cf4dff63ab7eefdde9df83783/tests/aws/services/lambda_/test_lambda_api.snapshot.json)); `Type` for 5xx is UNVERIFIED (`"Service"` is the usual Coral value).

## 3. Names, ARNs and qualifiers

- Function name grammar (CreateFunction, 1..140 chars; the 64-char cap applies to the bare name): `^(arn:(aws[a-zA-Z-]*)?:lambda:)?((eusc-)?[a-z]{2}((-gov)|(-iso([a-z]?)))?-[a-z]+-\d{1}:)?(\d{12}:)?(function:)?([a-zA-Z0-9-_]+)(:(\$LATEST|[a-zA-Z0-9-_]+))?$` ([SMITHY](https://github.com/aws/api-models-aws/blob/f3c23808b1414b9e9e23373dc40d3fc2bbca3608/models/lambda/service/2015-03-31/lambda-2015-03-31.json)); bare name limited to 64 chars ([API_Invoke](https://docs.aws.amazon.com/lambda/latest/api/API_Invoke.html)). Read-side operations (GetFunction, Invoke, AddPermission, GetPolicy, Delete) use the wider `NamespacedFunctionName` (1..256, name allows `.`, qualifier allows `$LATEST.PUBLISHED`). Same model.
- Accepted forms: `my-function`, `my-function:v1`, full ARN, `123456789012:function:my-function` ([API_Invoke](https://docs.aws.amazon.com/lambda/latest/api/API_Invoke.html)).
- Qualifier (query parameter): `^\$(LATEST(\.PUBLISHED)?)|[a-zA-Z0-9-_$]+$`, 1..128 ([SMITHY](https://github.com/aws/api-models-aws/blob/f3c23808b1414b9e9e23373dc40d3fc2bbca3608/models/lambda/service/2015-03-31/lambda-2015-03-31.json)). Function URL qualifier must be an alias name, not a version number and not `$LATEST` (`((?!^\d+$)^[0-9a-zA-Z-_]+$)`), same model; REC shows `ValidationException` for `$LATEST`, `1`, `2` on `CreateFunctionUrlConfig`.
- Alias name: `(?!^[0-9]+$)([a-zA-Z0-9-_]+)`, 1..128. Version string `^(\$LATEST|[0-9]+)$`. Same model.
- Function ARN in responses: `arn:aws:lambda:<region>:<account>:function:<name>` for `$LATEST` via Create/GetFunctionConfiguration without qualifier; `...:function:<name>:<version>` for versions; `...:<name>:$LATEST` when `$LATEST` was addressed explicitly, and in `ListFunctions?FunctionVersion=ALL` and `ListVersionsByFunction` for the `$LATEST` row ([REC](https://github.com/localstack/localstack/blob/8b9a79f05846835cf4dff63ab7eefdde9df83783/tests/aws/services/lambda_/test_lambda_api.snapshot.json), `test_publish_version_on_create`, `test_list_functions`).
- Mismatches recorded from AWS: name derives a qualifier that differs from the `Qualifier` param: `InvalidParameterValueException` `The derived qualifier from the function name does not match the specified qualifier.` Region mismatch in ARN: `ResourceNotFoundException` `Functions from 'ap-southeast-1' are not reachable in this region ('us-east-1')`. Same page.

### 4.2 Runtime enum and deprecation

The model's `Runtime` enum has 53 values, including long-dead ones: `nodejs`, `nodejs4.3`, ..., `go1.x`, `provided`, `provided.al2`, `provided.al2023`, `python3.6`..`python3.15`, `nodejs12.x`..`nodejs26.x`, `java8`..`java25`, `java8.al2023`, `java11.al2023`, `java17.al2023`, `dotnetcore*`, `dotnet6/8/10`, `ruby2.5`..`ruby4.0` ([SMITHY](https://github.com/aws/api-models-aws/blob/f3c23808b1414b9e9e23373dc40d3fc2bbca3608/models/lambda/service/2015-03-31/lambda-2015-03-31.json)). The real service accepts only a subset for create:

- Supported, with base images (AL2023 unless noted): `nodejs22.x`, `nodejs24.x`, `nodejs26.x` (preview), `python3.12`, `python3.13`, `python3.14`, `python3.15` (preview), `python3.10`/`python3.11` (AL2), `java21`, `java25`, `java8.al2023`/`java11.al2023`/`java17.al2023`, `java8.al2`/`java11`/`java17` (AL2), `dotnet8`, `dotnet10`, `ruby3.3`, `ruby3.4`, `ruby4.0`, `provided.al2023` ([lambda-runtimes](https://docs.aws.amazon.com/lambda/latest/dg/lambda-runtimes.html)).
- Deprecated: create already blocked or soon blocked. For a deprecated runtime, AWS returns `InvalidParameterValueException` (400): `The runtime parameter of go1.x is no longer supported for creating or updating AWS Lambda functions. ## 5. State machine

### 5.1 State and LastUpdateStatus

Model enums ([SMITHY](https://github.com/aws/api-models-aws/blob/f3c23808b1414b9e9e23373dc40d3fc2bbca3608/models/lambda/service/2015-03-31/lambda-2015-03-31.json)):

- `State`: `Pending`, `Active`, `Inactive`, `Failed`, `Deactivating`, `Deactivated`, `ActiveNonInvocable`, `Deleting`.
- `LastUpdateStatus`: `Successful`, `Failed`, `InProgress`.
- `StateReasonCode` (40 values) includes `Idle`, `Creating`, `Restoring`, `InvalidConfiguration`, `InternalError`, `ImageDeleted`, `ImageAccessDenied`, `InvalidImage`, `InvalidRuntime`, `InvalidZipFileException`, `FunctionError`, `FunctionError.InitTimeout`, `FunctionError.RuntimeInitError`, `FunctionError.InvalidEntryPoint`, `FunctionError.InvalidWorkingDirectory`, `FunctionError.PermissionDenied`, `FunctionError.InitResourceExhausted`, `KMSKeyAccessDenied`, `KMSKeyNotFound`, `DisabledKMSKey`, VPC/EFS codes. `LastUpdateStatusReasonCode` is the same set minus `Idle`, `Creating`, `Restoring`, `DrainingDurableExecutions`.

Semantics ([functions-states](https://docs.aws.amazon.com/lambda/latest/dg/functions-states.html)):

- `Pending`: after create, until resources are provisioned. "Lambda does not invoke a function during pending state. Any invocations or other API actions that operate on the function fail." Invoke, UpdateFunctionCode, UpdateFunctionConfiguration and PublishVersion all fail while creation is pending.
- `Active`: the only state in which invoke succeeds.
- `Failed`: "you must delete and recreate the function".
- `Inactive`: idle long enough that resources were reclaimed; an invoke "fails and Lambda sets the function to pending state until the function resources are recreated"; also used when the source image or S3 object is lost.
- During an update: `State` stays `Active`, `LastUpdateStatus` is `InProgress`; "Invocations continue to use the function's previous code and configuration until the update completes"; UpdateFunctionCode, UpdateFunctionConfiguration, PublishVersion and TagResource fail; on failure `State` stays `Active`, `LastUpdateStatus` is `Failed`, and invocations keep using the previous code and configuration.

Recorded real values:

- Create: `State Pending`, `StateReason "The function is being created."`, `StateReasonCode Creating`. After activation, `GetFunction` shows `State Active`, `LastUpdateStatus Successful` and no `StateReason` ([REC](https://github.com/localstack/localstack/blob/8b9a79f05846835cf4dff63ab7eefdde9df83783/tests/aws/services/lambda_/test_lambda.snapshot.json), `test_function_state`).
- UpdateFunctionCode / UpdateFunctionConfiguration response: `LastUpdateStatus InProgress`, `LastUpdateStatusReason "The function is being created."`, `LastUpdateStatusReasonCode Creating` (yes, the same wording as creation); after completion `LastUpdateStatus Successful` with no reason ([REC](https://github.com/localstack/localstack/blob/8b9a79f05846835cf4dff63ab7eefdde9df83783/tests/aws/services/lambda_/test_lambda_api.snapshot.json), `test_function_lifecycle`).
- `ListVersionsByFunction` and `ListFunctions` items omit `State`, `StateReason*`, `LastUpdateStatus*` and `RuntimeVersionConfig` (REC `test_publish_version_on_create`, `list_versions_result`).
- Terraform's code tolerates an empty `LastUpdateStatus` by treating it as `InProgress`, and accepts `Active` or `ActiveNonInvocable` as creation targets ([TF](https://github.com/hashicorp/terraform-provider-aws/blob/972faab3f6e4e37aff0453fe05366f3bd3fc2b97/internal/service/lambda/function.go), `statusFunctionConfigurationLastUpdateStatus`, `waitFunctionCreated`).

### 5.3 Waiters (what SDKs poll)

From the Smithy `smithy.waiters#waitable` traits ([SMITHY](https://github.com/aws/api-models-aws/blob/f3c23808b1414b9e9e23373dc40d3fc2bbca3608/models/lambda/service/2015-03-31/lambda-2015-03-31.json)):

|---|---|---|---|---|---|
| FunctionExists | GetFunction | any 2xx | none | `ResourceNotFoundException` | 1 / 20 s |

### 7.1 Versions

### 8.5 LogType Tail

`X-Amz-Log-Result` = base64 of the *last 4 KB* of the invocation's log, including the `START`, function output, `END` and `REPORT` lines. Recorded decoded content for a Python function: `START RequestId: <id> Version: $LATEST\n{}\nEND RequestId: <id>\nREPORT RequestId: <id>\tDuration: <x> ms\tBilled Duration: <y> ms\tMemory Size: 128 MB\tMax Memory Used: <z> MB\tInit Duration: <i> ms\t\n` ([REC](https://github.com/localstack/localstack/blob/8b9a79f05846835cf4dff63ab7eefdde9df83783/tests/aws/services/lambda_/test_lambda.snapshot.json), `test_invocation_with_logs`; "last 4 KB, base64-encoded" per [API_Invoke](https://docs.aws.amazon.com/lambda/latest/api/API_Invoke.html)). Applies to sync invokes only. Whether truncation lands on a line boundary: UNVERIFIED.

### 8.6 Async semantics

- `Event` invoke validates, enqueues, returns 202 with an empty body; if the event can't be queued the error is returned ([invocation-async](https://docs.aws.amazon.com/lambda/latest/dg/invocation-async.html)).
- Function errors (including timeouts) retry up to 2 more times: "one-minute wait between the first two attempts, and two minutes between the second and third attempts". Throttling (429) and system errors (5xx): the event goes back to the queue and is retried "for up to 6 hours by default", with exponential retry interval "from 1 second after the first attempt to a maximum of 5 minutes". Events can be delivered more than once even without errors. Expired or exhausted events are discarded, or sent to DLQ/destination ([invocation-async-error-handling](https://docs.aws.amazon.com/lambda/latest/dg/invocation-async-error-handling.html)).
- `MaximumRetryAttempts` and `MaximumEventAgeInSeconds` are configurable per function/version/alias (section 7.7). Unqualified invokes use the `$LATEST` config (UNVERIFIED; implied by the `$LATEST`-qualified ARN in the config response).
- Retries and request ids: "A single request ID might result in multiple invocation attempts, each with its own unique invocation ID" ([runtimes-api](https://docs.aws.amazon.com/lambda/latest/dg/runtimes-api.html)). So the same `Lambda-Runtime-Aws-Request-Id` is reused across retries of one async event and each attempt gets a new `Lambda-Runtime-Invocation-Id`. REC `test_request_id_async_invoke_with_retry` shows two `END` lines for one async invoke (ids normalized in the snapshot, so reuse of the id is inferred from the docs, not observed).
- Delays on the emulator clock: 60 s and 120 s between function-error attempts. Under the controllable clock these are skippable.

### 9.6 Init, invoke, timeout and shutdown semantics

([lambda-runtime-environment](https://docs.aws.amazon.com/lambda/latest/dg/lambda-runtime-environment.html))

- Init phase: extensions, runtime bootstrap, function static code. Limited to **10 s**; if it doesn't finish, "Lambda retries the `Init` phase at the time of the first function invocation with the configured function timeout" (so init can use the full function timeout on the retry). Failed or timed-out init emits `INIT_REPORT Init Duration: 1236.04 ms Phase: init Status: timeout` (or `Status: error Error Type: <type>`).
- Invoke phase: the function timeout bounds the whole invoke. After a crash or timeout, "Lambda resets the execution environment" (shutdown, then re-init on the next invoke) and the next invoke does a **suppressed init**: no separate INIT is logged, its duration is folded into the next `REPORT` duration. `/tmp` is not cleared by the reset.
- Shutdown: 0 ms with no extensions, 500 ms internal extension, 2000 ms external; processes still alive get SIGKILL. Environments are retained "for some time" then terminated "every few hours".
- Between invocations the environment is frozen; background work resumes on thaw. In a Docker emulation the equivalent is `docker pause`/`unpause` (UNVERIFIED as desirable) or simply leaving it running; the RIE does neither.
- Warm reuse: objects outside the handler persist. REC `test_lambda_invoke_timed_out_environment_reuse` records that after a timeout the next invoke runs in a new environment but `/tmp` content survives.
- Exact RIE behavior (PROBE): after a timeout it logs `Reset initiated: Timeout`, SIGKILLs the runtime, and the next invoke logs `INIT START(type: on-demand, phase: invoke)`: a suppressed init, new runtime process, same container. After a crash the same. After a failed init (bootstrap exits 1) the response is 502 and the following requests re-run init each time.

| timeout (`AWS_LAMBDA_FUNCTION_TIMEOUT=3`) | **`200`**, `Content-Type: text/plain`, body `Task timed out after 3.00 seconds`; wall time 3.11 s; log `Reset initiated: Timeout`, runtime SIGKILLed; `REPORT ... Duration: 3000.00 ms Billed Duration: 3000 ms` |
| runtime exits non-zero mid-invoke | `502`, `{"errorType":"Runtime.ExitError","errorMessage":"RequestId: <id> Error: Runtime exited with error: exit status 3"}` |
| bootstrap exits during init after POSTing `/init/error` | `502`, body = the posted init-error JSON |
| no bootstrap present | `502`, `{"errorMessage":"no bootstrap found at /var/task/bootstrap or /opt/bootstrap","errorType":"Runtime.InvalidEntrypoint"}` (that message comes from the image's own `/var/runtime/bootstrap`, not RIE) |
| second request while one is in flight | **RIE panics** (`nil pointer dereference` at `rapidcore/server.go:666` after `ReserveFailed: AlreadyReserved`), process exits, both HTTP connections get `Empty reply from server`. [server.go](https://github.com/aws/aws-lambda-runtime-interface-emulator/blob/3ccddd7d980cb7d0f12e8a44adce139b0176a2a5/internal/lambda/rapidcore/server.go) lines 627-740 show `reserveResp.Token` dereferenced after a failed `Reserve` |

Consequences for classification when using RIE as the invoke endpoint: success versus function-error is **not** distinguishable by status or headers; only by `502` (crash, init failure) or by sniffing the body for the `errorType` key. Sniffing is unsound: a function can legitimately return `{"errorType": ...}` (section 12 item 1).

Memory and CPU are not emulated: "Max Memory Used" repeats the configured memory (RIE-SRC). Docker `--memory`/`--cpus` can enforce the limit; AWS gives about one vCPU at 1,769 MB ([quotas](https://docs.aws.amazon.com/lambda/latest/dg/gettingstarted-limits.html)).

## 10. Function URL request and response (payload format 2.0)

Source: [urls-invocation](https://docs.aws.amazon.com/lambda/latest/dg/urls-invocation.html), [API Gateway payload format](https://docs.aws.amazon.com/apigateway/latest/developerguide/http-api-develop-integrations-lambda.html). A function URL uses the API Gateway HTTP API 2.0 schema with these Function-URL-specific values.

Event passed to the function:

```json
{"version":"2.0","routeKey":"$default","rawPath":"/my/path",
 "rawQueryString":"parameter1=value1&parameter1=value2&parameter2=value",
 "cookies":["cookie1","cookie2"],
 "headers":{"header1":"value1","header2":"value1,value2"},
 "queryStringParameters":{"parameter1":"value1,value2","parameter2":"value"},
 "requestContext":{"accountId":"123456789012","apiId":"<url-id>","authentication":null,
   "authorizer":{"iam":{"accessKey":"AKIA...","accountId":"111122223333","callerId":"AIDA...",
                        "cognitoIdentity":null,"principalOrgId":null,
                        "userArn":"arn:aws:iam::111122223333:user/example-user","userId":"AIDA..."}},
   "domainName":"<url-id>.lambda-url.us-west-2.on.aws","domainPrefix":"<url-id>",
   "http":{"method":"POST","path":"/my/path","protocol":"HTTP/1.1","sourceIp":"123.123.123.123","userAgent":"agent"},
   "requestId":"id","routeKey":"$default","stage":"$default",
   "time":"12/Mar/2020:19:03:58 +0000","timeEpoch":1583348638390},
 "body":"Hello from client!","pathParameters":null,"isBase64Encoded":false,"stageVariables":null}
```

- Header names are lowercased; duplicate headers and duplicate query values are joined with commas; all `Cookie` headers go into `cookies`, one element per cookie; `queryStringParameters` is omitted/absent when there is no query (shape not documented; UNVERIFIED) ([API Gateway payload format](https://docs.aws.amazon.com/apigateway/latest/developerguide/http-api-develop-integrations-lambda.html)).
- `routeKey`, `stage` are `$default`; `authentication` is `null`; `authorizer` is `null` unless `AWS_IAM`; `pathParameters` and `stageVariables` are `null` or absent; `rawQueryString` supports characters `a-z A-Z 0-9 . _ - % & = +`; `requestContext.apiId` is the URL id; `requestContext.requestId` is the invocation request id; `time` format `07/Sep/2021:22:50:22 +0000`; `timeEpoch` is epoch ms ([urls-invocation](https://docs.aws.amazon.com/lambda/latest/dg/urls-invocation.html)).
- `body` is base64 with `isBase64Encoded: true` "if the content type of the request is binary". The documented text does not define "binary"; the rule for which content types are base64'd is UNVERIFIED. LocalStack's recorded form-data upload shows a `multipart/form-data` body arriving base64-encoded, and JSON arriving as plain text ([REC](https://github.com/localstack/localstack/blob/8b9a79f05846835cf4dff63ab7eefdde9df83783/tests/aws/services/lambda_/test_lambda.snapshot.json), `test_lambda_url_form_payload`, `test_lambda_url_echo_http_fixture_default`). Real recorded request headers also include `x-amzn-tls-cipher-suite`, `x-amzn-tls-version`, `x-amzn-trace-id`, `x-forwarded-for`, `x-forwarded-port`, `x-forwarded-proto`, and `host: <url-id>.lambda-url...` (same snapshot).
- Response mapping: the function returns `{"statusCode", "headers", "body", "cookies", "isBase64Encoded"}`. If the function returns valid JSON without `statusCode`, Lambda infers `statusCode 200`, `content-type: application/json`, `body` = the JSON-serialized return value, `isBase64Encoded false`. Valid `statusCode` is 100..599. Cookies must be returned in `cookies`, becoming one `set-cookie` header each; do not set `set-cookie` in `headers`. Docs vs recorded behavior disagree on string returns: the docs example maps the function output `"Hello, world!"` to a 15-byte body (quotes kept, `content-length: 15`), while the recorded real response for a Python function returning the JSON string `"hello"` has `Content-Length: 5` (body `hello`, no quotes), `Content-Type: application/json`, status 200. Other recorded returns: dict `{"hello": "world"}` → `Content-Length: 17` (re-serialized compactly, `{"hello":"world"}`); list `["hello", 3, True]` → 16 bytes `["hello",3,true]`; integer `3` → body `3`; a structured `{statusCode, body}` return → the `body` string verbatim, still `Content-Type: application/json` when no `headers` set ([urls-invocation](https://docs.aws.amazon.com/lambda/latest/dg/urls-invocation.html), [REC snapshot](https://github.com/localstack/localstack/blob/8b9a79f05846835cf4dff63ab7eefdde9df83783/tests/aws/services/lambda_/test_lambda.snapshot.json) `test_lambda_url_invocation[*]` with [test inputs](https://github.com/localstack/localstack/blob/8b9a79f05846835cf4dff63ab7eefdde9df83783/tests/aws/services/lambda_/test_lambda.py)). Prefer the recorded behavior: parse the function output as JSON; a JSON string becomes the raw string body, any other non-structured JSON is re-serialized compactly. Floats/booleans were recorded but not inspected here.
- The response includes the `x-amzn-RequestId` header (REC `test_request_id_invoke_url`).
- Function error on a URL: the platform returns 502 `{"message": "Internal Server Error"}` (UNVERIFIED; not in any fetched primary source). Throttle: 429. Timeout: 502 (UNVERIFIED).
- CORS: when `Cors` is configured the platform answers preflight and adds the CORS response headers; function-set CORS headers are ignored/duplicated? UNVERIFIED. Fields as in section 7.6.
- Size limits: payload 6 MB for BUFFERED (`API_CreateFunctionUrlConfig` text); streaming 200 MB ([API_CreateFunctionUrlConfig](https://docs.aws.amazon.com/lambda/latest/api/API_CreateFunctionUrlConfig.html)).

## 11. What Terraform and SDKs actually call (Lambda subset)

Terraform `aws_lambda_function` ([TF](https://github.com/hashicorp/terraform-provider-aws/blob/972faab3f6e4e37aff0453fe05366f3bd3fc2b97/internal/service/lambda/function.go)):

## 12. Implications for understudy

Decisions the architecture and implementation owners should record. Each is grounded above.

1. **Execution topology: host the Runtime API in understudy, not behind the RIE.** Because the RIE cannot report `X-Amz-Function-Error`, cannot return AWS-shaped timeout/crash payloads, hard-codes the invoked ARN, reports fake memory, and crashes on concurrent requests (sections 1, 9.9), build per-function "execution environment" objects where understudy runs the Runtime API server for each container and sets `AWS_LAMBDA_RUNTIME_API` so the official entrypoint `exec`s the runtime directly (section 9.2). This still uses the official base images and the official runtime interface clients. It reproduces: `Lambda-Runtime-*` headers (including `Lambda-Runtime-Invocation-Id`), `Lambda-Runtime-Deadline-Ms` as wall-clock epoch ms (`dispatch_wall_ms + Timeout`; G4 correction, this said "from the emulator clock", which makes aws-lambda-go hand handlers a dead context when the header is stale: observed in [lambda-runtime-contract.md](lambda-runtime-contract.md) section 4), `X-Amz-Function-Error: Unhandled` for any `/error` or init error, `Sandbox.Timedout` (`RequestId: <id> Error: Task timed out after N.NN seconds`), `Runtime.ExitError` messages, `Function.ResponseSizeTooLarge`, accurate `Invoked-Function-Arn` and the START/END/REPORT lines with real wall-clock Durations (section 8.3, 9.7). Keep the RIE path available only as a fallback for a custom image whose entrypoint is not `lambda-entrypoint.sh`-compatible, or document that it is not used. This deviates from the brief's wording ("with the Runtime Interface Emulator") only in who serves the Runtime API; flag it for an ADR. If the architect rejects it, the fallback rules are: one in-flight request per RIE; treat `502` as function error with synthesized payload; treat timeouts by detecting the exact RIE text; for `200` bodies set `Unhandled` only when the body parses as a JSON object containing both `errorMessage` and `errorType`, accepting the false-positive risk.
2. **Single in-flight invocation per container; scale by containers.** Runtime API clients are strictly sequential (`next` returns one event at a time; managed instances is the only concurrent mode, [runtimes-api](https://docs.aws.amazon.com/lambda/latest/dg/runtimes-api.html)). Maintain a pool per (function, version, config hash): reuse an idle warm container; otherwise cold-start another up to the concurrency limit; excess gives 429 (sync) or queues (async). With RIE fallback, serialization is mandatory (crash otherwise).
3. **Function state machine on the emulator clock.** Create returns `Pending` / `The function is being created.` / `Creating`; flip to `Active` after a configurable (default small) interval; for `Image` functions stay `Pending` until the image is resolved and present locally, `Failed` with `ImageAccessDenied`/`InvalidImage`... on pull failure. Updates set `LastUpdateStatus InProgress` (reason `The function is being created.`, code `Creating`) and block conflicting operations with the exact `ResourceConflictException` text (section 5.2) until `Successful`. Terraform's 5 s initial wait means the default transition delay can be 0 to a few ms without affecting correctness; keep it configurable so tests can freeze `Pending` with the clock (`FunctionActive` waiter semantics). Emit only `Pending`, `Active`, `Failed`, `Deleting` in phase 1.
4. **Validation: generate from Smithy, then override documented limits.** Generated validators from the pinned model give pattern/length/enum checks, but: (a) real AWS reports them as `ValidationException` (no `Type`, camelCase member names, `1 validation error detected: ...`) for most members and as `InvalidParameterValueException` for `runtime`, `functionName` length 64 and several semantic checks (section 2.1); (b) tighten `Timeout` to 1..900, `MemorySize` to 128..10240, `EphemeralStorage` to 512..10240 and the 4 KB env limit (section 4.1); (c) reject deprecated runtimes with the exact message in section 4.2, using the dates in the docs table and the emulator clock; (d) the model's `Runtime` enum is a superset of what creates succeed on.
5. **Container networking.** Functions need to reach understudy for AWS API calls via `AWS_ENDPOINT_URL` and for the Runtime API. A listener on 127.0.0.1 is unreachable from a bridge-network container. Options: (i) additionally bind a listener on the Docker bridge gateway address (the IP behind `host-gateway`) on an ephemeral port, used for both the Runtime API and the AWS API endpoint given to containers, with the main API still on 127.0.0.1 by default; (ii) `--network host` (Linux only); (iii) per-container user-defined network. Option (i) honors the "bind 127.0.0.1 by default" security rule only if the second listener is opt-out-able and bound to the bridge gateway, not 0.0.0.0, and restricted to a per-container secret path or token (the Runtime API has no auth in AWS). Add `--add-host host.docker.internal:host-gateway` to every Lambda container ([docker run reference](https://docs.docker.com/reference/cli/docker/container/run/)); on Podman/Docker Desktop verify the name resolves. Open question for the architect.
6. **Credentials inside functions.** Inject `AWS_ACCESS_KEY_ID`/`AWS_SECRET_ACCESS_KEY`/`AWS_SESSION_TOKEN`, `AWS_REGION`, `AWS_DEFAULT_REGION`, `AWS_ENDPOINT_URL`. Since the brief derives the account from the access key, mint an access key that encodes the function's account (and, for the access recorder, the role) so that API calls from the function record the right principal. Session token: any opaque value. Do not log them (security default). Apply user `Environment.Variables` last for non-reserved keys; reserved keys must be rejected at API time. The exact rejection message for reserved keys is UNVERIFIED; fail with `InvalidParameterValueException` and a clear message until a recorded string is found.
7. **Environment fidelity checklist for every container** (section 9.4): set `AWS_LAMBDA_FUNCTION_NAME`, `AWS_LAMBDA_FUNCTION_VERSION` (`$LATEST` or number), `AWS_LAMBDA_FUNCTION_MEMORY_SIZE`, `AWS_LAMBDA_LOG_GROUP_NAME` (`/aws/lambda/<name>` or the configured `LogGroup`), `AWS_LAMBDA_LOG_STREAM_NAME`, `AWS_LAMBDA_INITIALIZATION_TYPE=on-demand`, `AWS_REGION`, `AWS_DEFAULT_REGION`, `_HANDLER`, `LAMBDA_TASK_ROOT`, `LAMBDA_RUNTIME_DIR`, `TZ=:UTC`, `AWS_LAMBDA_RUNTIME_API`. Set Docker `--memory`/`--cpus` from the configuration, `--read-only` root with a tmpfs or bind-mounted writable `/tmp` sized from `EphemeralStorage`, `--init`, and the label `understudy.dev/...` for cleanup. Mount code at `/var/task` read-only, layers at `/opt`.
8. **Logs.** Capture the container's stdout/stderr (Docker log stream) and write `INIT_START` (cold only), `START`, application lines, `END`, `REPORT` into `/aws/lambda/<name>` / a generated stream, honoring `LogFormat` and levels. Compute `Duration`/`Billed Duration` (rounded up to ms; billing granularity per the REC `Duration: 3.01 ms` → `Billed Duration: 4 ms`), `Memory Size`, `Max Memory Used` (from cgroup stats or the configured value), `Init Duration` on cold starts. For `LogType: Tail` return the base64 of the last 4 KB of that invocation's lines. Filter out RIE-internal `[INFO] (rapid)` lines if the fallback RIE path is used (they go to the same stdout, PROBE).
9. **Invoke contract.** Implement RequestResponse (200 + `X-Amz-Executed-Version`), Event (202, empty body, background queue with retry schedule 60 s, 120 s on the emulator clock, 6 h age default, destinations/DLQ), DryRun (204). Always emit `X-Amzn-RequestId`. Preserve the three limits (6,291,556 B sync response, 1 MB async request, 6,291,456 B sync request). Treat a body larger than the limit as `RequestEntityTooLargeException` 413 (section 8.2). Never reject non-JSON `Content-Type`. Accept empty payload. `ClientContext` is base64 JSON passed through as `Lambda-Runtime-Client-Context` (decoded JSON string).
10. **Event-invoke config and destinations (stretch in brief).** Store per qualifier; always return `DestinationConfig` with empty `OnSuccess`/`OnFailure` objects; implement the invocation-record format in section 7.7 for SQS/SNS/Lambda/EventBridge targets, S3 on-failure only; wire into the causal journal. Reserved concurrency 0 + async routes to on-failure with `ZeroReservedConcurrency`.
11. **Permissions are stored policy documents.** Store as structured statements, render `GetPolicy` as the JSON string `{"Version":"2012-10-17","Id":"default","Statement":[...]}` with insertion order, bump `RevisionId` on every change, serialize Add/Remove per function, enforce statement-id uniqueness, the `$LATEST` restriction, the 20 KB cap. IAM-enforcement-free phase 1 still evaluates the **function URL public-access check** (policy must grant `lambda:InvokeFunctionUrl` plus `lambda:InvokeFunction` with `InvokedViaFunctionUrl` to `*`/with `FunctionUrlAuthType NONE`) because it changes observable behavior (403 `Forbidden. For troubleshooting Function URL authorization issues, see: ...`). Decide whether to implement the October 2025 two-statement rule or accept either statement (the REC snapshots add only the `InvokeFunctionUrl` statement and predate the change); recommend requiring both, because `aws_lambda_function_url` adds both itself (section 11) and the current docs require both. Mind the Terraform idempotence path: the provider tolerates a duplicate-statement error whose text contains `The statement id (FunctionURLAllowPublicAccess) provided already exists`.
12. **Function URL data plane.** Route by `Host` header `<url-id>.lambda-url.<region>.<suffix>` on the main port; generate 32-char lowercase alphanumeric ids; return `FunctionUrl` as `https://...` only if TLS is served, else `http://<id>.lambda-url.<region>.localhost:<port>/` (decision; `*.localhost` resolves to loopback on glibc/systemd-resolved but not everywhere; Go's resolver follows the system). Build payload v2.0 events exactly per section 10, mark `isBase64Encoded` for non-text content types, apply response inference rules, split `cookies` into `set-cookie` headers, enforce 100..599. `AWS_IAM` auth: SigV4 validation is opt-in in the brief; decode the access key to fill `authorizer.iam` when present. Support `BUFFERED` only; reject or buffer `RESPONSE_STREAM`.
13. **Versions and aliases.** Immutable snapshots of config+code (keep the extracted code directory content-addressed), numbering monotonic per function and never reused after deletion (UNVERIFIED but standard), `PublishVersion` no-op when unchanged, `CodeSha256`/`RevisionId` preconditions, `ListVersionsByFunction` oldest-first with `$LATEST` first, ARN formats per section 3, `ExecutedVersion` resolution for aliases and weighted routing seeded by the fault/clock seed.
14. **Round-trip fidelity for Terraform.** Return every defaulted field exactly as in section 4.5 (including `LoggingConfig`, `EphemeralStorage`, `SnapStart`, `TracingConfig`, `RuntimeVersionConfig` for runtime-based zip functions, `Architectures`), keep `CodeSha256` = base64 SHA-256 of the zip, implement `ListVersionsByFunction`, `GetFunctionCodeSigningConfig` (return `{FunctionName, CodeSigningConfigArn: ""}`; both fields are `required` in the model, empty ARN for none is UNVERIFIED), `GetFunctionConcurrency` (empty object when unset), `GetRuntimeManagementConfig` (`{UpdateRuntimeOn: "Auto", FunctionArn}`), `GetFunctionRecursionConfig` (`{RecursiveLoop: "Terminate"}`), `GetAccountSettings`. Tags in `GetFunction.Tags`.
15. **Image handling.** Docker Engine API only: pull `ImageUri` if absent (it can be a plain local reference such as `my-fn:latest`; a real ECR URI would fail offline), store `ResolvedImageUri` as the image ID/digest, `Code.RepositoryType = "ECR"`, `Code.ImageUri`. Apply `ImageConfig.EntryPoint`/`Command`/`WorkingDirectory` as container overrides. Reject non-Linux images and multi-arch selection mismatches (architecture must match host or run under emulation; document).
16. **Clock integration.** G4 correction (this item said all durations come from the emulator clock; see [lambda-runtime-contract.md](lambda-runtime-contract.md) section 3 for evidence). On the emulator clock: async retry delays and max event age, `LastModified`, `FunctionEventInvokeConfig.LastModified`, state transition delays, ESM batching windows. On wall time (a monotonic timer from dispatch): function timeout enforcement, `Lambda-Runtime-Deadline-Ms`, `Duration`, `Billed Duration` (ceil to 1 ms), `Init Duration`, init limit and idle reaping, because the container runs on the kernel clock and the RICs subtract the header from it. A frozen or scaled emulator clock therefore never fires, shortens or lengthens a function timeout.
17. **Zip handling safety and speed.** Extract once per code SHA into a content-addressed directory with zip-slip checks, preserve mode bits (executable `bootstrap`), mount read-only at `/var/task`. Reject `Unzipped size must be smaller than 262144000 bytes`; `Zipped size must be smaller than 52428800 bytes` (413 `RequestEntityTooLargeException`); body-size cap of 70,167,211 bytes on CreateFunction.
