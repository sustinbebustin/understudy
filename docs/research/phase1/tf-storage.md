# Terraform AWS provider call sequences: storage, keys, secrets

Research input for understudy phase 1. Scope: the exact API traffic `hashicorp/terraform-provider-aws` generates for `aws_s3_bucket` and its separate resources (`aws_s3_bucket_policy`, `_public_access_block`, `_ownership_controls`, `_server_side_encryption_configuration`, `_lifecycle_configuration`, `_versioning`, `_notification`), `aws_dynamodb_table` (ttl, point_in_time_recovery, tags, billing mode), `aws_kms_key`, `aws_kms_alias`, `aws_secretsmanager_secret` and `aws_secretsmanager_secret_version`: calls per create/read/update/delete, every subresource read `aws_s3_bucket` performs and which errors it treats as "not configured", waiters, response fields the provider dereferences, and perpetual-diff risks.

Conventions:
- Every claim carries an inline source link. Provider links are pinned to a commit and line, so they do not drift.
- UNVERIFIED marks anything not confirmed in a primary source I could read (usually real-AWS runtime behavior that no document or recording pins down).
- PROBE means a request trace I captured by running the real Terraform and provider against a local stand-in (section 7). The client is the evidence; the stand-in's answers are not evidence of AWS behavior.
- Where source code, docs and the Smithy models disagree, the disagreement is stated and client behavior wins.
- Service semantics (what S3, DynamoDB, KMS and Secrets Manager return, field by field) are in the sibling documents: [s3.md](s3.md), [dynamodb-local.md](dynamodb-local.md), [iam-sts-kms.md](iam-sts-kms.md), [secrets-logs-events-alarms.md](secrets-logs-events-alarms.md). This document is the Terraform side: what is called, in which order, what is waited for, and what a wrong answer costs.

## 1. Provider machinery that shapes emulator behavior

### 1.1 Account discovery decides which S3 tag API is used

- With `skip_requesting_account_id = false` (the default) the provider resolves the account at configure time. CORRECTED (G6): the IAM-first order below applies only when `skip_credentials_validation = true`. With the default `skip_credentials_validation = false` the provider makes exactly one `sts:GetCallerIdentity` and no `iam:GetUser` ([tf-messaging.md 1.1](tf-messaging.md) flag table with [aws_config.go L310-L342](https://github.com/hashicorp/aws-sdk-go-base/blob/v2.0.0-beta.73/aws_config.go#L310-L342); observed on 6.68.0 with no `skip_*` flags in [tf-remaining.md section 10](tf-remaining.md)); the PROBE below most likely ran with `skip_credentials_validation = true` (inference; this file did not record the flags). PROBE with `iam` and `sts` endpoints overridden: two IAM Query `GetUser` calls (`POST /`, body `Action=GetUser&Version=2010-05-08`) and no STS call, because `GetUser` succeeded and its `Arn` carried the account. With `skip_requesting_account_id = true` no bootstrap call was made at all. The full discovery order (`GetUser`, `GetCallerIdentity`, `ListRoles`) and the ignored error codes are in [iam-sts-kms.md](iam-sts-kms.md).
- `c.AccountID(ctx)` empty vs non-empty selects the bucket tag API: non-empty uses S3 Control `ListTagsForResource`/`TagResource`/`UntagResource` and falls back to the classic `GetBucketTagging`/`PutBucketTagging`/`DeleteBucketTagging` only on "is not authorized to perform: s3:..." messages or `MethodNotAllowed`; empty uses the classic calls directly ([tags.go L168-L246](https://github.com/hashicorp/terraform-provider-aws/blob/972faab3f6e4e37aff0453fe05366f3bd3fc2b97/internal/service/s3/tags.go#L168-L246)). PROBE confirmed both: account resolved gave `GET /v20180820/tags/arn%3Aaws%3As3%3A%3A%3Aprobe-bucket-1` with `Host: 123456789012.localhost:<port>` and `x-amz-account-id: 123456789012`; `skip_requesting_account_id = true` gave `GET /probe-notags-1/?tagging=` answered `404 NoSuchTagSet`.
- The S3 Control host. S3 Control operations carry `RequiresAccountId = true`, and the endpoint rule for a custom endpoint is `{url#scheme}://{AccountId}.{url#authority}{url#path}` ([S3 Control model, `ListTagsForResource` `smithy.rules#staticContextParams` and the endpoint rule set](https://github.com/aws/api-models-aws/blob/1cfdfb4bb9ea858e65623e66d73af04bec353201/models/s3-control/service/2018-08-20/s3-control-2018-08-20.json), generated rule at [endpoints.go](https://github.com/aws/aws-sdk-go-v2/blob/service/s3control/v1.79.1/service/s3control/endpoints.go)). The provider passes the configured endpoint as the client's `BaseEndpoint` ([s3control service_package_gen.go L237](https://github.com/hashicorp/terraform-provider-aws/blob/972faab3f6e4e37aff0453fe05366f3bd3fc2b97/internal/service/s3control/service_package_gen.go#L237)). Consequence: a base URL of `http://127.0.0.1:4566` makes the tag read dial `123456789012.127.0.0.1:4566`, which does not resolve ([s3.md E3](s3.md) records the failure); a `localhost` base URL works wherever `*.localhost` resolves (PROBE: `123456789012.localhost` worked).
- The S3 Control calls are plain restXml on the same listener: `GET|POST|DELETE /v20180820/tags/{ResourceArn+}`, header `x-amz-account-id`, `UntagResource` passes keys as repeated `tagKeys` query parameters, `TagResource` sends a body whose only member is `<Tags><Tag><Key/><Value/></Tag></Tags>`, and the `ListTagsForResource` result is `<Tags><Tag>...</Tag></Tags>` ([S3 Control model](https://github.com/aws/api-models-aws/blob/1cfdfb4bb9ea858e65623e66d73af04bec353201/models/s3-control/service/2018-08-20/s3-control-2018-08-20.json), [serializer, `Tags` member element](https://github.com/aws/aws-sdk-go-v2/blob/service/s3control/v1.79.1/service/s3control/serializers.go)). The response root element name is not validated by the Go client: moto answered `<ListTagsForResourceResponse><Tags></Tags></ListTagsForResourceResponse>` and the provider accepted it (PROBE). The `TagResource` request root element name was not captured (no in-place tag change was run): UNVERIFIED, accept any root.

### 1.2 "Empty result" counts as "not found"

`tfresource.NewEmptyResultError()` implements `As(**retry.NotFoundError)`, so `retry.NotFound(err)` is true for it ([not_found_error.go L21-L53](https://github.com/hashicorp/terraform-provider-aws/blob/972faab3f6e4e37aff0453fe05366f3bd3fc2b97/internal/tfresource/not_found_error.go#L21-L53), [retry/error.go L24-L29](https://github.com/hashicorp/terraform-provider-aws/blob/972faab3f6e4e37aff0453fe05366f3bd3fc2b97/internal/retry/error.go#L24-L29)). Every `find*` function below returns it when the success body has no payload (nil `LoggingEnabled`, zero rules, nil `OwnershipControls`...). So an empty `200` is treated exactly like the "not configured" error code. The difference matters in create waiters: `RetryWhenNotFound` (`UntilFoundN(1)`) keeps polling on both ([op.go L22-L51](https://github.com/hashicorp/terraform-provider-aws/blob/972faab3f6e4e37aff0453fe05366f3bd3fc2b97/internal/retry/op.go#L22-L51)).

### 1.4 Transparent tagging

The SDKv2 interceptor sets `TagsIn` (config tags merged with `default_tags`) before Create, which each resource's Create hands to the API; after Create/Update/Read it calls the service package's `ListTags(identifier)` unless the resource's own Read already called `setTagsOut`; on Update it calls `UpdateTags(old, new)` when `tags_all` changed ([tags_interceptor.go L34-L200](https://github.com/hashicorp/terraform-provider-aws/blob/972faab3f6e4e37aff0453fe05366f3bd3fc2b97/internal/provider/sdkv2/tags_interceptor.go#L34-L200)). Identifiers: bucket name (`@Tags(identifierAttribute="bucket", resourceType="Bucket")`, [bucket.go L66-L67](https://github.com/hashicorp/terraform-provider-aws/blob/972faab3f6e4e37aff0453fe05366f3bd3fc2b97/internal/service/s3/bucket.go#L66-L67)), table ARN ([table.go L53](https://github.com/hashicorp/terraform-provider-aws/blob/972faab3f6e4e37aff0453fe05366f3bd3fc2b97/internal/service/dynamodb/table.go#L53)), key ID ([key.go L37](https://github.com/hashicorp/terraform-provider-aws/blob/972faab3f6e4e37aff0453fe05366f3bd3fc2b97/internal/service/kms/key.go#L37)), secret ARN, with the tags read from `DescribeSecret.Tags` ([secret.go L38, L285](https://github.com/hashicorp/terraform-provider-aws/blob/972faab3f6e4e37aff0453fe05366f3bd3fc2b97/internal/service/secretsmanager/secret.go#L285)). `aws_kms_alias`, `aws_secretsmanager_secret_version` and all separate S3 resources have no tags.

## 2. S3

The fresh-bucket state of every subresource (ownership controls `BucketOwnerEnforced`, public access block all `true`, default `AES256` encryption) and the not-configured error bodies are specified in [s3.md section 4](s3.md). This section is the Terraform sequence.

### 2.1 `aws_s3_bucket` create

1. us-east-1 only: `HEAD /{bucket}`; if it succeeds Terraform fails with `BucketAlreadyExists` itself, because us-east-1 `CreateBucket` on an owned bucket returns 200 and resets ACLs ([bucket.go L763-L769](https://github.com/hashicorp/terraform-provider-aws/blob/972faab3f6e4e37aff0453fe05366f3bd3fc2b97/internal/service/s3/bucket.go#L763-L769), [docs: BucketAlreadyOwnedByYou row](https://docs.aws.amazon.com/AmazonS3/latest/developerguide/ErrorResponses.html)). PROBE: `HEAD /probe-bucket-1/` answered `404`, empty body.
2. `PUT /{bucket}` (`CreateBucket`) with header `x-amz-acl: private` always, and a `CreateBucketConfiguration` body that is always present ([bucket.go L771-L814](https://github.com/hashicorp/terraform-provider-aws/blob/972faab3f6e4e37aff0453fe05366f3bd3fc2b97/internal/service/s3/bucket.go#L771-L814)). The body carries `LocationConstraint` outside us-east-1 and `Tags` when tags exist. PROBE bodies in us-east-1:
   - with tags: `<CreateBucketConfiguration xmlns="http://s3.amazonaws.com/doc/2006-03-01/"><Tags><Tag><Key>Name</Key><Value>probe</Value></Tag></Tags></CreateBucketConfiguration>`
   - without tags: `<CreateBucketConfiguration xmlns="http://s3.amazonaws.com/doc/2006-03-01/"></CreateBucketConfiguration>` (an empty element, not a missing body).
3. Retries: `OperationAborted` is retried for the create timeout; an error containing "is not authorized to perform: s3:TagResource" or code `UnsupportedArgument` or `MalformedXML` retries once without tags and then tags after creation; `MalformedXML` again retries with no `CreateBucketConfiguration` at all ([bucket.go L816-L860](https://github.com/hashicorp/terraform-provider-aws/blob/972faab3f6e4e37aff0453fe05366f3bd3fc2b97/internal/service/s3/bucket.go#L816-L860), added for S3-compatible services per [CHANGELOG L1228](https://github.com/hashicorp/terraform-provider-aws/blob/972faab3f6e4e37aff0453fe05366f3bd3fc2b97/CHANGELOG.md)). Accepting tags in `CreateBucket` is therefore the happy path; rejecting them degrades to extra calls but works.
4. Wait: `HEAD /{bucket}` until it returns 200 (`RetryWhenNotFound`) ([bucket.go L848-L854](https://github.com/hashicorp/terraform-provider-aws/blob/972faab3f6e4e37aff0453fe05366f3bd3fc2b97/internal/service/s3/bucket.go#L848-L854)). A 404 from `HeadBucket` has no body; the provider keys on HTTP status 404 ([bucket.go L1776-L1796](https://github.com/hashicorp/terraform-provider-aws/blob/972faab3f6e4e37aff0453fe05366f3bd3fc2b97/internal/service/s3/bucket.go#L1776-L1796)).
5. Create then runs Update, which on a plain bucket makes no API call: every legacy inline attribute (`policy`, `cors_rule`, `website`, `versioning`, `acl`, `grant`, `logging`, `lifecycle_rule`, `acceleration_status`, `request_payer`, `replication_configuration`, `server_side_encryption_configuration`, `object_lock_configuration`) is written only when it appears in the raw HCL ([bucket.go L1229-L1685](https://github.com/hashicorp/terraform-provider-aws/blob/972faab3f6e4e37aff0453fe05366f3bd3fc2b97/internal/service/s3/bucket.go#L1229-L1685), [guard L1687-L1706](https://github.com/hashicorp/terraform-provider-aws/blob/972faab3f6e4e37aff0453fe05366f3bd3fc2b97/internal/service/s3/bucket.go#L1687-L1706)). The one exception is `object_lock_enabled = true`, which sends `PutObjectLockConfiguration` ([L1640-L1655](https://github.com/hashicorp/terraform-provider-aws/blob/972faab3f6e4e37aff0453fe05366f3bd3fc2b97/internal/service/s3/bucket.go#L1640-L1655)). Update ends with the Read below.

### 2.3 `aws_s3_bucket` update and delete

- Update with only `tags` changed: the interceptor calls the S3 Control (or classic) tag APIs; no inline attribute is touched ([bucket.go L1687-L1706](https://github.com/hashicorp/terraform-provider-aws/blob/972faab3f6e4e37aff0453fe05366f3bd3fc2b97/internal/service/s3/bucket.go#L1687-L1706), [tags.go L57-L96](https://github.com/hashicorp/terraform-provider-aws/blob/972faab3f6e4e37aff0453fe05366f3bd3fc2b97/internal/service/s3/tags.go#L57-L96)). ### 2.6 Perpetual-diff and hang risks (S3)

1. **Bucket tags must round-trip from `CreateBucket`.** PROBE: moto accepted `CreateBucketConfiguration/Tags` but `ListTagsForResource` returned an empty `<Tags>`; the second `terraform plan` showed `aws_s3_bucket.b will be updated in-place` with `+ "Name" = "probe"` on `tags` and `tags_all`, exit code 2. Tags sent at create must appear in both S3 Control `ListTagsForResource` and `GetBucketTagging`.
2. **Lifecycle deep equality.** `lifecycleConfigEqual` compares the sent rules with the returned rules by `reflect.DeepEqual`, order-insensitive across rules, and compares `TransitionDefaultMinimumObjectSize` ([L658-L692](https://github.com/hashicorp/terraform-provider-aws/blob/972faab3f6e4e37aff0453fe05366f3bd3fc2b97/internal/service/s3/bucket_lifecycle_configuration.go#L658-L692)). A single differing field (an added `<Prefix/>`, a dropped `<Filter/>`, a missing header) makes the create wait time out after 3 minutes. The plan modifier defaults the header to `all_storage_classes_128K` for general purpose buckets, so the request always carries it and the response must echo it ([L1064-L1106](https://github.com/hashicorp/terraform-provider-aws/blob/972faab3f6e4e37aff0453fe05366f3bd3fc2b97/internal/service/s3/bucket_lifecycle_configuration.go#L1064-L1106)). Filter forms the provider sends: no `filter` block and no legacy `prefix` => empty `<Filter></Filter>`; `filter {}` => `<Filter><Prefix></Prefix></Filter>`; legacy `prefix` => `<Prefix>` and no `Filter` ([L753-L860](https://github.com/hashicorp/terraform-provider-aws/blob/972faab3f6e4e37aff0453fe05366f3bd3fc2b97/internal/service/s3/bucket_lifecycle_configuration.go#L753-L860)). Store what was sent and return it verbatim (PROBE: this passed with moto, 55 s).
3. **SSE rule set identity.** `rule` is a `TypeSet`; `kms_master_key_id` is `Optional+Computed` with no diff suppression, so an ARN sent must come back as the same ARN, not a key ID or alias ([schema L60-L98](https://github.com/hashicorp/terraform-provider-aws/blob/972faab3f6e4e37aff0453fe05366f3bd3fc2b97/internal/service/s3/bucket_server_side_encryption_configuration.go#L60-L98)). Return `BucketKeyEnabled` as stored.
4. **Public access block**: return all four elements; the provider writes all four on every Put ([L80-L97](https://github.com/hashicorp/terraform-provider-aws/blob/972faab3f6e4e37aff0453fe05366f3bd3fc2b97/internal/service/s3/bucket_public_access_block.go#L80-L97)).
5. **Policy**: Terraform compares semantically (`verify.PolicyToSet` keeps the configured text when the JSON is equivalent) but the stored string must be valid JSON ([json.go L176-L188](https://github.com/hashicorp/terraform-provider-aws/blob/972faab3f6e4e37aff0453fe05366f3bd3fc2b97/internal/verify/json.go#L176-L188)). A policy naming a principal that does not exist yet returns `MalformedPolicy` in AWS and Terraform retries for 2 minutes; an emulator that validates principals strictly would stall `aws_s3_bucket_policy` on any not-yet-created principal. Phase 1 stores policies without enforcement, so accept.
6. **Notification emptiness.** Create polls `GetBucketNotificationConfiguration` until the output is non-zero. The check is `inttypes.IsZero(output)` on the SDK output struct ([zero.go L11-L24](https://github.com/hashicorp/terraform-provider-aws/blob/972faab3f6e4e37aff0453fe05366f3bd3fc2b97/internal/types/zero.go#L11-L24)); whether `ResultMetadata` makes an empty `<NotificationConfiguration/>` non-zero is UNVERIFIED. Either way, a stored non-empty configuration returns a non-zero struct. Real S3 validates destinations on Put (it sends a test notification to SQS/SNS and checks the Lambda permission) and the provider does not set `x-amz-skip-destination-validation` ([API_PutBucketNotificationConfiguration](https://docs.aws.amazon.com/AmazonS3/latest/API/API_PutBucketNotificationConfiguration.html)); destination validation behavior is specified in [s3.md section 13](s3.md).
7. **Region header** on `HeadBucket` (section 2.2 notes).
8. **`GetBucketAcl`** must return at least one grant with a `Grantee` (`xsi:type="CanonicalUser"`, `ID`); the provider would panic dereferencing a nil `Grantee` ([L2211-L2256](https://github.com/hashicorp/terraform-provider-aws/blob/972faab3f6e4e37aff0453fe05366f3bd3fc2b97/internal/service/s3/bucket.go#L2211-L2256)). The empty-grants case is handled (`len == 0` returns an empty list).

### 3.4 Perpetual-diff and hang risks (DynamoDB)

1. `WarmThroughput` missing => apply fails after about 2.5 minutes (section 3.1 step 3).
2. `ListTagsOfResource` must return the tags passed to `CreateTable`, keyed by the same ARN `DescribeTable.TableArn` returns; otherwise `tags` shows a diff on every plan (the same trap as S3 tag-on-create). 4. ### 5.3 Perpetual-diff risks (Secrets Manager)

1. `kms_key_id` is written to state verbatim from `DescribeSecret.KmsKeyId` ([secret.go L231-L240](https://github.com/hashicorp/terraform-provider-aws/blob/972faab3f6e4e37aff0453fe05366f3bd3fc2b97/internal/service/secretsmanager/secret.go#L231-L240)): return exactly what `CreateSecret`/`UpdateSecret` received. What real AWS returns when a key ID or alias was passed is UNVERIFIED here (an alias or key ID in config against an ARN in the answer would diff).
2. `DescribeSecret.Tags` must reflect `CreateSecret.Tags`, or `tags` diffs forever.
3. `version_stages` on a version resource is `Optional+Computed`; a second `PutSecretValue` demotes the earlier version to `AWSPREVIOUS`, and the earlier `aws_secretsmanager_secret_version` then reads `["AWSPREVIOUS"]` in state without a diff (computed). Make the label moves exact ([secrets-logs-events-alarms.md section 2.2](secrets-logs-events-alarms.md)).
4. The secret ID in state is the ARN with the 6-character suffix (`-ZMysbk`); it must be stable for the secret's lifetime.

## 6. Cross-resource ordering the workload depends on

- `aws_s3_bucket_server_side_encryption_configuration` with `kms_master_key_id = aws_kms_key.k.arn` needs only the key ARN string at apply time (PROBE: the Put carried `<KMSMasterKeyID>arn:aws:kms:...:key/<id></KMSMasterKeyID>`); whether real S3 validates the key on `PutBucketEncryption` is UNVERIFIED (it validates on object writes, [s3.md section 5.7](s3.md)). The emulator may validate or not; Terraform does not depend on it.
- `aws_secretsmanager_secret.kms_key_id` likewise is passed through; `GetSecretValue` then exercises KMS in the emulator's own pipeline.
- Destroy order observed (PROBE): alias before key; secret version before secret; S3 subresources before the bucket; `ScheduleKeyDeletion` only after `DeleteAlias`, `DELETE ?encryption` and `DeleteSecret`, the three resources that referenced the key, had completed. Terraform's graph destroys dependents first, so the emulator never sees a key deleted while a Terraform-managed resource still references it.

## Implications for understudy

Requirements, each traceable to a section above.

1. **Serve S3 Control tagging on the main listener.** Route `GET|POST|DELETE /v20180820/tags/{arn}` on any host to the S3 tag store, read `x-amz-account-id`, accept any `<account>.<host>` prefix, and do not reject an unknown root element. Resolve the bucket from `arn:aws:s3:::<bucket>` (percent-encoded in the path). Tag-on-create (`CreateBucketConfiguration/Tags`), `PutBucketTagging`, `TagResource` and both read APIs share one store (sections 1.1, 2.6.1). Without this, every tagged `aws_s3_bucket` is a perpetual diff or a dial error.
2. **DNS-safe endpoint guidance.** An `AWS_ENDPOINT_URL` of `http://127.0.0.1:<port>` breaks the S3 Control tag read because the SDK prefixes the account id to the authority. Document `http://localhost:<port>` (and `*.localhost` resolution for virtual-hosted S3) as the supported Terraform endpoint, or accept that users must use a wildcard-DNS name; `understudy` should print the recommended value at start-up (section 1.1).
3. **Make the first poll final.** The emulator should publish every final state before returning the mutating call: table `ACTIVE`, TTL `ENABLED`, PITR `ENABLED`, KMS rotation/policy/tags/state visible, secret version labeled, bucket subresources readable. Then only the provider-side floors in section 1.3 remain (about 55 s per lifecycle configuration, about 6 s per table). Do not model `CREATING`, `ENABLING` or `DELETING` intermediates by default; if the clock feature adds them, they must be opt-in because they multiply apply time.
4. **Round-trip exactness for deep-equal and set-hash comparisons.** Store request documents as sent and return them without re-normalization: lifecycle rules (including `Filter` shape and header `x-amz-transition-default-minimum-object-size` on the GET), SSE rules (`KMSMasterKeyID` as given, `BucketKeyEnabled` as given), public access block (all four flags), bucket policy (valid JSON), notification configuration, key policy, resource policy (sections 2.6, 4.3, 5.3).
5. **Subresource defaults for a fresh bucket.** Return "unset" via the exact not-configured code for policy, CORS, website, lifecycle, replication, object lock and tagging; return empty `200` documents for versioning, accelerate, request payment, logging, notification; return the default objects for ownership controls, public access block and encryption (defaults from [s3.md section 4.1](s3.md)). All 14 reads in section 2.2 must succeed on a bucket with nothing configured, including `GetBucketAcl` with a grantee and `HeadBucket` with `X-Amz-Bucket-Region`.
6. **DynamoDB shim list from the Terraform side**: `WarmThroughput` on every `DescribeTable`; `ListTagsOfResource`/`TagResource`/`UntagResource` keyed by the `TableArn` the shim itself returns; `DescribeContinuousBackups` + `UpdateContinuousBackups` returning `PointInTimeRecoveryDescription` with `RecoveryPeriodInDays`; `DescribeTimeToLive` + `UpdateTimeToLive` (TTL on the emulator clock); `ResourceNotFoundException` with message "Requested resource not found: Table: <name> not found" after `DeleteTable` (sections 3.1, 3.4; Local itself cannot do the tag, PITR and warm-throughput parts, per [dynamodb-local.md](dynamodb-local.md)).
7. **KMS list/describe contract.** `ListAliases` without `KeyId` must return every alias with `AliasArn`, `AliasName` and `TargetKeyId` (bare ID); `GetKeyRotationStatus` must include `RotationPeriodInDays` whenever rotation is enabled; `DescribeKey` must report `Origin: AWS_KMS`, `KeyState`, `Enabled`, `KeySpec`, `KeyUsage`, `MultiRegion`; `ScheduleKeyDeletion` must flip `KeyState` to `PendingDeletion` immediately (the provider treats that as deleted); `ListResourceTags` returns `TagKey`/`TagValue` (section 4).
8. **Secrets Manager contract.** `CreateSecret` always receives `Description:""`; `DescribeSecret` must return `Tags` and `KmsKeyId` as stored and `DeletedDate` after `DeleteSecret`; with `ForceDeleteWithoutRecovery` the secret must read as `ResourceNotFoundException` at once; `GetResourcePolicy` on a secret with no policy returns `{ARN, Name}`; `PutSecretValue` must return `VersionStages` and the version must be readable with labels by `GetSecretValue(VersionId)` immediately (empty labels on a new version stall the apply for 2 minutes) (section 5).
9. **Account derivation for the bootstrap.** (CORRECTED (G6): with default provider flags the bootstrap is one `sts:GetCallerIdentity`, so STS is required; `GetUser` is first only with `skip_credentials_validation = true`, see section 1.1.) Provider configure uses IAM `GetUser` first and takes the account from its `Arn`; an emulator that answers `GetUser` with a user ARN in the access key's account (or with one of the error codes the provider ignores) avoids any STS dependency; see [iam-sts-kms.md](iam-sts-kms.md). The S3 tag path depends on this succeeding (section 1.1).
10. **Test plan.** A conformance suite under the Terraform harness should apply the section 7 configurations unchanged, assert `plan -detailed-exitcode` is 0 on the second run and `destroy` is clean, and record per-resource wall time against the floors in section 1.3 (lifecycle about 55 s, table about 6 s). Add a negative test: tags on `CreateBucket` must appear in `ListTagsForResource` (the diff in section 2.6.1 is a one-line regression).
11. **Decision (per brief working rules).** Where the AWS error table (400) and the pattern of the other not-configured codes (404) disagree for `ServerSideEncryptionConfigurationNotFoundError`, follow the AWS table; the code is unreachable on default buckets.
