### 1.1 CloudWatch needs three codecs

The CloudWatch model carries `aws.protocols#awsJson1_0`, `aws.protocols#awsQuery`, `aws.protocols#awsQueryCompatible` and `smithy.protocols#rpcv2Cbor` ([MODEL](https://github.com/aws/api-models-aws/blob/main/models/cloudwatch/service/2010-08-01/cloudwatch-2010-08-01.json)). What each client picks:

- **aws-sdk-go-v2** (and therefore Terraform's AWS provider and any Go app): `options.Protocol = rpcv2.NewCBOR(schemas.GraniteServiceVersion20100801)` ([api_client.go](https://github.com/aws/aws-sdk-go-v2/blob/main/service/cloudwatch/api_client.go)). The CloudWatch module changelog dates the switch: v1.53.0 (2025-12-10) "introduces two additional protocols AWS JSON 1.1 and Smithy RPC v2 CBOR, replacing the currently utilized one, AWSQuery" ([CHANGELOG](https://github.com/aws/aws-sdk-go-v2/blob/main/service/cloudwatch/CHANGELOG.md)). Older Go SDK builds still speak `awsQuery`.
- **botocore / boto3**: the service file lists `"protocols": ["smithy-rpc-v2-cbor","json","query"]`, `"jsonVersion": "1.0"`, `"targetPrefix": "GraniteServiceVersion20100801"` ([cloudwatch service-2.json](https://github.com/boto/botocore/blob/develop/botocore/data/cloudwatch/2010-08-01/service-2.json)). `ServiceModel.resolved_protocol` walks `PRIORITY_ORDERED_SUPPORTED_PROTOCOLS = ('json','rest-json','rest-xml','smithy-rpc-v2-cbor','query','ec2')` and returns the first member present in the service's list ([model.py](https://github.com/boto/botocore/blob/develop/botocore/model.py), [utils.py](https://github.com/boto/botocore/blob/develop/botocore/utils.py)). By that code boto3 therefore uses **JSON 1.0** (`X-Amz-Target: GraniteServiceVersion20100801.<Op>`, `application/x-amz-json-1.0`). CORRECTED (G1): now wire-captured: boto3 1.43.109 and AWS CLI 2.36.38 (own bundled botocore) both sent `POST /` with `X-Amz-Target: GraniteServiceVersion20100801.<Op>`, `Content-Type: application/x-amz-json-1.0` and `x-amzn-query-mode: true`; JS v3 3.1146.0 did the same ([wire-cbor.md section 2.1](wire-cbor.md)).
- **aws-sdk-js-v3**: `protocol: config?.protocol ?? AwsJson1_0Protocol` with `awsQueryCompatible: true` ([runtimeConfig.shared.ts](https://github.com/aws/aws-sdk-js-v3/blob/main/clients/client-cloudwatch/src/runtimeConfig.shared.ts)).

LocalStack parametrizes its AWS-validated CloudWatch tests over exactly `json`, `query` and `smithy-rpc-v2-cbor` and records the same error codes and messages for all three ([test_cloudwatch.snapshot.json](https://github.com/localstack/localstack/blob/main/tests/aws/services/cloudwatch/test_cloudwatch.snapshot.json), AWS-REC).

Wire rules (SDK/spec):

- `rpcv2Cbor`: `POST {prefix?}/service/{serviceName}/operation/{operationName}`; request header `Smithy-Protocol: rpc-v2-cbor`; `Content-Type: application/cbor` and `Accept: application/cbor`; MUST NOT carry `X-Amz-Target`; success is 200; errors are 400 unless the error shape has `httpError` or is a server fault (500); every response carries `Smithy-Protocol: rpc-v2-cbor`; the error type is the body field `__type` ([smithy-rpc-v2-cbor.rst](https://github.com/smithy-lang/smithy/blob/main/docs/source-2.0/additional-specs/protocols/smithy-rpc-v2-cbor.rst)). For CloudWatch the service name is `GraniteServiceVersion20100801`, so the path is `/service/GraniteServiceVersion20100801/operation/PutMetricAlarm` (derived from the Go client above; G1 captured it on the wire from cloudwatch v1.73.0, see [wire-cbor.md section 4](wire-cbor.md)).
- `awsJson1_x`: `POST /`; `X-Amz-Target: {service}.{op}`; error type in `__type` (body), `code`, or header `X-Amzn-Errortype`; clients strip everything after the first `:` then everything up to and including the first `#`; 1.0 servers send the full shape ID in `__type`, 1.1 servers send only the shape name, and clients must accept both ([Smithy awsJson1_1](https://smithy.io/2.0/aws/protocols/aws-json-1_1-protocol.html)).
- `awsQueryCompatible`: adds the response header `x-amzn-query-error: Code;Fault` where `Fault` is `Sender` or `Receiver`, so the legacy awsQuery error `Code` survives on the JSON and CBOR wires ([aws-query-protocol.rst](https://github.com/smithy-lang/smithy/blob/main/docs/source-2.0/aws/protocols/aws-query-protocol.rst)). The CloudWatch error codes in AWS-REC are the legacy ones: `ResourceNotFound` (404), `InvalidParameterCombination`, `InvalidParameterValue`, `ValidationError`, `MissingParameter`, `LimitExceeded`, `InvalidNextToken` ([PutMetricAlarm errors](https://docs.aws.amazon.com/AmazonCloudWatch/latest/APIReference/API_PutMetricAlarm.html), [test_cloudwatch.snapshot.json](https://github.com/localstack/localstack/blob/main/tests/aws/services/cloudwatch/test_cloudwatch.snapshot.json)).

Error body casing for Secrets Manager (AWS-REC, raw HTTP): `{"Message": "...", "__type": "InvalidRequestException"}` with status 400 ([test_no_client_request_token](https://github.com/localstack/localstack/blob/main/tests/aws/services/secretsmanager/test_secretsmanager.snapshot.json)). CloudWatch Logs and EventBridge errors surface as `Error.Code` + `Error.Message` through boto3; the casing of the raw `message` key is not captured. A mock server body seen in an unrelated project uses lowercase `{"__type":"ResourceNotFoundException","message":"The specified log stream does not exist."}` (EMU, [rotel awsemf test](https://github.com/rotel-dev/rotel/blob/main/src/exporters/awsemf/mod.rs)); SDKs accept either casing. UNVERIFIED for real AWS.

## 2. Secrets Manager

### 2.1 Identifiers

- **Name**: 1 to 512 characters; ASCII letters, digits and `/_+=.@-` ([CreateSecret](https://docs.aws.amazon.com/secretsmanager/latest/apireference/API_CreateSecret.html)). AWS-REC rejection text for bad names: `ValidationException` (400) "Invalid name. Must be a valid name containing alphanumeric characters, or any of the following: -/_+=.@!" for names containing a space, `*`, `?`, `]` ([test_invalid_secret_name](https://github.com/localstack/localstack/blob/main/tests/aws/services/secretsmanager/test_secretsmanager.snapshot.json)). The error text lists `!` while the DOC lists no `!`; treat the DOC list as authoritative for acceptance and accept `!` only if a later source confirms it. UNVERIFIED.
- **ARN**: `arn:aws:secretsmanager:<region>:<account>:secret:<name>-<6 random chars>` ([troubleshoot: partial ARN](https://docs.aws.amazon.com/secretsmanager/latest/userguide/troubleshoot.html)). The suffix makes a recreated secret with the same name a different ARN ([CreateSecret response](https://docs.aws.amazon.com/secretsmanager/latest/apireference/API_CreateSecret.html)); AWS-REC confirms a delete-then-recreate yields a different suffix ([test_can_recreate_delete_secret](https://github.com/localstack/localstack/blob/main/tests/aws/services/secretsmanager/test_secretsmanager.snapshot.json)).
- Suffix alphabet: DOC examples are `a1b2c3` and `nutBrk`, i.e. lower-case, upper-case and digits occur ([DescribeSecret](https://docs.aws.amazon.com/secretsmanager/latest/apireference/API_DescribeSecret.html), [troubleshoot](https://docs.aws.amazon.com/secretsmanager/latest/userguide/troubleshoot.html)). Generate 6 characters from `[A-Za-z0-9]`. UNVERIFIED whether AWS excludes any characters. (moto uses letters only: EMU, [moto utils](https://github.com/getmoto/moto/blob/master/moto/secretsmanager/utils.py).)
- Partial ARN lookup: Secrets Manager can usually find a secret from an ARN without the suffix, but a secret whose name itself ends in `-` plus six characters (example `MySecret-abcdef`, ARN `...:secret:MySecret-abcdef-nutBrk`) cannot be reliably found from a partial ARN ([troubleshoot](https://docs.aws.amazon.com/secretsmanager/latest/userguide/troubleshoot.html)). `SecretId` accepts name or ARN, 1 to 2048 characters ([GetSecretValue](https://docs.aws.amazon.com/secretsmanager/latest/apireference/API_GetSecretValue.html)). A name containing `/_+=.@-` round-trips through ARN construction (AWS-REC name `Valid/_+=.@-Name-a1b2c3-` produced ARN `...:secret:Valid/_+=.@-Name-a1b2c3--<suffix>`, [snapshot](https://github.com/localstack/localstack/blob/main/tests/aws/services/secretsmanager/test_secretsmanager.snapshot.json)).

### 2.2 Version and stage model

Facts ([PutSecretValue](https://docs.aws.amazon.com/secretsmanager/latest/apireference/API_PutSecretValue.html), [UpdateSecretVersionStage](https://docs.aws.amazon.com/secretsmanager/latest/apireference/API_UpdateSecretVersionStage.html), [DescribeSecret VersionIdsToStages](https://docs.aws.amazon.com/secretsmanager/latest/apireference/API_DescribeSecret.html)):

- A secret holds versions. `VersionId` is the `ClientRequestToken` (32 to 64 chars; "typically a UUID").
- Each staging label (1 to 256 chars) is attached to at most one version at a time. Attaching a label already on another version moves it. At most 20 labels across all versions of a secret; at most 100 versions ([quotas](https://docs.aws.amazon.com/secretsmanager/latest/userguide/reference_limits.html)).
- `AWSCURRENT` marks the current version, `AWSPENDING` the in-progress rotation version, `AWSPREVIOUS` the prior current version. Whenever `AWSCURRENT` moves from version X to Y, `AWSPREVIOUS` is moved to X automatically ([PutSecretValue](https://docs.aws.amazon.com/secretsmanager/latest/apireference/API_PutSecretValue.html), [UpdateSecretVersionStage](https://docs.aws.amazon.com/secretsmanager/latest/apireference/API_UpdateSecretVersionStage.html)).
- A version with no labels is "deprecated" and eligible for background deletion. `ListSecretVersionIds` omits deprecated versions unless `IncludeDeprecated=true`. Secrets Manager removes unlabeled versions only when there are more than 100, and never those younger than 24 hours ([quotas](https://docs.aws.amazon.com/secretsmanager/latest/userguide/reference_limits.html), [ListSecretVersionIds](https://docs.aws.amazon.com/secretsmanager/latest/apireference/API_ListSecretVersionIds.html)).
- `AWSCURRENT` cannot be removed from a secret entirely, only moved. Terraform's source quotes the server message: "InvalidParameterException: You can only move staging label AWSCURRENT to a different secret version. It can't be completely removed." ([secret_version.go](https://github.com/hashicorp/terraform-provider-aws/blob/main/internal/service/secretsmanager/secret_version.go)).

Transition rules, with the AWS-REC trace that proves each ([stage snapshots](https://github.com/localstack/localstack/blob/main/tests/aws/services/secretsmanager/test_secretsmanager.snapshot.json), tests `test_update_secret_version_stages_*`, `test_deprecated_secret_version_stage`, `test_non_versioning_version_stages_*`, validated 2024-03):

| Operation | Result | Evidence |
|---|---|---|
| Create with a value | v1 = {AWSCURRENT}; response has `VersionId`, no `VersionStages` | DOC + AWS-REC |
| Create with no value (empty secret) | no version; DescribeSecret has no `VersionIdsToStages`; GetSecretValue fails `ResourceNotFoundException` "Secrets Manager can't find the specified secret value for staging label: AWSCURRENT"; first PutSecretValue returns `VersionStages: ["AWSCURRENT"]` | AWS-REC `test_create_secret_version_from_empty_secret`, `test_secret_version_not_found` |
| PutSecretValue, no `VersionStages` | new version takes AWSCURRENT; old current gets AWSPREVIOUS; the version that previously held AWSPREVIOUS becomes unlabeled | AWS-REC `test_deprecated_secret_version_stage` |
| PutSecretValue with custom stages not including AWSCURRENT | new version gets exactly those labels; AWSCURRENT stays put; response `VersionStages` is **sorted** (`["one","three","two"]`); a later Put reusing labels steals them and the donor version, now unlabeled, disappears from the default listing | AWS-REC `test_non_versioning_version_stages_replacement`, `test_put_secret_value_with_version_stages` |
| PutSecretValue with `VersionStages=["AWSPENDING"]` | new version = {AWSPENDING}; AWSCURRENT unchanged | AWS-REC `test_update_secret_version_stages_current_pending` |

Mechanism UNVERIFIED (could be "default Put clears AWSPENDING from the demoted version"); observed only in this trace | AWS-REC same test, `list_secret_version_ids_res_2` |
| PutSecretValue with `VersionStages=["AWSPENDING"]` (v3) while v2 = {AWSCURRENT, AWSPENDING} | AWSPENDING moves to v3; v2 = {AWSCURRENT} | AWS-REC `..._pending_cycle` |
| Custom label (`PENDING`) behaves like any other label; moving AWSCURRENT onto a version keeps its other labels | v2 = {AWSCURRENT, PENDING}, v1 = {AWSPREVIOUS} | AWS-REC `..._custom_stages_3` |
| UpdateSecretVersionStage when label is on a different version and `RemoveFromVersionId` is absent or wrong | operation fails (exact error code UNVERIFIED; DOC says "the operation fails") | [DOC](https://docs.aws.amazon.com/secretsmanager/latest/apireference/API_UpdateSecretVersionStage.html) |

`UpdateSecretVersionStage` response is `{ARN, Name}` only ([DOC](https://docs.aws.amazon.com/secretsmanager/latest/apireference/API_UpdateSecretVersionStage.html), AWS-REC `test_update_secret_version_stages_return_type`).

### 2.3 ClientRequestToken and idempotency

- Parameter is 32 to 64 characters. SDKs and the CLI generate a UUID if absent. With a raw HTTP request the caller must supply it ([CreateSecret](https://docs.aws.amazon.com/secretsmanager/latest/apireference/API_CreateSecret.html), [PutSecretValue](https://docs.aws.amazon.com/secretsmanager/latest/apireference/API_PutSecretValue.html)).
- **Missing token on raw HTTP is an error** for CreateSecret, UpdateSecret, PutSecretValue and RotateSecret: HTTP 400, `InvalidRequestException`, "You must provide a ClientRequestToken value. We recommend a UUID-type value." (AWS-REC, [test_no_client_request_token](https://github.com/localstack/localstack/blob/main/tests/aws/services/secretsmanager/test_secretsmanager.snapshot.json), validated). Because SDKs always inject it, a token-less request only arises from hand-rolled clients; understudy should still reject it to match AWS.
- Same token + same `SecretString`/`SecretBinary` as an existing version: request succeeds, nothing changes (idempotent) ([CreateSecret](https://docs.aws.amazon.com/secretsmanager/latest/apireference/API_CreateSecret.html), [PutSecretValue](https://docs.aws.amazon.com/secretsmanager/latest/apireference/API_PutSecretValue.html)). AWS-REC for duplicate PutSecretValue (`test_http_put_secret_value_duplicate_req`) is `only_localstack`, not AWS-validated.
- Same token + different value: "the request fails because you can't modify an existing version" ([PutSecretValue](https://docs.aws.amazon.com/secretsmanager/latest/apireference/API_PutSecretValue.html)); for UpdateSecret a matching token "results in an error" regardless of content ([UpdateSecret](https://docs.aws.amazon.com/secretsmanager/latest/apireference/API_UpdateSecret.html)). The DOC gives no error name. Emulators use `ResourceExistsException` 400 "You can't use ClientRequestToken <token> because that value is already in use for a version of secret <arn>." (EMU, [moto models.py](https://github.com/getmoto/moto/blob/master/moto/secretsmanager/models.py), [floci](https://github.com/floci-io/floci/blob/main/src/main/java/io/github/hectorvent/floci/services/secretsmanager/SecretsManagerService.java)). The DOC error lists for all four write operations include `ResourceExistsException` ("A resource with the ID you requested already exists"), so the code is plausible. Exact message UNVERIFIED against AWS; LocalStack's own test for it is skipped as "not AWS validated" ([test_secretsmanager.py](https://github.com/localstack/localstack/blob/main/tests/aws/services/secretsmanager/test_secretsmanager.py)).
- CreateSecret when the name already exists, different token: `ResourceExistsException` 400 "The operation failed because the secret <name> already exists." (AWS-REC `test_secret_exists_snapshots`).
- CreateSecret when the name is in its deletion window: `InvalidRequestException` 400 "You can't create this secret because a secret with this name is already scheduled for deletion." (AWS-REC `test_exp_raised_on_creation_of_secret_scheduled_for_deletion`; same text quoted in [secret.go](https://github.com/hashicorp/terraform-provider-aws/blob/main/internal/service/secretsmanager/secret.go)).
- Terraform always sends its own `ClientRequestToken` and retries CreateSecret while the error contains "scheduled for deletion" or "was deleted" ([secret.go](https://github.com/hashicorp/terraform-provider-aws/blob/main/internal/service/secretsmanager/secret.go)), so replaying the same token after a transient failure must be safe.

### 2.4 Operations: request and response facts

**CreateSecret** ([DOC](https://docs.aws.amazon.com/secretsmanager/latest/apireference/API_CreateSecret.html))
- Request: `Name` (required), `ClientRequestToken`, `Description` (max 2048), `KmsKeyId` (max 2048; ARN, key id, or `alias/...`), `SecretString` or `SecretBinary` (not both; 1 to 65536; binary is base64 on the wire), `Tags`, `AddReplicaRegions`, `ForceOverwriteReplicaSecret`, `Type`.
- Response: `ARN`, `Name`, `VersionId` (only when a value was supplied), `ReplicationStatus`. AWS-REC response for a value-less create: `{ARN, Name}` only.
- Default key is `aws/secretsmanager`. DescribeSecret omits `KmsKeyId` for it; ListSecretVersionIds shows `KmsKeyIds: ["DefaultEncryptionKey"]` (DOC [DescribeSecret](https://docs.aws.amazon.com/secretsmanager/latest/apireference/API_DescribeSecret.html), AWS-REC `test_deprecated_secret_version_stage`).
- Phase 1 requires KMS integration "used by Secrets Manager" ([brief](../../brief/phase1-brief.md)): when `KmsKeyId` is supplied, the DOC requires `kms:GenerateDataKey` and `kms:Decrypt`; with a customer key that is disabled or pending deletion the error is `EncryptionFailure`/`DecryptionFailure` (400) ([DOC](https://docs.aws.amazon.com/secretsmanager/latest/apireference/API_CreateSecret.html)).

**PutSecretValue** ([DOC](https://docs.aws.amazon.com/secretsmanager/latest/apireference/API_PutSecretValue.html))
- Request: `SecretId`, `ClientRequestToken`, `SecretString`/`SecretBinary` (exactly one), `VersionStages` (1 to 20 strings), `RotationToken` (36 to 256, `^[a-zA-Z0-9\-]+$`, rotation only).
- Response: `ARN`, `Name`, `VersionId`, `VersionStages` (labels now on the new version).
- Errors: `ResourceNotFoundException`, `InvalidRequestException` (secret scheduled for deletion), `InvalidParameterException`, `LimitExceededException`, `ResourceExistsException`, `EncryptionFailure`, `DecryptionFailure`.

**UpdateSecret** ([DOC](https://docs.aws.amazon.com/secretsmanager/latest/apireference/API_UpdateSecret.html))
- Request: `SecretId`, `ClientRequestToken`, `Description`, `KmsKeyId` (empty string means the default key), `SecretString`/`SecretBinary`, `Type`.
- Creates a new version (AWSCURRENT moves, AWSPREVIOUS follows) only when a secret value is supplied. Response `VersionId` is present only then. AWS-REC: description-only and KMS-only updates return `{ARN, Name}` with no `VersionId`; a value update returns `{ARN, Name, VersionId}` ([test_update_secret_description](https://github.com/localstack/localstack/blob/main/tests/aws/services/secretsmanager/test_secretsmanager.snapshot.json)).
- Changing `KmsKeyId` re-encrypts versions labeled AWSCURRENT, AWSPENDING and AWSPREVIOUS if the caller has `kms:Encrypt` on the new key ([DOC](https://docs.aws.amazon.com/secretsmanager/latest/apireference/API_UpdateSecret.html)).
- Cannot change rotation (use RotateSecret) or tags (use TagResource) here.

**GetSecretValue** ([DOC](https://docs.aws.amazon.com/secretsmanager/latest/apireference/API_GetSecretValue.html))
- Request: `SecretId`, `VersionId` (32 to 64), `VersionStage` (1 to 256). Neither given means AWSCURRENT. Both given must refer to the same version.
- Response: `ARN`, `CreatedDate` (of the version), `Name`, `SecretString` or `SecretBinary` (whichever was stored; the other key is absent), `VersionId`, `VersionStages`.
- Errors (AWS-REC unless stated):
  - unknown secret: `ResourceNotFoundException` 400 "Secrets Manager can't find the specified secret."
  - stage with no version: `ResourceNotFoundException` "Secrets Manager can't find the specified secret value for staging label: AWSPREVIOUS"
  - unknown VersionId: `ResourceNotFoundException` "Secrets Manager can't find the specified secret value for VersionId: <id>" ([test_secret_version_not_found](https://github.com/localstack/localstack/blob/main/tests/aws/services/secretsmanager/test_secretsmanager.snapshot.json))
  - VersionId and VersionStage not the same version: `InvalidRequestException` "You provided a VersionStage that is not associated to the provided VersionId."
  - secret scheduled for deletion: `InvalidRequestException` "You can't perform this operation on the secret because it was marked for deletion." (AWS-REC `test_tag_untag_resource_on_deleted_secret` for Tag/Untag; Terraform matches the substring "because it was marked for deletion" on GetSecretValue and UpdateSecretVersionStage, [secret_version.go](https://github.com/hashicorp/terraform-provider-aws/blob/main/internal/service/secretsmanager/secret_version.go)). The GetSecretValue text itself is UNVERIFIED beyond that substring.
- `ResourceNotFoundException` is HTTP **400** on AWS ([DOC](https://docs.aws.amazon.com/secretsmanager/latest/apireference/API_GetSecretValue.html), AWS-REC). moto returns 404 (EMU, [exceptions.py](https://github.com/getmoto/moto/blob/master/moto/secretsmanager/exceptions.py)); do not copy that.

**DescribeSecret** ([DOC](https://docs.aws.amazon.com/secretsmanager/latest/apireference/API_DescribeSecret.html))
- Only fields with a value are returned. Fields: `ARN`, `Name`, `Description`, `KmsKeyId`, `CreatedDate`, `LastChangedDate`, `LastAccessedDate`, `DeletedDate`, `LastRotatedDate`, `NextRotationDate`, `RotationEnabled`, `RotationLambdaARN`, `RotationRules`, `Tags`, `VersionIdsToStages`, `OwningService`, `PrimaryRegion`, `ReplicationStatus`, `Type`, external-rotation fields.
- AWS-REC minimal shape of a fresh secret with a value: `{ARN, CreatedDate, LastChangedDate, Name, VersionIdsToStages}`; `Description` appears only if set; `LastAccessedDate` appears after a GetSecretValue; `Tags` is absent until a tag is added and becomes `[]` (present, empty) after the last tag is removed ([test_secret_tags](https://github.com/localstack/localstack/blob/main/tests/aws/services/secretsmanager/test_secretsmanager.snapshot.json)). DOC says `LastAccessedDate` is "the date" (day-level in DOC example `1606269226`); day-granularity UNVERIFIED.

### 2.5 Deletion window, force delete, restore (clock-driven)

- `DeleteSecret{SecretId, RecoveryWindowInDays (7 to 30, default 30), ForceDeleteWithoutRecovery}`. The two options are mutually exclusive ([DeleteSecret](https://docs.aws.amazon.com/secretsmanager/latest/apireference/API_DeleteSecret.html)). Response `{ARN, DeletionDate, Name}`; `DeletionDate` = request time + window. The secret is not removed from the store at once; permanent deletion is a low-priority background task "no guarantee of a specific time after the recovery window" ([DOC](https://docs.aws.amazon.com/secretsmanager/latest/apireference/API_DeleteSecret.html)). With the emulator clock, purge exactly when `now >= DeletionDate`.
- Force delete removes the secret immediately. "If you forcibly delete an already deleted or nonexistent secret, the operation does not return `ResourceNotFoundException`" ([DOC](https://docs.aws.amazon.com/secretsmanager/latest/apireference/API_DeleteSecret.html)). AWS-REC: force-deleting a secret that is already scheduled for deletion succeeds and returns `{ARN, DeletionDate, Name}` ([test_force_delete_deleted_secret](https://github.com/localstack/localstack/blob/main/tests/aws/services/secretsmanager/test_secretsmanager.snapshot.json)). The `DeletionDate` returned for a force delete of an already-gone secret is UNVERIFIED (moto returns "now": EMU, [moto models.py](https://github.com/getmoto/moto/blob/master/moto/secretsmanager/models.py)).
- A normal DeleteSecret on a secret already scheduled for deletion: DOC lists `InvalidRequestException` "The secret is scheduled for deletion"; exact message UNVERIFIED.
- Out-of-range window: `InvalidParameterException`; message UNVERIFIED (moto: "The RecoveryWindowInDays value must be between 7 and 30 days (inclusive)", EMU).
- While scheduled for deletion: GetSecretValue, PutSecretValue, UpdateSecret, UpdateSecretVersionStage, TagResource, UntagResource, PutResourcePolicy, GetResourcePolicy fail `InvalidRequestException` (DOC "Possible causes: The secret is scheduled for deletion", [GetSecretValue](https://docs.aws.amazon.com/secretsmanager/latest/apireference/API_GetSecretValue.html)); DescribeSecret and RestoreSecret succeed.
- `RestoreSecret{SecretId}` clears `DeletedDate`, returns `{ARN, Name}` ([DOC](https://docs.aws.amazon.com/secretsmanager/latest/apireference/API_RestoreSecret.html), AWS-REC `test_secret_restore`). Restoring a secret that is not scheduled for deletion: DOC says only `ResourceNotFoundException` or `InvalidRequestException`; behavior UNVERIFIED (moto treats it as a no-op).
- After a force delete the name is immediately reusable; after a scheduled delete the name is blocked until the window ends (see 2.3). DOC warns to "use appropriate back off and retry logic" because real deletion is asynchronous ([DOC](https://docs.aws.amazon.com/secretsmanager/latest/apireference/API_DeleteSecret.html)); a deterministic emulator can be exact.

### 2.6 Limits

Per region ([quotas](https://docs.aws.amazon.com/secretsmanager/latest/userguide/reference_limits.html)): 500,000 secrets; 100 versions per secret; 20 staging labels per secret; secret value 65,536 bytes; resource policy 20,480 characters. Request-rate quotas (for example CreateSecret 50/s, GetSecretValue 10,000/s) are the only throttling the fault-injection feature needs to model; no hard enforcement is required by the brief. `LimitExceededException` (400) is the error for quota breaches ([PutSecretValue errors](https://docs.aws.amazon.com/secretsmanager/latest/apireference/API_PutSecretValue.html)).

### 2.7 What Terraform calls (aws_secretsmanager_secret, aws_secretsmanager_secret_version)

From [secret.go](https://github.com/hashicorp/terraform-provider-aws/blob/main/internal/service/secretsmanager/secret.go) and [secret_version.go](https://github.com/hashicorp/terraform-provider-aws/blob/main/internal/service/secretsmanager/secret_version.go):

- Secret create: `CreateSecret` (own token, `Description` always sent, possibly empty string, tags inline) -> wait `DescribeSecret` -> optional `PutResourcePolicy`.
- Secret read: `DescribeSecret` (not-found if `ResourceNotFoundException` or `DeletedDate` set) + `GetResourcePolicy`; flattens `ARN`, `Description`, `KmsKeyId`, `Name`, `ReplicationStatus`, `Type`, `Tags`.
- Secret update: `UpdateSecret` only when description or KMS key changed; policy via Put/DeleteResourcePolicy; tags via TagResource/UntagResource.
- Secret delete: `DeleteSecret` with `ForceDeleteWithoutRecovery=true` when `recovery_window_in_days = 0`, else `RecoveryWindowInDays`; then polls DescribeSecret until not found. `ResourceNotFoundException` on delete is success.
- Version create: `PutSecretValue` (own token, optional `VersionStages`) -> wait via `GetSecretValue(VersionId)` or `ListSecretVersionIds` (when write-only values are used) -> read.
- Version update: `ListSecretVersionIds` to find the current version, then `UpdateSecretVersionStage` with `RemoveFromVersionId` / `MoveToVersionId`.
- Version delete: `UpdateSecretVersionStage(RemoveFromVersionId)` for each non-AWSCURRENT stage; skips AWSCURRENT and ignores `ResourceNotFoundException` and "because it was deleted" / "because it was marked for deletion".
- Hence `terraform destroy` is clean only if `UpdateSecretVersionStage` removal of a non-current label succeeds and GetSecretValue by VersionId keeps working until the labels are removed.

### 3.6 Filter pattern syntax (complete)

Source for everything in this subsection: [Filter pattern syntax](https://docs.aws.amazon.com/AmazonCloudWatch/latest/logs/FilterAndPatternSyntax.html), the same grammar used by FilterLogEvents, metric filters, subscription filters and Live Tail. Quotas on regex: at most 2 regex per JSON or delimited pattern when filtering log events; 5 regex-bearing patterns per log group for metric and subscription filters (not relevant to FilterLogEvents).

Pattern kind is chosen by the first character: `{` = JSON, `[` = space-delimited, anything else = unstructured text.

**A. Unstructured text**
- Terms are case-sensitive. Terms with non-alphanumeric characters, and exact phrases, go in double quotes.
- `ERROR ARGUMENTS` = both terms present (AND).
- `?ERROR ?ARGUMENTS` = either term (OR). If `?` terms are mixed with plain or `-` terms, **all `?` terms are ignored** (docs example: `?ERROR ?ARGUMENTS REQUEST` behaves as `REQUEST`).
- `"INTERNAL SERVER ERROR"` = exact phrase.
- `ERROR -ARGUMENTS` = include ERROR, exclude ARGUMENTS.
- `" "` matches every event.
- Regex term: `%regex%` (alphanumerics plus `: _ # = @ / ; , -`; operators `^ $ ? [ ] { } | \ * + .`; `\d \D \s \S \w \W \xhh`; **no `(` `)` groups**; no multi-byte characters; a literal space also occurs in the DOC example `%^starting|^initializing|^shutting down%`, so the list is not exhaustive: [syntax page](https://docs.aws.amazon.com/AmazonCloudWatch/latest/logs/FilterAndPatternSyntax.html)). Example `%AUTHORIZED%` matches `UNAUTHORIZED` and `AUTHORIZED`, so a regex term is a substring search.
- Token boundary rules for an unquoted term (does `ERROR` match `ERRORS`, `MYERROR`, `ERROR:`?) are not specified in prose. **Corrected by gap G3 ([logs-filter-patterns.md](logs-filter-patterns.md) section 5):** the earlier "whole-token" suggestion had no source and conflicts with the one AWS example that exercises it, where `Exception` matches inside `InvalidQueryException` ([TestMetricFilter](https://docs.aws.amazon.com/AmazonCloudWatchLogs/latest/APIReference/API_TestMetricFilter.html)). Working rule: case-sensitive substring, no word boundary, confidence about 60 percent, still UNVERIFIED by a recording. Keep the term test behind one function. See open question Q1.

**B. JSON patterns** `{ <expr> }`
- Selector: `$.a.b`, array index `$.arr[0]`, nested `$.coordinates[0][1]`, wildcard element `$.arr[*]`, wildcard field `$.*`, dotted key via `$.['cluster.name']` (single quotes only; double quotes inside brackets are a syntax error). Property names: alphanumerics, `-`, `_`. At most one wildcard selector per selector, at most three across a compound expression.
- A selector that points to an object or array never matches.
- String comparison: `=`, `!=` against a string; quotes optional if the string has only alphanumerics and `_`, required otherwise; `*` is a wildcard inside the string (for example `{ $.sourceIPAddress != 123.123.* }`).
- Numeric comparison: `=`, `!=`, `<`, `>`, `<=`, `>=` against integers (optional `+`/`-`) and scientific notation (`1e+3`, `1e-3`); `*` is a numeric wildcard.
- Regex: `{ $.eventType = %Trail% }`, `{ $.arrayKey[*] = %val.{2}% }`, `{ $.* = %111\.111\.111\.1[0-9]{1,2}% }`.
- Null/boolean: `{ $.SomeObject IS NULL }`, `IS TRUE`, `IS FALSE`. Existence: `{ $.SomeOtherObject NOT EXISTS }`. **Not supported**: `IS NOT` and `EXISTS` ("currently aren't supported").
- Compound: `&&`, `||`, parentheses; precedence `()` > `&&` > `||`. Examples: `{ ($.user.id = 1) && ($.users[0].email = "John.Doe@example.com") }`, `{ $.user.email = "John.Stiles@example.com" || $.coordinates[0][1] = "nonmatch" && $.actions[2] = "nonmatch" }` (matches because `&&` binds tighter).
- The event message must be valid JSON for a JSON pattern to match; a non-JSON message never matches (implied by the DOC; UNVERIFIED).

**C. Space-delimited patterns** `[f1, f2, ...]`
- Fields are named in brackets separated by commas: `[ip, user, username, timestamp, request, status_code, bytes]`. A bracketed (`[...]`) or double-quoted (`"..."`) token counts as one field.
- Conditions: `[ip=%127\.0\.0\.[1-9]%, user, username, timestamp, request =*.html*, status_code = 4*, bytes]`; operators `=`, `!=`, `<`, `>`, `<=`, `>=`; `*` wildcard; regex; `&&`/`||` within one field condition (`status_code = 404 || status_code = 410`); `...` stands for any number of unnamed fields (`[..., request =*.html*, status_code = 4*, bytes]`).
- Positional naming `w1`, `w2`: `[w1=ERROR, w2]` matches events whose first word is ERROR; a trailing blank indicator field is required; `[w1=ERROR || w1=WARNING, w2]`, `[w1!=ERROR && w1!=WARNING, w2]`.
- An event with fewer fields than the pattern does not match (INFERRED). **Corrected by gap G3 ([logs-filter-patterns.md](logs-filter-patterns.md) N6):** the earlier "more fields match only with a trailing `...`" contradicts the DOC's own example, where `[w1=ERROR, w2]` is presented as returning events whose first word is ERROR for events of 6 to 7 words ([syntax page](https://docs.aws.amazon.com/AmazonCloudWatch/latest/logs/FilterAndPatternSyntax.html)). Working rule: the last pattern field absorbs the remaining tokens; confidence LOW, UNVERIFIED (record case C6).

Invalid pattern: AWS rejects with `InvalidParameterException` (error text UNVERIFIED; moto, which only supports single terms, quoted terms and multi-term, falls back to returning all events: EMU, [moto logs utils](https://github.com/getmoto/moto/blob/master/moto/logs/utils.py) and the `filter_log_events` docstring in [models.py](https://github.com/getmoto/moto/blob/master/moto/logs/models.py)). **No surveyed emulator implements this grammar.** A real implementation is a visible differentiator. **Corrected by gap G3:** the claim that no AWS-REC test set exists for patterns needs a qualifier. LocalStack carries dated `aws.validated` pattern tests (2026-02-05) and a recorded unquoted-`=` term (2026-01-14), but none can separate the candidate token rules; a 167-vector corpus (DOC, REC, INFERRED) and the EBNF are in [logs-filter-patterns.md](logs-filter-patterns.md). The console wording for an unquoted illegal character is "Invalid character(s) in term" ([re:Post answer, non-primary](https://www.repost.aws/questions/QUauhBe_zRQp2VN0JPFVDPjA/why-i-do-hit-metric-resource-limit-exceeded)); API text still UNVERIFIED.

### 4.2 Schedule expressions (rate and cron)

Scope: scheduled rules exist only on the default bus: `ValidationException` "ScheduleExpression is supported only on the default event bus." (AWS-REC, [test_events_schedule.snapshot.json](https://github.com/localstack/localstack/blob/main/tests/aws/services/events/test_events_schedule.snapshot.json)). All schedules run in UTC; minimum precision is one minute; "there can be a delay of several seconds" ([DOC](https://docs.aws.amazon.com/eventbridge/latest/userguide/eb-create-rule-schedule.html)). Scheduled rules are "legacy"; EventBridge Scheduler is the successor and is out of phase 1 scope.

Any invalid expression: `ValidationException` 400 "Parameter ScheduleExpression is not valid." (one message for all invalid rate and cron inputs, AWS-REC).

**rate(value unit)** ([DOC](https://docs.aws.amazon.com/eventbridge/latest/userguide/eb-scheduled-rule-pattern.html))
- `value` positive integer; `unit` in `minute | minutes | hour | hours | day | days`; singular iff value is 1.
- AWS-REC rejections, all with the message above: `rate(10 seconds)`, `rate(10 years)`, `rate(1 minutes)`, `rate(1 hours)`, `rate(1 days)`, `rate(10 minute)`, `rate(10 hour)`, `rate(10 day)`, `rate()`, `rate(10)`, `rate(10 minutess)`, `rate(foo minutes)`, `rate(0 minutes)`, `rate(-10 minutes)`, `rate(10 MINUTES)` (units are case-sensitive), `rate( 10 minutes )` (no inner padding), ` rate(10 minutes)` (no leading whitespace) ([test_events_schedule.py](https://github.com/localstack/localstack/blob/main/tests/aws/services/events/test_events_schedule.py)). Accepted in the same corpus: `rate(1 minute)`.
- A rate rule "starts when you create the scheduled event rule" ([DOC](https://docs.aws.amazon.com/eventbridge/latest/userguide/eb-scheduled-rule-pattern.html)): first fire is at creation time + interval (AWS-REC `tests_schedule_rate_target_sqs` receives its first message about 60 s after creating a `rate(1 minute)` rule). Re-PutRule of an existing rate rule restarting the phase is UNVERIFIED.

**cron(minutes hours day-of-month month day-of-week year)** exactly six whitespace-separated fields ([DOC](https://docs.aws.amazon.com/eventbridge/latest/userguide/eb-scheduled-rule-pattern.html)):

| Field | Values | Special characters |
|---|---|---|
| Minutes | 0-59 | `, - * /` |
| Hours | 0-23 | `, - * /` |
| Day-of-month | 1-31 | `, - * ? / L W` |
| Month | 1-12 or JAN-DEC | `, - * /` |
| Day-of-week | 1-7 or SUN-SAT (**1 = Sunday**, so `6L` = last Friday) | `, - * ? L #` |
| Year | 1970-2199 | `, - * /` |

- `,` list, `-` range, `*` all, `/` increment (`1/10` = every tenth minute starting at minute 1: 1, 11, 21, ...), `?` "no specific value", `L` last day (of month or week), `W` nearest weekday (`3W`), `#` nth weekday (`3#2` = second Tuesday). With `#` only one expression is allowed in the field (`3#1,6#3` invalid).
- Day-of-month and day-of-week cannot both be specified: one must be `?`. AWS-REC rejects `cron(0 1 * * * *)`, `cron(0 dummy ? * MON-FRI *)`, `cron(71 8 1 * ? *)`, `cron(7 20 * * NOT *)`, `cron(INVALID)`.
- AWS-REC accepts: `cron(0 10 * * ? *)`, `cron(0 12 * * ? *)`, `cron(15 12 * * ? *)`, `cron(0 18 ? * MON-FRI *)`, `cron(0 8 1 * ? *)`, `cron(0/15 * * * ? *)`, `cron(0/10 * ? * MON-FRI *)`, `cron(0/5 8-17 ? * MON-FRI *)`, `cron(0/30 20-23 ? * MON-FRI *)`, `cron(0/30 0-2 ? * MON-FRI *)`, `cron(5,35 14 * * ? *)`, `cron(15 10 ? * 6L 2002-2005)`, `cron(0 2 ? * SAT *)`, `cron(0 2 ? * SAT#3 *)`, `cron(* * ? * SAT#3 *)`, `cron(0/5 5 ? JAN 1-5 2022)`.
- The DOC example `0/30 20-2 ? * MON-FRI *` implies wrapping hour ranges are valid; UNVERIFIED in AWS-REC (the corpus split it into `20-23` and `0-2`).
- Expressions that would fire more often than once a minute are unsupported ([DOC](https://docs.aws.amazon.com/eventbridge/latest/userguide/eb-scheduled-rule-pattern.html)). Valid combinations of `L`, `W`, `LW` with lists, 5-field legacy cron, lowercase names (`mon`), and out-of-order ranges are UNVERIFIED; see Q4.
- Understudy scheduler: evaluate "does this minute match" on the emulator clock (so `understudy clock advance 1h` fires 60 `rate(1 minute)` events in order), keep per-rule `nextFireAt`, and fire at most once per matching minute.

### 4.4 Event patterns (grammar and matching)

Primary sources: [content filtering operators](https://docs.aws.amazon.com/eventbridge/latest/userguide/eb-create-pattern-operators.html), [arrays](https://docs.aws.amazon.com/eventbridge/latest/userguide/eb-event-patterns-arrays.html), [null/empty](https://docs.aws.amazon.com/eventbridge/latest/userguide/eb-event-patterns-null-values.html), the open-source matcher [aws/event-ruler](https://github.com/aws/event-ruler/blob/main/README.md) (G2 correction, 2026-10-08: the EventBridge docs pages do not cite Ruler; AWS ties EventBridge to it in the [2024-02-01 announcement](https://aws.amazon.com/about-aws/whats-new/2024/02/amazon-eventbridge-event-bus-matching-event-ruler) and the [open-source blog](https://aws.amazon.com/blogs/opensource/open-sourcing-event-ruler); Ruler v2.2.0 reproduces 154 of 155 of the AWS-REC fixtures below, see [matching-engines.md](matching-engines.md)), and AWS-REC corpora ([event_pattern_templates](https://github.com/localstack/localstack/tree/main/tests/aws/services/events/event_pattern_templates), [test_events_patterns.snapshot.json](https://github.com/localstack/localstack/blob/main/tests/aws/services/events/test_events_patterns.snapshot.json)).

Structure and combination:
- A pattern is a JSON object with the same shape as the event. Leaf values are **arrays**; non-array leaf values are rejected (`InvalidEventPatternException` `"string" must be an object or an array`, AWS-REC). Empty arrays are rejected: "Empty arrays are not allowed".
- Fields combine with AND. Values within a leaf array combine with OR. If the event value is an array, the leaf matches when the intersection of the pattern array and the event array is non-empty ([arrays](https://docs.aws.amazon.com/eventbridge/latest/userguide/eb-event-patterns-arrays.html)).
- Arrays of objects in events are "crushed out" of the pattern: `{"employees":{"firstName":["Anna"]}}` matches an event with `employees:[{firstName:"John"},{firstName:"Anna"}]`. AWS's matcher is array-consistent: two fields from **different elements** of the same array do not match together (`{"employees":{"firstName":["Anna"],"lastName":["Jones"]}}` does not match the Anna/Smith, Peter/Jones event) ([Event Ruler](https://github.com/aws/event-ruler/blob/main/README.md)).
- Keys are case-sensitive (AWS-REC `key_case_sensitive_NEG`), operators are case-sensitive (`EXISTS` and `NUMERIC` rejected: "Unrecognized match type EXISTS").
- Dot joining: Event Ruler joins nested keys with `.`, so `{"detail":{"state":{"status":["running"]}}}` also matches an event whose detail has the literal key `"state.status"` (AWS-REC `dot_joining_event`; [Event Ruler caveat](https://github.com/aws/event-ruler/blob/main/README.md)).
- A repeated key in a JSON pattern object: the last one wins ([operators page](https://docs.aws.amazon.com/eventbridge/latest/userguide/eb-create-pattern-operators.html)).
- Pattern top-level and nested names that matter for events: `version`, `id`, `detail-type`, `source`, `account`, `time`, `region`, `resources`, `detail` (and `replay-name` only on replays) ([event structure](https://docs.aws.amazon.com/eventbridge/latest/ref/overiew-event-structure.html)).

Reason: `): `Filter is not an object` (top-level array), `Unexpected character (''' (code 39)): was expecting double-quote to start field name` (single-quoted JSON), `Unrecognized token 'closed': ...` (broken JSON), `prefix match pattern must be a string`, `suffix match pattern must be a string`, `prefix/suffix match pattern must be a string` (inside anything-but), `equals-ignore-case match pattern must be a string`, `wildcard match pattern must be a string`, `Value of anything-but must be an array or single string/number value.` (e.g. `anything-but` with `prefix`+`equals-ignore-case` combined). The real message also appends a Jackson parser location line (`MessageRaw`); the `Message` shown by SDKs strips it ([snapshot](https://github.com/localstack/localstack/blob/main/tests/aws/services/events/test_events_patterns.snapshot.json)). Event payload problems in `TestEventPattern`: `ValidationException` "Parameter Event is not valid." for non-object events.

The 150+ labeled fixtures in the AWS-validated `event_pattern_templates` directory (suffix `_NEG` = must not match, `_EXC` = pattern rejected, otherwise must match) are the best available conformance seed; re-derive them under understudy's own license and generate property tests around them (section 7).

**How EventBridge patterns differ from SNS filter policies** ([SNS filter policies](https://docs.aws.amazon.com/sns/latest/dg/sns-subscription-filter-policies.html), operators list; EventBridge from the table above):

| Aspect | EventBridge | SNS |
|---|---|---|
| Match target | whole event envelope (`source`, `detail-type`, `detail.*`, ...) | `MessageAttributes` scope or `MessageBody` scope chosen per subscription (`FilterPolicyScope`) |
| Operators listed by AWS | exact, null, empty, prefix, suffix, equals-ignore-case, each of those with ignore-case variants, anything-but (string, number, prefix, suffix, ignore-case, wildcard), numeric (comparison and ranges), exists / not exists, cidr, wildcard, `$or` | AND, OR, `$or`, key matching (exists), numeric exact, numeric anything-but, numeric range, string exact, string anything-but, anything-but + prefix, equals-ignore-case, IP address (cidr), prefix, suffix |
| Wildcard, anything-but suffix / wildcard / ignore-case, prefix ignore-case | present | absent from the SNS operator list (absence in a docs list is not proof; confirm in the SNS research) |
| Pattern container | JSON object of arrays | JSON object of arrays |
| Size limit | 4096 chars in the MODEL (quota page says 2048 default, adjustable) | see SNS research |
| Rule combinations cap | 1000 for `$or` | see SNS research |
| Propagation | "short period" ([PutRule](https://docs.aws.amazon.com/eventbridge/latest/APIReference/API_PutRule.html)) | up to 15 minutes ([SNS](https://docs.aws.amazon.com/sns/latest/dg/sns-subscription-filter-policies.html)) |

Recommendation: implement one shared matcher core (Event Ruler semantics) used by EventBridge and SNS with a per-service allowed-operator set, not two engines.

### 4.5 Targets

([PutTargets](https://docs.aws.amazon.com/eventbridge/latest/APIReference/API_PutTargets.html), [MODEL](https://github.com/aws/api-models-aws/blob/main/models/eventbridge/service/2015-10-07/eventbridge-2015-10-07.json))

- `PutTargets{Rule, EventBusName?, Targets[1..100]}`; `Target{Id (required), Arn (required), RoleArn, Input, InputPath, InputTransformer, SqsParameters{MessageGroupId}, DeadLetterConfig{Arn}, RetryPolicy{MaximumEventAgeInSeconds, MaximumRetryAttempts}, ...}`. Response `{FailedEntryCount, FailedEntries:[{TargetId, ErrorCode, ErrorMessage}]}`. The API reference says "The maximum number of entries per request is 10" while the model allows 100 (see section 6).
- **At most 5 targets per rule**: the 6th is rejected with `LimitExceededException` 400 "The requested resource exceeds the maximum number allowed." (AWS-REC `test_add_exceed_fife_targets_per_rule`; quota "Targets per rule 5", [quotas](https://docs.aws.amazon.com/eventbridge/latest/userguide/eb-quota.html)).
- A PutTargets entry with an existing `Id` replaces that target ([PutTargets](https://docs.aws.amazon.com/eventbridge/latest/APIReference/API_PutTargets.html) "or updates the targets if they are already associated").
- `Id` validation message (AWS-REC): `ValidationException` "1 validation error detected: Value '!@#$@!#$' at 'targets.1.member.id' failed to satisfy constraint: Member must satisfy regular expression pattern: [\.\-_A-Za-z0-9]+" and "... Member must have length less than or equal to 64". Note the path form `targets.1.member.id`.
- `Input`, `InputPath` and `InputTransformer` are mutually exclusive: `ValidationException` "Only one of Input, InputPath, or InputTransformer must be provided for target <target-id>." (AWS-REC).
- `RemoveTargets{Rule, Ids, Force}` returns `{FailedEntryCount, FailedEntries}`; `ListTargetsByRule{Rule, EventBusName, NextToken, Limit<=100}` returns `{Targets[], NextToken}` (AWS-REC list entry shape `{Arn, Id}` plus `Input` when set). Terraform reads targets with `ListTargetsByRule` and treats `ResourceNotFoundException`, `ValidationException`, or an error ending in " not found" as gone ([target.go](https://github.com/hashicorp/terraform-provider-aws/blob/main/internal/service/events/target.go)).
- Target kinds required in phase 1: Lambda, SQS, SNS. Permissions: "For AWS Lambda and Amazon SNS resources, EventBridge relies on resource-based policies" ([PutTargets](https://docs.aws.amazon.com/eventbridge/latest/APIReference/API_PutTargets.html)); SQS likewise needs a queue policy. Understudy phase 1 does not enforce IAM, so delivery should proceed without the permission check but record the access in the policy recorder. FIFO SQS targets require `SqsParameters.MessageGroupId`.
- `RoleArn` is only for targets that use IAM roles (EC2, Kinesis, Step Functions, API Gateway). PutRule-level `RoleArn` is stored and echoed.
- Delivery payload: with none of Input/InputPath/InputTransformer the entire event JSON; `Input` (valid JSON) replaces it; `InputPath` (JSONPath, dot notation only, no bracket notation) selects a subtree; `InputTransformer` builds from variables ([PutTargets](https://docs.aws.amazon.com/eventbridge/latest/APIReference/API_PutTargets.html)). AWS-REC `InputPath` outcomes: `$.detail` -> the detail object as the body; nested `$.detail.payload` -> the nested object; `$.detail.payload.sf_id` (a string) -> the body is the JSON text `"baz"` including quotes (SQS body `"\"baz\""`).

### 4.6 InputTransformer semantics

([DOC](https://docs.aws.amazon.com/eventbridge/latest/userguide/eb-transform-target-input.html), AWS-REC [test_events_inputs.snapshot.json](https://github.com/localstack/localstack/blob/main/tests/aws/services/events/test_events_inputs.snapshot.json))

- `InputPathsMap`: up to 100 variables, `{name: "$.json.path"}`; supported JSONPath subset: dot notation, `-`, `_`, alphanumerics, array indices, wildcards `*`, forward slashes.
- `InputTemplate` references `<name>`. Reserved names (cannot be redefined): `aws.events.rule-arn`, `aws.events.rule-name`, `aws.events.event.ingestion-time` (ISO 8601), `aws.events.event` (original event **without** `detail`), `aws.events.event.json` (full event). The last two "can only be used as a value for a JSON field".
- At PutTargets time every `<placeholder>` must be defined or reserved: `ValidationException` "InputTemplate for target <target-id> contains invalid placeholder notdefinedkey." (AWS-REC).
- At delivery time a variable whose JSONPath matches nothing in the event "isn't created and won't appear": strings render as empty (`... info extracted from detail ` and JSON `"command": ""` in AWS-REC), no error.
- Quoting: a template that is a JSON string literal `"..."` yields a JSON string body; a template that is a JSON object yields JSON. String variables are quoted automatically in JSON position (`<state>` and `"<state>"` both work); object/array variables must not be quoted (`{"detail": <detail>}`); inside a string template an object variable is rendered with quotes stripped and no spaces (`{acc_id:0a787ecb-4015,sf_id:baz}`), an array as `[HIGH]` or `[ACTIVE,INACTIVE]` (AWS-REC `test_input_transformer_nested_keys_replacement`). Values are not escaped. Multi-line text output is a template of several quoted lines separated by newlines. Unquoted bare text templates are not valid templates (AWS-REC records an empty result for `<listsingle> single list item`, so presumably rejected; exact error UNVERIFIED).
- `<aws.events.rule-arn>` in a string template renders the rule ARN; `<aws.events.rule-name>` the rule name; `<aws.events.event.ingestion-time>` a timestamp.
- CloudWatch Logs and SSM targets do not support `Input`/`InputPath`; for a CloudWatch Logs target the template must be `{"timestamp":<timestamp>,"message":<version-id>}` ([PutTargets](https://docs.aws.amazon.com/eventbridge/latest/APIReference/API_PutTargets.html)). Out of phase 1 scope.

### 4.7 PutEvents

([PutEvents](https://docs.aws.amazon.com/eventbridge/latest/APIReference/API_PutEvents.html), [PutEventsRequestEntry](https://docs.aws.amazon.com/eventbridge/latest/APIReference/API_PutEventsRequestEntry.html), [user guide](https://docs.aws.amazon.com/eventbridge/latest/userguide/eb-putevents.html))

- `Entries`: 1 to 10 (AWS-REC: more than 10 entries -> `ValidationException` "1 validation error detected: Value '[PutEventsRequestEntry(...)]' at 'entries' failed to satisfy constraint: Member must have length less than or equal to 10", [test_events.snapshot.json](https://github.com/localstack/localstack/blob/main/tests/aws/services/events/test_events.snapshot.json)). The user-guide quota table lists 100 entries only for the newer "Custom Event Bus" product, not for the classic rule-and-target bus used here ([quotas](https://docs.aws.amazon.com/eventbridge/latest/userguide/eb-quota.html)).
- Entry fields: `Source`, `DetailType` (max 128 chars), `Detail` (a JSON **object** as a string), `EventBusName` (name or ARN, default bus if omitted), `Resources[]` (each max 2048), `Time` (RFC 3339; defaults to the call time), `TraceHeader` (1 to 500). `Source`, `DetailType` and `Detail` are required "for EventBridge to successfully send an event"; a missing one fails **that entry**, and if no entry has all three, the whole request fails.
- Per-entry failures keep HTTP 200 with `FailedEntryCount` > 0 and `Entries[i]` = `{ErrorCode, ErrorMessage}` at the same index. AWS-REC codes and messages: missing `Source` -> `InvalidArgument` "Parameter Source is not valid. Reason: Source is a required argument."; missing `DetailType` (or empty) -> `InvalidArgument` "Parameter DetailType is not valid. Reason: DetailType is a required argument."; missing `Detail` -> `InvalidArgument` "Parameter Detail is not valid. Reason: Detail is a required argument."; malformed `Detail` (string, array, invalid JSON, JSON-in-a-string) -> `MalformedDetail` "Detail is malformed." Successful entries: `{EventId: "<uuid>"}` ([snapshot](https://github.com/localstack/localstack/blob/main/tests/aws/services/events/test_events.snapshot.json), recorded 2025-01).
- Size: the current user guide says the **whole request** (sum of all entries) must be below 1 MB (1,048,576 bytes), calculated per entry as 14 bytes for `Time` if present + UTF-8 bytes of `Source`, `DetailType`, `Detail` and each `Resources` element ([user guide](https://docs.aws.amazon.com/eventbridge/latest/userguide/eb-putevents.html)). The 2025-01 AWS recording shows the older rule: an entry with a ~256 KiB `Detail` returned `ValidationException` 400 "Total size of the entries in the request is over the limit." ([test_events.snapshot.json](https://github.com/localstack/localstack/blob/main/tests/aws/services/events/test_events.snapshot.json), validated 2025-01-08). The API reference text still says "less than 1MB". Use 1,048,576 bytes with that error text; see section 6.
- Nested JSON depth limit 1000 levels ([PutEvents](https://docs.aws.amazon.com/eventbridge/latest/APIReference/API_PutEvents.html)).
- Putting to a bus that does not exist: HTTP 200 with an `EventId` for the entry and the event is **dropped** (AWS-REC `test_put_events_nonexistent_event_bus`: both entries returned `EventId`, `FailedEntryCount: 0`; the user guide says the same: "EventBridge will send a 200 response, it will not fail the request"). `DescribeEventBus` on that name does raise `ResourceNotFoundException` "Event bus <name> does not exist.".
- The delivered event: `{version:"0", id:<new uuid, same as the EventId returned>, detail-type, source, account, time, region, resources:[...], detail:{...}}`, `resources` is `[]` when none supplied (AWS-REC SQS bodies in `test_put_events_time`). The `id` equals the `EventId` returned to the caller (AWS-REC `test_put_events_with_time_field`: `EventId` == body `id`). Whether a caller-supplied `Time` shows up in the delivered `time` is UNVERIFIED in the recordings (all normalized to `"date"`); the DOC says it is used.
- Service-owned `source` prefix `aws.` is reserved for AWS services; whether PutEvents rejects a customer `aws.*` source is UNVERIFIED here.
- Throttle: 10,000 PutEvents TPS in us-east-1 ([quotas](https://docs.aws.amazon.com/eventbridge/latest/userguide/eb-quota.html)); `ThrottlingException` and `InternalFailure` are per-entry or request-level errors for fault injection.

## 7. Implications for understudy

Numbered so they can be cited from ADRs.

**Protocol layer**
1. Secrets Manager, Logs and EventBridge are pure `awsJson1_1` (`X-Amz-Target` dispatch, `application/x-amz-json-1.1`). Reuse the same dispatcher for all three.
2. CloudWatch must accept `rpcv2Cbor` (Go v2 and therefore Terraform), `awsJson1_0` (boto3, JS v3, and the AWS CLI, wire-confirmed by G1), and `awsQuery` (older Go, Java, other tooling). It needs a CBOR codec in the standard library only (no CBOR dependency is permitted by the brief; an ADR is needed if a library is wanted, otherwise write a small CBOR encoder/decoder for the subset in the Smithy RPC v2 spec: maps, arrays, text, bytes, integers, floats, bool, null; timestamps are CBOR tag 1 epoch-seconds with millisecond resolution; decoders must accept half-precision floats, [Smithy RPC v2 CBOR](https://github.com/smithy-lang/smithy/blob/main/docs/source-2.0/additional-specs/protocols/smithy-rpc-v2-cbor.rst)). Emit the `x-amzn-query-error` header and the legacy error codes (`ResourceNotFound`, `ValidationError`, ...) on JSON and CBOR responses. Route by `Smithy-Protocol` header + path `/service/GraniteServiceVersion20100801/operation/<Op>`.
3. Error serialization: `__type` = shape name for 1.1 services; clients accept `Message`/`message`. Use `Message` for Secrets Manager (AWS-REC) and match each service's observed casing in the generated serializer tests.
4. Generated validation must emit the Smithy-constraint message shape `N validation error(s) detected: Value 'x' at 'path' failed to satisfy constraint: ...` with the service-specific path style (`targets.1.member.id` for EventBridge, `limit` for Logs). Corrected by gap G7, 2026-10-08: `MetricData.member.1.Value` is not a validation path; it is the Query parameter name inside CloudWatch's hand-written `InvalidParameterCombination` text (https://github.com/localstack/localstack/blob/8b9a79f05846835cf4dff63ab7eefdde9df83783/tests/aws/services/cloudwatch/test_cloudwatch.snapshot.json#L222). The recorded CloudWatch Coral path is lowerCamel, `stateValue` (https://github.com/localstack/localstack/blob/8b9a79f05846835cf4dff63ab7eefdde9df83783/tests/aws/services/cloudwatch/test_cloudwatch.snapshot.json#L156), and the list-element form for CloudWatch is UNVERIFIED. Full grammar and path styles: [error-matrix.md](error-matrix.md) section 4.

**Secrets Manager**
5. Model a secret as: `{name, arn(suffix), createdDate, lastChangedDate, lastAccessedDate?, description?, kmsKeyId?, tags, resourcePolicy?, deletedDate?, versions: map[VersionId]Version, stages: map[Label]VersionId}` where stage ownership is a map from label to a single VersionId (makes "label on two versions" unrepresentable) and a version's labels are derived. Enforce: at most one holder per label, `AWSCURRENT` never removable, `AWSPREVIOUS` maintained automatically on every `AWSCURRENT` move, 20-label and 100-version caps. Implement the observed "AWSPENDING dropped from a demoted version" behavior behind a documented rule and a regression test from section 2.2.
6. Idempotency: key on `(secret, ClientRequestToken)`; equal payload -> replay of the original response; different payload -> `ResourceExistsException`; absent token -> `InvalidRequestException` "You must provide a ClientRequestToken value. We recommend a UUID-type value.". The mismatch message text is UNVERIFIED (section 2.3); keep it in one constants table so it can change in one place.
7. Deletion on the emulator clock: store `deletedDate = now + window`; a background purge task keyed on the clock removes the secret when `clock.Now() >= deletedDate`; force delete removes immediately; `RestoreSecret` clears it; name reuse is blocked until purge with the recorded `InvalidRequestException`. Resource-policy, tag, value, and stage-mutating calls must fail with "marked for deletion" while scheduled; DescribeSecret and ListSecrets(`IncludePlannedDeletion`) still show it.
8. Secret values are encrypted with the KMS module (brief): store the ciphertext plus key id; `GetSecretValue` calls the KMS decrypt path so a disabled or scheduled-for-deletion key produces `DecryptionFailure`/`EncryptionFailure`. Never log `SecretString`, `SecretBinary` or `RotationToken` (brief security default); the journal must redact them.
9. ListSecrets filter engine: implement the seven filter keys and `!` negation with the documented case rules; order by `created-date asc` by default; pagination tokens opaque and stable.
10. Terraform compatibility checklist: DescribeSecret must keep working on deleted secrets; GetResourcePolicy returns no `ResourcePolicy` key when unset; `UpdateSecretVersionStage` removal of non-current labels works; `Tags` appears only after the first tag and becomes `[]` after the last is removed.

**CloudWatch Logs**
11. Store events per stream in a timestamp-ordered structure with `ingestionTime` and a monotonically increasing `eventId` (56-digit decimal string). `GetLogEvents` tokens: `f/<56 digits>` and `b/<56 digits>` encoding the position; at end return the same token; reject malformed tokens with "The specified nextToken is invalid.".
12. PutLogEvents: check order first (reject whole batch), then per-event too-new / too-old / expired classification producing `rejectedLogEventsInfo` indexes (old = exclusive end index, new = inclusive start index), then the 24-hour span rule; keep valid events; always return a `nextSequenceToken`. Retention reads the emulator clock, so `understudy clock advance` exercises retention deterministically. G4 correction: the 14-day and 2-hour windows judge a client-supplied timestamp that containers stamp with wall time, so an event is accepted if it is inside the window against the wall clock OR the emulator clock (emulator-originated Lambda lines are stamped with the emulator clock and skip the windows); an emulator-only window silently drops all container events when the clock is frozen more than 2 hours before wall time or advanced more than 14 days ([lambda-runtime-contract.md](lambda-runtime-contract.md) section 3 row 8, [PutLogEvents](https://docs.aws.amazon.com/AmazonCloudWatchLogs/latest/APIReference/API_PutLogEvents.html)); run the retention sweep as a clock-driven task (the "72 hours" laziness of real AWS is intentionally not reproduced and should be documented as an intentional deviation).
13. FilterLogEvents needs a real filter-pattern compiler: parse unstructured (terms, phrases, `-`, `?`), JSON (`{ }` with selectors, wildcards, `IS`, `NOT EXISTS`, `&&`/`||`), space-delimited (`[ ... ]`), and `%regex%` (RE2 syntax is a close fit for the supported subset: no groups, add the `\d \s \w \xhh` set, reject `(`). Parse once into an ADT (`Pattern = Terms | JSON | Delimited`), errors as values. Property tests: parser round-trips on generated patterns, `-term` is the complement of `term`, `A && B` equals `B && A`, precedence matches `()` > `&&` > `||`. Gap G3 narrowed Q1: implement the grammar and vectors in [logs-filter-patterns.md](logs-filter-patterns.md) now, with the term test (substring working rule) and the space-delimited field-count rule each behind one function until the recording script in that file's section 9 is run.
14. DescribeLogGroups must return both `arn` (with `:*`) and `logGroupArn`; omit `retentionInDays` when unset; `DescribeLogStreams` omits `firstEventTimestamp`, `lastEventTimestamp`, `lastIngestionTime`, `uploadSequenceToken` until the first event arrives.
15. Lambda integration: auto-create `/aws/lambda/<function>` and a per-container stream on first log line; the Lambda owner must define the stream-name format (Q6).

**EventBridge**
16. Scheduler: one clock-driven min-heap of (nextFireAt, rule). `rate` fires first at creation + interval; `cron` fires on wall-clock minute matches in UTC. Validate expressions at PutRule with the single AWS message ("Parameter ScheduleExpression is not valid."). Reject schedule on a non-default bus. Reuse section 4.2's accepted/rejected lists as table tests, plus property tests: a generated cron that matches at time T is matched again exactly at the next matching minute.
17. Event pattern engine: implement Event Ruler semantics as a pure function `Match(pattern, event) bool` with a compiled `Pattern` ADT covering every operator in 4.4, array-consistent object matching, dotted-key joining, `$or` combination cap of 1000, wildcard complexity rule. Reuse for SNS with an operator allow-list. Compile at PutRule (reject with `InvalidEventPatternException` and the recorded messages). Build the conformance suite from the AWS-validated fixtures (`_NEG`, `_EXC` naming) after license confirmation; also run `TestEventPattern` as an API to expose the matcher directly.
18. Targets: enforce 5 per rule, unique `Id`, the Input/InputPath/InputTransformer exclusivity, and placeholder validation at PutTargets; deliver to Lambda (async invoke), SQS (body = JSON text; FIFO needs `MessageGroupId`), SNS (publish JSON text). Each delivery is a journal edge (rule -> target) with the event id, enabling the causal journal in the brief. IAM is not enforced in phase 1; record `events:PutEvents`-style access in the recorder.
19. InputTransformer evaluator: JSONPath subset (dot, index, `*`, `/`), reserved variables, string vs JSON placement rules, auto-quoting of strings, quote-stripping of structured values in string templates, missing path -> empty string. Table-test against section 4.6 examples; add a property test that for any event the output of a JSON-object template parses as JSON.
20. PutEvents: validate per-entry (`InvalidArgument` / `MalformedDetail` / delivery of valid entries), whole-request size and count errors, generate one uuid used for both `EventId` and delivered `id`, drop events for unknown buses with HTTP 200, build the delivered envelope exactly as in 4.7.

**CloudWatch metrics and alarms**
21. Store alarms verbatim (all `PutMetricAlarm` fields including `Metrics`, `EvaluationCriteria`, `WarmUpConfiguration`) and echo them; synthesize `AlarmArn`, `AlarmConfigurationUpdatedTimestamp`, `StateReason` "Unchecked: Initial alarm creation", `StateValue` `INSUFFICIENT_DATA`, `StateUpdatedTimestamp`, `StateTransitionedTimestamp`; keep empty action arrays and `Dimensions: []` present. PutMetricAlarm on an existing alarm preserves state and tags.
22. Metrics store: keyed by (namespace, metric name, dimension set, unit); `GetMetricData` aggregates by period with the five statistics; implement the clock-rounding rule for `StartTime` and default descending order; keep it behind a small interface so a later alarm evaluator can read it.
23. Fail loudly with AWS-shaped "not implemented" errors for composite alarms, Metrics Insights, anomaly detection, dashboards, metric streams, and alarm history.

**Platform features**
24. Fault injection should be able to target the specific throttle and limit errors catalogued above (`LimitExceededException`, `ThrottlingException`, `InvalidNextToken`, per-entry PutEvents errors); the journal should record dropped PutEvents (unknown bus) and rejected log events.
25. Snapshots must include the deletion schedule (Secrets Manager), the scheduler's `nextFireAt` per rule and log retention state so that `clock advance` after a snapshot restore behaves identically.
