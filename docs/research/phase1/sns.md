# Amazon SNS semantics for an emulator

Primary-source research for understudy phase 1. Scope: topics, subscriptions, Publish and PublishBatch, delivery formats (SQS envelope, raw, FIFO, Lambda event, HTTP), the complete filter policy grammar, delivery retries and subscription DLQs.

## 1. Wire protocol (awsQuery)

- Request: `POST /`, `Content-Type: application/x-www-form-urlencoded`, body has `Action` and `Version=2010-03-31` ([Smithy awsQuery](https://smithy.io/2.0/aws/protocols/aws-query-protocol.html)). Lists serialize as `Name.member.N`, maps as `Name.entry.N.key` and `Name.entry.N.value`, N starting at 1 ([Smithy awsQuery](https://smithy.io/2.0/aws/protocols/aws-query-protocol.html)). Actions may also arrive as `GET /?Action=...` (the `SubscribeURL` and `UnsubscribeURL` in messages are GET URLs) ([HTTP confirmation format](https://docs.aws.amazon.com/sns/latest/dg/http-subscription-confirmation-json.html)).
- SNS-specific names from the model ([sns-2010-03-31.json](https://github.com/aws/api-models-aws/blob/1cfdfb4bb9ea858e65623e66d73af04bec353201/models/sns/service/2010-03-31/sns-2010-03-31.json)):
  - `MessageAttributes` is a map with `xmlName` `Name` (key) and `Value` (value): `MessageAttributes.entry.1.Name=k&MessageAttributes.entry.1.Value.DataType=String&MessageAttributes.entry.1.Value.StringValue=v`; `BinaryValue` is a base64 blob ([API_Publish](https://docs.aws.amazon.com/sns/latest/api/API_Publish.html), [API_MessageAttributeValue](https://docs.aws.amazon.com/sns/latest/api/API_MessageAttributeValue.html)).
  - `Attributes` (CreateTopic, Subscribe) and `AttributeName`/`AttributeValue` (Set*Attributes) use default `entry`/`key`/`value` naming: `Attributes.entry.1.key=FilterPolicy&Attributes.entry.1.value=...`.
  - `Tags.member.N.Key` / `Tags.member.N.Value`; `PublishBatchRequestEntries.member.N.Id`, `.Message`, `.MessageAttributes.entry.M.Name`, ...; `AWSAccountId.member.N` and `ActionName.member.N` for AddPermission.
  - The model lists no `xmlFlattened` on these collections, so every list uses the `.member.N` form.
- Success response: `<{Action}Response xmlns="..."><{Action}Result>...</{Action}Result><ResponseMetadata><RequestId>uuid</RequestId></ResponseMetadata></{Action}Response>`; actions with no output return `<{Action}Response>` with only `ResponseMetadata` ([Smithy awsQuery](https://smithy.io/2.0/aws/protocols/aws-query-protocol.html)). Namespace: the model and botocore say `http://sns.amazonaws.com/doc/2010-03-31/` ([botocore](https://github.com/boto/botocore/blob/develop/botocore/data/sns/2010-03-31/service-2.json)); the API Reference examples print `https://sns.amazonaws.com/doc/2010-03-31/` ([API_Publish](https://docs.aws.amazon.com/sns/latest/api/API_Publish.html)). ## 2. Topics

### 2.1 CreateTopic

- Name: 1 to 256 characters of `[A-Za-z0-9_-]`; FIFO names must end `.fifo` ([Smithy CreateTopic](https://github.com/aws/api-models-aws/blob/1cfdfb4bb9ea858e65623e66d73af04bec353201/models/sns/service/2010-03-31/sns-2010-03-31.json)). Terraform's own pre-check uses `^[0-9A-Za-z_-]{1,256}$` and `^[0-9A-Za-z_-]{1,251}\.fifo$` ([topic.go](https://github.com/hashicorp/terraform-provider-aws/blob/main/internal/service/sns/topic.go)). Violations return `InvalidParameter` `Invalid parameter: Topic Name` (too short, too long, bad char, `.fifo` suffix on a non-FIFO topic, missing suffix on a FIFO topic); AWS-recorded 2026-02-06 ([snapshot test_create_topic_name_constraints](https://github.com/localstack/localstack/blob/main/tests/aws/services/sns/test_sns.snapshot.json)).
- Idempotent: an existing topic with the same name returns its ARN without creating a new one ([Smithy CreateTopic](https://github.com/aws/api-models-aws/blob/1cfdfb4bb9ea858e65623e66d73af04bec353201/models/sns/service/2010-03-31/sns-2010-03-31.json)). Different attributes on repeat: `InvalidParameter` `Invalid parameter: Attributes Reason: Topic already exists with different attributes`; different tags: `Invalid parameter: Tags Reason: Topic already exists with different tags`; AWS-recorded 2026-02-06 and 2025-10-13 ([snapshots test_create_topic_different_attrs, test_create_duplicate_topic_with_more_tags](https://github.com/localstack/localstack/blob/main/tests/aws/services/sns/test_sns.snapshot.json)). A repeated `FifoTopic=false` on an existing standard topic is accepted (AWS does not store an explicit false) ([LocalStack provider.py, comment](https://github.com/localstack/localstack/blob/main/localstack-core/localstack/services/sns/provider.py)); UNVERIFIED beyond that comment.
- ARN: `arn:{partition}:sns:{region}:{account}:{name}`. Limits: 100,000 standard topics, 1,000 FIFO topics per account ([Smithy CreateTopic](https://github.com/aws/api-models-aws/blob/1cfdfb4bb9ea858e65623e66d73af04bec353201/models/sns/service/2010-03-31/sns-2010-03-31.json)); error `TopicLimitExceeded` 403.
- `FifoTopic` is accepted only at CreateTopic; `SetTopicAttributes` with `AttributeName=FifoTopic` fails `Invalid parameter: AttributeName`; AWS-recorded 2025-09-29 ([snapshot test_topic_get_attributes_with_fifo_false](https://github.com/localstack/localstack/blob/main/tests/aws/services/sns/test_sns.snapshot.json)). Terraform passes `FifoTopic` and `FifoThroughputScope` in CreateTopic and everything else through one `SetTopicAttributes` call per attribute ([topic.go](https://github.com/hashicorp/terraform-provider-aws/blob/main/internal/service/sns/topic.go)).

### 2.2 Topic attributes

Settable (CreateTopic `Attributes`, `SetTopicAttributes`) per the model ([Smithy](https://github.com/aws/api-models-aws/blob/1cfdfb4bb9ea858e65623e66d73af04bec353201/models/sns/service/2010-03-31/sns-2010-03-31.json)):

| Attribute | Notes |
|---|---|
| `DisplayName` | string |
| `Policy` | JSON access policy; stored |
| `DeliveryPolicy` | JSON; HTTP/S retry policy (section 7.3) |
| `MaximumMessageSize` | 1024 to 1048576, default 262144; above 256 KiB the topic must have 100 or fewer subscriptions, all SQS, Firehose or Lambda, else `InvalidParameter` |
| `SignatureVersion` | `1` default (SHA1withRSA) or `2` (SHA256withRSA); absent from GetTopicAttributes means 1 |
| `TracingConfig` | `PassThrough` (default) or `Active`; standard topics only |
| `KmsMasterKeyId` | SSE key |
| `{HTTP,Firehose,Lambda,Application,SQS}{Success,Failure}FeedbackRoleArn`, `...SuccessFeedbackSampleRate` (0-100) | delivery status logging |
| `ContentBasedDeduplication` | FIFO only; default `false` |
| `FifoThroughputScope` | FIFO only; `Topic` (default) or `MessageGroup` |
| `ArchivePolicy` | FIFO only |
| `FifoTopic` | create only |

- Returned by GetTopicAttributes ([Smithy GetTopicAttributes](https://github.com/aws/api-models-aws/blob/1cfdfb4bb9ea858e65623e66d73af04bec353201/models/sns/service/2010-03-31/sns-2010-03-31.json)): `DeliveryPolicy`, `DisplayName`, `EffectiveDeliveryPolicy`, `MaximumMessageSize` (only if explicitly set), `Owner`, `Policy`, `SignatureVersion`, `SubscriptionsConfirmed`, `SubscriptionsDeleted`, `SubscriptionsPending`, `TopicArn`, `TracingConfig`, `KmsMasterKeyId`, FIFO: `ArchivePolicy`, `BeginningArchiveTime`, `ContentBasedDeduplication`, `FifoTopic`.
- AWS-recorded defaults for a new standard topic (all values strings): `DisplayName` `""`, `Owner`, `Policy` (default policy below), `EffectiveDeliveryPolicy` (below), `SubscriptionsConfirmed`/`SubscriptionsDeleted`/`SubscriptionsPending` `"0"`, `TopicArn`; no `FifoTopic` key on a standard topic. A FIFO topic adds `FifoTopic` `"true"` and `ContentBasedDeduplication` `"false"` ([snapshots test_topic_get_attributes_with_fifo_false, test_create_topic_with_attributes](https://github.com/localstack/localstack/blob/main/tests/aws/services/sns/test_sns.snapshot.json), validated 2025-09-25 and 2025-12-17).
- Default `Policy` (JSON string; snapshots show it parsed):

```json
{"Version":"2008-10-17","Id":"__default_policy_ID","Statement":[{"Sid":"__default_statement_ID","Effect":"Allow","Principal":{"AWS":"*"},"Action":["SNS:GetTopicAttributes","SNS:SetTopicAttributes","SNS:AddPermission","SNS:RemovePermission","SNS:DeleteTopic","SNS:Subscribe","SNS:ListSubscriptionsByTopic","SNS:Publish"],"Resource":"<topic-arn>","Condition":{"StringEquals":{"AWS:SourceOwner":"<account>"}}}]}
```

  Terraform's `aws_sns_topic_policy` destroy resets to the same text plus `"SNS:Receive"` in `Action` ([topic_policy.go](https://github.com/hashicorp/terraform-provider-aws/blob/main/internal/service/sns/topic_policy.go)); both forms must round-trip.
- Default `EffectiveDeliveryPolicy` (AWS-recorded):

```json
{"http":{"defaultHealthyRetryPolicy":{"minDelayTarget":20,"maxDelayTarget":20,"numRetries":3,"numMaxDelayRetries":0,"numNoDelayRetries":0,"numMinDelayRetries":0,"backoffFunction":"linear"},"disableSubscriptionOverrides":false,"defaultRequestPolicy":{"headerContentType":"text/plain; charset=UTF-8"}}}
```

- Topic `DeliveryPolicy` round trip, AWS-recorded 2024-10-03 ([snapshot test_topic_delivery_policy_crud](https://github.com/localstack/localstack/blob/8b9a79f05846835cf4dff63ab7eefdde9df83783/tests/aws/services/sns/test_sns.snapshot.json), [validation date](https://github.com/localstack/localstack/blob/8b9a79f05846835cf4dff63ab7eefdde9df83783/tests/aws/services/sns/test_sns.validation.json)): setting `{"http":{"defaultRequestPolicy":{"headerContentType":"application/json"}}}` reads back as `DeliveryPolicy` with `"disableSubscriptionOverrides":false` injected into `http`; `EffectiveDeliveryPolicy` is the default policy overlaid with the user's keys (an unset `defaultHealthyRetryPolicy` stays at the 20 s / 3 retries / linear default; a partial `defaultHealthyRetryPolicy` such as `{"minDelayTarget":5,"maxDelayTarget":6,"numRetries":1}` gets the missing members `numMaxDelayRetries`, `numNoDelayRetries`, `numMinDelayRetries` = 0 and `backoffFunction` = `linear` filled in in the effective policy only). Each SetTopicAttributes call replaces the whole stored `DeliveryPolicy` rather than merging: after the second write the earlier `defaultRequestPolicy` was gone and the effective `headerContentType` was back to `text/plain; charset=UTF-8`. Setting `{"http":{"defaultHealthyRetryPolicy":null}}` leaves `DeliveryPolicy` = `{"http":{"disableSubscriptionOverrides":false}}`. Setting `DeliveryPolicy` to the empty string removes the attribute from GetTopicAttributes entirely while `EffectiveDeliveryPolicy` remains.
- Terraform reads topic attributes through GetTopicAttributes and maps missing keys to null (`WithMissingSetToNil("*")`), requires `Policy` principals to be an account id or ARN (`*` allowed), and treats `NotFound` on read as deleted ([topic.go](https://github.com/hashicorp/terraform-provider-aws/blob/main/internal/service/sns/topic.go)). Setting `Policy` to the empty string is skipped client-side; Terraform comment states a policy cannot be deleted or set empty ([topic_policy.go](https://github.com/hashicorp/terraform-provider-aws/blob/main/internal/service/sns/topic_policy.go)).
- Unknown topic: `NotFound`, 404, message `Topic does not exist`; AWS-recorded ([snapshot test_create_topic_with_attributes](https://github.com/localstack/localstack/blob/main/tests/aws/services/sns/test_sns.snapshot.json)).
- DeleteTopic is idempotent (deleting a missing topic returns 200) and deletes its subscriptions ([Smithy DeleteTopic](https://github.com/aws/api-models-aws/blob/1cfdfb4bb9ea858e65623e66d73af04bec353201/models/sns/service/2010-03-31/sns-2010-03-31.json); AWS-recorded in [snapshot test_delete_topic_idempotency](https://github.com/localstack/localstack/blob/main/tests/aws/services/sns/test_sns.snapshot.json)). After DeleteTopic its subscriptions stay readable through GetSubscriptionAttributes and removable by Unsubscribe (AWS-recorded in [snapshot test_delete_subscriptions_on_delete_topic](https://github.com/localstack/localstack/blob/main/tests/aws/services/sns/test_sns.snapshot.json)). How long they stay, about 48 hours, comes from a LocalStack comment ([provider.py](https://github.com/localstack/localstack/blob/main/localstack-core/localstack/services/sns/provider.py)) and is UNVERIFIED.
- ListTopics: pages of up to 100 with `NextToken` ([API_ListTopics](https://docs.aws.amazon.com/sns/latest/api/API_ListTopics.html)).

### 2.3 Tags and permissions

- TagResource, UntagResource, ListTagsForResource take `ResourceArn`; `Tag.Key` 1 to 128 chars, `Tag.Value` 0 to 256 ([API_Tag](https://docs.aws.amazon.com/sns/latest/api/API_Tag.html)). Limit 50 tags per topic, error `TagLimitExceeded` ([Smithy](https://github.com/aws/api-models-aws/blob/1cfdfb4bb9ea858e65623e66d73af04bec353201/models/sns/service/2010-03-31/sns-2010-03-31.json)). Duplicate keys in one request: `InvalidParameter` `Invalid parameter: Duplicated keys are not allowed.`; tag update replaces a value; AWS-recorded 2025-10-13 ([snapshot test_tags](https://github.com/localstack/localstack/blob/main/tests/aws/services/sns/test_sns.snapshot.json)). Tags can be sent in CreateTopic (needs `sns:CreateTopic` and `sns:TagResource`) ([Smithy CreateTopic](https://github.com/aws/api-models-aws/blob/1cfdfb4bb9ea858e65623e66d73af04bec353201/models/sns/service/2010-03-31/sns-2010-03-31.json)).
- AddPermission (`Label`, `AWSAccountId.member.N`, `ActionName.member.N`) appends a statement `{"Sid":label,"Effect":"Allow","Principal":{"AWS":"arn:aws:iam::<acct>:root"},"Action":"SNS:<name>","Resource":topic}`; single-element principals and actions are scalars, multiple are arrays. Errors: duplicate Sid `Invalid parameter: Statement already exists`; action outside `GetTopicAttributes, SetTopicAttributes, AddPermission, RemovePermission, DeleteTopic, Subscribe, ListSubscriptionsByTopic, Publish, Receive` gives `Invalid parameter: Policy statement action out of service scope!`; missing topic `NotFound`. Errors AWS-recorded 2025-12-11; the statement shape is from [LocalStack provider.py](https://github.com/localstack/localstack/blob/main/localstack-core/localstack/services/sns/provider.py) and is UNVERIFIED against a recorded Policy string. RemovePermission removes by Sid.
- IAM is not enforced in phase 1 (brief), so topic policies and SQS queue policies are stored, never evaluated.

## 3. Subscriptions

### 3.1 Subscribe

- Protocols: `http`, `https`, `email`, `email-json`, `sms`, `sqs`, `application`, `lambda`, `firehose` ([Smithy Subscribe](https://github.com/aws/api-models-aws/blob/1cfdfb4bb9ea858e65623e66d73af04bec353201/models/sns/service/2010-03-31/sns-2010-03-31.json)). Anything else: `Invalid parameter: Amazon SNS does not support this protocol string: test-protocol`; AWS-recorded 2025-10-06 ([snapshot test_subscribe_with_invalid_protocol](https://github.com/localstack/localstack/blob/main/tests/aws/services/sns/test_sns.snapshot.json)).
- Endpoint validation, AWS-recorded: `sqs` with a queue URL or any non-ARN gives `Invalid parameter: SQS endpoint ARN`; a well-formed ARN of a queue that does not exist is accepted and returns a subscription ARN (2025-10-06) ([snapshots test_subscribe_unknown_sqs_queue, test_subscribe_sqs_queue_url](https://github.com/localstack/localstack/blob/main/tests/aws/services/sns/test_sns.snapshot.json)). Unknown topic: `NotFound` `Topic does not exist` (404). A FIFO queue endpoint on a standard topic: `Invalid parameter: Invalid parameter: Endpoint Reason: FIFO SQS Queues can not be subscribed to standard SNS topics` (the doubled prefix is real; recorded 2025-08-18) ([snapshot test_validations_for_fifo](https://github.com/localstack/localstack/blob/main/tests/aws/services/sns/test_sns.snapshot.json)).
- `sms` endpoints must be E.164: `InvalidParameter` `Invalid SMS endpoint: {endpoint}` for `+15--551234567`, `NAA+15551234567`, `+15551234567.`, `/+15551234567` and `invalid-number`; AWS-recorded 2025-10-06 ([snapshots test_subscribe_invalid_sms, test_subscribe_bad_sms](https://github.com/localstack/localstack/blob/8b9a79f05846835cf4dff63ab7eefdde9df83783/tests/aws/services/sns/test_sns.snapshot.json), [validation dates](https://github.com/localstack/localstack/blob/8b9a79f05846835cf4dff63ab7eefdde9df83783/tests/aws/services/sns/test_sns.validation.json)). Publish to a bad `PhoneNumber` fails `Invalid parameter: PhoneNumber Reason: {number} is not valid to publish to` (recorded 2025-12-02, [snapshot test_publish_wrong_phone_format](https://github.com/localstack/localstack/blob/8b9a79f05846835cf4dff63ab7eefdde9df83783/tests/aws/services/sns/test_sns.snapshot.json)).
- Endpoint checks seen only in LocalStack code, UNVERIFIED against AWS: `http`/`https` endpoint must start with `{protocol}://` (`Invalid parameter: Endpoint must match the specified protocol`); `application` must be an ARN ([provider.py](https://github.com/localstack/localstack/blob/main/localstack-core/localstack/services/sns/provider.py)).
- Unconfirmed subscriptions are deleted automatically after 48 hours, except email/email-json subscriptions that SNS suspended for exceeding 10 messages per second, which stay `PendingConfirmation` for 30 days ([email doc](https://docs.aws.amazon.com/sns/latest/dg/sns-email-notifications.html)). Quotas: 5,000 pending subscriptions per account; standard topics 12,500,000 subscriptions per topic, FIFO topics 100 per topic; 200 filter policies per topic; PublishBatch 10 entries; default message size 262,144 bytes ([General Reference quotas](https://docs.aws.amazon.com/general/latest/gr/sns.html)).
- Idempotent per (topic, endpoint): a second Subscribe with the same endpoint returns the existing ARN; passing a differing value for an attribute that is already set fails `Invalid parameter: Attributes Reason: Subscription already exists with different attributes`; passing no attributes, or attributes equal to the existing ones, succeeds; AWS-recorded 2025-10-06 ([snapshot test_subscribe_idempotency](https://github.com/localstack/localstack/blob/main/tests/aws/services/sns/test_sns.snapshot.json)). Whether protocol participates in the identity is UNVERIFIED.
- Subscription ARN: `{topic-arn}:{uuid}`.
- Confirmation rules: "If the endpoint type is HTTP/S or email, or if the endpoint and the topic are not in the same Amazon Web Services account, the endpoint owner must run the ConfirmSubscription action"; tokens are valid for two days ([Smithy Subscribe](https://github.com/aws/api-models-aws/blob/1cfdfb4bb9ea858e65623e66d73af04bec353201/models/sns/service/2010-03-31/sns-2010-03-31.json)). Same-account SQS and Lambda subscriptions are confirmed on return: GetSubscriptionAttributes gives `PendingConfirmation` `"false"` and `ConfirmationWasAuthenticated` `"true"` (AWS-recorded 2025-10-06, [snapshot test_create_subscriptions_with_attributes](https://github.com/localstack/localstack/blob/main/tests/aws/services/sns/test_sns.snapshot.json)). ## 4. Publish and PublishBatch

### 4.1 Publish input rules

- Target: exactly one of `TopicArn`, `TargetArn`, `PhoneNumber`. Publishing with `TargetArn` set to a topic ARN works ([LocalStack provider.py comment](https://github.com/localstack/localstack/blob/main/localstack-core/localstack/services/sns/provider.py); UNVERIFIED but exercised by test_publish_message_by_target_arn, validated). Endpoint ARNs (`...:endpoint/...`) are mobile push, out of scope.
- `Message`: required, UTF-8, non-empty (`Invalid parameter: Empty message`, recorded 2025-11-19). Size: the sum of message body bytes plus, for each attribute, name bytes plus DataType bytes plus value bytes, must not exceed the topic's `MaximumMessageSize` (default 262144 bytes) ([attributes doc](https://docs.aws.amazon.com/sns/latest/dg/sns-message-attributes.html), [Smithy Publish](https://github.com/aws/api-models-aws/blob/1cfdfb4bb9ea858e65623e66d73af04bec353201/models/sns/service/2010-03-31/sns-2010-03-31.json)). Over the limit: `InvalidParameter` `Invalid parameter: Message too long`, including a body of exactly 262144 minus attribute bytes plus one; recorded 2025-11-19 ([snapshot test_publish_too_long_message](https://github.com/localstack/localstack/blob/main/tests/aws/services/sns/test_sns.snapshot.json)).
- `Subject`: UTF-8, no line breaks or control characters, under 100 characters; empty string fails `InvalidParameter` `Invalid parameter: Subject` (recorded 2025-11-19) ([Smithy Publish](https://github.com/aws/api-models-aws/blob/1cfdfb4bb9ea858e65623e66d73af04bec353201/models/sns/service/2010-03-31/sns-2010-03-31.json), [snapshot test_publish_with_empty_subject](https://github.com/localstack/localstack/blob/main/tests/aws/services/sns/test_sns.snapshot.json)). Error text for an over-length or control-character subject is UNVERIFIED.
- `MessageStructure=json`: `Message` must be a JSON object with a string-valued top-level `default` key; other keys are protocol names (`sqs`, `lambda`, `http`, `https`, `email`, `email-json`, `sms`, `firehose`, platform names); non-string values cause the key to be ignored; unknown keys ignored; duplicate keys not allowed; any parse failure fails the whole call with no partial delivery; values are unescaped before use and re-escaped on output ([Smithy Publish](https://github.com/aws/api-models-aws/blob/1cfdfb4bb9ea858e65623e66d73af04bec353201/models/sns/service/2010-03-31/sns-2010-03-31.json)). AWS-recorded errors (recorded 2025-11-19): unparsable `Invalid parameter: Message Structure - JSON message body failed to parse`; missing or non-string default `Invalid parameter: Message Structure - No default entry in JSON message body` ([snapshot test_message_structure_json_exc](https://github.com/localstack/localstack/blob/main/tests/aws/services/sns/test_sns.snapshot.json)). Delivery picks `message[protocol]` else `message["default"]`; for an SQS subscription the raw SQS body is that string ([snapshot test_message_structure_json_to_sqs](https://github.com/localstack/localstack/blob/main/tests/aws/services/sns/test_sns.snapshot.json)). Attributes are sent only with `MessageStructure` string, "not JSON" ([attributes doc](https://docs.aws.amazon.com/sns/latest/dg/sns-message-attributes.html)); the doc's wording is ambiguous about SQS and UNVERIFIED in effect.
- Returns `MessageId` (UUID, max 100 chars) and, for FIFO topics only, `SequenceNumber` ([Smithy PublishResponse](https://github.com/aws/api-models-aws/blob/1cfdfb4bb9ea858e65623e66d73af04bec353201/models/sns/service/2010-03-31/sns-2010-03-31.json)). "When a messageId is returned, the message is saved and Amazon SNS immediately delivers it to subscribers": delivery is asynchronous to the API call ([same](https://github.com/aws/api-models-aws/blob/1cfdfb4bb9ea858e65623e66d73af04bec353201/models/sns/service/2010-03-31/sns-2010-03-31.json)).

### 4.2 Message attributes

- Types: `String`, `String.Array`, `Number`, `Binary`; custom suffix labels allowed (`Number.int`, `String.Array`); the type prefix must be `String`, `Number` or `Binary` ([attributes doc](https://docs.aws.amazon.com/sns/latest/dg/sns-message-attributes.html)). `String.Array` value is a JSON array string whose elements are strings, numbers, `true`, `false` or `null`. `Number`: -10^9 to 10^9 with 5 digits after the decimal point, leading/trailing zeros trimmed (docs; see section 9 for a conflict).
- Name: `[A-Za-z0-9_.-]`, up to 256, not starting or ending with `.`, no `..`, case-sensitive, unique, must not start with `AWS.` or `Amazon.` in any casing ([attributes doc](https://docs.aws.amazon.com/sns/latest/dg/sns-message-attributes.html)). Surrogate characters are rejected with `Invalid attribute value was passed in for message attribute` (same doc; exact code UNVERIFIED).
- AWS-recorded errors, all `ParameterValueInvalid` 400 Sender (batch uses identical text), 2024-11-15 ([snapshot test_empty_or_wrong_message_attributes](https://github.com/localstack/localstack/blob/main/tests/aws/services/sns/test_sns.snapshot.json)):
  - empty string or binary value: `The message attribute 'attr1' must contain non-empty message attribute value for message attribute type 'String'.` (or `'Binary'`)
  - wrong value field: `The message attribute 'attr1' with type 'String' must use field 'String'.` (`'Number'` also `'String'`; `'Binary'` `must use field 'Binary'`)
  - bad type prefix: `The message attribute 'attr1' has an invalid message attribute type, the set of supported type prefixes is Binary, Number, and String.`
  - name > 256: `Length of message attribute name must be less than 256 bytes.`
  - bad character: `Invalid non-alphanumeric character '#x5E' was found in the message attribute name. Can only include alphanumeric characters, hyphens, underscores, or dots.`
  - `Invalid message attribute name starting with character '.' was found.`, `... ending with character '.' was found.`, `Message attribute name can not have successive '.' character.`
  - missing DataType: Code `ValidationError`, text in section 1.
- Not recorded: Number value that is not numeric, `AWS.`/`Amazon.` prefix rejection text, attribute count cap on Publish. ### 4.3 FIFO publish

AWS-recorded errors (2025-08-18): no group `Invalid parameter: The MessageGroupId parameter is required for FIFO topics`; no dedup id and no content dedup `Invalid parameter: The topic should either have ContentBasedDeduplication enabled or MessageDeduplicationId provided explicitly`; `MessageDeduplicationId` on a standard topic `Invalid parameter: MessageDeduplicationId Reason: The request includes MessageDeduplicationId parameter that is not valid for this topic type` ([snapshot test_validations_for_fifo](https://github.com/localstack/localstack/blob/main/tests/aws/services/sns/test_sns.snapshot.json)).

## 5. Delivery formats

### 5.1 SQS envelope (raw delivery disabled)

The SQS message body is the JSON document below. Field order as recorded from real AWS ([snapshots test_publish_sqs_from_sns, test_subscribe_sqs_queue, test_publish_before_subscribe](https://github.com/localstack/localstack/blob/main/tests/aws/services/sns/test_sns.snapshot.json), [docs](https://docs.aws.amazon.com/sns/latest/dg/sns-sqs-as-subscriber.html)):

```json
{
  "Type" : "Notification",
  "MessageId" : "63a3f6b6-d533-4a47-aef9-fcf5cf758c76",
  "TopicArn" : "arn:aws:sns:us-west-2:123456789012:MyTopic",
  "Subject" : "Testing publish to subscribed queues",
  "Message" : "Hello world!",
  "Timestamp" : "2012-03-29T05:12:16.901Z",
  "SignatureVersion" : "1",
  "Signature" : "EXAMPLEnTrFPa3...",
  "SigningCertURL" : "https://sns.us-west-2.amazonaws.com/SimpleNotificationService-f3ecfb7224c7233fe7bb5f59f96de52f.pem",
  "UnsubscribeURL" : "https://sns.us-west-2.amazonaws.com/?Action=Unsubscribe&SubscriptionArn=arn:aws:sns:us-west-2:123456789012:MyTopic:c7fe3a54-ab0e-4ec2-88e0-db410a0f2bee",
  "MessageAttributes" : {"attr1": {"Type": "Number", "Value": "99.12"}}
}
```

- `Subject` appears only when published with a Subject (between `TopicArn` and `Message`); `MessageAttributes` appears only when the publish had attributes, and is last. Each attribute is `{"Type": <DataType>, "Value": <StringValue>}`; Binary values are base64 strings, e.g. `{"Type":"Binary","Value":"AgME"}` for bytes 02 03 04 ([HTTP notification doc](https://docs.aws.amazon.com/sns/latest/dg/http-notification-json.html), recorded in [snapshot test_redrive_policy_sqs_queue_subscription](https://github.com/localstack/localstack/blob/main/tests/aws/services/sns/test_sns.snapshot.json)). Attribute order inside the map is not stable in AWS output (`attr2` before `attr1` recorded); do not assert on it.
- `Timestamp`: UTC, ISO 8601, exactly three fractional digits, `Z` suffix (`2012-03-29T05:12:16.901Z`) ([docs examples](https://docs.aws.amazon.com/sns/latest/dg/sns-sqs-as-subscriber.html)). `MessageId`: UUID of the SNS message; a retry reuses the original id ([HTTP notification doc](https://docs.aws.amazon.com/sns/latest/dg/http-notification-json.html)). `UnsubscribeURL`: `https://sns.<region>.amazonaws.com/?Action=Unsubscribe&SubscriptionArn=<subscription-arn>` (ampersand is a literal `&` in the SQS JSON).
- `SignatureVersion` is `"1"` or `"2"` per the topic attribute (AWS-recorded: `"2"` appears when the topic is set to 2, test validated 2024-01-04; [snapshot test_publish_sqs_verify_signature[2]](https://github.com/localstack/localstack/blob/main/tests/aws/services/sns/test_sns.snapshot.json)).
- The SQS message gets no SQS message attributes in this mode (attributes live inside the envelope). X-Ray header passthrough sets the SQS system attribute `AWSTraceHeader` ([snapshot test_publish_sqs_from_sns_with_xray_propagation](https://github.com/localstack/localstack/blob/main/tests/aws/services/sns/test_sns.snapshot.json)); optional for understudy.

### 5.2 Raw delivery (SQS, HTTP/S, Firehose)

- `RawMessageDelivery=true`: SNS metadata is stripped and the message is sent as is: the SQS body is exactly the `Message` string (after `MessageStructure` selection) ([raw delivery doc](https://docs.aws.amazon.com/sns/latest/dg/sns-large-payload-raw-message-delivery.html)). The `Subject` is dropped.
- Message attributes become SQS message attributes with the same `DataType`, `StringValue` or `BinaryValue` (AWS-recorded 2023-08: `{"DataType":"Number","StringValue":"111"}`, `{"DataType":"Binary","BinaryValue":...}`; [snapshots test_attribute_raw_subscribe, test_redrive_policy_sqs_queue_subscription[True]](https://github.com/localstack/localstack/blob/main/tests/aws/services/sns/test_sns.snapshot.json)). Limit: at most 10 attributes; more than 10 and the message is discarded as a client error, with no SQS message ([raw delivery doc](https://docs.aws.amazon.com/sns/latest/dg/sns-large-payload-raw-message-delivery.html)); whether it then goes to the subscription DLQ is UNVERIFIED.
- HTTP/S raw: body is the message, header `x-amz-sns-rawdelivery: true` is added, attributes are not sent. Firehose raw: body only ([raw delivery doc](https://docs.aws.amazon.com/sns/latest/dg/sns-large-payload-raw-message-delivery.html)).

### 5.3 FIFO topic to SQS

- Envelope for FIFO topics (AWS-recorded 2025-08-18): `Type`, `MessageId`, `SequenceNumber`, `TopicArn`, `Message`, `Timestamp`, `UnsubscribeURL`; no `SignatureVersion`, `Signature` or `SigningCertURL`; `Subject` and `MessageAttributes` as in 5.1 ([snapshots test_message_to_fifo_sqs[True], test_fifo_topic_to_regular_sqs[True]](https://github.com/localstack/localstack/blob/main/tests/aws/services/sns/test_sns.snapshot.json), validated 2025-08-18). The docs state the sequence number is in the body and absent under raw delivery ([ordering doc](https://docs.aws.amazon.com/sns/latest/dg/fifo-topic-message-ordering.html)).
- FIFO queue target: SNS sets SQS `MessageGroupId` to the publish group id and `MessageDeduplicationId` to the publish dedup id, or to the lowercase hex SHA-256 of the body for content-based dedup (recorded `532eaabd...0e345e25` for body `Test`). A standard SQS queue subscribed to a FIFO topic gets no group id.

### 5.4 Lambda event

SNS invokes the function asynchronously (`InvocationType=Event`) ([Lambda with SNS](https://docs.aws.amazon.com/lambda/latest/dg/with-sns.html)). Payload per the AWS-recorded snapshot (2025-10-06) differs from the SQS envelope in key casing and field presence ([snapshot test_python_lambda_subscribe_sns_topic](https://github.com/localstack/localstack/blob/main/tests/aws/services/sns/test_sns.snapshot.json), [aws-lambda-go events/sns.go](https://github.com/aws/aws-lambda-go/blob/main/events/sns.go)):

{"Records":[{"EventSource":"aws:sns","EventVersion":"1.0","EventSubscriptionArn":"arn:aws:sns:us-east-1:123456789012:topic:sub-uuid",
 "Sns":{"Type":"Notification","MessageId":"95df01b4-ee98-5cb9-9903-4c221d41eb5e","TopicArn":"arn:aws:sns:us-east-1:123456789012:topic","Subject":"TestInvoke","Message":"Hello from SNS!","Timestamp":"2019-01-02T12:45:07.000Z","SignatureVersion":"1","Signature":"...","SigningCertUrl":"https://sns.us-east-1.amazonaws.com/SimpleNotificationService-....pem","UnsubscribeUrl":"https://sns.us-east-1.amazonaws.com/?Action=Unsubscribe&SubscriptionArn=...","MessageAttributes":{"Test":{"Type":"String","Value":"TestString"}}}}]}

- `SignatureVersion` is always `"1"` in Lambda events even when the topic is set to `2`, yet a version 2 topic's Lambda event is signed with SHA256withRSA, so the label does not name the algorithm (AWS-recorded, validated 2025-11-25; [snapshot test_publish_lambda_verify_signature[2]](https://github.com/localstack/localstack/blob/main/tests/aws/services/sns/test_sns.snapshot.json)).

Binary `Value` base64. The `MessageStructure` json key for the subscription is `lambda`.
- `RawMessageDelivery` does not apply to Lambda. A Lambda subscription needs a function resource policy for `sns.amazonaws.com`; not enforced in phase 1 (brief).

### 5.5 HTTP/S

- Headers on every POST: `x-amz-sns-message-type` (`Notification`, `SubscriptionConfirmation`, `UnsubscribeConfirmation`), `x-amz-sns-message-id`, `x-amz-sns-topic-arn`, `x-amz-sns-subscription-arn` (absent on `SubscriptionConfirmation` in the doc sample), `Content-Type: text/plain; charset=UTF-8` by default (overridable by `headerContentType`), `User-Agent: Amazon Simple Notification Service Agent` ([HTTP headers](https://docs.aws.amazon.com/sns/latest/dg/http-header.html), [subscription confirmation](https://docs.aws.amazon.com/sns/latest/dg/http-subscription-confirmation-json.html)).
- Notification body: same field set as 5.1 with `SigningCertURL`/`UnsubscribeURL`. Basic and Digest auth via `https://user:password@host` URLs; SNI supported ([HTTPS doc](https://docs.aws.amazon.com/sns/latest/dg/sns-http-https-endpoint-as-subscriber.html)).
- `SubscriptionConfirmation` body: `Type`, `MessageId`, `Token`, `TopicArn`, `Message` (`You have chosen to subscribe to the topic <arn>.\nTo confirm the subscription, visit the SubscribeURL included in this message.`), `SubscribeURL` (`https://sns.<region>.amazonaws.com/?Action=ConfirmSubscription&TopicArn=<arn>&Token=<token>`), `Timestamp`, `SignatureVersion`, `Signature`, `SigningCertURL`. No notifications flow until confirmed ([confirmation doc](https://docs.aws.amazon.com/sns/latest/dg/http-subscription-confirmation-json.html)). Confirm by GET of `SubscribeURL` or ConfirmSubscription with the token ([confirm doc](https://docs.aws.amazon.com/sns/latest/dg/SendMessageToHttp.confirm.html)).
- `UnsubscribeConfirmation`: same fields, `Message` `You have chosen to deactivate subscription <sub-arn>.\nTo cancel this operation and restore the subscription, visit the SubscribeURL included in this message.` ([unsubscribe doc](https://docs.aws.amazon.com/sns/latest/dg/http-unsubscribe-confirmation-json.html)).

### 5.6 Signatures

- Canonical string: each name and value joined by `\n`, name then value, names in byte-sort order, ending with one trailing `\n`. Notification: `Message`, `MessageId`, `Subject` (only if present), `Timestamp`, `TopicArn`, `Type`. Confirmations: `Message`, `MessageId`, `SubscribeURL`, `Timestamp`, `Token`, `TopicArn`, `Type`. Version 1 is Base64 `SHA1withRSA`, version 2 `SHA256withRSA` (RSA PKCS#1 v1.5), verified against the X.509 certificate at `SigningCertURL` ([verification doc](https://docs.aws.amazon.com/sns/latest/dg/sns-verify-signature-of-message-verify-message-signature.html), [HTTP notification doc](https://docs.aws.amazon.com/sns/latest/dg/http-notification-json.html)).
- The verification doc tells consumers to "reject any URLs outside AWS domains" ([verification doc](https://docs.aws.amazon.com/sns/latest/dg/sns-verify-signature-of-message-verify-message-signature.html)), so a validator that follows it will refuse an emulator-hosted `SigningCertURL`; apps that validate need a relaxed validator in tests. Behavior of specific SDK validators is UNVERIFIED. Not a fidelity gap for the SQS and Lambda targets of phase 1.

## 6. Filter policy grammar and matching

Scope selection: `FilterPolicyScope` is `MessageAttributes` (default; if a policy exists without a scope the scope is `MessageAttributes`) or `MessageBody` ([scope doc](https://docs.aws.amazon.com/sns/latest/dg/sns-message-filtering-scope.html)). A subscription with no policy receives everything ([filtering overview](https://docs.aws.amazon.com/sns/latest/dg/sns-message-filtering.html)). Policy changes take up to 15 minutes in AWS ([policies doc](https://docs.aws.amazon.com/sns/latest/dg/sns-subscription-filter-policies.html)); apply immediately in an emulator.

### 6.1 Structure

- A policy is a JSON object. Each key maps to an array of rules (OR within the array) and all keys must match (AND across keys) ([AND/OR doc](https://docs.aws.amazon.com/sns/latest/dg/and-or-logic.html)). "You can't apply AND logic to values of the same attribute."
- A rule is a JSON string, number, `true`, `false`, `null`, or a single-key object (operator). Policy JSON may contain strings, numbers, and the literals `true`, `false`, `null` ([constraints](https://docs.aws.amazon.com/sns/latest/dg/subscription-filter-policy-constraints.html)). Anything else (`[["value"]]`) fails `Match value must be String, number, true, false, or null` (AWS-recorded 2024-05-14, [snapshot test_validate_policy](https://github.com/localstack/localstack/blob/main/tests/aws/services/sns/test_sns_filter_policy.snapshot.json)).
- Message body scope: keys may nest as objects to any depth reflecting the JSON path; attribute scope forbids nesting ([constraints](https://docs.aws.amazon.com/sns/latest/dg/subscription-filter-policy-constraints.html)). A key containing dots also matches the nested path: policy `{"object.nested":["string.value"]}` matched a payload of `{"object":{"nested":"string.value"}}` (AWS-recorded, validated 2024-12-03; [snapshot](https://github.com/localstack/localstack/blob/main/tests/aws/services/sns/test_sns_filter_policy.snapshot.json), [test source](https://github.com/localstack/localstack/blob/main/tests/aws/services/sns/test_sns_filter_policy.py); exact semantics beyond that test UNVERIFIED).
- `$or`: recognized only when the value is an array with at least two objects and no object contains a reserved operator keyword as a field name; otherwise `$or` is an ordinary key ([AND/OR doc](https://docs.aws.amazon.com/sns/latest/dg/and-or-logic.html)). G2 note: in Ruler "ordinary key" holds only for an object value or an array of plain values; a one-object array or a member with an operator key is an error on both compile paths ([matching-engines.md 4.8](matching-engines.md), executed), so the doc sentence is unverified for SNS (H10). `$or` may nest, and may appear inside nested objects in body scope. Semantics: policy equals the OR of the branches, each branch ANDed with its siblings ([AND/OR doc](https://docs.aws.amazon.com/sns/latest/dg/and-or-logic.html), example `source && (metricName || namespace)`; AWS-recorded 5 of 12 message matrix in [snapshot test_filter_policy_on_message_body_or_attribute, validated 2024-12-03](https://github.com/localstack/localstack/blob/main/tests/aws/services/sns/test_sns_filter_policy.snapshot.json)). `$or` works under `MessageAttributes` scope at top level (the 150-complexity test used it with that scope).

### 6.2 Operators

All from [string-value-matching](https://docs.aws.amazon.com/sns/latest/dg/string-value-matching.html), [numeric-value-matching](https://docs.aws.amazon.com/sns/latest/dg/numeric-value-matching.html), [attribute-key-matching](https://docs.aws.amazon.com/sns/latest/dg/attribute-key-matching.html) unless noted.

| Rule | Meaning |
|---|---|
| `"abc"` | exact, case-sensitive string equality |
| `123`, `true`, `false`, `null` | literal equality on the typed value (body scope); numeric literal against `Number` attribute UNVERIFIED (see 6.4) |
| `{"prefix":"p"}` / `{"suffix":"s"}` | string starts/ends with; string values only |
| `{"equals-ignore-case":"x"}` | case-insensitive equality |
| `{"anything-but":"x"}`, `{"anything-but":["x","y"]}`, `{"anything-but":123}`, `{"anything-but":[100,500]}` | not equal to any listed value; strings or numbers; may combine with `exists:false` in the same array |
| `{"anything-but":{"prefix":"p"}}` | string not starting with p |
| `{"anything-but":{"suffix":"s"}}` | documented; real-AWS acceptance UNVERIFIED (Dec 2024 recording rejected it, see 6.5) |
| `{"anything-but":{"wildcard":"*ball"}}` | documented (announcement 2025-07-31) |
| `{"wildcard":"*ball"}` | `*` matches any run; added 2025-07-31 ([announcement](https://aws.amazon.com/about-aws/whats-new/2025/07/amazon-sns-message-filtering-operators)) |
| `{"numeric":["=",301.5]}` | operators `=`, `<`, `<=`, `>`, `>=`; a range is two terms `[">",0,"<=",150]` (lower op `>`/`>=`, upper op `<`/`<=`) |
| `{"exists":true}` / `{"exists":false}` | key present with non-null, non-empty value / key absent; leaf nodes only |
| `{"cidr":"10.0.0.0/24"}` | IPv4 or IPv6 membership of a string value (IPv6 AWS-recorded 2024-12-04) |

- Numeric equality also matches exponent forms (`3.015e2` equals `301.5`) ([numeric doc](https://docs.aws.amazon.com/sns/latest/dg/numeric-value-matching.html)).
- Wildcard grammar (Event Ruler, the open-source pattern library of EventBridge; G2 update 2026-10-08: AWS does not document SNS as using it, but 35 of the 37 AWS-recorded policy errors in 6.5 are byte-identical to Ruler's compiler output and SNS gates operators with its own allow-list, so treat SNS as a Ruler-derived compiler, see [matching-engines.md section 3](matching-engines.md)): zero or more `*`, no consecutive `*`, `\*` is a literal asterisk, `\\` a backslash, other escapes invalid ([Event Ruler README](https://github.com/aws/event-ruler/blob/main/README.md)). Wildcard complexity limits in SNS: total across all fields at most 100 points, at most 3 wildcards per pattern; per field `(sum of pattern points) x (number of patterns)` with a single wildcard 1 point, multiple wildcards 3 points each, anything-but 1 point ([constraints](https://docs.aws.amazon.com/sns/latest/dg/subscription-filter-policy-constraints.html)). Error text UNVERIFIED.
- Event Ruler also defines prefix/suffix `equals-ignore-case` and anything-but variants (`prefix` list, `suffix` list, `equals-ignore-case`); the SNS docs do not list them, so treat as unsupported/UNVERIFIED ([Event Ruler README](https://github.com/aws/event-ruler/blob/main/README.md)).

### 6.3 Matching semantics

MessageAttributes scope:
- Evaluate only attributes named in the policy; extra attributes are ignored ([policies doc](https://docs.aws.amazon.com/sns/latest/dg/sns-subscription-filter-policies.html)).
- Types considered: `String`, `String.Array`, `Number` ("Amazon SNS compares policy properties only to message attributes that have the following data types: String, String.Array"; Number is supported for numeric values). `Binary` attributes are ignored ([constraints](https://docs.aws.amazon.com/sns/latest/dg/subscription-filter-policy-constraints.html)).
- `String.Array`: each element is tested as a separate string; the rule matches if any element matches (policy `["rugby","tennis"]` matches `["rugby","tennis"]`, not `["baseball"]`) ([string-value-matching](https://docs.aws.amazon.com/sns/latest/dg/string-value-matching.html)). AWS-recorded 2024-05-14: policy `{"store":["value1"]}` matches `String.Array ["value1","value2"]` and not `["value2","value3"]` ([snapshot test_exists_filter_policy_attributes_array](https://github.com/localstack/localstack/blob/main/tests/aws/services/sns/test_sns_filter_policy.snapshot.json)). `anything-but` over an array: see section 9 (docs contradict themselves).
- `exists:true` is satisfied by an attribute of any recorded type including `Number` (AWS-recorded: `Number` attribute `store` matched `{"store":[{"exists":true}]}`, 2024-05-14). `exists:false` matches when the key is absent. The docs add: "exists:false only matches if at least one attribute is present. An empty set of attributes results in the filter not matching" ([key matching](https://docs.aws.amazon.com/sns/latest/dg/attribute-key-matching.html)); see section 9.
- A message missing a key named in the policy does not match, regardless of the rule values ([example policies](https://docs.aws.amazon.com/sns/latest/dg/example-filter-policies.html), key `encrypted` example), except for `exists:false` rules. AWS-recorded: policy `{"attr1":[null,{"anything-but":"whatever"}]}` did not deliver a message with no attributes (2024-05-14).
- Attribute value used in comparisons is the `StringValue`; the type tag matters only for `String.Array` (JSON-parse) and numeric operators.

MessageBody scope:
- The message must be a well-formed JSON object; otherwise it is filtered out (metric `NumberOfNotificationsFilteredOut-InvalidMessageBody`) ([filtering overview](https://docs.aws.amazon.com/sns/latest/dg/sns-message-filtering.html), [payload-filtering blog](https://aws.amazon.com/blogs/compute/introducing-payload-based-message-filtering-for-amazon-sns/)). AWS-recorded 2024-12-03: a plain string and a JSON-encoded string both fail to match ([snapshot test_filter_policy_on_message_body](https://github.com/localstack/localstack/blob/main/tests/aws/services/sns/test_sns_filter_policy.snapshot.json)).
- Arrays in the payload are transparent: policy `{"headers":{"route-to":["queue1"]}}` matches `{"headers":{"route-to":["queue1","queue2"]}}`; policy `Records.s3.object.key` traverses `Records` arrays of objects, including arrays nested in arrays (AWS-recorded 2024-12-03). Empty arrays in the payload do not break matching of other keys (AWS-recorded 2024-12-04: policy `{"detail":{"eventVersion":[""]}}` matched `"eventVersion": ""` with `"resources": []` present).
- `exists:false` on a key that is an intermediate object is not supported ("exists works only on leaf nodes") ([key matching](https://docs.aws.amazon.com/sns/latest/dg/attribute-key-matching.html)); a payload where the policy's leaf is absent satisfies `exists:false`.
- Whether sibling keys inside different elements of the same array must be satisfied by the same element: Event Ruler's `rulesForJSONEvent` refuses cross-element matches ([Event Ruler README](https://github.com/aws/event-ruler/blob/main/README.md)); SNS behavior UNVERIFIED (no recorded case separates the two).
- Numbers: body JSON numbers compare numerically; whether a JSON string `"5"` satisfies a numeric rule is UNVERIFIED (Event Ruler: numeric rules apply only to JSON numbers; LocalStack coerces strings).
- Type distinctness: `true` and `"true"` are different values in policy and payload ([Event Ruler README](https://github.com/aws/event-ruler/blob/main/README.md); doc example `"encrypted":[false]` in [example policies](https://docs.aws.amazon.com/sns/latest/dg/example-filter-policies.html)).
- Filtering happens before delivery: filtered-out messages are never sent to the subscription DLQ ([DLQ blog](https://aws.amazon.com/blogs/compute/designing-durable-serverless-apps-with-dlqs-for-amazon-sns-amazon-sqs-aws-lambda/)).

### 6.4 Bare numbers

The docs show numeric equality only via `{"numeric":["=",n]}`. A bare number rule (`"price":[100]`) is accepted by validation. Moto matches it against `Number` attributes and numbers inside `String.Array` with 6-digit precision ([moto utils.py](https://github.com/getmoto/moto/blob/master/moto/sns/utils.py)); LocalStack compares the `StringValue` string to the number and so never matches a `Number` attribute ([filter.py](https://github.com/localstack/localstack/blob/main/localstack-core/localstack/services/sns/filter.py)). Real behavior UNVERIFIED; the moto behavior is the sensible reading of the documented `[100, 500]` policies in [and-or-logic](https://docs.aws.amazon.com/sns/latest/dg/and-or-logic.html) (`"metricId": [1234, 4321]`). G2 note: Ruler compiles a bare number to numeric equality plus exact text ([writeRules](https://github.com/aws/event-ruler/blob/ced786201c1f43ec73482b78f3d1843aa4bd2f89/src/main/software/amazon/event/ruler/JsonRuleCompiler.java#L394-L408)), and the AWS-validated `test_filter_policy` shows a `Number` attribute satisfying a `numeric` rule, which needs a JSON number on the engine side; together these make LocalStack's never-match the likely wrong one. Still unrecorded ([matching-engines.md H6](matching-engines.md)).

### 6.5 Limits and validation

Limits ([constraints](https://docs.aws.amazon.com/sns/latest/dg/subscription-filter-policy-constraints.html)):
- At most 5 keys. Docs: "For a nested policy, only leaf keys are counted towards the five key limit." LocalStack counts only top-level keys (`len(policy) > 5`) ([filter.py](https://github.com/localstack/localstack/blob/main/localstack-core/localstack/services/sns/filter.py)); how `$or` branches count is UNVERIFIED.
- Total combinations at most 150: the product of the number of rules per key; for a nested key each key's rule count is also multiplied by its nesting level (nesting level 1 for a top-level key). Doc example: `key_c` 4 rules at level 3 times `key_e` 3 rules at level 2 = `4*3*3*2 = 72`. With `$or`, the total is the sum over expanded branches of each branch's product, with sibling keys outside the `$or` multiplying into every branch ([AND/OR doc](https://docs.aws.amazon.com/sns/latest/dg/and-or-logic.html)). AWS-recorded boundaries (2024-05-14, [snapshot test_policy_complexity, test_policy_complexity_with_or](https://github.com/localstack/localstack/blob/main/tests/aws/services/sns/test_sns_filter_policy.snapshot.json)): `{"key":[151 values]}` fails; `{"key1":[100],"key2":[51]}` fails; flat `$or` policy computing 152 fails and 150 passes; nested body-scope `$or` policy computing 160 fails.
- Policy size at most 256 KB, valid UTF-8; 200 filter policies per topic, 10,000 per account (`FilterPolicyLimitExceeded` 403) ([constraints](https://docs.aws.amazon.com/sns/latest/dg/subscription-filter-policy-constraints.html)). Exact error for oversize policy UNVERIFIED.
- Numeric rule values range -10^9 to 10^9, five digits after the decimal point (docs). LocalStack and its recording found values beyond that range accepted ([filter.py comment](https://github.com/localstack/localstack/blob/main/localstack-core/localstack/services/sns/filter.py)); see section 9.
- Attribute scope: nested object values are rejected; attribute names and `Binary` as above.

Validation errors. Prefix depends on the call that carries the policy: SetSubscriptionAttributes uses `Invalid parameter: FilterPolicy: <detail>`; Subscribe (policy inside `Attributes`) uses `Invalid parameter: Attributes Reason: FilterPolicy: <detail>`. All `InvalidParameter`, 400, Sender. Structural errors append a Jackson line `\n at [Source: (String)"<policy>"; line: 1, column: N]`; tests normalize on the first line, so match on the first line only. ## 7. Delivery retries and dead-letter queues

### 7.1 Failure classes

- Client-side error (stale metadata: endpoint deleted, permissions revoked): no retries; message goes to the DLQ if configured, else is discarded. Server-side error (endpoint unavailable or erroring): retried per the delivery policy; after exhaustion it goes to the DLQ or is discarded. Failed deliveries do not change subscription status ([DLQ doc](https://docs.aws.amazon.com/sns/latest/dg/sns-dead-letter-queues.html), [retries doc](https://docs.aws.amazon.com/sns/latest/dg/sns-message-delivery-retries.html)).
- For HTTP/S: "all 5XX errors and 429" are retryable; every other status is a permanent failure with no retry ([retries doc](https://docs.aws.amazon.com/sns/latest/dg/sns-message-delivery-retries.html)). Messages self-throttled by `maxReceivesPerSecond` are requeued without consuming retries. The endpoint-preparation page adds that "the connection times out in about 15 seconds" (a timeout is a failed attempt, retried about 35 seconds after the previous attempt under the default policy) and that a status "outside the range of 200-4xx" is a failed attempt, which read literally makes 4xx a non-failure, whereas the retries page makes 4xx other than 429 permanent failures (see section 9) ([endpoint preparation](https://docs.aws.amazon.com/sns/latest/dg/SendMessageToHttp.prepare.html)). Whether a 3xx counts as success is UNVERIFIED. Deliveries of the `UnsubscribeConfirmation` message that fail are not redriven to the DLQ (LocalStack comment, [publisher.py](https://github.com/localstack/localstack/blob/main/localstack-core/localstack/services/sns/publisher.py); UNVERIFIED).
- SQS target queue deleted: logged as client error with provider response `AWS.SimpleQueueService.NonExistentQueue`, HTTP 400, no retry ([DLQ blog](https://aws.amazon.com/blogs/compute/designing-durable-serverless-apps-with-dlqs-for-amazon-sns-amazon-sqs-aws-lambda/)). AWS-recorded: the message lands in the DLQ even though the subscription still points at the deleted queue ([snapshot test_redrive_policy_sqs_queue_subscription](https://github.com/localstack/localstack/blob/main/tests/aws/services/sns/test_sns.snapshot.json), 2023-08-24).
- Lambda: SNS invokes asynchronously and treats acceptance by Lambda as delivery; a function error is Lambda's concern (async retries, Lambda DLQ/destinations), not SNS's. SNS retries only when Lambda is unreachable or rejects the invoke ([Lambda with SNS](https://docs.aws.amazon.com/lambda/latest/dg/with-sns.html), [DLQ blog](https://aws.amazon.com/blogs/compute/designing-durable-serverless-apps-with-dlqs-for-amazon-sns-amazon-sqs-aws-lambda/)). A missing function is a client error and goes to the subscription DLQ (AWS-recorded 2023-08-24, [snapshot test_redrive_policy_lambda_subscription](https://github.com/localstack/localstack/blob/main/tests/aws/services/sns/test_sns.snapshot.json)).

### 7.2 Built-in policy by endpoint type ([retries doc](https://docs.aws.amazon.com/sns/latest/dg/sns-message-delivery-retries.html))

| Endpoint | Immediate | Pre-backoff | Backoff | Post-backoff | Total |
|---|---|---|---|---|---|
| SQS, Lambda (AWS managed) | 3 retries, no delay | 2 retries, 1 s apart | 10 retries, exponential 1 s to 20 s | 100,000 retries, 20 s apart | 100,015 attempts over 23 days |
| SMTP, SMS, mobile push | 0 | 2, 10 s apart | 10, exponential 10 s to 600 s | 38, 600 s apart | 50 attempts over 6 hours |
| HTTP/S default | `EffectiveDeliveryPolicy`: 3 retries, 20 s, linear (AWS-recorded) | | | | 4 attempts |

Jitter is applied to retry delays. The doc's phase diagram does not give formulas for `arithmetic`, `geometric`, `exponential` and `linear` backoff, nor the jitter distribution; exact delay series UNVERIFIED.

### 7.3 Custom HTTP/S delivery policy ([retries doc](https://docs.aws.amazon.com/sns/latest/dg/sns-message-delivery-retries.html))

| Field | Constraint | Default |
|---|---|---|
| `minDelayTarget` | 1 to `maxDelayTarget`, seconds | 20 |
| `maxDelayTarget` | `minDelayTarget` to 3600 | 20 |
| `numRetries` | 0 to 100, total incl. all phases | 3 |
| `numNoDelayRetries` | >= 0 | 0 |
| `numMinDelayRetries` | >= 0 | 0 |
| `numMaxDelayRetries` | >= 0 | 0 |
| `backoffFunction` | `arithmetic`, `exponential`, `geometric`, `linear` | `linear` |
| `maxReceivesPerSecond` | >= 1 | no throttling |
| `headerContentType` | `text/plain`, `application/json` (non-raw or topic level); raw adds css, csv, html, xml, atom+xml, octet-stream, soap+xml, x-www-form-urlencoded, xhtml+xml, xml | `text/plain; charset=UTF-8` |

Backoff-phase retry count is `numRetries - numNoDelayRetries - numMinDelayRetries - numMaxDelayRetries`. Total policy retry time for HTTP/S is capped at 3,600 seconds ("hard limit"). Error text for violations UNVERIFIED.

### 7.4 Subscription DLQ

- A standard SQS queue (FIFO topic subscriptions need a FIFO DLQ) in the same account and Region as the subscription, attached via `RedrivePolicy` ([DLQ doc](https://docs.aws.amazon.com/sns/latest/dg/sns-dead-letter-queues.html)). The queue needs a policy allowing `sns.amazonaws.com` `SQS:SendMessage` conditioned on `aws:SourceArn` of the topic ([DLQ configuration doc](https://docs.aws.amazon.com/sns/latest/dg/sns-configure-dead-letter-queue.html)); not enforced in phase 1.
- Message content in the DLQ, AWS-recorded: with raw delivery on, the DLQ message body is the raw message and the original message attributes are carried as SQS message attributes; with raw off, the body is the full notification envelope (including `MessageAttributes` inside) (2023-08-24, [snapshot test_redrive_policy_sqs_queue_subscription](https://github.com/localstack/localstack/blob/main/tests/aws/services/sns/test_sns.snapshot.json)). Extra error-detail attributes on SNS subscription DLQ messages: none recorded and none documented; do not invent them (the `ErrorCode`/`ErrorMessage`/`RequestID` attributes belong to Lambda's own DLQ feature) ([Lambda DLQ attributes seen in snapshot test_sns_topic_as_lambda_dead_letter_queue](https://github.com/localstack/localstack/blob/main/tests/aws/services/sns/test_sns.snapshot.json)).
- Metrics: `NumberOfNotificationsRedrivenToDlq`, `NumberOfNotificationsFailedToRedriveToDlq` ([DLQ blog](https://aws.amazon.com/blogs/compute/designing-durable-serverless-apps-with-dlqs-for-amazon-sns-amazon-sqs-aws-lambda/)). If the DLQ send fails, the message is lost and the failure counted.
- Recommended DLQ retention 14 days; DLQ is "an ordinary Amazon SQS queue" ([DLQ doc](https://docs.aws.amazon.com/sns/latest/dg/sns-dead-letter-queues.html)).

### 7.5 Delivery status logging

Topic attributes `{Protocol}SuccessFeedbackRoleArn`, `{Protocol}FailureFeedbackRoleArn`, `{Protocol}SuccessFeedbackSampleRate` make SNS write one JSON record per delivery to CloudWatch Logs; the record carries `providerResponse` (for SQS `{"sqsRequestId":...,"sqsMessageId":...}`, for a missing queue `{"ErrorCode":"AWS.SimpleQueueService.NonExistentQueue",...,"sqsRequestId":"Unrecoverable"}`), a status code (200 success, 400 client failure) and the subscription `redrivePolicy` ([DLQ blog](https://aws.amazon.com/blogs/compute/designing-durable-serverless-apps-with-dlqs-for-amazon-sns-amazon-sqs-aws-lambda/)). The log group name and full record schema are UNVERIFIED here (LocalStack records Lambda delivery events in [snapshot test_delivery_lambda](https://github.com/localstack/localstack/blob/main/tests/aws/services/sns/test_sns.snapshot.json)). Stretch for understudy; the journal covers the same need.

## 8. Client behavior that constrains the design

- Terraform topic resource: one CreateTopic (name, tags, `FifoTopic`, `FifoThroughputScope`), then one SetTopicAttributes per non-default attribute, then GetTopicAttributes; on update only changed attributes; delete tolerates NotFound ([topic.go](https://github.com/hashicorp/terraform-provider-aws/blob/main/internal/service/sns/topic.go)). ## Implications for understudy

1. **One pipeline, journaled at each hop.** Publish validates, allocates the SNS `MessageId` (UUID) and returns before delivery; fan-out is asynchronous on the emulator clock. Journal events: `sns.publish` (message id, topic, size), one `sns.filter` decision per subscription (match or filtered, with the rule that decided), one `sns.deliver` per attempt (protocol, outcome, attempt number), `sns.redrive` when a message lands in a DLQ. The causal parent of an SQS message is the `sns.deliver` event; the causal parent of a Lambda invocation is the same. Keep the SNS `MessageId` in the SQS message body (envelope) so the link survives raw delivery only through the journal.
2. **Package split** (one primary type each, per repo rules): `filterpolicy` (parse to a typed AST, validate with exact error texts, evaluate, count complexity), `snsenvelope` (SQS, FIFO, Lambda and HTTP bodies, signing), `snsmodel` (topic, subscription, attribute maps), `snsdelivery` (retry state machine). Rules are a sum type: `Exact(string|number|bool|null)`, `Prefix`, `Suffix`, `EqualsIgnoreCase`, `AnythingBut(strings|numbers|prefix)`, `Wildcard`, `Numeric(range)`, `Exists(bool)`, `Cidr`. The AST makes illegal policies unrepresentable; the parser returns typed errors carrying the exact AWS message and call-site prefix (`Attributes Reason: ` vs none).
3. **Filter engine tests** (rapid): generate policies from the AST and messages that satisfy them by construction; invariants: `$or` expansion is equivalent to disjunction of branches; adding an unrelated attribute never changes the outcome; scope `MessageAttributes` and `MessageBody` agree on flat policies when the attributes equal the body values for String types; complexity function matches the doc examples (72, 7, 32 in [and-or-logic](https://docs.aws.amazon.com/sns/latest/dg/and-or-logic.html) and [constraints](https://docs.aws.amazon.com/sns/latest/dg/subscription-filter-policy-constraints.html)) and the recorded boundaries (150 pass, 151 and 152 fail; nested `$or` 160 fails). Encode every row of the section 6.5 error table as a table-driven test; compare first message line only.
4. **Resolve UNVERIFIED matching questions with a switch, not scattered branches.** Candidate semantic toggles (each isolated in one place and documented in an ADR): any-element `anything-but` on arrays (recommended), `exists:false` with no attributes (recommended: no match, per docs), leaf-key counting (recommended: leaves), bare-number rules on `Number` attributes (recommended: numeric equality), string-vs-number coercion in body scope (recommended: strict). List these in the coverage report as "behavior from docs/emulators, not AWS-recorded".
5. **Delivery targets for phase 1.** Required: `sqs` (envelope, raw, FIFO, fair-queue `MessageGroupId`), `lambda` (async invoke with the exact event, casing, `Subject: null`, `MessageAttributes: {}`, `SignatureVersion: "1"` always), `http`/`https` (headers, confirmation handshake, raw header, retry policy). `email`, `email-json`: accept Subscribe and leave `PendingConfirmation=true` (Terraform does not wait; the token should be readable through the admin API so tests can confirm); delivery recorded in the journal only. `sms`, `application`, `firehose`: reject Subscribe with an AWS-shaped error that names the protocol as unimplemented in understudy (per the brief, never silently fake). `PublishBatch` and `Publish` to `PhoneNumber` or endpoint ARNs: unimplemented error.
6. **Confirmation model.** Same-account `sqs`/`lambda`: confirmed at Subscribe (`PendingConfirmation=false`, `ConfirmationWasAuthenticated=true`). Cross-account or `http(s)`/`email*`: pending; Subscribe returns `pending confirmation` unless `ReturnSubscriptionArn=true`; `ListSubscriptions*` shows `PendingConfirmation` as the ARN; token stored with a two-day expiry on the emulator clock; `ConfirmSubscription` accepts unauthenticated GET and POST. Since the account derives from the access key (brief), the confirmation rule compares the topic's account to the endpoint ARN's account.
7. **Envelope builder fixtures.** Byte-exact JSON with the recorded key order for SQS, FIFO (no signature fields, `SequenceNumber` after `MessageId`) and the Lambda record; millisecond `Z` timestamps from the emulator clock; `UnsubscribeURL`, `SigningCertURL` and `SubscribeURL` point at the emulator under a reserved path prefix (for example the admin prefix) and the SigV4-free GET handler. Generate one RSA key per account-region (persist it in snapshots), publish the cert at `SigningCertURL`, sign the canonical string exactly as in 5.6 with `SHA1withRSA` or `SHA256withRSA` per topic `SignatureVersion`.
8. **Error fidelity.** Use awsQuery with `Type=Sender` and the shape-to-Code table in section 1 (e.g. `InvalidParameterValueException` serializes as `ParameterValueInvalid`). Keep a registry of the recorded message strings in this document; add them as golden tests. Do not enforce IAM or SQS/Lambda resource policies, but store them and return them from reads.
9. **Retry and DLQ engine on the clock.** Model each delivery as a state machine `{phase, attempt, nextAt}` driven by the emulator clock, with the built-in AWS-managed policy (3 + 2 + 10 + 100,000 retries) and the HTTP policy from `DeliveryPolicy`/topic default. Classify results: SQS queue missing or Lambda function missing is client-side (no retry, redrive immediately); 5xx/429 or connection failure for HTTP is retryable; Lambda throttling or service errors retryable. Jitter must be deterministic under the fault-injection seed. A message that exhausts retries or hits a client error goes to the subscription `RedrivePolicy` DLQ with the same body shape as live delivery (raw: raw body plus SQS attributes; envelope otherwise); no extra error attributes. Filtered-out messages never reach the DLQ.
10. **FIFO.** Dedup table keyed by `MessageDeduplicationId` (or SHA-256 of body) with a five-minute expiry on the clock, scope per `FifoThroughputScope`; duplicate publish returns success and a fresh `MessageId` but no delivery and no journal delivery events beyond a `deduplicated` mark. Per-group monotonically increasing sequence numbers. Preserve per-subscription order per group.
11. **Terraform read fidelity checklist.** CreateTopic idempotency with attribute and tag comparison errors; `GetTopicAttributes` returns the full default set from section 2.2 with string values; `Policy` default text (plus Terraform's `SNS:Receive` variant on reset); `EffectiveDeliveryPolicy` default; `SubscriptionsConfirmed/Pending/Deleted` counters kept accurate; `GetSubscriptionAttributes` hides `FilterPolicy*` until a policy exists and includes `SubscriptionPrincipal`; ListTagsForResource; unsubscribe-then-NotFound polling. Run the Terraform conformance suite twice (`plan` after `apply` shows no changes).
12. **Items to schedule for the human-run parity harness** (record mode is never run by agents): bare-number rules, `anything-but` arrays, `anything-but` suffix and wildcard acceptance, `exists:false` with empty attributes, leaf-key counting, over-256 KB policy error, Subject length error, Number attribute value validation, FIFO subscribe error for customer-managed endpoints, raw-delivery over-10-attributes handling, PublishBatch `Failed` entries, HTTP/S 3xx and 4xx classification, Lambda `Number` attribute type, the real token length, and the sequence-number text format.
