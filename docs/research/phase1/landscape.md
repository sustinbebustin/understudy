# How existing AWS emulators are built and where they hurt

Primary-source research for understudy phase 1. Scope: architecture, routing, protocol handling, Lambda execution, event source mappings, S3 virtual-host addressing, persistence and parity testing of the active AWS emulators; the bug classes their trackers show; concrete ways understudy can be clearly better; traps to avoid. Research date: 2026-10-08. Starting point: [localstack-vs-aws-tooling.md](../localstack-vs-aws-tooling.md) (plans, licensing, timeline; not repeated here).

## 2. Architecture of each emulator

### 2.1 LocalStack: generated stubs over botocore specs, moto as a backend

- **Generation.** AWS specs are turned into server-side stubs (shape types plus an `<Service>Api` class of operation functions) by `python -m localstack.aws.scaffold generate <service> --save` ([concepts](https://github.com/localstack/localstack/blob/8b9a79f05846835cf4dff63ab7eefdde9df83783/docs/localstack-concepts/README.md#L17-L44)). The specs are botocore `service-2` JSON, not Smithy: [scaffold.py](https://github.com/localstack/localstack/blob/8b9a79f05846835cf4dff63ab7eefdde9df83783/localstack-core/localstack/aws/scaffold.py#L1-L25) imports `botocore.model`.
- **Spec patching.** botocore models are patched at load time with JSON Patch: [spec-patches.json](https://github.com/localstack/localstack/blob/8b9a79f05846835cf4dff63ab7eefdde9df83783/localstack-core/localstack/aws/spec-patches.json) holds 106 `op` entries for `s3`, `apigatewayv2` and `apigateway`. S3 examples: it adds missing error shapes `NoSuchLifecycleConfiguration` and `InvalidBucketName` with `httpStatusCode` 404 and 400 ([lines 2-48](https://github.com/localstack/localstack/blob/8b9a79f05846835cf4dff63ab7eefdde9df83783/localstack-core/localstack/aws/spec-patches.json#L2-L48)). Lesson: client-model gaps for server-side errors are real and were patched by hand.
- **Parsing and serializing.** A generic parser (1,613 lines) and serializer (2,488 lines) cover query, json, ec2, rest-json, rest-xml and smithy-rpc-v2-cbor ([parser.py](https://github.com/localstack/localstack/blob/8b9a79f05846835cf4dff63ab7eefdde9df83783/localstack-core/localstack/aws/protocol/parser.py), [serializer.py](https://github.com/localstack/localstack/blob/8b9a79f05846835cf4dff63ab7eefdde9df83783/localstack-core/localstack/aws/protocol/serializer.py)). Input validation extends botocore's `ParamValidator` ([validate.py L135](https://github.com/localstack/localstack/blob/8b9a79f05846835cf4dff63ab7eefdde9df83783/localstack-core/localstack/aws/protocol/validate.py#L135)).
- **Backends.** Many providers call moto: `moto-ext[all]>=5.1.22` is a runtime dependency ([pyproject.toml L101](https://github.com/localstack/localstack/blob/8b9a79f05846835cf4dff63ab7eefdde9df83783/pyproject.toml#L101)); `call_moto` is used by providers for secretsmanager, iam, logs, sts, cloudwatch, ec2, ssm, ses, route53, acm and others ([moto.py](https://github.com/localstack/localstack/blob/8b9a79f05846835cf4dff63ab7eefdde9df83783/localstack-core/localstack/services/moto.py), [secretsmanager provider](https://github.com/localstack/localstack/blob/8b9a79f05846835cf4dff63ab7eefdde9df83783/localstack-core/localstack/services/secretsmanager/provider.py), [logs provider](https://github.com/localstack/localstack/blob/8b9a79f05846835cf4dff63ab7eefdde9df83783/localstack-core/localstack/services/logs/provider.py)). Consequence for phase 1 services: Secrets Manager, Logs, IAM, STS and CloudWatch fidelity in LocalStack is bounded by moto's (logs and cloudwatch 44% per moto's own coverage file, link in section 1). SQS, SNS, S3, Lambda, KMS and EventBridge v2 have their own providers (UNVERIFIED for EventBridge v2 and KMS: inferred from absence in the `call_moto` file list).
- **DynamoDB.** DynamoDB Local is run as a Java subprocess with a `-javaagent` bytecode patch "that enables 20+ GSIs" ([packages.py L81](https://github.com/localstack/localstack/blob/8b9a79f05846835cf4dff63ab7eefdde9df83783/localstack-core/localstack/services/dynamodb/packages.py#L81), jar URL [L17](https://github.com/localstack/localstack/blob/8b9a79f05846835cf4dff63ab7eefdde9df83783/localstack-core/localstack/services/dynamodb/packages.py#L17)). Flags `-inMemory`, `-dbPath`, `-sharedDb` are passed from config ([server.py](https://github.com/localstack/localstack/blob/8b9a79f05846835cf4dff63ab7eefdde9df83783/localstack-core/localstack/services/dynamodb/server.py#L176-L183)). TTL expiry is a background worker on a 60 minute period with the comment "the background process seems slow on AWS" ([provider.py L511](https://github.com/localstack/localstack/blob/8b9a79f05846835cf4dff63ab7eefdde9df83783/localstack-core/localstack/services/dynamodb/provider.py#L511)); an internal route `DELETE /_aws/dynamodb/expired` forces it ([provider.py L428-L440](https://github.com/localstack/localstack/blob/8b9a79f05846835cf4dff63ab7eefdde9df83783/localstack-core/localstack/services/dynamodb/provider.py#L428-L440)).
- **Handler chain.** One gateway runs a chain of named request, response, exception and finalizer handlers (service-name parsing, request parsing, region, account, CORS, logging, validation) ([handlers/__init__.py](https://github.com/localstack/localstack/blob/8b9a79f05846835cf4dff63ab7eefdde9df83783/localstack-core/localstack/aws/handlers/__init__.py)).
- **State.** Per-account, per-region stores ([concepts](https://github.com/localstack/localstack/blob/8b9a79f05846835cf4dff63ab7eefdde9df83783/docs/localstack-concepts/README.md#L72)).

### 2.2 moto: mock the SDK, or serve with Flask

- **Two entry points.** In library mode a single global `BotocoreStubber` is registered on botocore's `before-send` event, so "botocore is still responsible for any client-side validation"; a nested-decorator counter disables it only after the last decorator exits; requests made with the `requests` module are caught by the `responses` library ([_mock_architecture.md L11-L40](https://github.com/getmoto/moto/blob/5cab9c903b2a26d08f353da2afc753b1adc1eb10/moto/core/_mock_architecture.md#L11-L40)). Server mode dispatches on Host header against each backend's `url_bases`, and infers the service from the SigV4 credential scope or `X-Amz-Target` ([werkzeug_app.py L66-L130](https://github.com/getmoto/moto/blob/5cab9c903b2a26d08f353da2afc753b1adc1eb10/moto/moto_server/werkzeug_app.py#L66-L130)). A table `SIGNING_ALIASES` maps signing names that differ from service names, for example `eventbridge` to `events` and `execute-api` to `iot` ([L54-L60](https://github.com/getmoto/moto/blob/5cab9c903b2a26d08f353da2afc753b1adc1eb10/moto/moto_server/werkzeug_app.py#L54-L60)).
- **Hand-written handlers with URL regex tables.** SQS: `url_bases = [r"https?://(.*\.)?(queue|sqs)\.(.*\.)?amazonaws\.com"]` and two path patterns ([sqs/urls.py](https://github.com/getmoto/moto/blob/5cab9c903b2a26d08f353da2afc753b1adc1eb10/moto/sqs/urls.py)).
- **Newer core.** `moto/core/parse.py` and `serialize.py` are botocore-model-driven protocol parsers and serializers, the same idea as LocalStack's ([serialize.py](https://github.com/getmoto/moto/blob/5cab9c903b2a26d08f353da2afc753b1adc1eb10/moto/core/serialize.py#L1-L30)). Both files carry `mypy: ignore-errors`/`disable-error-code` headers.
- **S3 bucket-vs-key ambiguity.** `url_paths` has a handler named `ambiguous_dispatch` for `/{key_or_bucket_name}` ([s3/urls.py L5-L22](https://github.com/getmoto/moto/blob/5cab9c903b2a26d08f353da2afc753b1adc1eb10/moto/s3/urls.py#L5-L22), [responses.py L375](https://github.com/getmoto/moto/blob/5cab9c903b2a26d08f353da2afc753b1adc1eb10/moto/s3/responses.py#L375)). Virtual-host detection is a heuristic cascade (section 4).
- **No persistence.** Users ask how to save server state ([moto#2882](https://github.com/getmoto/moto/issues/2882)); the codebase has no snapshot module (UNVERIFIED as an absolute).

### 2.3 Floci: Quarkus controllers per wire protocol

- Protocol-to-implementation table in the contributor guide: Query (SQS, SNS, IAM, STS, CloudWatch Metrics) via `AwsQueryController`; JSON 1.1 (EventBridge, Logs, KMS, Secrets Manager) via `AwsJson11Controller`; REST JSON (Lambda) and REST XML (S3) via JAX-RS ([AGENTS.md](https://github.com/floci-io/floci/blob/da53fc1c051e1a985272cd4532cfe71ffb87ca3b/AGENTS.md)). The guide states "SQS and SNS may expose multiple compatibility paths; do not let them drift".
- **Storage backends.** `InMemoryStorage`, `PersistentStorage`, `HybridStorage`, `WalStorage`, plus `StorageQuarantine` and `PersistentPathValidator` ([core/storage](https://github.com/floci-io/floci/tree/da53fc1c051e1a985272cd4532cfe71ffb87ca3b/src/main/java/io/github/hectorvent/floci/core/storage)).

### 2.4 MiniStack: regex router, JSON state, local-first Lambda

- Service detection is a registry of `host_patterns` regexes plus `X-Amz-Target` prefixes and credential scope; ordering matters ("dynamodbstreams must be listed BEFORE dynamodb because the host...") ([router.py L53-L80](https://github.com/ministackorg/ministack/blob/a63cb7ccc84261291fd41002256698f3de9719af/ministack/core/router.py#L53-L80)).
- Every registered service must implement `get_state()`, `load_persisted_state(data)` and `reset()`, enforced by a test ([AGENTS.md](https://github.com/ministackorg/ministack/blob/a63cb7ccc84261291fd41002256698f3de9719af/AGENTS.md)).
- Contributor rule worth copying: "Never claim behavior was validated against AWS unless it was actually run against a real AWS account", with evidence labelled as real AWS observation, official docs, botocore model inspection, existing tests, or inference ([AGENTS.md](https://github.com/ministackorg/ministack/blob/a63cb7ccc84261291fd41002256698f3de9719af/AGENTS.md)).

### 2.5 fakecloud and kumo: the closest design neighbours

- **fakecloud conformance harness.** Reads AWS Smithy JSON committed in `aws-models/` (109 files), generates inputs with nine strategies (boundary, enum exhaustion, optionals permutation, property-based, model `@examples`, negative, examples-diff, round-trip echo, identifier-form fanout), signs and sends them, then validates responses against the model's output shape (`MissingField`, `WrongType`, `UnexpectedField`, `ParseError`) and 4xx bodies against the operation's declared error shapes ([conformance README](https://github.com/faiscadev/fakecloud/blob/c1704f4842584ca28189946c8237b6b0d24477b3/crates/fakecloud-conformance/README.md)). Results are ratcheted in [conformance-baseline.json](https://github.com/faiscadev/fakecloud/blob/c1704f4842584ca28189946c8237b6b0d24477b3/conformance-baseline.json); a macro hashes each operation's full shape tree so tests go stale loudly when the model changes (same README, "Level 2").
  - Caveat: this checks wire shape and declared-error conformance, not behavior. The README calls it "behavioral parity"; the harness validates shapes. Its AGENTS.md separately gates DynamoDB behavior on an independent suite "recorded against live DynamoDB" ([AGENTS.md](https://github.com/faiscadev/fakecloud/blob/c1704f4842584ca28189946c8237b6b0d24477b3/AGENTS.md)).
  - Flake lesson: two services needed a floor below observed pass count until cross-test state leakage in the harness was fixed ([conformance-baseline-notes.md](https://github.com/faiscadev/fakecloud/blob/c1704f4842584ca28189946c8237b6b0d24477b3/conformance-baseline-notes.md)).
  - Terraform: `fakecloud-tfacc` runs upstream `TestAcc*` functions from `hashicorp/terraform-provider-aws` with `TF_ACC=1` and per-service `AWS_ENDPOINT_URL_<SERVICE>`, against a pinned provider tag, using an allow list ([tfacc lib.rs](https://github.com/faiscadev/fakecloud/blob/c1704f4842584ca28189946c8237b6b0d24477b3/crates/fakecloud-tfacc/src/lib.rs#L1-L25)). Prior art: [bblommers/localstack-terraform-test](https://github.com/bblommers/localstack-terraform-test) (last push 2022-03-20) and LocalStack's CI use of the same idea ([terraform-tests](https://github.com/localstack/localstack/blob/8b9a79f05846835cf4dff63ab7eefdde9df83783/docs/testing/terraform-tests/README.md)).
  - Real-AWS parity job is weekly, has no `pull_request` trigger, and is gated by a protected environment with a required reviewer ([parity-aws.yml](https://github.com/faiscadev/fakecloud/blob/c1704f4842584ca28189946c8237b6b0d24477b3/.github/workflows/parity-aws.yml#L1-L30)).
- **kumo** imports aws-sdk-go-v2 service modules (go.mod above) and keeps a `vhost` package for host-based recognition, for example `{urlId}.lambda-url.localhost` and `{urlId}.lambda-url.{region}.on.aws` ([vhost.go](https://github.com/sivchari/kumo/blob/7e164b5ab1188327a2ad22cd887760864a9811cb/internal/vhost/vhost.go#L1-L35)).

## 3. Request routing and protocol handling

### 3.1 LocalStack's detection order

- Protocol priority when a service speaks several: `smithy-rpc-v2-cbor`, `json`, `query`, `ec2`, `rest-json`, `rest-xml` ([service_router.py L22-L29](https://github.com/localstack/localstack/blob/8b9a79f05846835cf4dff63ab7eefdde9df83783/localstack-core/localstack/aws/protocol/service_router.py#L22-L29)). A request matches `json` by `Content-Type` prefix `application/x-amz-json`, `query` by `application/x-www-form-urlencoded` or an `Action` query arg ([L73-L100](https://github.com/localstack/localstack/blob/8b9a79f05846835cf4dff63ab7eefdde9df83783/localstack-core/localstack/aws/protocol/service_router.py#L73-L100)).
- Indicators extracted without reading the body: SigV4 credential scope signing name, `X-Amz-Target` prefix and operation, Host, path ([L40-L70](https://github.com/localstack/localstack/blob/8b9a79f05846835cf4dff63ab7eefdde9df83783/localstack-core/localstack/aws/protocol/service_router.py#L40-L70)).
- Signing-name collisions need hand rules by path prefix: `s3` with `/v20180820` is S3 Control; `ses` `/v2` vs `/v1`; `execute-api` splits to three services; `servicecatalog` splits on `path == "/"` ([L130-L205](https://github.com/localstack/localstack/blob/8b9a79f05846835cf4dff63ab7eefdde9df83783/localstack-core/localstack/aws/protocol/service_router.py#L130-L205)).
- **S3 is the catch-all, and its fallback is a pile of heuristics.** `legacy_s3_rules` treats any GET/HEAD on `/<x>/...` as S3, any `aws-cli/` user agent as S3, any request carrying `AWSAccessKeyId`, `Signature`, `X-Amz-Algorithm`, `X-Amz-Credential`... as S3, `POST ?delete` with `<Delete` in the body as S3, and Authorization headers starting with `AWS ` (SigV2) as S3; the docstring says these "should be removed once we make sure it would not break any use-cases" ([L232-L297](https://github.com/localstack/localstack/blob/8b9a79f05846835cf4dff63ab7eefdde9df83783/localstack-core/localstack/aws/protocol/service_router.py#L232-L297)).
- Host rules: `.lambda-url.` routes to Lambda, `.s3-website.` to S3 ([L207-L218](https://github.com/localstack/localstack/blob/8b9a79f05846835cf4dff63ab7eefdde9df83783/localstack-core/localstack/aws/protocol/service_router.py#L207-L218)).

### 3.2 SQS has two protocols in the same endpoint, and it has bitten everyone

- LocalStack carries two SQS specs (`sqs` for json, `sqs-query`) sharing one provider, resolved by `Content-Type`: "The `application/x-amz-json-1.0` header is mandatory for requests targeting SQS with the `json` protocol" ([service_router.py L300-L330](https://github.com/localstack/localstack/blob/8b9a79f05846835cf4dff63ab7eefdde9df83783/localstack-core/localstack/aws/protocol/service_router.py#L300-L330)). A queue URL path alone also routes to SQS query ([L222-L227](https://github.com/localstack/localstack/blob/8b9a79f05846835cf4dff63ab7eefdde9df83783/localstack-core/localstack/aws/protocol/service_router.py#L222-L227)).
- History: botocore 1.29.127 (2023-05) switched SQS to JSON, AWS rolled it back, and clients broke on both sides: LocalStack returned `Operation detection failed. Missing Action in request for query-protocol service` and `UnknownOperationException` ([localstack#8267](https://github.com/localstack/localstack/issues/8267), 54 comments, 19 reactions); moto had the same break ([moto#6286](https://github.com/getmoto/moto/issues/6286), 26 reactions). It recurred in 2023-11 with botocore 1.31.81, and the PHP SDK 3.285.1 did not follow the spec so LocalStack added an SDK-specific workaround (same thread, 2023-11-14 comments). AWS documents the JSON form: `Content-Type: application/x-amz-json-1.0` plus `X-Amz-Target: AmazonSQS.<operation>` ([SQS JSON requests](https://docs.aws.amazon.com/AWSSimpleQueueService/latest/SQSDeveloperGuide/sqs-making-api-requests-json.html)).
- Trap: AWS can switch the default protocol of a service inside an SDK release without notice. Serve both on one endpoint, always.

### 3.3 Where generic parsers need escape hatches

- LocalStack patches and special-cases S3 (largest patch set), API Gateway, SQS queue URL shapes. Treat S3 as a hand-routed REST service from day one.
- Floci's S3 virtual-host filter declines to rewrite when `Authorization` carries a credential scope other than `/s3/aws4_request`, or when content type is `application/x-www-form-urlencoded` or `application/x-amz-json-` without an explicit S3 scope, so other services on the shared edge host are not hijacked; S3 Control (`/v20180820/`) is also excluded ([S3VirtualHostFilter.java L120-L170](https://github.com/floci-io/floci/blob/da53fc1c051e1a985272cd4532cfe71ffb87ca3b/src/main/java/io/github/hectorvent/floci/services/s3/S3VirtualHostFilter.java#L120-L170)).

## 4. S3 virtual-host addressing: what clients send, and how emulators cope

### 4.1 MEASURED: what current SDKs send to a custom endpoint

Net: JS v3 and Go v2 send `Host: <bucket>.<endpoint-host>` by default, boto3 and the CLI send path style. Java v2 follows the rule set (not read; UNVERIFIED).
- Floci's maintainers hit exactly the dotted-bucket variant: splitting the Host at the first dot made `www.example.com.localhost` look like bucket `www`, so lookups fell to path style where `HEAD /` answered 200, "and the AWS provider reads that as 'bucket already exists'" ([S3VirtualHostFilter.java L223-L260](https://github.com/floci-io/floci/blob/da53fc1c051e1a985272cd4532cfe71ffb87ca3b/src/main/java/io/github/hectorvent/floci/services/s3/S3VirtualHostFilter.java#L223-L260)).

### 4.3 MEASURED: `*.localhost` on this host

- `getent hosts foo.localhost` returned `::1`; Go (pure and cgo resolvers) and Python `getaddrinfo` both returned `[::1, 127.0.0.1]` for `foo.localhost` and `bucket.s3.localhost`. The host uses systemd-resolved (`/etc/resolv.conf` points at its stub). Go's own resolver has no `.localhost` special case beyond choosing cgo when `nsswitch` lists `myhostname` ([net/conf.go L519-L522](https://go.googlesource.com/go/+/refs/tags/go1.27.1/src/net/conf.go#L519)). RFC 6761 section 6.3 says name resolution libraries "SHOULD recognize localhost names as special and SHOULD always return the IP loopback address" ([RFC 6761](https://www.rfc-editor.org/rfc/rfc6761#section-6.3)): a SHOULD, so platforms differ. macOS and Windows behavior: UNVERIFIED.
- `getent hosts s3.localhost.localstack.cloud` resolved to 127.0.0.1 through public DNS on this networked host; offline behavior depends on resolver caches and is UNVERIFIED.
- Resolvers return `::1` first. A server bound only to `127.0.0.1` costs one refused connect per new connection to `bucket.localhost` before the IPv4 fallback.
- Inside a Docker container `*.localhost` resolves to the container's own loopback. A Lambda container given `AWS_ENDPOINT_URL=http://localhost:PORT` cannot reach the emulator at all; one given a hostname endpoint such as `host.docker.internal` makes Go v2 build `my-bucket.host.docker.internal`, which has no DNS answer unless an emulator-run DNS server provides one (inference from the MEASURED Go behavior above; the hostname variant was not run). IP-literal endpoints select path style in Go v2 (MEASURED with 127.0.0.1 only). moto uses `extra_hosts: {"host.docker.internal": "host-gateway"}` for Lambda containers ([awslambda/models.py L1046](https://github.com/getmoto/moto/blob/5cab9c903b2a26d08f353da2afc753b1adc1eb10/moto/awslambda/models.py#L1046)).

## 5. S3 checksums, aws-chunked and trailers: the biggest SDK-upgrade break

### 5.1 What clients do (owner sources)

- AWS made CRC checksums default in SDKs: `request_checksum_calculation` / `response_checksum_validation` default `WHEN_SUPPORTED`; opt out with `WHEN_REQUIRED` via config key, env var `AWS_REQUEST_CHECKSUM_CALCULATION`, or JVM property. Defaults per SDK: AWS CLI v2 and C++ `CRC64NVME`; Go v2, Java 2.x, JS v3, Python, Rust, .NET `CRC32` ([SDK reference](https://docs.aws.amazon.com/sdkref/latest/guide/feature-dataintegrity.html)). JS v3 shipped it in 3.729.0; the SDK team's own notice says SDKs "may introduce and enable new features by default... prior to them being supported or otherwise handled by third-party service implementations" ([aws-sdk-js-v3#6810](https://github.com/aws/aws-sdk-js-v3/issues/6810)).
- Algorithms S3 accepts now: CRC64NVME, CRC32, CRC32C, SHA1, SHA256, MD5, XXHASH64, XXHASH3, XXHASH128, SHA512. Multipart type support: CRC64NVME full-object only; CRC32 and CRC32C both; SHA1, SHA256, MD5, XXHash*, SHA512 composite only. Trailer names currently listed: `x-amz-checksum-crc32`, `-crc32c`, `-crc64nvme`, `-sha1`, `-sha256` only ([S3 checking object integrity](https://docs.aws.amazon.com/AmazonS3/latest/userguide/checking-object-integrity-upload.html)). That page also says: for the four older algorithms, a checksum in `CompleteMultipartUpload` without the algorithm in `CreateMultipartUpload` is "currently accepted but not validated or stored"; for the newer five, it fails `InvalidRequest`; non-consecutive part numbers on composite uploads give an `HTTP 500`; with no checksum supplied S3 attaches `CRC64NVME`; mismatch yields `BadDigest`.
- Trailer wire format from the same page: headers `Content-Encoding: aws-chunked`, `x-amz-decoded-content-length`, `x-amz-trailer: x-amz-checksum-crc32`, `x-amz-content-sha256: STREAMING-UNSIGNED-PAYLOAD-TRAILER` (or `STREAMING-AWS4-HMAC-SHA256-PAYLOAD-TRAILER` when payload-signed); body chunks `{hex}\r\n{bytes}\r\n`, completion chunk `0\r\n`, trailer `x-amz-checksum-crc32:{base64}\n\r\n\r\n`, and the page notes "The usage of the linefeed `\n` at the end of the checksum value might vary across clients". Minimum non-final chunk 8,192 bytes. Signed variants add `;chunk-signature=` and a trailer signature.
- **Scheme decides the encoding (MEASURED, matches SDK source).**
  - botocore 1.43.109: over `http://` it sends the header form (`x-amz-checksum-crc32: NhCmhg==`, `x-amz-sdk-checksum-algorithm: CRC32`, `Expect: 100-continue`, `x-amz-content-sha256` = real SHA-256); over `https://` it sends `Content-Encoding: aws-chunked`, `Transfer-Encoding: chunked`, `X-Amz-Trailer: x-amz-checksum-crc32`, `X-Amz-Decoded-Content-Length`, `X-Amz-Content-SHA256: STREAMING-UNSIGNED-PAYLOAD-TRAILER`. This held for `put_object`, `upload_fileobj` (small) and `upload_part`.
  - aws-sdk-go-v2 s3 v1.114.1 with `RequestChecksumCalculation=WhenSupported`: `http` gives `X-Amz-Checksum-Crc32` plus a real payload hash; `https` gives the aws-chunked trailer form. Source: the trailer path is taken only `if req.IsHTTPS()`, and non-seekable streams fail without TLS ([middleware_compute_input_checksum.go L99-L176](https://github.com/aws/aws-sdk-go-v2/blob/ab2110b01f03b3990bfd50208a8a05df1d8c5eac/service/internal/checksum/middleware_compute_input_checksum.go#L99-L176)). With bare `s3.New` and no option set, Go sent no checksum at all (MEASURED); the default applies through `config.LoadDefaultConfig` per the docs above.
  - Implication: understudy's plain-HTTP default sees header checksums and signed payload hashes; any TLS front (CDK, Traefik, Testcontainers wrappers) sees trailers.
- **Presigned URLs.** JS v3 signs `x-amz-checksum-crc32` of the empty body into the query string. Real S3 includes it in the signature but does not verify it against the body. Evidence cited in [ministack#1695](https://github.com/ministackorg/ministack/issues/1695): LocalStack's AWS-recorded test `test_presigned_url_v4_x_amz_in_qs` (snapshot recorded 2026-02-21) uploads 6 bytes to a URL with `x-amz-checksum-crc32=AAAAAA%3D%3D`, gets 200 and `ContentLength: 6`, and gets 403 when the query value is edited; LocalStack concluded "AWS is just flat out ignoring the query string parameter" ([localstack#12164](https://github.com/localstack/localstack/issues/12164) as quoted in that issue).
- **Header checksum verification does not need `x-amz-sdk-checksum-algorithm`.** [ministack#1497](https://github.com/ministackorg/ministack/issues/1497) records a script run against real S3 us-east-1 (botocore-signed raw requests): a wrong `x-amz-checksum-crc32: AAAAAA==` with no `x-amz-sdk-checksum-algorithm` returns `400 BadDigest: The CRC32 you specified did not match the calculated checksum.` The reporter's run shows MiniStack stored it and later returned it as if verified. Reporter-recorded, not first-party AWS.

| moto | **Push on send**: inside `SendMessage`, for each enabled mapping the queue itself calls `receive_message` and `send_sqs_batch` synchronously | No batching window, no polling, no concurrency; the sender's request waits for the Lambda |
| Floci | Vert.x periodic timer per mapping on a cached thread pool; skips a tick while a poll is in flight | Visibility set to `function timeout + MaximumBatchingWindowInSeconds + 30`; underfilled batches are held across polls while the window is open; failed messages get `ChangeMessageVisibility` reset to the queue's own timeout; `ReportBatchItemFailures` handled |
| MiniStack | Poller threads; persisted mappings must be restarted | Restore bug: mappings were listed `Enabled` after restart but not polled |

Tracker evidence:

- LocalStack processed batches **sequentially**, unlike AWS's scaling toward `MaximumConcurrency` ([localstack#13328](https://github.com/localstack/localstack/issues/13328), 2025-11; AWS behavior: [Lambda SQS scaling](https://docs.aws.amazon.com/lambda/latest/dg/with-sqs.html#events-sqs-scaling)).
- Earlier v1 engine: RedrivePolicy not respected ([#5283](https://github.com/localstack/localstack/issues/5283)), FIFO consumers stopped after inactivity ([#10290](https://github.com/localstack/localstack/issues/10290); maintainers pointed to the v2 engine in 3.7.0 and to v4), partial batch failure only a feature request until late ([#5301](https://github.com/localstack/localstack/issues/5301)), filter criteria ([#5942](https://github.com/localstack/localstack/issues/5942)).
- Tags on event source mappings were silently dropped, so Terraform re-planned them forever ([ministack#442](https://github.com/ministackorg/ministack/issues/442)).
- A different ESM defect class: queue-level attributes stored but never applied (`ReceiveMessageWaitTimeSeconds`, [floci#2826](https://github.com/floci-io/floci/issues/2826); `DelaySeconds`, floci#1567 referenced there).

| Emulator | Mechanism | Strength | Weakness |

## 10. Bug classes and complaints, with evidence

1. **SDK default changes outrun emulators.** Checksums (section 5), SQS JSON protocol (3.2), Terraform provider releases (below). Evidence is the same shape every time: a client release changes the wire form, the emulator 500s or stores garbage, users pin the SDK or set `WHEN_REQUIRED`. See [ministack#1695](https://github.com/ministackorg/ministack/issues/1695) ("setting `requestChecksumCalculation: WHEN_REQUIRED`... is the workaround we are using").
2. **Terraform: read-after-write fidelity, waiters, and drift.**
   - LocalStack `DescribeTable` omitted `WarmThroughput`; provider 6.13.0+ polled forever and failed with "couldn't find resource (21 retries)" ([localstack#13140](https://github.com/localstack/localstack/issues/13140), [#13155](https://github.com/localstack/localstack/issues/13155); workaround: pin provider 6.12.0). The provider's refresh function returns `nil` (not found) when `output.WarmThroughput == nil` ([dynamodb/status.go L43-L45](https://github.com/hashicorp/terraform-provider-aws/blob/main/internal/service/dynamodb/status.go#L43-L45), read from `main` 2026-10-08; line numbers can move).
   - Floci: three resources applied cleanly but a second plan showed changes (a field not echoed, or one invented by the read path); the compat suite only asserted apply success ([floci#2200](https://github.com/floci-io/floci/issues/2200)).
   - MiniStack: S3 lifecycle configuration creation hung ([ministack#306](https://github.com/ministackorg/ministack/issues/306)); ESM tags dropped ([ministack#442](https://github.com/ministackorg/ministack/issues/442)).
   - moto: `aws_lb` broke with provider 5.73.0+ ([moto#8314](https://github.com/getmoto/moto/issues/8314)); ACM validation options not idempotent ([moto#7228](https://github.com/getmoto/moto/issues/7228)).
3. **Settings stored but not applied.** `ReceiveMessageWaitTimeSeconds`, `DelaySeconds` ([floci#2826](https://github.com/floci-io/floci/issues/2826)); LocalStack documents S3 SSE-C and RDS encryption as stored-only (existing doc).
4. **Networking between the emulator and the code it runs** (section 6; DNS in 4.3).
5. **Event-driven semantics** (section 7): concurrency, redrive, FIFO ordering, restart.
6. **State and thread safety.** moto reused one `Response` class instance across requests for some services ([moto#6745](https://github.com/getmoto/moto/issues/6745), 5 reactions); LocalStack boto client caching in the forwarder caused a major memory leak ([localstack#9126](https://github.com/localstack/localstack/issues/9126)); fakecloud's own harness leaked state across tests until fixed.
7. **Resource leaks**: containers (MiniStack reaper), file descriptors ([ministack#1836](https://github.com/ministackorg/ministack/issues/1836)).
8. **Test-harness design**: success-only assertions (Floci), self-graded hand tests (moto), coverage numbers that mean shape-conformance (fakecloud).
9. **Business risk**: LocalStack's relicensing is the reason this category is open (existing doc).

## Implications for understudy

### How understudy can be clearly better

1. **Generate from Smithy, and own the server-side error gap.** LocalStack generates from botocore models and still needed 106 hand patch operations on S3/API Gateway specs ([spec-patches.json](https://github.com/localstack/localstack/blob/8b9a79f05846835cf4dff63ab7eefdde9df83783/localstack-core/localstack/aws/spec-patches.json)). Do not assume Smithy closes that gap: the S3 Smithy model (api-models-aws `a0767ac`, read 2026-10-08) declares only 21 `@error` shapes (AccessDenied, BucketAlreadyExists, BucketAlreadyOwnedByYou, InvalidObjectState, InvalidRequest, NoSuchBucket, NoSuchKey, NoSuchUpload, NotFound, TooManyParts, and similar) and has none of `NoSuchLifecycleConfiguration`, `InvalidBucketName`, `NoSuchBucketPolicy`, `NoSuchTagSet` or `NoSuchCORSConfiguration` (jq over `.shapes`; [model](https://github.com/aws/api-models-aws/blob/a0767ac42e279dfc8b311564c33436f8abfd3031/models/s3/service/2006-03-01/s3-2006-03-01.json)). The brief requires "unset ones must return AWS's exact 'not configured' errors" for every subresource Terraform reads, so these codes, their HTTP statuses and messages must come from the S3 error-code docs and recorded fixtures, not the model. Keep an explicit, reviewable overlay layer for known model gaps instead of editing models, and make `understudy coverage` list every overlay entry.
2. **Ground-truth fixtures with provenance.** Adopt LocalStack's snapshot idea (record once from real AWS by a human, replay forever, store `recorded-date` and transformers) but add MiniStack's evidence label to each fixture ("real AWS", "docs", "SDK source", "inference"). Phase 1 agents must never run record mode (brief), so ship the replay half plus the recording tool.
3. **Behavioral conformance on top of shape conformance.** Reuse fakecloud's best generators that catch real bugs: round-trip echo (Create/Put then Get/Describe must echo every optional field; caught dropped Lambda `Layers`) and identifier-form fanout (name, `name:qualifier`, partial ARN, full ARN, URL-encoded ARN); validate 4xx bodies against the operation's declared errors. State publicly that this is shape plus echo, and test semantics (visibility, redrive, filter policy, ESM) separately.
4. **Terraform acceptance as a gate, with the "second plan is empty" assertion on every resource from day one.** Pin the provider tag per CI run and also run a canary against latest (WarmThroughput broke on a minor release). Floci's lesson: apply-success is not enough.
5. **Make the clock and journal solve the problems others hack around.** LocalStack's TTL worker is hourly with a force route; Floci has to compute `timeout + window + 30` visibility by hand; moto's ESM fires synchronously inside `SendMessage`. One emulator clock driving visibility, batching windows, TTL and schedules, plus a journal link from SQS message to Lambda invocation, removes whole classes of flake and makes "why didn't my Lambda run" answerable.
6. **Do not loop internal services through HTTP.** LocalStack's poller issues real `ReceiveMessage` calls through the gateway with private override headers and blocks a gateway thread per long poll. Call the SQS component directly through its Go interface (still journaled and fault-injectable), so batch sizes above 10 and long waits need no protocol bending.
7. **Scheme-aware, measured S3 data plane.** Implement both checksum encodings by transport (header form over HTTP, `aws-chunked` trailer over TLS), all ten algorithms, composite and full-object multipart, and CompleteMultipartUpload checksum rules; make the aws-chunked decoder a rapid-tested pure function (round-trip against an encoder written from the S3 doc, with and without optional `\n`, signed and unsigned).
8. **Honest addressing story.** No DNS server by default (offline requirement). Accept `{bucket}.localhost`, `{bucket}.s3.localhost`, `{bucket}.s3.{region}.localhost` and the configured base host, with dotted buckets and `X-Forwarded-Host`; ship an `understudy env` command that prints the exact variables for each SDK, including path-style settings; give Lambda containers an IP-literal or `host-gateway` endpoint. Document that Go v2 (MEASURED) and JS v3 (source) use virtual-hosted style against `localhost` by default while boto3 and the CLI use path style, so Go and JS users need `*.localhost` resolution or `UsePathStyle`/`forcePathStyle`.
9. **Persistence that is a contract.** Versioned, deterministic, explicit format with a newer-version refusal (MiniStack) rather than pickles (LocalStack). On load, re-arm everything with runtime side effects (ESM pollers, schedules, TTL) from state and cover it with a restart test (MiniStack#889).
10. **Container hygiene as a feature.** Label every container with instance identity plus a boot nonce, reap conservatively (MiniStack rules), and test crash recovery. This matches the brief's security defaults and beats every emulator reviewed.

### Traps to avoid

- **S3 greedy fallbacks.** LocalStack's `legacy_s3_rules` shows where catch-all routing ends up. Route by explicit signals: SigV4 credential scope service, `X-Amz-Target`, content type, path/host forms; treat unsigned presigned (query-credential) requests and SigV2 as separate documented rules; test that other services' traffic on shared hosts is never captured by the S3 virtual-host rewrite (Floci guards exactly this).
- **Bucket name equals first Host label.** Dotted buckets and `HEAD /` returning 200 on a "missing" bucket make Terraform believe the bucket exists.
- **Verify what AWS verifies, ignore what it ignores.** Header checksums verified even without `x-amz-sdk-checksum-algorithm`; query-string checksums signed but never verified; `\n` after trailer value optional; older-algorithm checksums on `CompleteMultipartUpload` without a `CreateMultipartUpload` algorithm accepted but not stored.
- **Stored-but-not-applied attributes.** Every attribute in the Smithy model needs a semantic test (queue defaults vs request values, SSE flags, redrive allow policy) or an explicit "stored only" entry in the coverage report.
- **Describe/Get must return the newest model's fields.** Terraform waiters poll fields older clients never read (`WarmThroughput`); a nil is read as "not found".
- **One protocol per service assumption.** SQS speaks JSON and Query on one URL, and AWS flipped the SDK default twice. Test every service's protocols with every SDK.
- **Hostnames inside Lambda containers.** `localhost` and `*.localhost` mean the container; hostname endpoints make Go build `bucket.<hostname>` virtual-host URLs. Inject an IP literal or provide DNS deliberately.
- **QueueUrl host stickiness.** The URL embeds the creator's view of the host; decide one canonical form, and document the effect for containers (LocalStack needed five strategies).
- **Patching upstream binaries.** LocalStack patches DynamoDB Local bytecode through a javaagent and downloads the jar from its own repo ([packages.py L17, L81](https://github.com/localstack/localstack/blob/8b9a79f05846835cf4dff63ab7eefdde9df83783/localstack-core/localstack/services/dynamodb/packages.py#L17)). The brief forbids bundling DynamoDB Local; do not patch it either. Know the limits instead: account/region isolation is not supported at the client level and the access key must be alphanumeric, so decide up front between one container per (account, region) and `-sharedDb` with table-name mapping (design decision, not settled by sources).
- **Shape conformance sold as parity.** Report shape conformance, behavioral tests and AWS-recorded fixtures as three separate numbers in `understudy coverage`.
- **Success-only compat tests.** Always assert second-plan emptiness and clean destroy.
- **Harness state leakage.** fakecloud's harness flaked until per-test isolation was fixed; give every conformance test its own account or region namespace on the emulator.
- **TLS front ends change the wire form.** Tests must cover both `http` and `https` endpoints for every S3 write path.
