# Terraform AWS provider call sequences: compute, IAM, events, logs

Research input for understudy phase 1. Scope: the exact API traffic `hashicorp/terraform-provider-aws` generates for `aws_lambda_function`, `aws_lambda_permission`, `aws_lambda_event_source_mapping`, `aws_lambda_function_url`, `aws_iam_role`, `aws_iam_role_policy`, `aws_iam_role_policy_attachment`, `aws_iam_policy`, `aws_cloudwatch_event_rule`, `aws_cloudwatch_event_target`, `aws_cloudwatch_log_group`, `aws_cloudwatch_metric_alarm`: calls per create/read/update/delete, waiters, response fields the provider dereferences, retries and the errors they key on, and perpetual-diff traps.

Conventions:
- Every claim carries an inline source link. Provider links are pinned to a commit and line, so they do not drift.
- UNVERIFIED marks anything not confirmed in a primary source I could read (usually real-AWS runtime behavior that no document or code pins down).
- "Derived" request bodies are reconstructed from the provider code, not captured from the wire.
- Where the Smithy model, the AWS docs and client code disagree, the disagreement is stated and client behavior wins.

The service trait list is `['aws.protocols#awsJson1_0', 'aws.protocols#awsQuery', 'aws.protocols#awsQueryCompatible', 'smithy.protocols#rpcv2Cbor']` ([cloudwatch model](https://github.com/aws/api-models-aws/blob/1cfdfb4bb9ea858e65623e66d73af04bec353201/models/cloudwatch/service/2010-08-01/cloudwatch-2010-08-01.json)). boto3 does NOT do the same. CORRECTED (G1): botocore's CloudWatch metadata has the legacy field `"protocol":"smithy-rpc-v2-cbor"` ([service-2.json L8](https://github.com/boto/botocore/blob/develop/botocore/data/cloudwatch/2010-08-01/service-2.json#L8)) but also `"protocols": ["smithy-rpc-v2-cbor","json","query"]`, and `resolved_protocol` returns `json` ([model.py L436](https://github.com/boto/botocore/blob/1.43.109/botocore/model.py#L436), [utils.py L194](https://github.com/boto/botocore/blob/1.43.109/botocore/utils.py#L194)); boto3 1.43.109 and AWS CLI 2.36.38 were captured sending `awsJson1_0` ([wire-cbor.md section 2.1](wire-cbor.md)). The service shape name, and so the URL segment, is `GraniteServiceVersion20100801`.

What an rpcv2Cbor client sends and expects (smithy-go links are to `main`; G1 checked that the pinned SDK resolves smithy-go v1.28.2 and read it at that tag, with the same behavior, in [wire-cbor.md](wire-cbor.md)):
- `POST /service/GraniteServiceVersion20100801/operation/PutMetricAlarm`, headers `Smithy-Protocol: rpc-v2-cbor`, `Accept: application/cbor`, `Content-Type: application/cbor` only when there is a body; no body and no `Content-Type` only for operations whose input is `smithy.api#Unit` (CORRECTED (G1): no CloudWatch operation has `Unit` input, so the Go client sends `bfff` with `Content-Type: application/cbor` for an empty `DescribeAlarmsInput`, [wire-cbor.md section 4](wire-cbor.md), smithy-go v1.28.2 [rpcv2.go L84-L100](https://github.com/aws/smithy-go/blob/v1.28.2/transport/http/protocol/rpcv2/rpcv2.go#L84)); no `X-Amz-Target` ([smithy-go rpcv2.go L70-L101](https://github.com/aws/smithy-go/blob/main/transport/http/protocol/rpcv2/rpcv2.go#L70), [spec: requests](https://github.com/smithy-lang/smithy/blob/main/docs/source-2.0/additional-specs/protocols/smithy-rpc-v2-cbor.rst)).
- Because the service has `awsQueryCompatible`, the Go client also sends `X-Amzn-Query-Mode: true` ([rpcv2.go L75-L77](https://github.com/aws/smithy-go/blob/main/transport/http/protocol/rpcv2/rpcv2.go#L75)).
- Success is `200` with `Smithy-Protocol: rpc-v2-cbor` and `Content-Type: application/cbor`. Errors: `httpError` trait status, else `500` for server faults, else `400`; body carries `__type` (absolute shape id) and `message` ([spec: responses and error serialization](https://github.com/smithy-lang/smithy/blob/main/docs/source-2.0/additional-specs/protocols/smithy-rpc-v2-cbor.rst)).
- The Go client maps `__type` to a typed error by shape name after sanitizing, then, if the `X-Amzn-Query-Error` response header is present, overrides the reported code with the query code ([rpcv2.go L180-L255](https://github.com/aws/smithy-go/blob/main/transport/http/protocol/rpcv2/rpcv2.go#L180)).

Other protocols' error signalling, for reference:
- restJson1 (Lambda): `X-Amzn-Errortype` header carrying the shape name; clients also accept `__type` or `code` in the body and strip anything up to `#` and after `:` ([restjson1 spec](https://github.com/smithy-lang/smithy/blob/main/docs/source-2.0/aws/protocols/aws-restjson1-protocol.rst)).
- awsJson1_1 (EventBridge, Logs): `X-Amz-Target: {ServiceShapeName}.{Operation}` (so `AWSEvents.PutRule`, `Logs_20140328.CreateLogGroup`), `__type` in the body ([aws-json spec template](https://github.com/smithy-lang/smithy/blob/main/docs/source-2.0/aws/protocols/aws-json.rst.template)).
- awsQuery (IAM): `<ErrorResponse><Error><Type>Sender</Type><Code>...</Code><Message>...</Message></Error>...</ErrorResponse>`, with the wire `Code` and HTTP status taken from the `awsQueryError` trait, not from the shape name ([aws-query spec](https://github.com/smithy-lang/smithy/blob/main/docs/source-2.0/aws/protocols/aws-query-protocol.rst)). For IAM that means shape `NoSuchEntityException` is wire code `NoSuchEntity`, HTTP 404 ([iam model](https://github.com/aws/api-models-aws/blob/1cfdfb4bb9ea858e65623e66d73af04bec353201/models/iam/service/2010-05-08/iam-2010-05-08.json)).

### 1.2 Polling: what `StateChangeConf` actually does

- The first refresh happens after `Delay`, then waits grow by doubling from 100 ms (first wait becomes 200 ms because the increment applies first), floored at `MinTimeout` and capped at 10 s. With `PollInterval` set, that fixed interval is used instead ([backoff.go L63-L102](https://github.com/hashicorp/terraform-provider-aws/blob/972faab3f6e4e37aff0453fe05366f3bd3fc2b97/internal/backoff/backoff.go#L63), [state.go L67-L172](https://github.com/hashicorp/terraform-provider-aws/blob/972faab3f6e4e37aff0453fe05366f3bd3fc2b97/internal/retry/state.go#L67)).
- `Delay` is `5 * time.Second` on every Lambda function waiter: created, updated, configuration-updated, deleted ([function.go L1487, L1507, L1527, L1547](https://github.com/hashicorp/terraform-provider-aws/blob/972faab3f6e4e37aff0453fe05366f3bd3fc2b97/internal/service/lambda/function.go#L1487)). Event source mapping waiters set no `Delay`, so the first poll is immediate ([event_source_mapping.go L1053-L1108](https://github.com/hashicorp/terraform-provider-aws/blob/972faab3f6e4e37aff0453fe05366f3bd3fc2b97/internal/service/lambda/event_source_mapping.go#L1053)).
- A refresh that returns "not found" (nil object) is tolerated `NotFoundChecks` times, default 20, then fails with `NotFoundError`; with an empty `Target` (wait-for-deletion) a nil object ends the wait successfully ([state.go L67-L130](https://github.com/hashicorp/terraform-provider-aws/blob/972faab3f6e4e37aff0453fe05366f3bd3fc2b97/internal/retry/state.go#L67)).
- A state that is in neither `Pending` nor `Target` aborts immediately with `UnexpectedStateError` ([state.go L145-L151](https://github.com/hashicorp/terraform-provider-aws/blob/972faab3f6e4e37aff0453fe05366f3bd3fc2b97/internal/retry/state.go#L145)).
- `RetryWhen` family (non-waiter retries): first attempt immediate, then waits 500 ms, 1 s, 2 s, 4 s, 8 s, 10 s cap; one extra attempt is granted after the timeout expires (30 s grace period) ([backoff.go L63-L102, L183-L190](https://github.com/hashicorp/terraform-provider-aws/blob/972faab3f6e4e37aff0453fe05366f3bd3fc2b97/internal/backoff/backoff.go#L63), [op.go L77-L112](https://github.com/hashicorp/terraform-provider-aws/blob/972faab3f6e4e37aff0453fe05366f3bd3fc2b97/internal/retry/op.go#L77), [tfresource/retry.go L28-L115, L259-L263](https://github.com/hashicorp/terraform-provider-aws/blob/972faab3f6e4e37aff0453fe05366f3bd3fc2b97/internal/tfresource/retry.go#L28)).
- `RetryWhenNotFound` means "retry until the first successful read"; `RetryUntilNotFound` means "retry until a NotFound error" ([tfresource/retry.go L133-L141](https://github.com/hashicorp/terraform-provider-aws/blob/972faab3f6e4e37aff0453fe05366f3bd3fc2b97/internal/tfresource/retry.go#L133), [op.go L22-L75](https://github.com/hashicorp/terraform-provider-aws/blob/972faab3f6e4e37aff0453fe05366f3bd3fc2b97/internal/retry/op.go#L22)).

### 1.3 SDK-level retries (below the provider)

- Provider default `MaxRetries` is 25 ([provider.go L352](https://github.com/hashicorp/terraform-provider-aws/blob/972faab3f6e4e37aff0453fe05366f3bd3fc2b97/internal/provider/sdkv2/provider.go#L352)); the SDK default is 3 attempts, 20 s max backoff ([standard.go](https://github.com/aws/aws-sdk-go-v2/blob/main/aws/retry/standard.go)).
- SDK-retried without any provider involvement: HTTP `500`, `502`, `503`, `504`; error codes `RequestTimeout`, `RequestTimeoutException`; and the throttle set `Throttling`, `ThrottlingException`, `ThrottledException`, `RequestThrottledException`, `TooManyRequestsException`, `ProvisionedThroughputExceededException`, `TransactionInProgressException`, `RequestLimitExceeded`, `BandwidthLimitExceeded`, **`LimitExceededException`**, `RequestThrottled`, `SlowDown`, `PriorRequestNotComplete`, `EC2ThrottledException` ([standard.go: DefaultRetryable* and DefaultThrottleErrorCodes](https://github.com/aws/aws-sdk-go-v2/blob/main/aws/retry/standard.go)). An emulator returning any of these (for example fault injection) makes Terraform retry silently, up to 25 attempts.
- EventBridge and Logs opt out for one message each: a `LimitExceededException` whose message contains `The requested resource exceeds the maximum number allowed` (events) or `Resource limit exceeded` (logs) is not retried ([events service_package.go L22-L31](https://github.com/hashicorp/terraform-provider-aws/blob/972faab3f6e4e37aff0453fe05366f3bd3fc2b97/internal/service/events/service_package.go#L22), [logs service_package.go L22-L31](https://github.com/hashicorp/terraform-provider-aws/blob/972faab3f6e4e37aff0453fe05366f3bd3fc2b97/internal/service/logs/service_package.go#L22)).

### 1.4 Error matching

Two styles, both strict. Typed: `errs.IsA[*awstypes.X](err)` requires the wire error to deserialize into the SDK's typed error for that shape. Message: `errs.IsAErrorMessageContains[T](err, needle)` is typed match plus `strings.Contains` on the error message ([errs.go L23-L44](https://github.com/hashicorp/terraform-provider-aws/blob/972faab3f6e4e37aff0453fe05366f3bd3fc2b97/internal/errs/errs.go#L23)). Consequence: the error shape must be right and a handful of message substrings are load-bearing; they are collected in section 8.

### 1.5 Transparent tagging flow

## 9. Latency budget Terraform imposes

- Lambda function create: >= 5 s (waiter `Delay`), plus the GetFunction retry. Each config update and each code update: >= 5 s each. Publish: >= 5 s. Delete: >= 5 s ([function.go L1487-L1547](https://github.com/hashicorp/terraform-provider-aws/blob/972faab3f6e4e37aff0453fe05366f3bd3fc2b97/internal/service/lambda/function.go#L1487)). A function whose config and code both change spends >= 10 s in waiters regardless of how fast the emulator is. Terraform's default parallelism of 10 hides this for independent functions.
- Event source mapping waits start immediately with 200 ms steps, so a mapping that reaches `Enabled` in under a second costs under a second.
- IAM, EventBridge, Logs, CloudWatch have no fixed delay; the first read-after-write must succeed or the provider enters 500 ms-10 s retry loops of up to 2 min.

## 10. Implications for understudy

1. **CloudWatch needs rpcv2Cbor.** The pinned Go SDK speaks Smithy RPC v2 CBOR for CloudWatch (CORRECTED (G1): this said "and boto3"; boto3, the CLI and JS v3 send awsJson1_0, see [wire-cbor.md](wire-cbor.md), which also holds the full server contract and golden vectors) (path `/service/GraniteServiceVersion20100801/operation/<Op>`, `Smithy-Protocol: rpc-v2-cbor`, `application/cbor`). Query and JSON 1.0 alone will not serve `aws_cloudwatch_metric_alarm`. Serve CBOR, keep `awsQueryCompatible` behavior (send `X-Amzn-Query-Error` on errors; accept `X-Amzn-Query-Mode`), and verify the same question for every other service against the SDK pins used in the conformance suites rather than assuming Query. IAM stays awsQuery; Lambda restJson1; EventBridge and Logs awsJson1_1.
2. **Implement the Lambda state machine with real, observable transitions.** CreateFunction returns `State: Pending`, `StateReasonCode: Creating`, then flips to `Active`; updates flip `LastUpdateStatus` to `InProgress` then `Successful` while `State` stays `Active`. Reject `UpdateFunctionConfiguration`, `UpdateFunctionCode`, `PublishVersion`, `TagResource` with `ResourceConflictException` (409) while `Pending`/`InProgress`. Make the transition duration emulator-clock driven (default short, for example 50-500 ms); Terraform's own 5 s waiter `Delay` sets the floor either way.
3. **GetFunction contract.** Always include `Code` (non-nil) and `Configuration`; include `Tags`; include `Concurrency` only when reserved concurrency is set; echo the full list of stored config fields from section 2.1; omit unset optional objects (`Environment`, `ImageConfigResponse`, `DeadLetterConfig`, `Cors`, `ScalingConfig`, `FilterCriteria`, `RetryPolicy`).
4. **Versions.** `ListVersionsByFunction` returns `$LATEST` first, then ascending numeric versions, with working `Marker`/`NextMarker` and `MaxItems` up to 10000. `PublishVersion` returns the qualified ARN; `GetFunctionConfiguration` must accept `FunctionName=<qualified ARN>` together with an equal `Qualifier`.
5. **Resource policy engine for Lambda.** Store statements as the provider parses them: scalar `Action`/`Resource`, `Principal` as string or `{AWS|Service}`, `Condition` as `map[string]map[string]string` with `ArnLike -> AWS:SourceArn`, `StringEquals -> AWS:SourceAccount | lambda:FunctionUrlAuthType | aws:PrincipalOrgID | lambda:EventSourceToken`, `Bool -> lambda:InvokedViaFunctionUrl`. Duplicate Sid is `ResourceConflictException` with the AWS wording `The statement id (<sid>) provided already exists...` (the function-URL resource matches on that substring). Last statement removed -> `GetPolicy` returns 404.
6. **GetFunctionCodeSigningConfig** must exist and return 200 for any function in a signer-listed region (all commonly used test regions are): the provider calls it on every Zip function read. Return the function name and no config ARN (the response shape requires both fields; behavior when unset is UNVERIFIED).
7. **Event source mappings.** UUID ids; `EventSourceMappingArn` of the form `arn:aws:lambda:<region>:<acct>:event-source-mapping:<uuid>` (UNVERIFIED format; the tag APIs take whatever ARN the response carried). State machine `Creating -> Enabled|Disabled`, `Updating`, `Enabling`/`Disabling`, `Deleting -> 404`; `Updating` is pending only for update waits, so never report `Updating` during create. SQS defaults: `BatchSize` 10, window 0; reject `BatchSize` > 10 with window 0 as AWS documents. `UpdateEventSourceMapping` and `DeleteEventSourceMapping` return `202`; `ResourceInUseException` (400) while transitioning. Emit `FunctionResponseTypes` as given.
8. **Function URLs.** Return `FunctionUrl` as a parseable URL whose first host label is the url id (provider derives `url_id` from it); a local form such as `http://<url-id>.lambda-url.<region>.localhost:<port>/` keeps that contract (host-header routing); verify `*.localhost` resolution on the CI resolvers before relying on it (UNVERIFIED). Always return `InvokeMode`.
9. **IAM is stored-only but format-exact.** URL-encode policy documents in `GetRole`, `GetRolePolicy`, `GetPolicyVersion` (RFC 3986; `+` as `%2B`); include `Tags` in `GetRole`/`GetPolicy`; return `MaxSessionDuration` 3600 default and `CreateDate`; role ARN `arn:aws:iam::<acct>:role<path><name>`; paginate `ListRolePolicies`, `ListAttachedRolePolicies`, `ListPolicyVersions` with `Marker`/`IsTruncated`; `ListInstanceProfilesForRole` must work (called on every role delete); enforce `DeleteConflict` for roles/policies still holding attachments, 5-version cap with `LimitExceeded`, `EntityAlreadyExists`, `NoSuchEntity` with HTTP 404 and wire codes from the `awsQueryError` trait.
10. **AWS-managed policy ARNs.** Terraform attaches `arn:aws:iam::aws:policy/...` ARNs for Lambda roles. Accept any well-formed AWS-managed ARN on `AttachRolePolicy` and derive `PolicyName` from the last path segment for `ListAttachedRolePolicies`, or ship a small catalog of stubs; do not return `NoSuchEntity`. Do not emulate the "Invalid principal in policy" rejection (phase 1 stores only); Terraform would otherwise retry for 2 minutes.
11. **EventBridge.** Default bus must exist implicitly. `PutTargets` returns `FailedEntryCount: 0`; `ListTargetsByRule` must list a just-written target (no retry on read) and honour `Limit`/`NextToken`; `DeleteRule` with targets fails with `ValidationException` and a message containing `Rule can't be deleted since it has targets`; store and echo `Input`, `InputPath`, `InputTransformer` exactly; never add a default `RetryPolicy`; `PutRule` replaces (not merges) and ignores `Tags` on update; echo `EventPattern` and `ScheduleExpression` unchanged.
12. **CloudWatch Logs.** `DescribeLogGroups` prefix filter and `nextToken` pagination; return both `arn` (with `:*`) and `logGroupArn`; tag APIs keyed by the ARN without `:*` (accept both); absent `retentionInDays` means no expiry; Lambda must not pre-create `/aws/lambda/<name>`, only the first invocation does (on the emulator clock), and only if missing.
13. **CloudWatch alarms.** `DescribeAlarms` with `AlarmNames` + `AlarmTypes=["MetricAlarm"]`, `NextToken`; `PutMetricAlarm` replaces config, keeps state, ignores tags on update; initial `StateValue: INSUFFICIENT_DATA`; `DeleteAlarms` of unknown names succeeds; no invented defaults for unset optional fields; `ListTagsForResource`/`TagResource`/`UntagResource` keyed by `AlarmArn`.
14. **Fault injection and throttling interplay.** Injected `LimitExceededException`, `TooManyRequestsException`, `Throttling*` or any 5xx will be retried by the SDK up to 25 times before Terraform even sees them (section 1.3); injected conflict-type errors (`ResourceConflictException`, IAM `ConcurrentModification`) are retried by the provider for minutes. Document this so fault rules produce the intended signal.
15. **Conformance fixtures to derive from this note.** A Terraform module per resource group with the sequence `apply`, `plan -detailed-exitcode` (expect 0), update one attribute, `apply`, `plan` (expect 0), `destroy`. The register in section 7 is the checklist of attributes to cover; the targeted provider version is 6.68.0.
16. **Control-plane rate limits are not worth emulating** (GetFunction 100 rps, GetPolicy 15 rps, other control plane 15 rps on real AWS, [quotas](https://docs.aws.amazon.com/lambda/latest/dg/gettingstarted-limits.html)), but bodies are: direct zip upload 50 MB, unzipped 250 MB, env vars 4 KB total, resource policy 20 KB, 5 layers, memory 128-32768 MB in the API schema ([quotas](https://docs.aws.amazon.com/lambda/latest/dg/gettingstarted-limits.html), [CreateFunction](https://docs.aws.amazon.com/lambda/latest/api/API_CreateFunction.html)). A request-body cap above ~67 MB (base64 of 50 MB) is needed for `CreateFunction` with an inline `ZipFile`.
