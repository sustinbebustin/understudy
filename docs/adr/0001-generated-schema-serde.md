# ADR 0001: Generated schema serde, not reflection codecs

Status: accepted, 2026-10-08.

## Context

Phase 1 serves six wire protocols (awsJson1_0, awsJson1_1, awsQuery, restJson1, restXml, rpcv2Cbor) for twelve services and must pass the Smithy protocol compliance corpus, whose synthetic services use shape kinds the AWS models do not (documents, `intEnum`, sparse collections, `byte`, `short`, `float`, `bigInteger`) (`smithy-protocol-tests.md 3`, `smithy-models.md 2`). The brief requires generated request and response shapes. Two designs were proposed: generated per-shape `Serialize`/`Deserialize` methods driving codec interfaces (the aws-sdk-go-v2 schema-serde design, `go-toolchain.md 14.2`), or hand-written reflective codecs walking struct tags with a per-type plan cache (the simplicity proposal, 4.4).

## Decision

Generate `Serialize(smithy.Serializer)` and `Deserialize(smithy.Deserializer) error` for every shape in every operation's closure, plus static `smithy.Schema` descriptors carrying the wire traits. Each protocol is one hand-written codec implementing the two interfaces (`internal/protocol/<proto>`), with `restbind` splitting HTTP-bound members in front of the body codecs. The same generator emits the synthetic protocol-test services, so the codecs under test are the ones the real services use. Generated code lives in `internal/api/<svc>api` and `internal/protocoltest/gen`.

## Alternatives considered

- Reflective codecs over struct tags: six codecs instead of six emitters and roughly a tenth of the generated volume. Rejected because wire traits would be duplicated into tags (a second, less reviewable schema), reflection cannot express the corpus's shape kinds without extra tag vocabulary, and a tag typo is a runtime failure rather than a compile error. The plan cache seam the proposal offered as an escape hatch is exactly the serde interface this decision starts from.
- A runtime schema interpreter with no per-shape generated code: smaller output, slower, and every shape walk is dynamic. Rejected for the same type-safety reason; the descriptors are still generated, so the interpreter buys little.
- The SDK's legacy per-operation middleware serializers (`service/s3`): not a server model (`go-toolchain.md 17.10`).

## Consequences

- Generated volume is large (5,487 shapes across the models). Wave 1 measures build time and binary size on the SQS slice and records them here; if they become a problem, the escape hatch is pruning the generated closure per service through `codegen/services/<svc>.json`, not a change of design.
- A codec bug is fixed in one codec and proven by the corpus; generated serde never contains protocol logic.
- Adding a shape kind means one emitter change and one method on two interfaces.
- `encoding/json/v2` and `jsontext` are imported only by `protocol/jsonx`, so a toolchain-era API change is a one-file fix (`go-toolchain.md 2`).

## Amendments (review, 2026-10-08)

- Serde is generated by shape role (engineering M13): `Deserialize` and `Validate` for shapes reachable from inputs, `Serialize` for shapes reachable from outputs and errors, both for shapes in both roles, for `rawBinding` services and for `protocoltest/gen`. Internal calls pass Go values, so the server needs no other direction.
- `@streaming` blob members are generated as `smithy.Body` (input) and `smithy.BodySource` (output), never `[]byte` (fidelity F1). The head of a REST request is decoded and validated before the handler; the handler pulls the body after its own pre-checks.
- Budgets are numbers, not a measurement to record (product M6): stripped `linux/amd64` binary 48 MiB, ready `/health` within 250 ms, idle RSS 128 MiB, cold `go build ./...` 180 s, `golangci-lint` 600 s. `just budgets` gates them in CI from the wave that generates all twelve models; a breach is fixed by role pruning or closure tightening.
