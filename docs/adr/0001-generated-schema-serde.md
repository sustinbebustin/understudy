# ADR 0001: Generated schema serde, not reflection codecs

Status: accepted, 2026-10-08.

## Context

understudy serves six wire protocols (awsJson1_0, awsJson1_1, awsQuery, restJson1, restXml, rpcv2Cbor), at first for twelve services. It must pass the Smithy protocol compliance corpus, whose synthetic services use shape kinds the AWS models do not: documents, `intEnum`, sparse collections, `byte`, `short`, `float`, `bigInteger` (`smithy-protocol-tests.md 3`, `smithy-models.md 2`). Request and response shapes must be generated from the models. Two designs were considered: generated per-shape `Serialize`/`Deserialize` methods driving codec interfaces (the aws-sdk-go-v2 schema-serde design, `go-toolchain.md 14.2`), or hand-written reflective codecs walking struct tags with a per-type plan cache.

## Decision

Generate `Serialize(smithy.Serializer)` and `Deserialize(smithy.Deserializer) error` for every shape in every operation's closure, plus static `smithy.Schema` descriptors carrying the wire traits. (The amendment of 2026-10-08 generates each direction only where a shape's role needs it; the amendment of 2026-11-02 prunes the closure to bound operations.) Each protocol is one hand-written codec implementing the two interfaces (`internal/protocol/<proto>`), with `restbind` splitting HTTP-bound members in front of the body codecs. The same generator emits the synthetic protocol-test services, so the codecs under test are the ones the real services use. Generated code lives in `internal/api/<svc>api` and `internal/protocoltest/gen`.

## Alternatives considered

- Reflective codecs over struct tags: six codecs instead of six emitters and roughly a tenth of the generated volume. Rejected because wire traits would be duplicated into tags (a second, less reviewable schema), reflection cannot express the corpus's shape kinds without extra tag vocabulary, and a tag typo is a runtime failure rather than a compile error. The plan cache seam that design offered as an escape hatch is exactly the serde interface this decision starts from.
- A runtime schema interpreter with no per-shape generated code: smaller output, slower, and every shape walk is dynamic. Rejected for the same type-safety reason; the descriptors are still generated, so the interpreter buys little.
- The SDK's legacy per-operation middleware serializers (`service/s3`): not a server model (`go-toolchain.md 17.10`).

## Consequences

- Generated volume is large (5,487 shapes across the models). Build time and binary size are budgeted (amendment of 2026-10-08). If they become a problem, the escape hatch is pruning the generated closure per service through `codegen/services/<svc>.json`, not a change of design. The amendment of 2026-11-02 takes it.
- A codec bug is fixed in one codec and proven by the corpus; generated serde never contains protocol logic.
- Adding a shape kind means one emitter change and one method on two interfaces.
- `encoding/json/v2` and `jsontext` are imported only by `protocol/jsonx`, so a toolchain-era API change is a one-file fix (`go-toolchain.md 2`).

## Amendment 2026-10-08: serde by shape role, streaming bodies and budgets

- Serde is generated by shape role: `Deserialize` and `Validate` for shapes reachable from inputs, `Serialize` for shapes reachable from outputs and errors, both for shapes in both roles, for `rawBinding` services and for `protocoltest/gen`. Internal calls pass Go values, so the server needs no other direction.
- `@streaming` blob members are generated as `smithy.Body` (input) and `smithy.BodySource` (output), never `[]byte`. The head of a REST request is decoded and validated before the handler; the handler pulls the body after its own pre-checks.
- Budgets are numbers, not a measurement to record: stripped `linux/amd64` binary 48 MiB, ready `/health` within 250 ms, idle RSS 128 MiB, cold `go build ./...` 180 s, `golangci-lint` 600 s. `just budgets` gates them in CI; a breach is fixed by role pruning or closure tightening.

## Amendment 2026-11-02: closure pruning

- The escape hatch is taken, at 47.5 of the 48 MiB. A `codegen/services/<svc>.json` that lists `boundOperations` gets schema members only for the error shapes and the closures of the listed operations' inputs and outputs. Every other shape keeps its `smithy.Schema` with ID and traits but no members, so descriptors, `docs/coverage.md` and the coverage JSON are unchanged. Go types, serde, validation, `Op` handles and binder methods stay for every operation: tests use the unbound ones, and the linker already drops the dead serde. One exception: an unbound input with a member targeting a `@streaming` shape keeps its own members, because signature verification reads them before the 501 (`internal/edge/verify.go`, the restxml `BodyLimit`).
- Why this is safe: an unbound operation answers 501 before reading its input (`Kernel.NewInput`), REST routing matches generated route rows, and coverage reads only schema IDs.
- Why a list in config: the bound set exists only once `internal/server` wires the services, which import the generated packages, so the generator cannot derive it. `internal/server/bound_config_impl_test.go` ties each list to the kernel's bound set and names the edit when they differ.
- Schemas are also linked statically (`Target` and `Members` in the variable literals) instead of in `init`, except recursive shapes. Together: 47.5 to 44.3 MiB stripped.

## Amendment 2026-11-11: next binary-size levers

- A stripped `linux/amd64` build (`CGO_ENABLED=0 go build -trimpath -ldflags='-s -w' ./cmd/understudy`, as `just budgets` builds it) measures 44.48 MiB against the 48 MiB budget. If the budget binds again, cut in this order. Sizes are the text of the symbols concerned, from `go tool nm -size -sort size` on the same build without `-s -w`, summing `T` symbols that match the pattern; an overlapping symbol counts once per lever.
- Per-shape `slices.*CmpFunc` instantiations: 651 instantiations, 0.97 MiB (pattern `slices\.[A-Za-z]*CmpFunc\[`). Total-order comparators over distinct element types each stamp out their own sort and search bodies. Sharing one comparator shape per ordering (sort a slice of keys, not of structs) removes most of them.
- `jsonx` `Variant` and `Union`: 1,116 generic instantiations, 0.43 MiB (pattern `jsonx\.\(?\*?(Variant|Union)\[`); 0.51 MiB counting their non-generic helpers. The earlier estimate of 0.13 MiB was low.
- Binding all of a large service: removing `boundOperations` from `codegen/services/ssm.json` (13 bound operations of the service's full set), regenerating `ssmapi` and rebuilding grew the stripped binary from 44.48 to 44.98 MiB, +0.50 MiB. That is the cost of unpruned schema members for one large service; binding another service's operations costs the same order, in handler code on top.
